NiceEval 将运行后的数据分成三层。Record 保存封口后的运行事实。Inspection operation 关闭读取语义。三个 consumer 各自交付结果。

```text
sealed Record facts
        ↓
fixed Inspection operations
        ↓
machine Query | terminal Show | browser View
```

## Record 保存事实

每个完整 Run 发布到项目的 `.niceeval/record/record.sqlite`。已发布事实不可修改。这个 operational database 属于 Record Host，不能直接复制给另一个进程读取。

需要携带已封口事实时，运行 `niceeval record snapshot --output <path>`。得到的 `RecordSnapshot` 是唯一可传给 `--record` 的输入。

## Inspection 关闭读取语义

Inspection operation 在返回前决定 source、selector、sealed cutoff、数据缺口、issues、Evidence 和比较方式。它返回可编码 plain data，不把 reader、数据库连接或文件路径交给调用者。

固定 catalog 提供 Run、Attempt、trace、diff、sources、artifacts 和 Run comparison。新的读取需求通过新 operation 或穷尽 union 扩展表达，不通过临时 SQL、JSON path 或公式实现。

## 三个独立 Consumer

- `niceeval query` 是 machine Query，面向 AI、脚本和 CI。它输出 `niceeval.query/v1` JSON document。
- `niceeval show` 是 terminal Show，面向人在终端快速审阅和下钻。
- `niceeval view` 是 browser View，面向人在 loopback 浏览器使用固定第一方 Insight。

三个 consumer 共享同一个固定 Inspection result。它们各自负责 JSON protocol、终端文字布局或浏览器界面，不共享 formatter、路由、组件、主题或呈现 schema，也不重选成员或重算业务结果。
