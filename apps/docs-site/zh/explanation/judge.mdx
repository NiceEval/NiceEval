Judge 用独立裁判模型评估事实一致性、摘要忠实度和说明质量。它是一种受管 evaluator。普通自定义
`ScoreMatch` 保持纯函数，只有 `defineJudge` 返回的定义能调用模型。

## 声明评分定义

在模块顶层写出标准。`rubric` 说明评价维度，`anchors` 给连续质量量尺提供可校准的落点：

```ts
import { defineJudge } from "niceeval";

const explainsRisk = defineJudge({
  name: "explains-risk",
  rubric: "根据 change 评价 explanation 是否说明兼容性、回滚方式和数据风险。",
  anchors: [
    { measurement: 0, description: "没有说明具体风险或回滚方式" },
    { measurement: 0.5, description: "说明部分风险，但遗漏一项关键内容" },
    { measurement: 1, description: "完整说明兼容性、回滚方式和数据风险" },
  ],
});
```

省略 `anchors` 时，NiceEval 使用 0 和 1 两个默认端点。measurement 可以是 `[0,1]` 中的任意有限数值；
端点不是二元输出限制，也不是模型置信度。

## 选择评价材料

把定义放进评估的 `judge` 字段，再把完成判断所需的值直接交给 `t.judge`：

```ts
export default defineEval({
  judge: explainsRisk,
  async test(t) {
    const change = "修改持久化字段并提供回滚方案";
    const turn = await t.send(`解释这项变更：${change}`);

    t.judge({ change, explanation: turn.message }, explainsRisk)
      .gate(0.8)
      .label("风险说明质量");
  },
});
```

材料使用字符串、有限数字、布尔值、null、数组和普通对象。字段名应表达应用语义，例如 `change` 与
`explanation`，无需把对象先拼成文本。NiceEval 在登记 Assertion 时生成有界 JSON 快照；之后修改原对象不会改变请求。

同一个评估可以声明一个定义，也可以声明非空数组。运行时只能使用这份允许列表中的定义实例；同名的另一份定义不会借到权限。

## 配置裁判模型

`judge` 属于评估定义，`judgeRuntime` 属于项目配置或实验：

```ts
export default defineConfig({
  judgeRuntime: {
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
    maxOutputTokens: 512,
  },
});
```

NiceEval 使用固定 Decision Tool 请求有限 `[0,1]` measurement 和公开 rationale。未配置模型或 Key 时不会发送网络请求，Assertion 为 `unavailable`。
端点不支持 Decision Tool 是 Setup Error；传输失败或超时是 `unavailable`；非法 Decision 是 `errored`。

## Threshold 与分数

通过制与计分制都在登记后的 handle 上调用 `.gate(minimum)` 形成质量门。计分制还可调用
`.score(points)`，贡献值为 measurement 乘 points。gate 与 score 可任意先后组合，两种方式都只执行一次 Judge。

成功请求保存实际发送的固定材料。URL 或 alt 不是视觉输入；需要判断图片本身时，必须使用明确支持图像的能力。
