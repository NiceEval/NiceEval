Judge 用独立裁判模型评估事实一致性、摘要忠实度和说明质量。它是一种受管 evaluator。普通自定义
`ScoreMatch` 保持纯函数；`defineJudge`、现成 factory 与高级受管 `defineScoreMatch` 都走同一条 Assertion 路径。

## 声明评分定义

在模块顶层写出标准。`rubric` 说明评价维度，`anchors` 给连续质量量尺提供可校准的落点：

```ts
import { closeQA, defineJudge } from "niceeval";

const explainsRisk = defineJudge({
  name: "explains-risk",
  rubric: "根据 change 评价 explanation 是否说明兼容性、回滚方式和数据风险。",
  anchors: [
    { measurement: 0, description: "没有说明具体风险或回滚方式" },
    { measurement: 0.5, description: "说明部分风险，但遗漏一项关键内容" },
    { measurement: 1, description: "完整说明兼容性、回滚方式和数据风险" },
  ],
});
```

省略 `anchors` 时，NiceEval 使用 0 和 1 两个默认端点。measurement 可以是 `[0,1]` 中的任意有限数值；
端点不是二元输出限制，也不是模型置信度。

## 选择评价材料

把完成判断所需的值直接交给 `t.judge`。Eval 的 `judge` 只用于为这道题指定模型配置：

```ts
export default defineEval({
  judge: "judge-model",
  async test(t) {
    const change = "修改持久化字段并提供回滚方案";
    const turn = await t.send(`解释这项变更：${change}`);

    t.judge({ change, explanation: turn.message }, explainsRisk)
      .gate(0.8)
      .label("风险说明质量");
  },
});
```

材料使用字符串、有限数字、布尔值、null、数组和普通对象。字段名应表达应用语义，例如 `change` 与
`explanation`，无需把对象先拼成文本。NiceEval 在登记 Assertion 时生成有界 JSON 快照；之后修改原对象不会改变请求。

`t.judge(material, explainsRisk)` 与 `t.check(material, explainsRisk)` 都登记一条测量 Assertion。它们会共享材料快照、预算、求值、审计、封口和 handle；没有 Match 允许列表。

## 直接使用现成 Judge

root `t`、Session 与 Turn 都提供现成方法，并返回 Assertions 的 `MeasurementAssertionHandle<Kind>`。例如：

```ts
const answer = await t.send("根据材料回答问题。");

answer.closeQA({
  input: "根据材料回答问题。",
  output: answer.message,
  context: "材料只说明产品在周五发布。",
}).gate(0.8).label("只依据材料回答");

// 与上一条调用等价的 factory 形式：
answer.check(
  { input: "根据材料回答问题。", output: answer.message, context: "材料只说明产品在周五发布。" },
  closeQA(),
).gate(0.8);
```

可直接调用的方法是 `factuality(material, options?)`、`faithfulness(material, options?)`、`instructionFollowing(material, options?)`、`pairwisePreference(material, options?)` 和 `closeQA(material, options?)`。它们只 factory 后交给当前接收者的 `check`，不会多登记 Assertion。

## 配置裁判 Provider

项目配置用具名 Provider 工厂显式选择服务。下例连接 OpenAI 或显式兼容网关：

```ts
import { defineConfig } from "niceeval";
import { OpenAIProvider } from "niceeval/judge";

export default defineConfig({
  judgeRuntime: OpenAIProvider({
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
    maxOutputTokens: 512,
  }),
});
```

| 工厂 | 服务 | 默认 key 变量 |
| --- | --- | --- |
| `OpenAIProvider` | OpenAI 或显式兼容网关 | `OPENAI_API_KEY` |
| `VercelProvider` | Vercel AI Gateway | `AI_GATEWAY_API_KEY` |
| `OpenRouterProvider` | OpenRouter | `OPENROUTER_API_KEY` |
| `TypesafeProvider` | TypeSafe System One | `TYPESAFE_API_KEY` |

四个工厂都从 `niceeval/judge` 导出。Vercel 工厂表示 AI Gateway，不表示 Vercel Sandbox 或通用 AI SDK model object。

某道评估只需换模型时，写下这一项即可：

```ts
export default defineEval({
  judge: "another-model",
  async test(t) {
    const answer = await t.send("法国首都是哪里？");
    t.factuality({ input: "法国首都是哪里？", output: answer.message, expected: "巴黎" }).gate(1);
  },
});
```

这里继续使用全局 Provider 的端点、凭据来源和执行限制，只替换 `model`。
Eval 和 Experiment 也能提供完整 Provider；这会整体替换服务、默认模型和限制。
没有按 hostname、模型前缀或已存在的 key 猜测服务的规则。

NiceEval 使用所选 Provider 的受管协议请求取得有限 `[0,1]` measurement 和公开 rationale。聊天服务使用 forced-function 请求，TypeSafe 使用 `/systemone`。未配置模型或 Key 时不会发送网络请求，Assertion 为 `unavailable`。传输失败或超时是 `unavailable`；HTTP 400、协议不兼容或非法响应是 `errored`。静态配置校验不会探测网络。

TypeSafe 使用 `/systemone` 协议。它支持 score、classify 和 batch classify，但不支持 extract。
因此 `faithfulness()` 在 `TypesafeProvider` 上得到 `unavailable`，不会改为整体估分或更换分母。

## Threshold 与分数

通过制与计分制都在登记后的 handle 上调用 `.gate(minimum)` 形成质量门。计分制还可调用
`.score(points)`，贡献值为 measurement 乘 points。gate 与 score 可任意先后组合，两种方式都只执行一次 Judge。

成功请求保存实际发送的固定材料。URL 或 alt 不是视觉输入；需要判断图片本身时，必须使用明确支持图像的能力。
