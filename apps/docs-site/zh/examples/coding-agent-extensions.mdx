这个案例把扩展内容作为 Experiment 变量，让同一个 Coding Agent 在同一批真实开发任务上运行，再比较任务成功率、成本、耗时和行为差异。

- [查看完整源码](https://github.com/CorrectRoadH/coding-agent-skill)
- [查看 Fixtures 指南](/zh/tutorials/fixtures)

## 两组实验

| 实验 | 对照 | 测什么 |
| --- | --- | --- |
| Zod Skill | `with-skill` vs `baseline` | Skill 是否让 Agent 稳定使用 `z.object().safeParse()`，而不是退回手写校验 |
| Ponytail Benchmark | Baseline / Caveman / Ponytail / YAGNI One-liner | 完整决策 Skill 是否比不加 Skill 的 Agent、简短风格 Skill 或一句提示更有效 |

Ponytail 这一组迁移自第三方 Plugin 的 Agentic Benchmark，但这个仓库实际比较的是注入给 Agent 的内容与提示。它不用于证明某个原生 Plugin 包装或安装协议是否正确。原生 Skill / Plugin 的安装配置见 [官方适配器](/zh/reference/official-adapters)。

## 实验设计

每个 Arm 固定相同的模型、Sandbox、任务集、Runs 和预算，只改变注入内容。评估用例不读取“当前是哪个 Arm”，也不为某个对照配置降低验收标准。

```text
coding-agent-skill/
├── skills/                  # 各 Arm 注入的内容
├── workspaces/ts-starter/   # 每个评估用例的初始项目
├── evals/                   # 真实开发任务与验证
├── experiments/             # Baseline 和实验 Arm
```

验证优先看最终产物：项目测试、隐藏探针、源码和 Diff。只有事件稳定且完整时，才把 Skill Load 或工具调用作为 Gate。

## 评估自己项目的随包指引

开发工具常常没有 AI 入口，只给 coding agent 分发指引：托管的 `AGENTS.md` 段落、skill、`--skill` 命令，或用 `init` 装进用户项目的文档。要回答「这套指引有没有让 Agent 按工具的流程干活」，被测对象是 Coding Agent，处理组和基线组的差别就是这套指引。不要给工具的 CLI 写 Adapter，那只能测出工具本身对不对。

- **两组只差指引本身。** 安装步骤除了写指引还生成脚手架（配置、模板、目录结构）时，基线也要拿到同样的脚手架，只是不带指引文件；否则比较的是「初始化过的项目」和「没初始化的项目」。基线也不能从工作区里已有的 `AGENTS.md` 或 skill 读到同样的内容。
- **锁定工具版本。** Sandbox 里安装的工具钉到具体版本或提交，不装 latest，也不直接构建会变的本地工作区。
- **任务是真实开发。** 给 Agent 一个由这个工具管理的项目，让它改一个行为或修一个缺陷；不要问「这个工具怎么用」这类问答。至少准备两类不同流程的任务，例如新增行为和修复缺陷。
- **判据要能抓住跳过流程。** 用命令退出码和文件内容检查指引要求的流程产物，例如规定先改的设计文件确实改了、测试确实带着指引要求的标记、工具自带的检查命令通过。只检查项目测试通过的话，Agent 跳过指引直接改代码也能拿满分，两组就分不出差别。
- **内层 Agent 也花钱。** 它照样调用模型。首跑前和用户确认 Judge、Attempt 数和预算。

## 跑起来

```bash
git clone https://github.com/CorrectRoadH/coding-agent-skill.git
cd coding-agent-skill
pnpm install
cp .env.example .env
docker info

pnpm exec niceeval exp ponytail-baseline
pnpm exec niceeval exp caveman
pnpm exec niceeval exp ponytail
pnpm exec niceeval exp yagni-oneliner
pnpm exec niceeval view run:<baseline-run-id> run:<candidate-run-id>
```

## 从这个案例复用什么

- 用 Experiment 表达有扩展和无扩展的对照，不让评估用例知道实验条件。
- Prompt 不泄露答案。验证阶段再检查测试、源码、Diff 和行为证据。
- 把任务成功率作为主指标，把 Token、成本、耗时和行为作为解释指标。
- [题型与断言](/zh/tutorials/evaluation-kinds) 负责选择 Gate、Soft 和 Judge。本页不复制断言 API。
