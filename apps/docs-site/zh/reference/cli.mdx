运行评估用 `niceeval exp`。读取结果有三条路：脚本和 CI 用 `niceeval show --json` 取 JSON，人和 Coding Agent 在终端用 `niceeval show` 逐层查看，在浏览器里审阅用 `niceeval view`。

三条路读的是同一份运行记录 `.niceeval/record.sqlite`。每次读取开始时，NiceEval 会固定一个可见边界：此刻已经写入的结果都能看到，之后写入的不会混进这次读取。所属 Run 还在运行时，已经写入的 Attempt 也能读到。

把 `niceeval exp` 的输出接到管道时，stdout 仍会显示进度。每行带上 Experiment、评估用例和 Attempt 序号。同一个 Attempt 每秒最多输出一次，内容没变就不重复输出。直接在终端里运行时显示动态面板。脚本要读结构化结果时加 `--json`。

重复传入 `--experiment` 可以一次运行多个实验，例如 `niceeval exp --experiment baseline --experiment memory --max-concurrency 4`。这些实验在同一次运行里共享并发上限和预算。同一个 ID 写两次只运行一次。只要有一个 ID 不存在，整条命令在开始执行前就会失败。用了 `--experiment` 后，位置参数用来筛选评估用例。

### `--dry` 沿用状态

`niceeval exp <experiment> --dry` 只读计划，不执行评估。每行是一个实验与评估用例的组合，`reused 0`、`gap 0:...` 中的数字是从 0 开始的 Attempt 序号。

| 状态 | 含义与是否需要处理 | 下一步 |
| --- | --- | --- |
| `reused` | 旧结果符合当前条件，会沿用；无需处理 | `niceeval show @<locator>` 查看来源，去掉 `--dry` 执行计划 |
| `gap` | 当前槽位没有可沿用的结果；先核对冒号后的原因 | `niceeval exp <experiment> <eval-prefix> --dry --json` 查看比较明细 |
| `locked` | 检测到该实验与评估用例的执行锁；不代表已完成，也不代表可沿用 | 等持锁执行结束，用 `niceeval show --run <run-id>` 查看，再运行 `--dry` |
| `prior` | `source` 行是历史候选，并未被这次计划采用；无需删除旧结果 | `niceeval show @<locator>` 查看候选，按 `gap` 原因处理 |
| `via` | 通过具名的身份计算版本变更证明输入等价；无需手动接受 | `niceeval exp <experiment> --dry --json` 核对变更名 |
| `no slots` | 这一行没有当前计划槽位；不能当作成功执行 | `niceeval exp <experiment> --dry --json` 核对选择范围 |

`source` 后面的 `verdict` 是历史判定：`passed` 为通过，`failed` 为断言失败，`errored` 为执行出错，`skipped` 为跳过。
`errored`、`skipped` 需要按缺口原因决定重跑；用 `niceeval show @<locator>` 查看详情。
若显示 `not-recorded`、`migration-required`、`unsupported` 或 `invalid`，表示判定附件未记录、需要迁移、版本不支持或内容无效；不能把它们读成通过。
先运行 `niceeval show @<locator> --assertions` 取证。支持的历史格式由 NiceEval 自动升级；不支持或无效的记录应保留并报告。

### `--dry` 缺口代码

下表列出 `gap <序号>:<代码>` 的全部原因。表中的“重跑”指先核对费用与选择范围，再运行 `niceeval exp <experiment> <eval-prefix>`；这会保留历史结果。
同时显示 `locked` 时先等待持锁执行结束，再判断缺口。

| 代码 | 含义 | 需要的动作与下一步命令 |
| --- | --- | --- |
| `no-source-run` | 没有该目标的历史 Run | 首次执行，核对范围后重跑 |
| `source-slot-missing` | 最近来源 Run 没有这个 Attempt 槽位 | 常见于增加次数；核对 `--dry --json` 后重跑缺口 |
| `source-member-missing` | 来源 Run 有计划槽位，但没有已发布的 Attempt 成员 | 可能尚在执行或已中断；先 `niceeval show --run <run-id>`，结束后重跑缺口 |
| `source-core-invalid` | 来源的核心记录或关联不合法 | 保留证据，用 `niceeval show --run <run-id>` 取证并报告；不要改写 Record |
| `source-publication-unavailable` | 来源 Attempt 的发布证据不可用 | 用 `niceeval show @<locator>` 取证；确认运行结束后重跑缺口 |
| `source-attachment-unavailable` | 沿用所需附件未记录或缺失 | 用 `niceeval show @<locator> --assertions` 和 `--timing` 取证，再重跑 |
| `source-attachment-migration-required` | 所需附件需要格式迁移 | 保留原项目及 `.niceeval`，用原 NiceEval 版本读取或导出；需要重新执行时使用不含 `.niceeval` 的独立项目副本 |
| `source-attachment-unsupported` | 当前安装版本不支持来源附件 | 核对安装版本，用 `niceeval show @<locator>` 保存诊断并报告 |
| `source-attachment-invalid` | 所需附件内容无效 | 保留记录，用 `niceeval show @<locator>` 取证并报告 |
| `reuse-contract-domain-mismatch` | 两次结果采用不同的沿用契约版本域 | 核对 `--dry --json`；无法证明等价时重跑 |
| `reuse-contract-mismatch` | 沿用契约不同 | 核对 `--dry --json` 中的比较项，再重跑 |
| `identity-mismatch` | 当前执行身份与来源不同 | 阅读具体差异；必要时用 `niceeval accept @<locator> --dry` 检查采用资格，否则重跑 |
| `identity-domain-mismatch` | 身份计算的版本域不同 | 核对 `--dry --json` 中的诊断；未登记的变化应报告，行为变化需要重跑 |
| `duration-domain-mismatch` | 历史耗时与当前超时规则使用不同的计量域 | 用 `niceeval show @<locator> --timing` 核对，再重跑 |
| `timeout-exceeded` | 历史执行耗时超过当前超时限制 | 核对当前 `timeout`；用 `--timing` 查看耗时，确认限制后重跑 |
| `attempt-outcome-ineligible` | 历史执行状态不符合沿用条件 | 用 `niceeval show @<locator>` 排查执行问题，再重跑 |
| `adoption-unproven` | 无法证明引用的旧结果适用于当前目标 | 用 `niceeval accept @<locator> --dry` 查看拒绝原因；不要强行采用，必要时重跑 |
| `verdict-ineligible` | 历史判定不是可沿用的 `passed` 或 `failed` | 用 `niceeval show @<locator>` 排查 `errored` 或 `skipped`，再重跑 |
| `score-incomplete` | 纯分数评估没有完整分数 | 用 `niceeval show @<locator> --assertions` 排查判分，再重跑 |
| `adapter-behavior-revision-required` | Adapter 未声明可用于沿用的行为版本 | 作者声明 `behaviorRevision` 后再运行 `--dry`；不要把缺失版本当作等价 |
| `rerun-requested` | 本次 `--rerun` 主动要求执行 | 符合意图就执行；希望沿用时去掉 `--rerun` 再预览 |
| `sandbox-retention-requested` | 本次 `--keep-sandbox` 要求真实执行 | 符合意图就执行；希望沿用时去掉该选项再预览 |
| `unknown` | 没有可显示的原因代码 | 用 `--dry --json` 保存明细并报告，不猜测原因 |

### `--dry` 差异摘要

`changed`、`added`、`removed` 分别表示输入变化、新增或移除；先审阅该输入，再决定执行。`unknown` 表示无法比较，应查看 `--dry --json` 的诊断。
`config:` 是配置，`plan:physical` 是执行计划，`plugins:` 是生命周期插件，`source:` 与 `data:` 分别是源码和受管数据。

结构化摘要完整时会显示具体值。摘要不完整时，`summary sha256:<短哈希>` 区分两侧已保存的摘要；它不是完整执行身份的 digest，也不能恢复被省略的字段。
如果两份不完整摘要恰好相同，会显示一次 `comparison unavailable`，并说明无法比较的原因；这不代表输入相同。
需要更多证据时运行 `niceeval exp <experiment> --dry --json`。`--dry` 不修改历史 manifest，也不因摘要可读性改变沿用决定。

## `niceeval query`


```sh
niceeval query discover
niceeval query explain [--record <file>] (--request <file|-> | --request-json <document>)
niceeval query run [--record <file>] (--request <file|-> | --request-json <document>)
```

`query` 使用带版本号的 JSON 请求协议 `niceeval.query/v3`，每一种固定的读取问题叫一个 operation。成功的结果和协议里定义的失败，都会向 stdout 写出恰好一个 JSON 文档。参数无效时返回 failure 文档，退出码为 `2`。进程出错到无法生成文档时，错误只写到 stderr。

- `discover` 列出当前版本支持的 operation ID。它不读运行记录，所以不接受 `--record`，也不返回请求的字段结构。
- `explain` 校验完整请求，说明它会运行哪个 operation，以及接下来可以发哪些请求。
- `run` 执行请求，返回该 operation 的完整结果。

先用 `discover` 确认当前版本有哪些 operation，再按本页或[查看结果](/zh/tutorials/viewing-results)里的最小请求来写，并用 `explain` 校验。不要猜字段，也不要用 SQL、JSON path 或公式拼出另一种查询语言。

结果分页时会带一个续读 token。这个 token 记住了 operation、请求内容、读取的记录文件和这次读取的可见边界。任何一项变了，`query` 都不会接着读，而是返回 restart correction，表示调用方要从 `discover` 或重新发请求开始。

### 跨实验比较判据

```sh
niceeval show --experiment baseline --experiment candidate --assertions
niceeval show --experiment baseline --experiment candidate --assertions --eval install/db-gpt -o json
```

每张表对应一条评估用例，每列对应一个实验中的一次 Attempt。列标题给出实验 ID、Attempt 序号与可复制的定位符。
计分项显示得分与满分，不计分项显示判定，缺项显示 `—`。`*` 标记在各列间得分或判定不同的行。

机器读面是 `experiments.assertions`，请求包含 `experimentIds`，以及可选的 `evalIdPrefix` 路径前缀。
实验 ID 至少一个、最多 32 个，去重后排序；任一 ID 不存在时整个请求失败。
结果 `matrix.evals[]` 提供 `columns`、`rows` 与逐列 `unlabeled` 计数。同一 Attempt 内的重复身份保存在 cell 的 `entries[]`，不互相覆盖。
断言事实不可读时，cell 保留 `not-recorded`、`unsupported` 或 `failed`，不把这些状态冒充缺项。

矩阵最多包含 100 条评估用例，每条最多 100 列，总共最多 1000 行与 10000 格。
重复身份的每个条目各占一格；结果正文的 JSON 数组最多 450000 UTF-8 字节。
超限时 `matrix.state` 为 `partial`，`matrix.omitted` 分别列出省略的评估用例、行与列数。
`--entry`、`--compact` 和 `--full` 仅供查看单个 Attempt 的详情，不与矩阵组合。

### 常用 operation 的请求与结果字段

下面只列读取运行结果时常用的字段。请求顶层必须包含 `protocol: "niceeval.query/v3"` 和 `operation`，表中的参数放在 `operation` 内，与 `kind` 并列。成功响应的顶层 `outcome` 为 `"success"`。

| `operation.kind` | 必填参数 | 关键结果字段（从响应顶层开始） |
| --- | --- | --- |
| `run.list` | 无 | `runs[]` 中的 `runId`、`experimentId`、`state`、`startedAt`、`invocationId`、`coverage` |
| `run.get` | `runId`：Run ID | `run.plannedAttempts[]` 中的 `evalId`、`outcome`、`verdict`、`publication.action`、`publication.attemptLocator` |
| `experiment.get` | `experimentId`：实验 ID | `experiment.cells[]` 中的 `evalId`，以及 `members[]` 中的 `verdict`、`publication.attemptLocator`、`publication.action` |
| `attempt.get` | `locator`：包含 `@` 的 Attempt 定位符 | `attempt.verdict`、`attempt.core.evalId`、`attempt.originRun.experimentId` |

`run.get` 读取指定 Run 的计划与发布结果，`experiment.get` 读取每条评估用例当前采用的结果。局部重跑后，实验当前结果可以包含不同 Run 的 Attempt。发布结果的 `action` 为 `executed`、`carried` 或 `accepted`，分别表示本次执行、沿用已有结果或显式采用结果。

`run.plannedAttempts[]` 与 `experiment.cells[].members[]` 使用相同成员字段。`verdict`、`score`、`costUSD`、`durationMs` 和 `tokens` 与 `publication` 同级；未发布时，判定为 `null`，指标为 unavailable。

`publication` 只描述发布绑定。先检查 `publication.state` 是否为 `published`，再从 `publication.attemptLocator` 读取 Attempt 定位符。

用 `--request -` 从标准输入传入完整请求：

```sh
pnpm --silent exec niceeval query run --request - <<'JSON'
{
  "protocol": "niceeval.query/v3",
  "operation": { "kind": "run.list" }
}
JSON
```

不能写标准输入的调用方可以把完整请求作为一个 argv 值传入：

```sh
niceeval query run --request-json '{"protocol":"niceeval.query/v3","operation":{"kind":"run.list"}}'
```

两种传输使用同一套校验，不接受 operation 简写或部分字段。缺少传输选项，或同时传入两种选项，均为用法错误。

响应的 `runs[]` 会列出 Run ID。读取其中一个 Run 时，把请求的 `operation` 换为 `{ "kind": "run.get", "runId": "<run-id>" }`。请求必须通过 `--request <file|->` 或 `--request-json <document>` 传入，恰好选择一种。

选择的 Run、实验或 Attempt 不存在时，响应顶层为 `outcome: "failure"`，`failure.code` 为 `"inspection-selection-missing"`，退出码为 `2`。这表示选择对象缺失，不是评估判定为 `failed`；先用 `run.list` 核对 ID，并确认读取的是对应项目的运行记录。

## `niceeval show`

`niceeval show` 在身份缺口下直接说明变化：`Changed` 后列出配置、源码或数据的 selector，以及两侧的有界摘要。
源码和数据哈希只显示前 8 位；新增与移除注明 `added` 或 `removed`。每个缺口最多列三项，其余显示 `+N more`。
同一 Experiment 的全部缺口说明相同时，只显示一次并注明 `all N gaps`。
无法解释的身份变化显示 `Unexplained` 和诊断摘要。运行末尾 `Next` 提示的 `niceeval exp <experiment> --dry` 查看完整变化。


```sh
niceeval show [--record <file>]
niceeval show --run <run-id>... [--record <file>]
niceeval show --experiment <experiment-id>... [--record <file>]
niceeval show @<locator> [--record <file>]
niceeval show @<locator> --assertions [--entry <entry-id>] [--record <file>]
niceeval show @<locator> --source [--record <file>]
niceeval show @<locator> --execution [--expand <stable-id>] [--record <file>]
niceeval show @<locator> --timing [--record <file>]
niceeval show @<locator> --usage [--record <file>]
niceeval show @<locator> --diff [--record <file>]
```

`show` 在终端里按固定格式显示结果。不带选择参数时显示默认总览。`--run <run-id>` 显示指定的 Run，`--experiment <experiment-id>` 显示指定的 Experiment，两者都可以重复传入。

通过率和分数按评估用例的类型显示：

- 通过制的评估显示 `Verdicts` 和 `Pass rate`。
- 纯计分制的评估显示 `Verdicts` 和 `Score`，不显示通过率。
- 两种混在一起时，只有通过制的行显示通过率。

分数“完整”只说明这个分数算得出来，不代表评估通过。判定为 `failed` 的评估即使分数完整，也显示失败，同时保留它拿到的分数。只有判定为 `passed` 且分数完整的评估才进入成功排名。

判定为 `passed` 且分数完整时，终端详情显示 `scored`，浏览器显示“评分完成”。零分也可以是完整评分：它说明评分做完了，不说明目标已经达成，NiceEval 也没有默认的及格线。gate 失败照样显示失败。分数不完整（`partial`）时只保留已知分数的下限，不算有效评分。

`@<locator>` 选中一个 Attempt。一条命令最多给一个 locator，它不能和 `--run` 或 `--experiment` 同时使用；`--run` 和 `--experiment` 之间也不能同时使用。

选中 Attempt 后，可以加下面任意一个选项看某一方面。这六个选项互斥，都必须配合 Attempt locator：

- `--assertions`：断言的角色、判定、分数与理由；用 `--entry <entry-id>` 查看一条断言。
- `--source`：记录下来的源码信息，以及每条断言在源码里的位置。
- `--execution`：执行过程的概要，篇幅有上限。
- `--timing`：各阶段的耗时。
- `--usage`：用量合计，以及每一次上报的用量。
- `--diff`：运行期间的文件改动。

`--execution` 的输出分开显示三件事：采集状态、上报方是否声明数据完整、分页状态。即使当前页为空或已到最后一页，上报方标记的 `partial` 和限制原因也会保留。

- 用 `--actor <id>` 和 `--type <event-type>` 按参与方和事件类型筛选。
- 用 `--continuation <token>` 翻页时，要带上相同的筛选条件。
- 用 `--expand <stable-id>` 直接展开一项详情。ID 必须取自概要里的 `itemId`、`toolOccurrenceId` 或 `commandId`，不能用位置序号。`--expand` 只能和 `--execution` 一起用，也不能和筛选、翻页参数同时出现。

### 断言角色与参照结果

`--assertions`、`--entry` 的条目标题和运行结束时的断言反馈使用相同标记：

- `GATE pass` / `GATE fail` / `GATE n/a`：该条是否满足 gate。
- `SCORE earned/possible`：计分贡献；同时承担 gate 的条目并列显示两种标记。
- `NOTE met` / `NOTE unmet`：只记录条件是否满足，包括 stop-only 条件。

详情先显示 `Verdict failed · Score 1/4`，再显示 `Gates 1 pass, 1 fail · Scored 3 · Notes 1 met, 1 unmet`。条目自己的名称即使含有“gate”，也不决定它的角色。机器 JSON 与 query 继续保留结构化字段。

当前计划有缺口且存在旧结果时，总览显示 `Reference results (from previous recorded attempts)`。`Previous attempts N of K gaps` 只统计当前缺口能找到的上次结果；其后列出 `Verdicts`、通过制的 `Pass rate` 和计分制的 `Score earned/possible`。每条 `Previous result @…` 后显示判定，计分制同时显示分数。这些结果来自先前配置，更新当前目标需要重跑。`niceeval show --reference` 展开相同的参照摘要和条目。

## `niceeval view`

```sh
niceeval view [--run <run-id>...] [--no-open] [--port <port>] [--json]
```

`view` 在本机打开 NiceEval 自带的浏览器界面。不带 `--run` 时打开默认总览，重复传入 `--run` 可以预先选中多个 Run。它不接受位置参数，也不加载项目自己的页面、主题、组件或渲染器。

`--no-open` 只启动服务，不自动打开浏览器。`--port` 指定端口，服务只监听 `127.0.0.1`。页面资源、本机访问授权和读取接口都准备好后，命令向 stdout 输出一次可以打开的本机地址。

加 `--json` 时，stdout 改为 `niceeval.view/v1` 格式的 NDJSON：就绪时输出 `ready` 事件，关闭时输出 `closed` 事件。启动或运行失败时，通过退出码和 stderr 报告。

`view` 只读取当前项目的 `.niceeval/record.sqlite`。打开期间有新结果写入时，页面会提示刷新，确认后才切换到新数据。它没有 `--record`、SQL、部署或分享选项，也不能指定自定义报告、页面、主题、路由或 operation。

## 选择读取方式

三条路读取得到的是同一份结果，但各自负责自己的排版和展示。

| 目标 | 使用 |
| --- | --- |
| 让脚本或 CI 取得稳定的 JSON | `niceeval show --json` |
| 人或 Coding Agent 在终端查看总览、Run、Experiment 或 Attempt 的摘要 | `niceeval show` |
| 在浏览器里审阅总览或某个 Run | `niceeval view` |

## 发现和恢复 Run

`niceeval run list` 按创建时间从新到旧列出 Run；时间相同则按 Run ID 排序。多个 `--state` 取并集，不同筛选项取交集：

```bash
niceeval run list --state active --state recovering --experiment suite --limit 10
niceeval run list --invocation <invocation-id> --json
niceeval run list --record ./record.sqlite --state active --json
```

`--experiment suite` 匹配 `suite` 和 `suite/...`，不会匹配 `suite-other`。`--limit` 必须是正整数；不传时不截断。JSON 的 `omitted` 是筛选后被省略的数量。

active、recovering 行会显示 owner 的 `alive`、`gone` 或 `unknown` 观察及观察时间。`alive` 表示观察时记录的进程仍存在，`gone` 表示已证明终止。`unknown` 的 reason 区分异机记录、缺失进程身份、外部 Record 或探测失败。观察不会修改 Run 状态；读取外部 Record 不会探测本机进程。

```bash
niceeval run recover <run-id> --yes
niceeval run recover --orphaned --yes --json
```

`--orphaned` 在一次读取边界上冻结 active、recovering 候选集，确认前列出 Run ID，再逐项重验状态、写入世代和进程身份。它会跳过 alive、unknown owner；单项失败不阻止其余项，存在失败时退出码非零。JSON 的 `items` 为每个 Run 列出 `recovered`、`skipped` 或 `failed` 结果。没有候选是成功的空结果。JSON 模式必须传 `--yes`；人读模式只在交互终端询问一次确认。

recovering 表示恢复已经取得写入权，但这个 Run 还没有被标为结束。恢复进程中断后可重试同一命令；仍需证明上一个恢复进程已终止。恢复只为未发布的位置补上 absence 并结束这个 Run，保留已发布的 Attempt。它不会释放共享 State、执行 Experiment after 或清理 Sandbox；这些操作需要各自的显式命令。
