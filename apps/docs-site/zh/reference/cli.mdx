运行评估使用 `niceeval exp`。运行完成后，NiceEval 只提供两条读取路径：给 AI、脚本和 CI 的 `niceeval query`，以及给人的 `niceeval view`。两者都只读取已封口的 Record。

## `niceeval query`

```sh
niceeval query discover [--record <RecordSnapshot>]
niceeval query explain [--record <RecordSnapshot>] --request <file|->
niceeval query run [--record <RecordSnapshot>] --request <file|->
```

`query` 是 versioned `niceeval.query/v1` JSON operation protocol。成功与协议级领域失败都会向 stdout 写入恰好一个 canonical document。进度、命令用法错误和无法形成 document 的进程失败只写 stderr。

- `discover` 返回紧凑 bootstrap，以及每个 operation 的 schema、selector、错误 union 和下一条最小 request。
- `explain` 验证完整 request，说明将运行的 operation 与合法的后续请求。
- `run` 执行 request，并返回该 operation 的闭合结果。

先调用 `discover`，再从返回的 schema 构造 request。不要猜字段，不要用 SQL、JSON path 或公式拼出另一种查询语言。catalog 包含 `runs.list`、`run.get`、`run.summary`、`attempt.get`、`attempt.trace`、`attempt.diff`、`attempt.sources`、`attempt.artifacts` 与 `runs.compare`。

continuation token 绑定 operation、canonical request、content identity 和 sealed cutoff。任一绑定变化都会得到 restart correction。

## `niceeval view`

```sh
niceeval view [@<attempt-locator> | --run <run-id>...] \
  [--record <RecordSnapshot>] [--no-open] [--port <port>] [--json]
```

`view` 是固定的第一方本地 Insight。省略 selector 时打开默认 overview；`@<attempt-locator>` 打开一个明确 Attempt 的 detail；重复 `--run` 可选择多个 Run。它不装载项目页面、主题、组件或 renderer。

`--record` 只选择输入。`--no-open` 不请求操作系统打开浏览器。`--port` 选择 loopback port。`--json` 输出 `niceeval.view-lifecycle/v1` NDJSON 的 `ready`、`closed` 或 `failed` lifecycle event，而不是结果 JSON。`ready` 中的 URL 含一次性 fragment credential；不要上传原始 stdout。

没有 `--record` 时，View 从项目 operational Store 读取 sealed cutoff。用户可在有新封口发布时确认 refresh。使用 Snapshot 时固定 exact Seal，不会 watch 或 refresh。

## `niceeval record snapshot`

```sh
niceeval record snapshot --output ./snapshots/baseline.record-snapshot
```

Snapshot 是唯一可复制并传给 `--record` 的 Record 输入。命令关闭未发布 closure，验证 exact Seal 后发布 sealed-only `RecordSnapshot`。项目中的 `.niceeval/record/record.sqlite`、普通 SQLite copy、WAL 拼接和外部文件都不能作为 `--record` 输入。

Snapshot 可能仍含源码、prompt、对话或第三方 attachment。复制或提交前，请自行判断权限、脱敏和保留策略。

## 选择读取方式

| 目标 | 使用 |
| --- | --- |
| 让脚本、AI 或 CI 发现并取得稳定 JSON | `niceeval query discover`，再用 `explain` / `run` |
| 在浏览器审阅 overview 或某个 Attempt | `niceeval view` |
| 把同一封口事实交给另一台兼容 runtime | `niceeval record snapshot --output ...`，再传入 `--record` |
