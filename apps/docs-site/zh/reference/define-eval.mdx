`defineEval` 是编写评估用例的主要入口。每个评估用例文件调用一次，传入描述和 `test(t)`，并默认导出结果。

```ts
import { defineEval } from "niceeval";

export default defineEval({
  description: "Brooklyn weather query",
  async test(t) {
    const turn = await t.send("What's the weather like in Brooklyn today?");
    turn.succeeded().label("Turn 完成");
  },
});
```

<Note>
  不要提供 `id` 或 `name`。[NiceEval](https://niceeval.com/) 从文件路径推导评估用例 ID。
</Note>

## Test context: `t`

`t`（`TestContext`）是评估用例作者拿到的高层上下文。每一次作者入口调用都直接登记一条 Assertion。`t.check(subject, match)` 严格接收两个参数。`t.succeeded()`、`session.succeeded()`、`turn.succeeded()`、`calledTool(...)`、`notCalledTool(...)` 与 Judge Match 的显式 `check(...)` 也直接登记 Assertion。handle 只配置同一条 entry 的 `key`、`label`、无参 `.gate()` 与 `.score(n)`。`.orStop()` 也只作用于此 entry，绝不登记第二条 Assertion。

通过制评估用 Boolean condition 折叠 Attempt Verdict。measurement 先用 `ScoreMatch.atLeast(n)` 形成 threshold，再用无参 `.gate()` 才进入 failed；`await handle.orStop()` 在 mismatch 或 threshold 未满足时停止当前 continuation。

`defineScoreEval` 的 `ScoreTestContext` 额外提供 `t.score(n)` 直接登记 contribution，`n` 必须 finite 且不小于零；已有 Assertion 用 `.score(n)` 贡献分数，`n` 必须 finite 且大于零。`calledTool` 与 `notCalledTool` 的完整契约见 [Scoped assertions](https://github.com/NiceEval/NiceEval/blob/main/docs/feature/assertions/library/scoped-assertions.md)。全部成员：

## Judge measurement

先用 `defineJudge` 声明 Recipe 和参考材料，再把返回值放进 `defineEval` 或 `defineScoreEval` 的 `judge` 字段：

```ts
const judging = defineJudge({
  recipes: [judge.recipes.factuality],
  material: {
    expected: judge.referenceText({ name: "expected", text: expected }),
  },
});

const turn = await t.send("总结需求。");
const check = judge.check({
  recipe: judging.recipes[0],
  material: {
    task: turn.material.input,
    reply: turn.material.reply,
    expected: judging.material.expected,
  },
});
t.check(check, judge.llm().atLeast(0.8)).gate().label("事实一致");
```

`judge.check` 只接受 Recipe 声明的受管 Material View。模型配置从 Experiment 和项目配置的 `judgeRuntime` 解析一次；没有单次模型覆盖。通过制评估先在 `JudgeMatch` 上形成 Threshold，再调用无参 `.gate()`；计分制评估直接 `.score(n)`。

## 测试集导出

```ts
export default rows.map((row) =>
  defineEval({
    description: row.task,
    async test(t) {
      await t.send(row.prompt);
    },
  }),
);
```

数组导出会生成稳定 ID：`file/0000`、`file/0001` 等。

已有稳定业务 key 时也可以默认导出 `Record<string, EvalDef>`。例如 key `15193` 在 `swelancer.eval.ts` 中生成 `swelancer/15193`。key 必须是非空单一路径片段，不能是 `.` / `..`，不能含 `/`、`\\` 或控制字符。发现顺序按 key 字典序固定。
