这一页带你对自己的应用跑通第一条评估用例。你会写三个文件：

- **Adapter**：告诉 NiceEval 怎样调用你的应用。
- **Experiment**：说明对着哪个 Adapter、用哪个模型跑。
- **评估用例**：说明发什么消息、怎样算做对。

有两种走法。让 Coding Agent 帮你写最快；自己动手写能更清楚每个文件管什么。

## 让 Coding Agent 帮你接入

<Steps>
  <Step title="把指令发给 Agent">
    在当前项目里打开你正在用的 Coding Agent，例如 Claude Code 或 Codex，发送下面这段话：

    ```text
    阅读 https://niceeval.com/INIT.md，为当前仓库安装并接入 niceeval，端到端跑通第一条评估用例。完成时列出创建的 Experiment ID、运行命令和结果查看命令。
    ```

    Agent 会先探索你的项目，确认要测哪个接口，再写出三个文件并跑一次。
  </Step>
  <Step title="自己再跑一次">
    用 Agent 最后列出的 Experiment ID 运行。它没有列出时，先用 `pnpm exec niceeval exp list` 查看有哪些 Experiment：

    ```bash
    pnpm exec niceeval exp <experiment-id>
    ```
  </Step>
  <Step title="看结果">
    ```bash
    pnpm exec niceeval show
    ```

    终端里会列出每条评估用例的结果，失败的排在前面。结果怎么读，见下文[读懂结果](#读懂结果)。
  </Step>
</Steps>

## 自己动手接入

### 准备被测应用

先把你的应用启动起来，并确认它有一个能调用的接口。下面的示例假设：

- 接口是 `POST http://localhost:3000/chat`；
- 请求体是 `{ "message": "...", "model": "..." }`；
- 响应体是 `{ "reply": "..." }`。

你的接口不一样也没关系，只需要改 Adapter 里的地址、请求体和读取回复的那一行。手边还没有能启动的应用时，先从 [Examples](/zh/examples) 挑一个可运行项目。

### 安装

```bash
pnpm add -D niceeval
pnpm exec niceeval init
```

`init` 会创建 `niceeval.config.ts`。它还会在 `AGENTS.md` 或 `CLAUDE.md` 里写一段说明，让你的 Coding Agent 读取和安装版本匹配的文档。

### 写 Adapter

Adapter 负责一件事：把评估用例里的消息发给你的应用，再把回复交回给 NiceEval。

```ts
// agents/my-agent.ts
import { completeEvidenceCoverage, defineAgent } from "niceeval/adapter";

export default defineAgent({
  name: "my-agent",
  evidenceCoverage: completeEvidenceCoverage,
  async send(input, ctx) {
    // 换成你自己应用的地址
    const r = await fetch("http://localhost:3000/chat", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ message: input.text, model: ctx.model }), // ctx.model 来自 Experiment
      signal: ctx.signal,
    });
    const body = await r.json();
    return {
      status: r.ok ? "completed" : "failed",
      events: [{ type: "message", role: "assistant", text: body.reply }],
    };
  },
});
```

`events` 是 NiceEval 读懂回复的方式。这里只交回一条助手消息，后面可以再加工具调用、用量等事件。

### 写 Experiment

```ts
// experiments/my-agent.ts
import { defineExperiment } from "niceeval";
import myAgent from "../agents/my-agent.ts";

export default defineExperiment({
  description: "my-agent 基线",
  agent: myAgent,
  model: "gpt-4o",
  attempts: 1,
});
```

文件名就是 Experiment ID，这里是 `my-agent`。以后想对比另一个模型，复制一份改 `model` 就行，评估用例不用动。

### 写评估用例

```ts
// evals/refund-policy.eval.ts
import { defineEval } from "niceeval";
import { pattern } from "niceeval/expect";

export default defineEval({
  description: "能正确回答退款政策",
  async test(t) {
    await t.send("你们的退款政策是什么？");
    t.succeeded();
    t.check(t.reply, pattern(/30\s*天|一个月/));
  },
});
```

模型每次的措辞都会变，所以这里用正则匹配“30 天”或“一个月”，而不是要求一字不差。

### 运行

```bash
pnpm exec niceeval exp my-agent
```

运行过程中终端会显示进度。结束后你会看到类似这样的输出：

## 读懂结果

标题告诉你这次运行的结论：

| 标题 | 意思 | 先做什么 |
|---|---|---|
| `PASSED` | 所有断言都满足了。 | 继续加评估用例。 |
| `FAILED` | 应用正常回复了，但至少一条断言没满足。 | 看 Agent 实际回了什么，判断是应用的问题还是断言写得太严。 |
| `ERRORED` | 没能拿到结果，例如应用没启动、接口报错、Adapter 抛了异常。 | 看 `FAILURES` 面板里的 `error:` 行，通常能直接看出原因；需要更多细节时运行它下面的 `details:` 命令。 |

失败的 Attempt 下面都有一行 `details: niceeval show @<locator>`，复制它就能在终端里看到这一次运行的对话和断言。看整次运行，复制 `NEXT` 面板里的 `show:` 命令；想在浏览器里翻对话、看耗时，复制 `view:` 那一行。

更多查看方式见[查看运行结果](/zh/tutorials/viewing-results)。

## 接下来

这个最小 Adapter 只支持单轮对话，第二轮不会带上第一轮的历史，也看不到工具调用。按你的下一步需要选：

- 要测多轮对话、工具调用或用量：按[编写 Send](/zh/tutorials/write-send)扩展 Adapter，已有评估用例不用改。
- 要写更多、更有区分度的评估用例：读[编写评估用例](/zh/tutorials/authoring)。
- 要比较两个模型或两版 prompt：读[编写实验](/zh/tutorials/write-experiment)。
- 要在 PR 上自动跑：读 [CI 集成](/zh/tutorials/ci-integration)。
