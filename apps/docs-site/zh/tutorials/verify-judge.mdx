Judge 适合规则难以写成精确 Match 的开放式质量判断。先用一条最小评估确认模型、Key 和端点能完成真实判分。

## 配置 Judge Runtime

```ts title="niceeval.config.ts"
import { defineConfig } from "niceeval";
import { OpenAIProvider } from "niceeval/judge";

export default defineConfig({
  judgeRuntime: OpenAIProvider({
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
    maxOutputTokens: 512,
  }),
});
```

Key 只放进进程变量。配置文件只保存变量名，不保存值：

```sh
export JUDGE_GATEWAY_KEY="..."
```

## 写一条最小评估

```ts title="evals/judge-smoke.eval.ts"
import { defineEval } from "niceeval";

export default defineEval({
  judge: "judge-model",
  async test(t) {
    const operation = "完成数据导入";
    const turn = await t.send(operation);
    t.closeQA({
      input: operation,
      output: turn.message,
      context: "操作完成后，回复必须明确说明数据导入成功。",
    })
      .gate(0.8)
      .label("成功表达");
  },
});
```

`t.closeQA` 在登记时快照显式材料，`.gate(0.8)` 在同一 `MeasurementAssertionHandle` 上形成条件并参与通过制判定。它等价于 `t.check(material, closeQA())`，不会创建第二条 Assertion。

## 附加图片材料

只有判据确实需要图片时才附图。沿用同一个 `defineJudge` 和 `t.judge`，不用增加第二个裁判或评分门槛。
先在现有聊天 Provider 配置中设置 `supportsImages: true`，并将 `model` 换成支持图片及工具调用的模型。`TypesafeProvider` 不支持图片。

下面的 Eval 读取应用已经保存的 `screenshot.png`，不会因评估重新生成截图：

```ts
import { readFile } from "node:fs/promises";
import { defineEval, defineJudge } from "niceeval";
import { judgeImage } from "niceeval/judge";

const actionQuality = defineJudge({
  name: "action-quality",
  rubric: "根据已知事实评价行为是否合理；图片仅作为补充，不推断画面外的行为。",
});

export default defineEval({
  async test(t) {
    const screenshot = judgeImage({
      body: await readFile("screenshot.png"),
      mediaType: "image/png",
    });
    t.judge({ action: "角色完成搬运", screenshot }, actionQuality).gate(0.8);
  },
});
```

图片必须是 PNG 或 JPEG，每张最多 4 MiB；超限或头部无效会在发送前拒绝。不要传路径、URL 或普通 base64 字符串来代替图片。

封存后，`attempt.assertion.detail` 给出图片的稳定 `imageId` 与摘要。用固定 query 操作 `attempt.assertion.image`，传入同一 Attempt 的 `entryId` 和 `imageId`，即可分页读取原图；`offset` 是字节偏移，`limit` 最多 256 KiB。它读取 Record 中的证据，不会重新访问文件或调用模型。

## 运行并查看

确保现有 Experiment 的 `evals` 包含 `judge-smoke`，再运行：

```sh
pnpm exec niceeval exp local judge-smoke
pnpm exec niceeval view --run <run-id>
```

静态配置校验不会请求 endpoint。实际 Judge Assertion 使用 forced-function 请求；成功结果包含 measurement、threshold、公开 rationale 和实际发送的固定材料。

| 结果 | 含义 |
|---|---|
| `judge-provider-unresolved` / `judge-key-unresolved` | Provider 或凭据缺失，未发网络请求 |
| `errored` | endpoint 返回 HTTP 400、协议不兼容，或响应不符合严格 schema |
| `unavailable` | 请求传输失败或超时 |
| `errored` | Decision 缺失、格式错误或 measurement 越界 |

比较 Judge 时，让多个 Experiment 使用不同模型字符串或具名 Provider，再用 `labels` 标明对比坐标。
