Judge 适合规则难以写成精确 Match 的开放式质量判断。先用一条最小评估确认模型、Key 和端点能真实判分。

## 配置 Judge Runtime

```ts title="niceeval.config.ts"
import { defineConfig } from "niceeval";

export default defineConfig({
  judgeRuntime: {
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
    maxOutputTokens: 512,
  },
});
```

Key 只放进进程变量。配置文件只保存变量名，不保存值：

```sh
export JUDGE_GATEWAY_KEY="..."
```

## 写一条最小评估

```ts title="evals/judge-smoke.eval.ts"
import { defineEval, defineJudge } from "niceeval";

const expressesSuccess = defineJudge({
  name: "expresses-success",
  rubric: "根据 operation 评价 response 是否明确表达操作成功。",
});

export default defineEval({
  judge: expressesSuccess,
  async test(t) {
    const operation = "完成数据导入";
    const turn = await t.send(operation);
    t.check({ operation, response: turn.message }, expressesSuccess.atLeast(0.8))
      .gate()
      .label("成功表达");
  },
});
```

`defineJudge` 返回受管 Match。`t.check` 在登记时快照材料，`.atLeast(0.8)` 形成 threshold，无参 `.gate()` 让条件参与通过制判定。

## 运行并查看

确保现有 Experiment 的 `evals` 包含 `judge-smoke`，再运行：

```sh
pnpm exec niceeval exp local judge-smoke
pnpm exec niceeval view --run <run-id>
```

配置完整时，runner 会用正式请求相同的 Decision Tool 预检。成功结果包含 measurement、threshold、公开 rationale 和实际发送的固定材料。

| 结果 | 含义 |
|---|---|
| `judge-model-unresolved` / `judge-key-unresolved` | 配置缺失，未发网络请求 |
| Setup Error | endpoint 不支持固定 Decision Tool |
| `unavailable` | 请求传输失败或超时 |
| `errored` | Decision 缺失、格式错误或 measurement 越界 |

比较 Judge 模型时，让多个 Experiment 使用不同 `judgeRuntime.model` 和 `labels`，并选择同一批评估。
