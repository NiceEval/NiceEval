Judge 适合规则难以写成精确 Match 的开放式质量判断。先用一条最小评估确认模型、Key 和端点能真实判分。

## 配置 Judge Runtime

```ts title="niceeval.config.ts"
import { defineConfig } from "niceeval";

export default defineConfig({
  judgeRuntime: {
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
    maxOutputTokens: 512,
  },
});
```

Key 只放进进程变量。配置文件只保存变量名，不保存值：

```sh
export JUDGE_GATEWAY_KEY="..."
```

## 写一条最小评估

```ts title="evals/judge-smoke.eval.ts"
import { defineEval, defineJudge, judge } from "niceeval";

const judging = defineJudge({
  recipes: [judge.recipes.closedQA],
  material: {
    criterion: judge.referenceText({ name: "criterion", text: "文本是否明确表达成功？" }),
  },
});

export default defineEval({
  judge: judging,
  async test(t) {
    const turn = await t.send("operation completed successfully");
    const check = judge.check({
      recipe: judging.recipes[0],
      material: {
        task: turn.material.input,
        reply: turn.material.reply,
        criterion: judging.material.criterion,
      },
    });
    t.check(check, judge.llm().atLeast(0.8)).gate().label("成功表达");
  },
});
```

`defineJudge` 封口 Recipe 与参考材料。`judge.check` 绑定当前 Turn，`judge.llm().atLeast(0.8)` 形成
Threshold，无参 `.gate()` 让条件参与通过制判定。

## 运行并查看

确保现有 Experiment 的 `evals` 包含 `judge-smoke`，再运行：

```sh
pnpm exec niceeval exp local judge-smoke
pnpm exec niceeval view --run <run-id>
```

配置完整时，Runner 会用正式请求相同的 forced Function Tool 预检。成功结果包含 Measurement、Threshold、
公开 Rationale 和实际发送材料的 Manifest。

| 结果 | 含义 |
|---|---|
| `judge-model-unresolved` / `judge-key-unresolved` | 配置缺失，未发网络请求 |
| Setup Error | Endpoint 不支持固定 Decision Tool |
| `unavailable` | 请求传输失败或超时 |
| `errored` | Decision 缺失、格式错误或 Measurement 越界 |

比较 Judge 模型时，让多个 Experiment 使用不同 `judgeRuntime.model` 和 `labels`，并选择同一批评估。
