一次完整评估要调用几百次模型，再加上 Sandbox 的费用，账单很容易超出预期。控制成本前，先想清楚你要省的是什么：是重复运行的次数、失控时的上限，还是同时占用的资源。

每个设置管一件事，不能互相替代。

| 目标 | 使用方式 |
| --- | --- |
| 测完整稳定性分布 | 设置 `attempts: N`，默认跑满。 |
| 只确认至少能成功一次 | 使用 `--early-exit`。 |
| 给每个 Experiment 的花费加保护 | 使用 `--budget <美元>`。 |
| 限制同时占用的资源 | 使用 `--max-concurrency <数量>`。 |
| 跳过没有受影响的结果 | 使用默认沿用或 `--rerun`。 |
| 分摊 Sandbox 创建和准备成本 | 使用 `sandboxReuse`。 |

## 运行前先看要跑多少

花钱之前，先确认这次选中了多少评估用例、多少个 Experiment、每道题跑几次：

```sh
pnpm exec niceeval exp regression --dry
```

`--dry` 不调用模型，也不创建 Sandbox。第一行给出这次计划的 Attempt 总数，后面每行是一道题，标出哪些会沿用上次的结果、哪些要重新跑。

`--dry` 不预测最终费用。它的作用是在派发前发现范围选错或重复次数过大。总数比预期大得多时，先查 Experiment 的 `evals` 选择和 `attempts`。

## 只关心能否成功时首过即停

只想知道“这道题能不能做到”，不在乎通过率分布时，打开首过即停：

```sh
pnpm exec niceeval exp regression --early-exit
```

某道题的一个 Attempt 得到 `passed` 后，这道题还没开始的 Attempt 不再派发，结果里记为 `not-dispatched`。同一道题已经在跑的 Attempt 会通过 `ctx.signal` 收到取消信号；它能多快结束，取决于 Adapter 是否及时响应这个信号。

首过即停触发之后才返回的同题 Attempt 不会进入结果。

`failed`、`errored` 或 `skipped` 不触发首过即停。需要完整通过率分布时不要打开这个选项。默认并发下，同一道题的几次 Attempt 可能已经同时开跑，省不下钱；要让它真的省钱，配法见[让首过即停真的省钱](/zh/tutorials/concurrency#让首过即停真的省钱)。

## 给花费设置保护上限

担心某次运行失控、花得比预期多时，设置一个美元上限：

```sh
pnpm exec niceeval exp regression --budget 25
```

预算按每个 Experiment ID 分别计算。每完成一个 Attempt，NiceEval 用 Experiment 的 `model`、上报的 token 用量和价格表估算这个 Attempt 的花费（`estimatedCostUSD`），再累加进预算。Provider 或 Adapter 自己上报的实际金额 `usage.costUSD` 只用于展示，不参与预算判断。

累计估算到达上限后，NiceEval 停止派发新 Attempt，已经在跑的不会被中途终止。所以 `--budget` 是保护上限，不是精确账单：几个并发任务还没结算时，最终花费可能短暂超过设置值。

预算耗尽时，你会看到：

- 一条 `budget_exhausted` 诊断；
- 没来得及派发的 Attempt 记为 `not-dispatched`；
- 命令以非零状态退出。

提高预算后重跑同一范围，已经完成且符合沿用条件的 Attempt 直接沿用，只补剩下的部分。

缺少 `model`、token 用量或匹配的价格时，NiceEval 算不出估算花费，`usage.costUSD` 也不能补上。这时运行会给出警告，而不是假装预算仍在生效。看到这条警告时，先确认 Experiment 写了 `model`，Adapter 上报了 token 用量。

## 并发只控制资源占用

本机或 Provider 吃不消时，限制同时运行的 Attempt 数：

```sh
pnpm exec niceeval exp regression --max-concurrency 4
```

并发上限不是费用上限，费用保护仍然用 `--budget`。Sandbox 构建的并发由另一个 flag `--max-build-concurrency` 控制。

还想分摊每个 Sandbox 的创建和准备时间，见[复用 Sandbox](/zh/tutorials/sandbox-reuse)。要选择只重跑失败项还是全部重验，见[重跑与沿用结果](/zh/tutorials/rerun-and-cache)。

## 查看花了多少钱

跑完后在终端查看一个 Attempt 或整个实验的费用：

```sh
pnpm exec niceeval show @attempt-locator
pnpm exec niceeval show exp:regression
```

想在浏览器里翻看，运行 `pnpm exec niceeval view`。

Attempt 页面先显示应用和 Judge 的合计费用：

- 费用完整时显示总额。
- 缺少回执、价格或完整调用记录时，显示已知小计和缺了哪些部分。
- 明确记录的零金额算作已知费用。失败和重试已经花掉的钱也会保留。

模型用途、每次实际调用和 Judge 的费用放在后面的明细里。

实验页面汇总每道题每次 Attempt 最新的一条结果，同一个原始 Attempt 只算一次。被重跑替换掉的旧结果不累计，没重跑的保留原结果。所以它显示的是当前这批结果的费用，不是全部历史运行的账单。明细省略几行不会减少总额；不同币种分别展示，不换算汇率。

## 让自定义 Adapter 上报费用

自己写的应用 Adapter 要让费用出现在上面的页面里，需要上报每次调用的用量：

- 用 `ctx.recordUsage(call)` 上报每次物理调用的最终快照。
- 全部记录取得后调用 `ctx.sealUsage({ state: "complete" })`，告诉 NiceEval 这份记录是完整的。
- 只读到一部分记录时，调用 `ctx.sealUsage({ state: "partial", reason: "source-incomplete" })`。

没有声明完整的空记录会显示为未知费用，不会显示成零。

## 按模型用途检查缓存读取率

Headless Adapter 使用 `ctx.recordUsage` 登记真实调用，并在采集结束后调用 `ctx.sealUsage`。随后可以直接用 `t.usage.cacheRead` 设置缓存读取率门槛：

```ts
import { atLeast, ratio } from "niceeval/expect";

t.check(t.usage.cacheRead.rate("planner"), atLeast(ratio(0.6))).gate();
// 不区分用途时，检查所有已登记调用的合计。
t.check(t.usage.cacheRead.rate(), atLeast(ratio(0.6))).gate();
```

读取率是同组调用的 **缓存读取 token 总量 / 含缓存输入 token 总量**，包括失败调用与重试。它不是逐次百分比的平均值。每次调用优先使用 `inputTotalTokens`；没有独立总量时，必须同时提供 `inputTokens`、`cacheReadTokens`、`cacheWriteTokens` 三个互斥桶。

`cacheRead.total` 给出整个 Attempt 的结果，`roles` 按用途分组，`models` 进一步按真实 `provider` 和 `model` 分组。未知身份保持 `null`，不会用配置值补齐。`coveredCalls / recordedCalls` 表示已登记调用的输入覆盖率；`collectionComplete` 单独表示采集是否完整。

缺失输入、未 seal、partial seal、unknown 调用状态、空组或零分母均返回 `unavailable`，`reasons` 列出原因。缺失不按零处理；完整且有正输入总量的零缓存读取率才是数值 0。旧账本没有明确的生产者完整性声明时，也返回不可判定。

使用 `niceeval show <Attempt locator> usage` 或 View 查看读取率、覆盖情况与原因；脚本通过 `attempt.usage` 的 `usage.cacheRead` 读取相同报告。已有 `recordUsage` 调用无需改名，但必须登记缓存 token，并在采集完成后诚实 seal。无需迁移历史结果文件。


角色名来自 Experiment 的 `models` 键，不是框架内置名单。`model` 单模型简写对应 `default`。
传入未声明的角色会在调用处报错，并列出可用名称。已声明但完整记录中没有调用的角色返回 `role-has-no-calls`；采集不完整时仍返回 `collection-incomplete`。
Eval 可以被多个 Experiment 复用，因此此入口在运行回调里校验角色，不在定义期检查动态字符串。

### 登记命令行 Agent 的用量

Adapter 应按外部回执记录真实调用，并将 `modelRole` 设为 Experiment 声明的用途，例如 `mind`。
同一请求的流式增量和最终回执不能各登记一次；先按请求 ID 合并，收到最终回执后再登记。

```ts
// 单次 Claude 请求的最终 usage；字段缺失时保留 null。
ctx.recordUsage({
  callId: requestId,
  modelRole: "mind",
  provider: observedProvider,
  model: observedModel,
  status: observedStatus,
  inputTokens: usage.input_tokens ?? null,
  cacheReadTokens: usage.cache_read_input_tokens ?? null,
  cacheWriteTokens: usage.cache_creation_input_tokens ?? null,
  outputTokens: usage.output_tokens ?? null,
});
```

Claude 的 `input_tokens` 是未命中缓存的输入桶，含缓存总量需加上读取和写入桶，见 [Claude 缓存用量说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。
Codex 的 usage 若提供含缓存的 `input_tokens`，应映射到 `inputTotalTokens`，`cached_input_tokens` 映射到 `cacheReadTokens`，不要再把缓存加进总量。
不能仅因命令成功退出就认定全部模型调用都已被记录；需核对所用 CLI 版本输出的是逐请求、Turn 还是会话合计。

只有会话总量时，不要把多次物理调用伪装成一次调用，也不要把合计与明细同时登记。
当前 `recordUsage` 的单位是物理调用；将会话合计保存在统计附件中，并声明 `partial`，缓存判据会诚实地显示不可判定。
完全没有 usage 时同样声明 `partial`，不要填零或声明完整空账本：

```ts
ctx.sealUsage({ state: "partial", reason: "usage-not-exposed" });
// 只提供会话总量、不能证明逐调用完整性时：
// ctx.sealUsage({ state: "partial", reason: "session-totals-only" });
```

确实拿到全部物理调用的最终记录后，再调用 `ctx.sealUsage({ state: "complete" })`。

## 让模型用途名称参与类型检查

从 0.18 起，共享声明让同一评估可用于多个实验，同时在编译时检查用途名称：

```ts title="models.ts"
import { defineModelRoles } from "niceeval";

export const roles = defineModelRoles({
  mind: { model: "provider/planner" },
  speech: { model: "provider/speaker" },
});
```

在已有 Adapter 的绑定工厂上声明要求。也可解构 `adapter.defineScoreEval`，但根入口的同名工厂不接受 `requires`：

```ts title="evals/cache.eval.ts"
import { atLeast, ratio } from "niceeval/expect";
import { adapter } from "../adapter";
import { roles } from "../models";

export default adapter.defineScoreEval({
  requires: { models: roles },
  test(t) {
    t.check(t.usage.cacheRead.rate("mind"), atLeast(ratio(0.6))).gate();
    // rate("mimd") 会产生 TypeScript 错误；rate() 仍查询全部用途的合计。
  },
});
```

实验使用 `defineExperiment({ adapter, models: roles, evals: ["cache"] })`。
其它实验可为这些用途选择不同模型；`requires` 要求用途存在，不要求模型值相同。
加载实验时会检查它选中的全部评估，CLI 的标签或前缀过滤不能隐藏缺失用途。

给 `defineAdapter` 也传入 `requires: { models: roles }`，即可同时收窄 `ctx.models` 和 `ctx.recordUsage` 的 `modelRole`。
`null` 或省略的 `modelRole` 仍表示未归属到用途的调用。已声明但本次没有调用时，`rate` 返回原因 `role-has-no-calls` 的不可用材料。

0.17.x 中省略 `requires` 的写法在 0.18 继续兼容，名称仍在调用时校验。
迁移时先提取共享声明，再给 Adapter 和绑定评估分别添加 `requires`。
不要先把声明标注成 `Record<string, ModelRoleSelection>`，否则 TypeScript 已丢失具体键，无法检测拼写错误。
