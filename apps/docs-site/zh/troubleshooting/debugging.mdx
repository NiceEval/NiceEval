---

从明确的 Run 或 Attempt 开始。终端排障先用 `niceeval show`，机器和 CI 用 `query` 的固定 JSON 协议，浏览器审阅则用 `view`。

```sh
niceeval show --run <run-id>
niceeval show @<attempt-locator>
```

先用 `niceeval show --run <run-id>` 确认这个 Run 的时间、Member、判定、分数、coverage、usage 和限制。输出中的 Attempt locator 是下一步的精确目标。对一个 Attempt 先运行 `niceeval show @<attempt-locator>`，再按问题选择一个投影：

```sh
niceeval show @<attempt-locator> --source
niceeval show @<attempt-locator> --execution
niceeval show @<attempt-locator> --timing
niceeval show @<attempt-locator> --usage
niceeval show @<attempt-locator> --diff
```

`--source` 查看已封存的源码和 Assertion 事实；`--execution` 查看有界的执行 outline；`--timing` 查看活动、阶段和耗时；`--usage` 查看已封口的 token、request 和 cost totals；`--diff` 查看已封存的文件变更窗口。要展开 execution outline 中的一项，使用它显示的稳定 ID：`niceeval show @<attempt-locator> --execution --expand <stable-id>`。

## 无法打开结果

| 错误 | 下一步 |
| --- | --- |
| `record-root-missing` | 检查项目目录或 `--record` 输入。 |
| `record-schema-migration-required` | 显式运行 `niceeval migrate`。 |
| `record-schema-unsupported` | 使用支持该 Record 的 NiceEval 版本。 |
| `record-database-invalid` | 停止普通读取，修复或重新取得有效 Snapshot。 |

已发布事实没有手动编辑的修复路径。需要不同事实时创建新 Run。`niceeval clean` 只处理重新验证后的未完成 rows。

## 结果不完整或无法比较

脚本、AI 或 CI 先运行 `niceeval query discover` 找到正确的固定 operation，再用 `explain` 检查 request，最后运行 `run`。结果会指出 missing、issues、Evidence 与 correction。`query` 只输出机器协议，不用来阅读终端排版。

需要浏览器界面时运行 `niceeval view --run <run-id> --no-open`。不要解析 View 页面，也不要读取私有 `.niceeval/` 文件。

比较使用 `runs.compare`。它的 `exact` 和 `paired` 模式会拒绝不兼容的 domain 或 pair，不会悄悄缩小分母。

## View 没有刷新

operational View 只在用户确认后替换 active sealed cutoff。候选读取失败时，上一份可用 View 仍然可读。Snapshot View 固定 exact Seal，因此不会 watch 或 refresh。

正常流程见[查看已封口的运行结果](/zh/tutorials/viewing-results)，命令细节见 [CLI](/zh/reference/cli)。
