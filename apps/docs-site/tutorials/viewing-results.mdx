A batch of evals finishes and the terminal shows `FAILED`: 3 of 12 did not pass. You want to know which ones, what the Agent actually said in those runs, which tools it called, and why it did not meet the assertions.

NiceEval gives different readers three entry points, all reading the same results:

| Entry point | For | Suits |
|---|---|---|
| `niceeval show` | You and Coding Agents, in the terminal | Finding failures quickly and drilling into details |
| `niceeval view` | People, in the browser | Browsing full conversations, duration waterfalls, and comparing several Runs |
| `niceeval show --json` | Scripts and CI, and Agents that need exact fields | Reading structured JSON |

Results are readable as soon as each Attempt finishes; you do not have to wait for the whole batch.

## Start from the overview

```sh
pnpm exec niceeval show
```

The default overview answers "which results is the current project still missing": the denominator is your current Experiments and evals, not everything ever run. Attempts without problems are collapsed by default, so failures and the next command to run stay on one screen. The output looks like this:

```text
Current results
  Totals

  Covered    11/12
  Gaps       1
  Verdicts   8 passed; 3 failed; 0 errored; 0 skipped
  Pass rate  72.73% (partial)

Experiments
  Experiment  Covered  Gaps  Pass rate
  ----------  -------  ----  -----------------
  my-agent    11/12    1     72.73% (partial)

Attempts · my-agent
  Eval refund-policy
  Gap identity-mismatch
  Previous result @1K1P0VJAPVJ12

  8 passed Attempts hidden
  See more  niceeval show exp:my-agent

Next: niceeval exp my-agent --dry
```

A few numbers worth looking at first:

- `Covered` is the number of positions that currently have a usable result, out of the planned number. When `Gaps` is not 0, some positions have no result yet, or the old result no longer applies, for example because you changed this eval. Under each gap is the reason and an entry to the last result; old scores are not counted in the current pass rate, and the pass rate is followed by `(partial)` to remind you it is based only on available results.
- When `errored` is not 0, handle those first. `errored` means the run itself did not complete, for example the application was not running or the interface returned an error, so those Attempts reached no conclusion.
- Scored evals show `Score` instead of a pass rate; see [Pass/Fail and Scored Evals](/tutorials/evaluation-kinds) for how to read it.

To fill the gaps, run the suggested `niceeval exp <id> --dry` on the last line to see what would run, then drop `--dry` to run for real.

When you see `Attempts hidden`, narrow the scope with the suggested command; to show every Attempt, add `--all`.

## Narrow to one Experiment or one run

```sh
pnpm exec niceeval show exp:my-agent
pnpm exec niceeval show run:<run-id>
```

`exp:<id>` shows the result of each eval under one Experiment. `run:<id>` shows one run; the Run ID is in the `NEXT` panel when `exp` finishes. Both can be passed several times.

You can also look while a run is still going: finished Attempts appear, and unfinished ones show as `pending`.

## Look at one failed run

In the overview and Experiment views, each Attempt is preceded by an Attempt locator starting with `@`, which uniquely points to that run within the project. Copy it:

```sh
pnpm exec niceeval show @1K1P0VJAPVJ12
```

The main part of the output looks like this:

```text
Attempt @1K1P0VJAPVJ12 · failed
  Experiment  my-agent
  Eval        refund-policy
  Outcome     completed
  Verdict     failed

assertions available · 3 entries
  Assertion                   Entry ID  Group
  Called the weather tool     e1        root
  Explains the weather        e2        root
  Answer is grounded          e3        root

Sections
  Source      available
  Execution   available
  Timing      available
  Usage       available
  Diff        not-recorded

Next
  niceeval show @1K1P0VJAPVJ12 source
  niceeval show @1K1P0VJAPVJ12 execution
  niceeval show @1K1P0VJAPVJ12 timing
  niceeval show @1K1P0VJAPVJ12 usage
  niceeval show @1K1P0VJAPVJ12 diff
```

`Next` lists the aspects you can keep looking at. Choose by the question you want to answer:

| To find out | Command |
|---|---|
| What the Agent said and which tools it called | `execution` |
| Which assertion failed, and which source line it is on | `source` |
| Which step the time went to | `timing` |
| How many tokens were used and how much it cost | `usage` |
| Which files the Agent changed | `diff` |

`execution` gives an outline of the conversation and tool calls. To expand one item, copy the ID shown in the outline:

```sh
pnpm exec niceeval show @1K1P0VJAPVJ12 execution <id>
```

When an item shows `not-recorded`, `partial`, or `unavailable`, that information was not collected or is incomplete; it does not mean zero or failure. For example, a directly connected application has no file changes, so `diff` is `not-recorded`.

## Decide whether to change the application or the assertion

`failed` only means at least one assertion was not met; it does not necessarily mean the Agent got it wrong. After reading `execution`, there are three cases:

- The Agent's output really does not meet the task requirements: change the application or the prompt.
- The Agent's output meets the task requirements, but the assertion rejected it, for example a regex that is too rigid: change the eval.
- The task itself is vague, so you cannot say whether the Agent got it right: first make the task and criteria clear.

Do not loosen assertions arbitrarily just to turn results green.

## View in the browser

```sh
pnpm exec niceeval view
pnpm exec niceeval view run:<run-id>
```

Without arguments it opens the overview, and `run:<id>` opens one or more specific runs. In the browser you see full conversations, the inputs and outputs of tool calls, and duration waterfalls.

When new results are published, the page prompts you to refresh and only switches after you confirm, so what you are looking at does not change suddenly. `--no-open` does not open the browser automatically, and `--port` sets the port.

## See why an assertion got its score

`show` tells you which assertion failed. To see the reasons the Judge gave and exactly how many points a scoring item got, read that assertion's detail with `show assertions <entry-id> --json`. First get this run's list of assertions:

```sh
pnpm --silent exec niceeval show @1K1P0VJAPVJ12 --json
```

Pick an `entryId` from the returned `assertions.entries`, then read its detail:

```sh
pnpm --silent exec niceeval show @1K1P0VJAPVJ12 assertions <entry-id> --json
```

In the detail, contribution is how many points this item earned, evaluation is the actual measured result, and the Judge's reasons are in explanation. When a field is missing or marked `unavailable`, interpret it by the returned reason; do not infer it from other fields.

## Let scripts and CI read results

`show --json` outputs only JSON and does no terminal formatting. Do not parse the text output of `show`, and do not read files under `.niceeval/` directly; the format may change between versions.

```sh
pnpm --silent exec niceeval show runs --json
```

`show runs --json` lists Runs; `show run:<run-id> --json` reads one Run. See the [CLI reference](/reference/cli) for other selectors.

In pnpm projects, add `--silent`; otherwise pnpm's own output gets mixed into the JSON.

To compare two runs, see [Compare Two Runs](/tutorials/compare-runs).
