title: "Compare Multiple Fixed Runs"
sidebarTitle: "Compare Multiple Runs"
description: "Use explicit Run IDs to fix the comparison denominator, check result coverage, then compare pass rates, scores, cost, and duration without new results changing an open comparison."
---

When comparing models, prompts, or Agent versions, first fix the Runs you want to examine. Do not let “latest results” stand in for an experiment boundary; a newly published Run must not silently change a comparison already in progress.

## Get the Run ID for each execution

TTY completion feedback shows the Run ID. Machine workflows read `runIds` from the final receipt produced by `exp --json`:

```sh
pnpm exec niceeval exp baseline --json > baseline.ndjson
pnpm exec niceeval exp candidate --json > candidate.ndjson
```

Keep those two fixed IDs. They define the planned slots and expected-slot denominator used by the comparison.

## Check result coverage separately first

```sh
pnpm exec niceeval show --run <baseline-run-id>
pnpm exec niceeval show --run <candidate-run-id>
```

First check how many positions in each Run were executed, carried automatically, accepted manually, not dispatched, or interrupted. Do not treat missing positions as a failure, zero score, or success when result coverage is incomplete.

When a Run leaves `not-dispatched` positions because of a budget, early exit, or partial acceptance, decide whether to fill those positions, accept an incomplete denominator, or compare only an explicit shared scope.

## Compare within one fixed selection

```sh
pnpm exec niceeval show \
  --run <baseline-run-id> \
  --run <candidate-run-id>
```

Use the same parameters when you need the complete page in a browser:

```sh
pnpm exec niceeval view \
  --run <baseline-run-id> \
  --run <candidate-run-id>
```

Compare pass rates for pass/fail evals and earned scores for scored evals. In a mixed Experiment, keep the two primary readings separate rather than combining them into one percentage.

Compare cost and duration only when Observability is complete. Missing, partially collected, or unsupported data must remain visible; do not fill it in as zero.

## Drill into the source of a difference

Copy an Attempt locator from the Run page:

```sh
pnpm exec niceeval show @1K1P0VJAPVJ12
```

The detail page lets you inspect Assertions, Judge reasons, tool calls, usage, timing, and File Changes. The Run page explains why this position used that Attempt; the Attempt page explains what actually happened during that execution.

For custom grouping, cost Profiles, or dedicated pages, continue with [Write Custom Reports](/tutorials/custom-reports).
