Record stores Runs, Attempts, Attachments, Content, and Seals. The project's canonical SQLite file lives at `.niceeval/record.sqlite`; it can contain both work in progress and published facts.

Only sealed Runs are available to Inspection, `query`, and `view`. Published facts are immutable. Cache, credentials, coordination state, and OS-user Service state are not Record facts.

```sh
cp .niceeval/record.sqlite ./baseline.record.sqlite
niceeval query explain --record ./baseline.record.sqlite --request request.json
niceeval view --record ./baseline.record.sqlite
```

The canonical file itself can be copied or archived. Do not copy WAL, checkpoint, or staging files, and do not modify SQLite content after copying it.

`query`, `show`, and `view` treat a file selected by `--record` as hostile input. They read it only after exact current-schema, SQLite-integrity, and domain-invariant validation. A Record can still contain sensitive business data, so its sender owns permissions, redaction, and retention.

Record does not own presentation, statistics, or comparisons. Fixed Inspection operations close those read semantics before passing results to `query` or first-party `view`.
