`defineEval` is the main entry point for authoring an Eval. Each Eval file calls it once, supplies a description and `test(t)`, and default-exports the result.

```ts
import { defineEval } from "niceeval";

export default defineEval({
  description: "Brooklyn weather query",
  async test(t) {
    const turn = await t.send("What's the weather like in Brooklyn today?");
    turn.succeeded().label("Turn completed");
  },
});
```

<Note>
  Do not provide `id` or `name`. [NiceEval](https://niceeval.com/) derives the Eval ID from the file path.
</Note>

#### `diff`

```ts
diff?: { include?: string[]; ignore?: string[] };
```

Adjusts the exclusion list for Agent-diff attribution, only for Sandbox Agents. See `docs/feature/eval/README.md`. Both arrays contain gitignore-style globs relative to workdir. The default excludes `.git`, `node_modules`, build output, and package-manager caches. `ignore` adds exclusions to the default list; `include` has highest priority and explicitly adds matching paths back. The composition rule is fixed: default ∪ ignore, with holes cut by include. The list freezes at the ledger anchor.

## Test context: `t`

`t` (`TestContext`) is the high-level context an Eval author receives. `check(subject, match)` is the sole Assertion registration primitive and takes exactly two arguments. Scoped helpers such as `succeeded()`, `calledTool(...)`, and `notCalledTool(...)` select their managed subject and Match, then register through that same path. A handle configures only its registered entry's `key`, `label`, parameterless `.gate()`, and `.score(n)`. `.orStop()` also applies only to that entry and never registers a second Assertion.

Pass/fail Evals fold Boolean conditions into an Attempt Verdict. A `ScoreMatch` forms its threshold with `.atLeast(n)` before registration. The registered thresholded handle's parameterless `.gate()` includes that local condition in `failed`. `await handle.orStop()` stops the current continuation on a mismatch or below-threshold result.

`defineScoreEval`'s `ScoreTestContext` additionally offers `t.score(n)` to directly register a contribution; `n` must be finite and non-negative. An existing Assertion contributes a score through `.score(n)`, where `n` must be finite and greater than zero. For the complete contract for `calledTool` and `notCalledTool`, see [Scoped assertions](https://github.com/NiceEval/NiceEval/blob/main/docs/feature/assertions/library/scoped-assertions.md). ## Judge measurement

Declare the Judge model or Provider in the Eval or its resolved runtime, then register explicit material through `t.judge` or a scoped Judge helper:

```ts
import { closeQA, defineEval } from "niceeval";

export default defineEval({
  judge: "judge-model",
  async test(t) {
    const turn = await t.send("Summarize the requirements.");
    t.judge({
      input: turn.input,
      output: turn.message,
      context: "The summary must cover the requirements stated in the input.",
    }, closeQA())
      .gate(0.8)
      .label("Answer quality");
  },
});
```

The built-in Judge helpers accept explicit material and register one measurement Assertion. For a Turn, use its immutable `input` and `message`. Judge material also accepts explicit `judgeImage()` values, and is snapshotted when registered. A pass/fail Eval uses `.gate(minimum)`; a scored Eval uses `.score(n)` on the registered handle.

### Image material

Import `judgeImage` from `niceeval/judge`. It synchronously copies the original image bytes. PNG and JPEG are supported, with a maximum of 4 MiB and 16,777,216 pixels per image. Each Assertion and model request accepts at most 4 image references and 8 MiB in total; repeated references count toward the limits. Each Attempt retains at most 32 MiB of image data. Input validation checks the signature, header bounds, and dimensions without fully decoding or transcoding the image.

`OpenAIProvider`, `VercelProvider`, and `OpenRouterProvider` must explicitly set `supportsImages: true` and select a model that supports both images and tool calls. Image support is disabled by default; `TypesafeProvider` does not support images. When image capability is unavailable, NiceEval returns `judge-capability-unavailable` instead of degrading the image to text.

## Test-suite exports

```ts
export default rows.map((row) =>
  defineEval({
    description: row.task,
    async test(t) {
      await t.send(row.prompt);
    },
  }),
);
```

An array export creates stable IDs: `file/0000`, `file/0001`, and so on.

When you already have stable business keys, you can instead default-export `Record<string, EvalDef>`. For example, key `15193` in `swelancer.eval.ts` produces `swelancer/15193`. A key must be a nonempty single path segment. It cannot be `.` or `..`, and cannot contain `/`, `\\`, or control characters. Discovery order is fixed by lexical key order.
