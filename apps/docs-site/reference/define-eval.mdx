`defineEval` is the main entry point for authoring an Eval. Each Eval file calls it once, supplies a description and `test(t)`, and default-exports the result.

```ts
import { defineEval } from "niceeval";

export default defineEval({
  description: "Brooklyn weather query",
  async test(t) {
    const turn = await t.send("What's the weather like in Brooklyn today?");
    turn.succeeded().label("Turn completed");
  },
});
```

<Note>
  Do not provide `id` or `name`. [NiceEval](https://niceeval.com/) derives the Eval ID from the file path.
</Note>

#### `diff`

```ts
diff?: { include?: string[]; ignore?: string[] };
```

Adjusts the exclusion list for Agent-diff attribution, only for Sandbox Agents. See `docs/feature/eval/README.md`. Both arrays contain gitignore-style globs relative to workdir. The default excludes `.git`, `node_modules`, build output, and package-manager caches. `ignore` adds exclusions to the default list; `include` has highest priority and explicitly adds matching paths back. The composition rule is fixed: default ∪ ignore, with holes cut by include. The list freezes at the ledger anchor.

## Test context: `t`

`t` (`TestContext`) is the high-level context an Eval author receives. Every author-facing entry-point call directly registers one Assertion. `t.check(value, match)` takes exactly two arguments. `t.succeeded()`, `session.succeeded()`, `turn.succeeded()`, `calledTool(...)`, `notCalledTool(...)`, and Judge recipes also directly register an Assertion. A handle only configures its same entry's `key`, `label`, `.atLeast(n)`, `.gate(n)`, and `.score(n)`. `.orStop()` also applies only to that entry and never registers a second Assertion.

Pass/fail Evals fold Boolean conditions into an Attempt Verdict. A measurement enters `failed` only with `.gate(n)`; `.atLeast(n)` adds only a local condition. `await handle.orStop()` stops the current continuation on a mismatch or below-threshold result.

`defineScoreEval`'s `ScoreTestContext` additionally offers `t.score(n)` to directly register a contribution; `n` must be finite and non-negative. An existing Assertion contributes a score through `.score(n)`, where `n` must be finite and greater than zero. For the complete contract for `calledTool` and `notCalledTool`, see [Scoped assertions](https://github.com/NiceEval/NiceEval/blob/main/docs/feature/assertions/library/scoped-assertions.md). ## Judge measurement

First declare `judge: true` in `defineEval` or `defineScoreEval`, then directly register a Judge Assertion:

```ts
const turn = await t.send("Summarize the requirements.");
turn.judge.autoevals.factuality(expected).gate(0.8).label("Factual consistency");
turn.judge.autoevals.closedQA(question).gate(0.7).label("Answer quality");
turn.judge.autoevals.summarizes(sourceText).score(20).label("Summary quality");
```

The root-level recipes in `t.judge.autoevals` additionally accept string `{ input, output }` material. `turn.judge` is already bound to immutable Turn material. Model configuration resolves once by Eval, Experiment, then project configuration. There is no single-call model override or `{ on }` option. A pass/fail Eval uses `.gate(n)`; a scored Eval uses `.score(n)` directly.

## `Turn` return type

`t.send(...)` returns a `TurnHandle`: convenience fields derived from the event stream plus a complete set of Assertions scoped to this turn.

`calledTool` and `notCalledTool` are also Turn-scoped Assertions. Their signatures and Match rules are defined only in [Scoped assertions](https://github.com/NiceEval/NiceEval/blob/main/docs/feature/assertions/library/scoped-assertions.md).

## Test-suite exports

```ts
export default rows.map((row) =>
  defineEval({
    description: row.task,
    async test(t) {
      await t.send(row.prompt);
    },
  }),
);
```

An array export creates stable IDs: `file/0000`, `file/0001`, and so on.

When you already have stable business keys, you can instead default-export `Record<string, EvalDef>`. For example, key `15193` in `swelancer.eval.ts` produces `swelancer/15193`. A key must be a nonempty single path segment. It cannot be `.` or `..`, and cannot contain `/`, `\\`, or control characters. Discovery order is fixed by lexical key order.
