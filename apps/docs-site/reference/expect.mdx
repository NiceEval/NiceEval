`niceeval/expect` provides only pure Match factories. A Match compares one candidate value; it does not record a result or decide a Verdict or score. `t.check(value, match)` reads `value` when called and registers an Assertion directly; the returned handle only configures that same entry.

```ts
import { and, excludes, includes, pattern } from "niceeval/expect";
```

## How to use it

```ts
t.check(t.reply, includes("confirmed"));
t.check(t.reply, and(pattern(/order #\d+/i), excludes("cancelled")));
const config = await t.check(rawConfig, pattern(/runtime/)).orStop();
```

| Entry point | Purpose |
|---|---|
| `t.check(value, match)` | Takes exactly two arguments and registers an Assertion when called; a failure does not stop later code |
| `await handle.orStop()` | An async barrier on the same handle; stops the current continuation on mismatch or below |
| `handle.score(n)` / `t.score(n)` | Lets this item contribute a score in a scored Eval, or registers a contribution directly |

## Numeric units

Calculate with ordinary numbers, then wrap the result with `ms`, `seconds`, `tokens`, `usd`, `ratio`, `count`, or `bytes`. Each constructor returns a frozen `Quantity<U>` with `.value` and `.unit`. Quantities do not support arithmetic or automatic conversion.

Constructors require finite numbers. `ratio(n)` also requires `0 ≤ n ≤ 1`; invalid values throw `RangeError`.

```ts
import { atMost, between, measured, ms, quantile, ratio } from "niceeval/expect";

const latency = measured(ms(512), { unavailable: "missing" });
t.check(latency, atMost(ms(600)));
t.check(quantile([ms(100), ms(200)], 0.9), between(ms(100), ms(200)));
t.check(t.usage.cacheRead.rate(), atMost(ratio(0.9)));
```

`measured` accepts `number | null` or `Quantity<U> | null`. `quantile` accepts ordinary numbers or quantities sharing one unit, and preserves that unit. Mixing units or mixing numbers with quantities throws `TypeError`. Empty samples and missing observations remain unavailable.

`atLeast`, `atMost`, `greaterThan`, and `lessThan` require thresholds with the observation's unit. `between(minimum, maximum)` uses inclusive bounds with one unit, ordered from lower to upper. Unitless observations require ordinary numeric thresholds.

TypeScript rejects incompatible units. When JavaScript bypasses the types, the check becomes unavailable and reports the mismatch. `show` and `view` format units as `512 ms`, `61.2%`, and `$0.031`.

### Match tool calls

`ToolMatch` compares one `LogicalToolOccurrence`, and expresses the occurrence count with methods such as `.exactly(n)` and `.atLeast(n)`. `calledTool` accepts a name, an unquantified `ToolMatch`, or a positive occurrence Match; `notCalledTool` uses an unquantified selector to express zero matches.

```ts
import {
  commandMatch,
  jsonMatch,
  referencesAnyPath,
  toolMatch,
} from "niceeval/expect";

turn.calledTool(
  toolMatch("get_weather", {
    input: jsonMatch({ city: "Taipei", unit: "celsius" }),
    status: "completed",
  }).exactly(1),
).label("Query weather precisely");

turn.calledTool(
  toolMatch("read_file", {
    input: referencesAnyPath([".env", "secrets/**"]),
  }),
).label("Read a restricted path");

turn.notCalledTool(commandMatch("rm", { argsStart: ["-rf"] }));
```

Use `jsonMatch` for ordinary JSON, `referencesAnyPath` for paths, and `commandMatch` for command tokens. When output is absent, material is incomplete, or HITL has not finished, the Match becomes unavailable; it does not pretend to be an ordinary mismatch.

For complete signatures, material states, and three-valued counting rules, see [Scoped assertions](https://github.com/NiceEval/NiceEval/blob/main/docs/feature/assertions/library/scoped-assertions.md).

## Composition and three states

```ts
t.check(t.reply, and(includes("required"), excludes("forbidden")));
t.check(t.reply, or(includes("approved"), includes("accepted")));
```

Matches within the same `and` / `or` must belong to the same domain. The internal result of a Boolean Match is `matched`, `mismatched`, or `unavailable`. `or` returns `unavailable` only when no child matches and at least one child's evidence is incomplete; it does not treat unknown as negative. A Match itself holds no Verdict, scoring, or control flow; `.gate(minimum)`, `.score(n)`, and `.orStop(minimum)` for a continuous measurement all belong to the registered AssertionHandle.

## Ordering conditions in a collection

`inOrder` combines 2–64 ordinary value Matches into a collection Match, which you pass to `t.check` or to an application's collection assertion method.
It accepts a read-only array or a `MaterialCollection` with a completeness state, and looks for a strictly increasing subsequence by original position; the items need not be adjacent.

```ts
import { equals, inOrder, not, or } from "niceeval/expect";

t.check([1, 0, 2], inOrder([equals(1), equals(2)])).gate();
t.check([2, 1], not(inOrder([equals(1), equals(2)]))).gate();
t.check([3, 4], or(
  inOrder([equals(1), equals(2)]),
  inOrder([equals(3), equals(4)]),
)).gate();
```

The same item cannot satisfy two steps, and each step can use `and` to constrain the same fact. The application is responsible for providing the formal commit order; a request being sent does not mean the operation was adopted or finished executing.
When you only need both parties to have spoken, check existence separately.

An incomplete collection returns undecidable. A complete collection passes when there is known ordering evidence, fails when no ordering is possible, and is undecidable when it can only hold by depending on unknown items.
Diagnostics keep the original positions, material IDs, and step judgments. Ordering combinations of ToolMatch and EventMatch keep their own Agent scope and cannot be mixed with ordinary value steps.

## Custom matchers

```ts
import { defineValueMatch } from "niceeval/expect";

const validEmail = () =>
  defineValueMatch<string>({
    name: "valid email",
    evaluate(value) {
      return value.includes("@");
    },
  });

t.check(t.reply, validEmail());
```

Use `defineValueMatch` for a custom Boolean Match and `defineScoreMatch` for a continuous score. Both implement only a single-candidate comparison; reading files, scanning events, deciding coverage, and changing a Verdict remain the responsibility of Assertion registration entry points and the Runner.
