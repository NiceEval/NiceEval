An Experiment decides what you run against, including the Agent under test, the model, and the run conditions. It is kept separate from Evals, so the same set of Evals can compare different configurations. For the complete approach, see [Write an Experiment](/tutorials/write-experiment).

```ts
// experiments/local.ts
import { defineExperiment } from "niceeval";
import { webAgent } from "../agents/web-agent.ts";

export default defineExperiment({
  agent: webAgent({ baseUrl: "http://127.0.0.1:5188" }),
});
```

#### `models`

```ts
models?: Readonly<Record<string, ModelRoleSelection>>;
```

Selects a model for each named model role of a custom Adapter; cannot be combined with the single-model shorthand.

#### `description`

```ts
description?: string;
```

A one-sentence description shown in the view and CLI; purely informational, it does not affect scheduling or scoring.

#### `adapter`

```ts
adapter?: Adapter;
```

The Adapter implementation this Experiment uses.

#### `model`

```ts
model?: string;
```

A single model (decided by the Experiment when the agent leaves it empty); omitted = use the agent's native default. To compare models, write several Experiment files instead of an array.

#### `reasoningEffort`

```ts
reasoningEffort?: string;
```

The model's reasoning effort (such as "low"/"medium"/"high"; valid values depend on the specific model/adapter); omitted = use the agent's native default. Passed to the adapter and eval through ctx.reasoningEffort.

#### `judge`

```ts
judge?: JudgeSelection;
```

This Experiment's Judge execution configuration. It overrides only the model / endpoint / credential selector / call budget;
the rubric is owned by the Match, and the material and consumption threshold come from the Assertion. Each field resolves in the order
Experiment → Eval → Config → built-in default.

#### `flags`

```ts
flags?: globalThis.Record<string, FlagValue>;
```

Experiment conditions (the feature flags in an A/B), declared by the Experiment file; must be a flat scalar object
 (strings, finite numbers, or booleans only, validated when defineExperiment parses it). Passed to the adapter through ctx.flags,
 exposed to the eval as t.flags, and copied verbatim into the result snapshot's ExperimentRunInfo.flags.

#### `labels`

```ts
labels?: globalThis.Record<string, string | number>;
```

Report grouping labels: the Experiment's coordinates on each comparison axis (such as `{ line: "codex", memory: "mempal" }`).
Values are string | number (validated at parse time). The line between labels and `flags` is "does it change what happens in the attempt":
labels are not passed to ctx / t (the agent and eval cannot see them) and do not take part in the comparability configuration (changing them does not invalidate existing results);
they are only projected verbatim into the snapshot's `ExperimentRunInfo.labels` for report dimensions (`label()` / `numericLabel()`)
to group by. The default report recognizes the `line` key: when any Experiment in the group declares it, scatter points are grouped by line and connected.
See docs/feature/experiments/library/README.md "labels".

#### `attempts`

```ts
attempts?: number;
```

How many times to repeat the same eval (each result counts as one attempt); defaults to 1 when omitted or when CLI `--attempts` overrides it.

#### `earlyExit`

```ts
earlyExit?: boolean;
```

Within a repetition (attempts &gt; 1), whether to skip the remaining repeats after one attempt passes; defaults to false when omitted (`attempts` run in full to measure the complete pass rate).
 Turn it on explicitly to save cost when you only want to know whether it can pass.

#### `evals`

```ts
evals?: "*" | readonly string[] | ((e: EvalDescriptor) => boolean);
```

Which evals this Experiment covers: `"*"` for all, a string array matched by id prefix, or a custom predicate (which receives each discovered and fanned-out
read-only `EvalDescriptor`, with no path / execution fields exposed); omitted is equivalent to `"*"`. The predicate is evaluated once per
candidate eval of this invocation, and the result becomes the in-memory `selectedEvalIds` plan, not a filter called repeatedly at runtime
(see docs/feature/eval/library/README.md "EvalDescriptor" and docs/feature/experiments/library/README.md
"evals: iterate discovery results, choose your own").

#### `timeoutMs`

```ts
timeoutMs?: number;
```

Overrides the project-level / CLI per-attempt timeout (milliseconds), only for this Experiment.

#### `sandbox`

```ts
sandbox?: SandboxLayer;
```

The Sandbox declaration layer this Experiment contributes. It is linked pairwise with the same field of each selected Eval;
in each pair, exactly one side provides a template-bearing layer.

#### `sandboxCache`

```ts
sandboxCache?: SandboxCacheConfig;
```

The Host's execution cache policy; unlike the Sandbox declaration layer, this field does not take part in identity computation.

#### `sandboxLabels`

```ts
sandboxLabels?: "run-only";
```

Emit only Run-level Provider labels, omitting the Attempt and Eval creation labels. Does not affect execution identity.

#### `plugins`

```ts
plugins?: readonly PluginInstance<"experiment">[];
```

The list of Plugin instances this Experiment declares explicitly, normalized by `defineExperiment()`.

#### `sandboxReuse`

```ts
sandboxReuse?: boolean;
```

Reuse Sandboxes within the same Run; such runs are isolated from history carry in both directions.

#### `sharedState`

```ts
sharedState?: SharedStateConfig;
```

Declares shared external state this Experiment needs exclusively. Invocations with the same key in the same project
Coordination domain are mutually exclusive from before Experiment/Sandbox before until Sandbox after,
provider finalizers, and Experiment after have all finished; waiters do not create a Sandbox first,
and continue their own plan after acquiring the lease. It is not a state store, a transaction, or a cross-machine lock.

#### `budget`

```ts
budget?: number;
```

This Experiment's estimated spend limit (USD). The scheduler accumulates the `estimatedCostUSD` of finished attempts; that value is
computed from the model, token usage, and the runtime/config pricing table, independent of the
observed `usage.costUSD` reported by the Provider / Adapter, which does not drive the budget. Once the estimate reaches the limit, the Experiment's remaining
attempts that have not started are skipped and `run:budgetExceeded` is reported once (attempts already in flight still finish).

#### `maxConcurrency`

```ts
maxConcurrency?: number;
```

This Experiment's own concurrency limit within this Invocation: the scheduler throttles only this Experiment's attempts; other Experiments in the batch are unaffected
and still run under the global concurrency (CLI / env / config / Sandbox default). Use it to serialize Experiments with shared state
(such as memory accumulated across evals: `maxConcurrency: 1` guarantees attempts run one by one in eval order),
or to slow down an Experiment that hits provider limits. A concurrency permit shares the attempt's lifetime: it is held from before Sandbox creation until
after and Sandbox destruction finish, and any wait along the way (including turn retry backoff) keeps holding it.
`maxConcurrency: 1` is therefore a strict critical section that the next attempt of the same Experiment cannot enter early.
It does not span Invocations; for shared external state across Invocations, declare `sharedState`.

#### `before`

```ts
before?: ExperimentHook;
```

The before side of the Experiment-level lifecycle hook pair: at most once per run, on the host side, for host resources that are "one per Experiment, shared by all attempts"
(tunnels, mock servers, license leases). Triggered by the first attempt of this Experiment that passes dispatch admission
(memoized: concurrent attempts wait for the same result; not run when all results are carried in).
before returns no value; write products to module-level variables, and `after` and agent / sandbox hooks in the same file read them from the closure;
the runner does not mediate values. If before throws, every Attempt of this Experiment gets an `errored` Verdict
(code `"experiment-setup-failed"`, phase `"experiment.before"`); other Experiments in the batch are unaffected.
The function body does not enter the fingerprint; after changing hook logic, use `--rerun all` to explicitly rerun everything.
See docs/feature/experiments/architecture/README.md "Experiment-level lifecycle".

#### `after`

```ts
after?: ExperimentHook;
```

The after side of the Experiment-level lifecycle hook pair: runs after all of this Experiment's attempts finish (also when the run is interrupted),
if and only if execution reached the before point. A before throw does not exempt it (a half-initialized scene also needs cleanup; after should guard closure variables
that may be unassigned); having no before declared does not prevent it from firing; it is skipped when no attempt is dispatched.
A throw or exceeding the 30s cleanup limit records only a run-level diagnostic (`experiment-teardown-failed`) and does not change the Verdict.
