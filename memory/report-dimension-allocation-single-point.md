# 维度槽位分配单点声明补齐，dimensionPins 与惰性 page 消解

- **现象**：外审指出 dimensionPins 与惰性跨页矛盾——shell.md 说
  「跨页视觉分配要先看到完整分配」，而动态分组值只有执行 page render 才知道，
  「不开其它页」与「按全报告出现顺序分配未钉住值」不可兼得。
  核查发现更深一层：presentation.md 与 theme.md 都把分配规则
  「单点声明」链到 components/README.md 的两个小节，而那两个小节不存在
  （引擎侧规则只散落在 docs/engineering/testing/unit/reports.md 的覆盖规范里）。
- **裁决**（2026-07-29）：分配单位是页，钉住是跨页一致性的唯一承诺：
  1. 钉住且出现在本页 visual keyset 的值原样占用钉住下标（重复下标不探测）；
  2. 未钉住的值按（维度名，完整值）稳定哈希取起点、在剩余槽位向后探测，
     哈希与探测算法属公开契约；
  3. 钉住但未出现的值不占槽；visual keyset 超 24 拒绝该页。
  未钉住值只保证页内自洽、跨页不承诺一致——要跨页一致就钉住。
  分配只依赖钉住声明（装载期可读）与本页 keyset，与惰性求值零冲突。
- **曾选方案**：按全报告出现顺序分配未钉住值——需要求值全部 page 才知道全集，
  与「未打开的 page 不执行」直接冲突，否决。
- **修法**：单点小节落在 components/README.md
  （「维度呈现分配单位是页」+「视觉编码容量（24 个身份）」，补上悬空锚点）；
  shell.md 定义 `DimensionPins = Record<维度, Record<值, 1–24 槽位号>>` 并改写理由句。
- **同日两处修正**（外审第二轮）：槽位号基数曾写成 0–23，
  与实现（presentation.ts `[1, 24]`）和 CSS 令牌 `--niceeval-color-series-1..6`
  的一基不合，改回 1–24；「未知维度名装载期拒绝」删除——
  自定义分组键只在 page render 里出现，装载期没有维度名全集，
  装载期校验只看结构（槽位号整数与范围、值键非空）。
