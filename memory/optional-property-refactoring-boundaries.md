# 可选属性重构必须由构造者与编码边界驱动

开启 `exactOptionalPropertyTypes` 后，在每个调用处加条件展开，会把同一个缺席判断复制到整个流水线。
反过来，把全部字段改为必需键并机械补 `undefined`，也没有加强领域约束，还会覆盖已有 spread 中的真实值。

有效的拆分依据是构造者：作者输入允许省略；内部先消除冗余字段、补真实默认值，再把相关状态建模为判别联合。
只有独立且确实可能缺失的事实保留 `T | undefined`。Record、摘要材料、合并补丁和第三方协议按实际键语义编码。
内部对象直接进入精确 Schema 的风险不能靠 `JSON.stringify` 掩盖；检查器应在唯一投影边界拒绝非法对象。

这次重构的实际反例包括 Run 级附件被当成 Attempt 附件、内部断言结果携带 undefined 进入 Score Record，以及 action step 的缺省 cwd 进入身份材料。
修复都落在所有者联合或已有编码入口，不放宽持久 Schema。
冻结也不能只看对象是否内部构造：向作者回调交付的材料与跨异步边界的快照仍需隔离可变别名，`readonly` 无法替代这个保证。

计数下降只能帮助定位。类型检查通过仍不能证明键序、身份摘要、公开冻结承诺和所有构造路径保持语义。
验收应覆盖公开调用、序列化结果和资源终态，再检查对应生产者的类型。
