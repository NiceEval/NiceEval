# Waterfall 呈现的四条裁决(2026-07-28)

起因:真机报告里的执行时间轴读不动——kind 渲染成彩色小方块、208 个节点的色带条是一整块
灰、几十行同名 span 平铺、几十条 `command ×1 · 合计 257ms` 的单节点摘要。逐条查下来一半是
契约留白让实现自由发挥,一半是实现违反了已经写死的契约。

契约正文在 `docs/feature/reports/components/primitives/waterfall.md`,这里只留否决理由。

## 裁决一:kind 着色由字面散列到分类色五槽,原语不建词表

- **曾选方案 A**:`.niceeval-span-phase / -agent / -model / -tool` 四条硬编码 CSS,`agent` 借
  `--good`、`model` 借 `--warn`。
- **否决理由**:`WaterfallNode.kind` 的词表由数据源给,原语为具体词配色等于把开放词表钉死——
  数据源换一套词,新词全部落到无背景的兜底。借语义色更糟:`DESIGN.md` 规定 positive /
  negative / warning 含义固定,`model` 染成 warning 会被读成「这一段有问题」。
- **曾选方案 B**(同日推翻):散列到四档明度,条上全灰。当时读 `DESIGN.md` 只读到「区分靠位置
  和明度」,漏了下一条——分类色本来就是给「实验、agent、标签」这类名义身份留的通道,`kind` 正是
  同一类东西。用户看到全灰的条直接说「没色」,方案 B 是过度保守,不是保守得对。
- **落点**:`kindSlot()` 散列到 `niceeval-span-kind-0..4`,映射到 `--c0 --c1 --c2 --c3 --c5`。
  跳过 `--c4`:它离 `--bad` 太近,而失败段在条上只有颜色一个载体,两个红就分不出失败。整段面积
  上色前兑 32% 面色——色板是给线和点定的,原样铺满整条会盖过页面。
  `test/unit/report-css-contract.test.ts` 钉住五槽各有规则。

## 裁决二:清单里的 kind 不着色,改成定宽文字列

- **曾选方案**:kind 文本复用条段的 `niceeval-span-${kind}` 类。
- **否决理由**:那组类唯一的属性就是 `background`,inline 文本吃了条段背景就成了色块标签,
  与 `DESIGN.md`「盒子默认不带颜色、不用装饰性色条」直接抵触。
- **落点**:清单定为四列(指示符 / 类别 / 名字 / 时长),类别列靠定宽位置和次级文字色区分。
  同一次改动里把展开指示符改成原语自绘的 `▸` / `▾`——三列是 flex 行,浏览器给 `<summary>`
  的默认标记在 `display: flex` 下不出现,可展开与不可展开的行长得一模一样。

## 裁决三:分解条画叶子,不画顶层也不画全部

- **曾选方案**:条画 `row.nodes` 顶层(实现);契约正文写的是「恒绘全部节点」。
- **否决理由**:两个都不成立。父节点在时间上包住子节点,画上去只会盖住子段——一个占满全行的
  `eval.run` 足以让整条变成一块实心,这正是真机上那条灰带。画「全部」则父子叠涂,更糟。
- **落点**:`leafNodes()` 递归取无 `children` 的节点。同时把段的最小宽度从 `0.5%` 改成 `1px`:
  取百分比时几百个下限段叠起来会把整条铺满,条越密反而越没信息。

## 裁决四:清单收敛加两条门槛——短摘要 ≥2 条、重复摘要 ≥3 条

- **曾选方案**:只有「低于行总时长 1% 的连续节点折成摘要」一条规则,不设条数下限。
- **否决理由**:一条规则收不住两种噪音。摘要只收到一条时(`command ×1 · 合计 257ms`)与那个
  节点各占一行,省不下高度却把名字换成了计数,严格更差。反过来,agent 循环里重复几十次的同名
  span 每条都够长、够显著,短节点那条规则根本碰不到它们。
- **落点**:`SHORT_MIN = 2` 与 `REPEAT_MIN = 3`;重复摘要判据是连续 + 同 `kind` + `label` 同文,
  `failed` / `open` / 时长缺失的节点两条规则都豁免。真机上同一份 attempt 的摘要行从 78 条
  降到 7 条。

## 裁决五:DiffView 摘要行的增删数各自着色

- **曾选方案**:`+N / -M` 一个 span,整体 `--muted`。
- **否决理由**:同一件事在折叠态是灰的、展开后 patch 里的增删行是绿红的——收起来就变灰没有道理。
- **落点**:拆成 `niceeval-diff-lines-added` / `-removed` 两个 span 读 `--good` / `--bad`,
  与 `niceeval-diff-patch-line--add/--remove` 同一套。text 面不动,仍是 `(+N/-M)`。
