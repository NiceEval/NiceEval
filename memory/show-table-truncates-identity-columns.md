# show 的表格把 eval id 压成几个字符,`COLUMNS=200` 也不生效

**现象。**(2026-07-25,MemoryBench 真实使用)想拿到「这一轮哪些 eval 失败了」的完整清单,
`niceeval show` 的表格里身份列被终端宽度压到两三个字符宽,读不出是哪条 eval;显式
`COLUMNS=200 niceeval show` 不改变排版。最后是写了个 node 脚本遍历 `.niceeval/**/result.json`
才拿到完整 id 列表。

**根因(判断,未逐行核实)。** 两个独立问题叠在一起:

1. 表格超宽的收缩策略没有身份列下限——按「压最宽的左对齐列」的规则,eval id 恰好就是最宽的那列,
   于是被一路压到不可读;而它是读者要复制去执行下一条命令的可操作字段,压掉它整张表就没有用了。
2. 宽度来源大概率只取 TTY 实测(或按非 TTY 走固定兜底),没有读 `COLUMNS`。管道 / CI / `tee`
   到文件时实测拿不到宽度,`COLUMNS` 是读者唯一能表达「按这个宽度排」的手段。

**修法。** docs 侧契约已补(2026-07-25,`docs/feature/reports/library/layout.md`):

- `Table` 渲染契约加一条「身份列压不到不可读」——eval id / experiment id / `locator` 下限 24 显示列,
  其余列压到下限仍放不下就从右侧丢列,窄到放不下一列身份时整体降级成每行一条身份的纵向清单。
- 区域框「几何」加一条宽度来源优先级:显式传入 → `COLUMNS` → TTY 实测 → 80 兜底,且 `COLUMNS`
  不因为输出不是 TTY 就被忽略(降级成无框纯文本与按 80 列排版是两件事)。

代码侧未修。改的时候注意这两条要落在 `Table` 的收缩规划与宿主的宽度解析两处,不是在 show 的某个页面
里特判。

**相关。** 「挖失败 id」这个需求本身已被 [rerun-gear-replaces-force](rerun-gear-replaces-force.md)
削掉大半:`--rerun` 按判定收窄重跑,常见路径下不再需要人肉拿到 id 列表。这条记的是剩下的那半——
确实要读清单时,表格必须可读。
