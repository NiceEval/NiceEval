Import Report authoring APIs from `niceeval/report` and the `Sample` type from `niceeval/record`. The 0.12 classic facade is the default authoring surface: define pages with `defineReport({ title, pages })`, render each page with `render(sample)`, and compose reusable business components with `defineComponent((props, ctx) => ...)`.

Use the lower-level projection API when you need custom projections or Calculations. Neither API gives authors a reader, path, raw Attachment, or disk field.

```text
Record
    ↓ fixed projection plan / RecordProjection declarations
frozen Sample / ProjectedSample
    ↓ page.render(sample) / Calculation / Page / PageFamily / Download
closed semantic validation
    ↓
immutable ReportExecution
        ├─ show
        ├─ view revision
        └─ static export
```

## Classic facade

### `defineReport` and `render(sample)`

The classic overload accepts a Report title and a list of pages. Each `render(sample)` call receives a frozen `Sample` after the host has projected it once, then returns a controlled JSX tree.

```tsx
import type { Sample } from "niceeval/record";
import {
  aggregate,
  Bars,
  Col,
  defineReport,
  experiment,
  passRate,
} from "niceeval/report";

async function overview(sample: Sample) {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });

  return (
    <Col>
      <Bars
        points={rows}
        x="experiment"
        y="passRate"
        layout="horizontal"
      />
    </Col>
  );
}

export default defineReport({
  title: "Memory condition comparison",
  pages: [{
    id: "overview",
    title: "Report",
    render: overview,
  }],
});
```

`Sample` has no reader, path, Record I/O, or deferred data lookup. The host selects the locale before it creates an execution, so changing the browser language never calls `render` again.

Reusable components use the same 0.12 composition shape. `ctx.scope` is the frozen `Sample` for the current page:

```tsx
import {
  aggregate,
  Bars,
  defineComponent,
  experiment,
  passRate,
} from "niceeval/report";

const Leaderboard = defineComponent(async (_props, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { experiment },
    values: { passRate },
  });

  return (
    <Bars
      points={rows}
      x="experiment"
      y="passRate"
      layout="horizontal"
    />
  );
});
```

Existing React Reports can keep `"jsx": "react-jsx"`. NiceEval accepts the React element but expands only controlled components. To use the JSX runtime bundled with NiceEval instead, set both options in the Report project's `tsconfig.json`:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "niceeval/report"
  }
}
```

Both choices produce the same classic element tree.

### Controlled JSX boundary

The tree accepts built-in components and `Fragment`. Children can be arrays, strings, numbers, or `null`. It rejects:

- Native tags such as `div` and `span`, and arbitrary unbranded components.
- `head`, scripts, styles, fonts, workers, WASM, and raw HTML.
- Custom text/web dual renderers.

A trusted TypeScript module is not a sandbox. It can still import `node:fs` or read environment variables. NiceEval guarantees only that classic components do not receive a reader, Effect, Record root or path, or append-I/O capability.

### Built-in components

| Component | Purpose |
| --- | --- |
| `Col` | A vertical layout container that keeps child blocks in declaration order. |
| `Section` | A titled block. |
| `Hero` | The page's opening summary. It accepts `title`, `logo`, `description`, and `links`. Links must use absolute HTTPS URLs; NiceEval serializes the URL but does not fetch it. |
| `SampleSummary` | A summary of the current Sample: Experiments, Evals, Attempts, and coverage. |
| `Bars` | A bar chart. Set `layout="horizontal"` for horizontal bars. |
| `ExperimentScatter` | A scatter plot by Experiment. Pass `input={sample}` to use an explicit Sample. A point links to its Experiment page only when the current Report expands that page. |
| `ExperimentTable` | An Experiment-level readings table. Pass `input={sample}` to use an explicit Sample. |
| `SampleNotices` | Renders the partial-selection warning from the closed Sample. |
| `RunNotices` | Preserves the 0.12 author import and composition position. The current closed Sample has no Run-diagnostics projection, so this component renders no block rather than inventing an empty diagnostic result. |

Official themes remain available from both classic import locations:

```ts
import { basalt, chalk } from "niceeval/report/built-in";
```

These are the same `ThemeDefinition` values exported from `niceeval/report`.

### `aggregate`, `passRate`, and `costUSD`

An aggregation group function receives the Experiment ID, Eval ID, and the Run's declared Experiment fields:

```ts
type AggregationSubject = {
  readonly experimentId: string;
  readonly evalId: string;
  readonly run: {
    readonly experiment?: {
      readonly labels?: Readonly<Record<string, string | number>>;
      readonly flags?: Readonly<Record<string, unknown>>;
    };
  };
};

type GroupFunction = (subject: AggregationSubject) => string;
```

`experiment` groups by `experimentId`. `aggregate(sample, { by, values })` groups at Eval granularity, so it never separates Attempts for the same Eval.

`passRate` uses a strict two-level denominator:

- For each `(experiment, eval)` unit, it averages Attempts: `passed` is 1, while `failed` and `errored` are 0.
- `skipped` and missing values do not enter the numerator or become invented values. Coverage shows the gap.
- It then averages the unit values equally across Evals.

`costUSD` uses the same two-level denominator. Missing cost and timing stay missing; they never become zero.

### Sample metadata

Sample metadata identifies its source instead of using the current project declaration to fill historical data:

- `project-current` uses the complete current-declaration profile and records `metadataOrigin: "current-declaration"`.
- Explicit Runs passed through `--run` have unknown or partial metadata when the Record has no durable profile. Experiment IDs fall back to an ID or `unknown`, and NiceEval shows a structured notice.

These modes never mix metadata from the current declaration with historical data.

## Lower-level projection API

Use the lower-level API when a Report needs a custom projection or Calculation. It shares the same `ReportExecution` path as the classic facade.

### Declare a `RecordProjection`

NiceEval's opaque projectors create typed views. A Report declares logical access with one of three constructors; authors cannot define a raw family or projector.

| Constructor | Alignment |
| --- | --- |
| `attemptSlotProjection(projector)` | Creates one entry for every Sample slot and reads the exact Attempt Attachment that slot references. |
| `attemptOriginRunProjection(projector)` | Creates one entry for every Sample slot and reads the included Attempt's origin Run Attachment. |
| `selectedRunProjection(projector)` | Creates one entry for each selected Run and reads that Run Attachment. |

The first two forms preserve excluded, not-recorded, and core-invalid slots. If multiple slots reference the same Attempt, the public result remains slot-aligned.

```ts
import { Either } from "effect";
import {
  attemptSlotProjection,
  defineCalculation,
  definePage,
  defineReport,
  reportComponentId,
  reportDocument,
  reportId,
  reportInputs,
  reportMetric,
  reportRoute,
  verdictProjector,
} from "niceeval/report";

const verdicts = attemptSlotProjection(verdictProjector);
const inputs = reportInputs({ verdicts });

const verdictEntryCount = defineCalculation({
  id: Either.getOrThrow(reportComponentId("verdict-entry-count")),
  inputs,
  completeness: "allow-partial",
  calculate: ({ inputs }) => inputs.verdicts.entries.length,
});

const overview = definePage({
  id: Either.getOrThrow(reportComponentId("overview")),
  route: Either.getOrThrow(reportRoute("/")),
  calculations: { verdictEntryCount },
  render: ({ calculations }) =>
    reportDocument({
      title: "Summary",
      children: [
        reportMetric({
          label: "Verdict entries",
          value: calculations.verdictEntryCount.state === "available"
            ? calculations.verdictEntryCount.value
            : null,
        }),
      ],
    }),
});

export default defineReport({
  id: Either.getOrThrow(reportId("summary")),
  calculations: { verdictEntryCount },
  pages: [overview],
});
```

`reportInputs` creates the named input shape and preserves the exact type of each `ProjectedSample`. The host closes all projection dependencies before Record I/O and runs each projection at most once.

Every Calculation, Page, PageFamily, or Download that directly consumes a projection chooses one completeness mode:

| Mode | Behavior |
| --- | --- |
| `"allow-partial"` | The callback receives the complete `ProjectedSample`, coverage, and issues. It can render a partial result. |
| `"require-complete"` | NiceEval does not call the callback when required data is incomplete. The result is `data-unavailable`. |

`unavailable`, `migration-required`, `migration-unavailable`, `unsupported`, `invalid`, and partial collection are recorded-data problems. A projector or author callback that throws is an execution problem instead.

Pages return a closed `ReportDocument` semantic tree, not arbitrary HTML, DOM, or React elements. A `PageFamily` can expand routes only from already projected or calculated in-memory values; it cannot add Attachment I/O while expanding a route.

## Run a Report through the CLI

Application code does not call the Report host. `niceeval show`, `niceeval view`, and `niceeval view --out` select Runs, execute the projection and author graph, and create an immutable, self-contained `ReportExecution`.

The package does not export `niceeval/report/host`, `niceeval/report/host/node`, or `executeReport()`. A `ReportExecution` contains the Sample, projection summary, Calculations, families, pages, downloads, and problem table, but not a reader, path, Scope, callback, or projector token.

Each projection, Calculation, PageFamily, page instance, and Download runs at most once in an execution. `show`, `view`, and static export consume only the completed execution.

| Condition | `show` and `view` | Static export |
| --- | --- | --- |
| Recorded-data problem | Shows the problem and keeps other successful content. | Can export, and the problem remains visible. |
| Execution problem | Shows the problem and keeps other successful pages. | Does not export that execution. |

## `view` and static export

Each `view` rebuild creates a new immutable `ReportExecution`. NiceEval replaces the current revision only after a complete success; a failed rebuild retains the last good execution and shows a bounded rebuild problem.

Static export writes one completed execution. It validates the semantic tree, routes, downloads, and execution problems before writing pages, host data, downloads, the manifest, and the bundled runtime. It writes the `complete` marker last.
