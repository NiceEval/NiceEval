A Report only handles display. Define statistical meaning in Analysis first, then obtain closed results in a Page or component. A Report author does not read result files, register durable data types, or handle migration or storage paths.

```text
Published run results
        ↓
Analysis: Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report: Page + component
        ↓
ReportExecution → show / view / static export
```

## Define statistical meaning first

`niceeval/analysis` provides NiceEval's published inputs. Use `defineMeasure()` to make the population, aggregation, denominator, and missing-data policy explicit. No separate input-registration step is needed.

```ts
import {
  allLogicalSlots,
  attemptPassed,
  defineDimension,
  defineMeasure,
  latestCompletedAttempt,
  logicalSlots,
  oneValue,
  partial,
  ratio,
  retainContributingEvidence,
} from "niceeval/analysis";

export const experiment = defineDimension({
  id: "example.experiment",
  population: logicalSlots,
  value: slot => slot.experimentId,
});

export const passRate = defineMeasure({
  id: "example.pass-rate",
  population: logicalSlots,
  input: attemptPassed,
  withinAttempt: oneValue<boolean>(),
  withinSlot: latestCompletedAttempt<boolean>(),
  acrossSlots: ratio(),
  denominator: allLogicalSlots(),
  missing: partial(),
  evidence: retainContributingEvidence(),
  unit: "ratio",
  format: "percent",
  better: "higher",
});
```

A `MetricValue` retains its value, state, actual contributor count, fixed denominator, problems, and evidence references. Do not unwrap a number and then recalculate or wrap it again in a Report.

## Read closed values in a Page or component

`aggregate()` is for table or chart rows grouped by a Dimension. It runs on the `Sample` that a Page or composite component receives, and returns `ClosedRows` that you can pass directly to `Table`, `Bars`, `Line`, or `Scatter`.

```ts
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const Comparison = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });

  return Grid({
    children: [
      Bars({ points: rows, x: "experiment", y: "passRate" }),
      Table({ rows, caption: "Pass rate by experiment" }),
    ],
  });
});

export default defineReport({
  title: "Quality overview",
  pages: [
    {
      id: "overview",
      path: "/",
      title: "Overview",
      render: () => Comparison({}),
    },
  ],
});
```

For a complete tabular request or a domain view, import `query()` from `niceeval/analysis`. For example, `attemptEvidenceView` returns a closed evidence view. It never gives a component a reader or raw run data.

## Two component forms

A composite component receives a `Sample` while it executes, then combines existing components. `Comparison` above is this kind of component.

A new display primitive provides both a text surface and a web surface. Its optional `resolve()` is the only phase that can retrieve a closed value asynchronously. `text` and `web` then read the same result.

```ts
import {
  defineComponent,
  Stat,
  Text,
  type MetricValue,
} from "niceeval/report";

const PassRateState = defineComponent({
  text: ({ value }: { readonly value: MetricValue }) =>
    Text({ value: `Pass-rate state: ${value.state}` }),
  web: ({ value }) => Stat({ label: "Pass rate", value }),
});
```

Both surfaces can return only NiceEval semantic nodes. Do not return DOM, raw HTML, browser side effects, or a separate text result.

## Pages, parameters, and routes

`defineReport({ pages })` is the only Report-definition entry point. An ordinary Page can read closed values directly in `render(sample)`. For a family of detail routes, provide `params`, `load`, and `render` on that same Page. `params.enumerate(sample)` lists every instance for static export. `load` can use `context.evidence(locator)` to obtain a closed evidence view.

A Page's `id` supports diagnostics and stable ordering. Its `path` is the base address a user visits. A parameterized Page must set `navigation: false` and make `encode()` and `decode()` round trip canonically. Report validates page definitions, IDs, and ordinary paths before it calls author callbacks. After instantiation, it checks parameter-route and download-path conflicts.

## Execution and problems

`show`, `view`, and static export run Pages and components while the Sample is available. They then retain only an immutable `ReportExecution`. It contains completed pages, downloads, and problems. It has no capability to read results again.

Analysis problems remain in `MetricValue`, `ClosedRows`, and domain views. A callback that throws, invalid parameters, an invalid semantic tree, or a route conflict is an execution problem. `show` and `view` continue to display other successful pages. Static export does not publish a site with an execution problem.
