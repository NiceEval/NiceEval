title: "Report API"
description: "Write terminal, web, and static Reports with standard React JSX, Pages, and closed Analysis values."

Report authors only organize Analysis values that are already closed. Author files use standard React JSX; they do not read Record paths, obtain a reader, or need a NiceEval-specific JSX runtime or `jsxImportSource`.

```text
Published Record
        ↓ selection
Sample → Analysis ClosedRows / MetricValue / DomainView
        ↓
Report: Page + component
        ├─ show: one selected Page → terminal text or JSON
        └─ view / view --out: all Pages → complete static site
```

## Define a Report

Write a Report as a `.tsx` module, and enable `"jsx": "react-jsx"` in the project's TypeScript configuration. A composite component uses `ctx.scope` to obtain the Sample fixed for this command, then passes the `ClosedRows` returned by `aggregate()` to standard components.

```tsx
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  model,
  passRate,
  Section,
  Table,
} from "niceeval/report";

const Overview = defineComponent(async (_props: {}, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { model },
    values: { passRate },
  });

  return (
    <Section title={ctx.report.title}>
      <Grid>
        <Bars points={rows} x="model" y="passRate" />
        <Table rows={rows} />
      </Grid>
    </Section>
  );
});

export default defineReport({
  title: { en: "Quality", "zh-CN": "质量" },
  pages: [{
    id: "overview",
    path: "/",
    title: { en: "Overview", "zh-CN": "概览" },
    render: () => <Overview />,
  }],
});
```

`ctx.scope` is the component's only field for obtaining a Sample. `ctx.report` provides the Report title, navigation Page summaries, and read-only `pricing`. The latter is a validated `PricingProfile` or `null`, the same value as `ReportDefinition.pricing`; it does not expose Config, the Runner price table, or another price input. `ctx.report` does not provide the current directory, Record, theme, or data-reading access to other Pages.

A cost Measure must explicitly call `costUSD(profile)` or `totalCostUSD(profile)`, where `profile` is the Report's validated `pricing`; there is no no-argument or alias entry point. Analysis owns the slot-provider ledger, exact total, and `numerator / denominator` mean; the Host only closes and presents these results.

`MetricValue` comes from Analysis and fully retains `value`, `state`, `samples`, `total`, `issues`, and `refs`. `value: 0` is valid. Do not recalculate a denominator from visible rows or write zero for `null`.

## Two component forms

The preceding example is a composite component. It can asynchronously read closed values on the fixed Sample while the Page executes.

Display primitives use another `defineComponent()` form. Optional `resolve()` runs once; synchronous `text()` and `web()` read the same closed result.

```tsx
import {
  defineComponent,
  formatMetricValue,
  Stat,
  type MetricValue,
} from "niceeval/report";

const MetricCard = defineComponent<
  { readonly label: string; readonly value: MetricValue },
  { readonly label: string; readonly value: MetricValue }
>({
  resolve: props => props,
  text: data => `${data.label}: ${formatMetricValue(data.value)}`,
  web: data => <Stat label={data.label} value={formatMetricValue(data.value)} />,
});
```

`text()` returns text and `web()` returns React JSX. Neither surface can read a Sample again, make a network request, or calculate statistics separately. Do not infer machine data back from HTML, text, or a React element.

## Pages, parameters, and page selection

An ordinary Page's `render` can receive the fixed Sample directly, or first close inputs with `load(sample, params, context)`. A parameter Page must also declare `navigation: false` and `params`:

- `encode(params)` produces the canonical key.
- `decode(key)` must restore the same kind of key.
- `enumerate(sample)` lists instances only for a complete site.
- `context.evidence(locator)` returns only the closed Evidence view within the current Sample.

`pages` is a Report's only page collection. Details must be explicitly declared as a Page or parameter Page; the Host does not add routes. `niceeval show --page <route>` only decodes, loads, and renders that target Page. It does not call `enumerate()` or execute other Pages. Only `niceeval view` and `niceeval view --out` enumerate all ordinary Pages and parameter instances, then form a complete site after all paths, links, resources, and budgets pass validation.

## JSON, web, and static sites

`show --json` always outputs English JSON. The built-in Report outputs Host-owned named domain documents; a custom Report outputs one Page's route, title, 80-column rendered text, download summary, and problem table. Both v1 JSON forms carry the closed cost data for that target Page in the same top-level `projections` object. They do not contain the author tree, HTML, whole-site routes, or site identity.

View and static export use the same complete site version. The HTTP body for a route and the page body in the export directory are byte-for-byte identical. Both include the same reload client; when a static directory cannot find the view endpoint, it quietly disables itself. With JavaScript disabled or the network disconnected, body content, navigation, details, coverage, problems, and downloads remain readable.

## Style and resource boundaries

Report CSS is the only owner of product styling. It handles reset, base typography, theme tokens, and component styling. The View shell only handles browser language switching, reload state, and Host notices; it does not redraw Report content.

A Report can declare structured `meta`, `link`, `style`, and `script` in `head`, and can choose a theme. Scripts may provide progressive enhancement only; they cannot be the sole entry point for body content, navigation, Evidence, or machine documents. Custom styling cannot create a second reset, theme, or View shell.
