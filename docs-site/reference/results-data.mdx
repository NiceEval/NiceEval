A `Record` is editable current data under `.niceeval/record/`. It stores Runs, Members, Attempts, and their named channels. Read and write it only while the directory is quiescent.

This page explains the data boundary. To inspect results in the terminal or browser, read [Viewing Results](/tutorials/viewing-results). To define pages and calculations, read [Write a Custom Report](/tutorials/custom-reports).

## Open a quiescent Record

The library receives the actual Record root and does not append `.niceeval` or `record`. Open a reader, then form a Sample with an explicit Run selection.

```ts
import { openRecordReader } from "niceeval/record";
import { selectSample } from "niceeval/sample";

let sample: Sample;
{
  await using reader = await openRecordReader({
    root: ".niceeval/record",
  });

  sample = await selectSample(reader, {
    kind: "runs",
    runIds: ["01J8ZK3M6P4T7V9X2C5N8QW0RY"],
  });
}
```

You can also use the `latest` policy. It selects the final completed Run for each matching Experiment; select unfinished Runs explicitly with `runIds`.

```ts
let latest: Sample;
{
  await using reader = await openRecordReader({ root: ".niceeval/record" });
  latest = await selectSample(reader, {
    kind: "latest",
    experimentIds: ["checkout"],
  });
}
```

Every read uses the files as they exist when it runs. If a user edits a Verdict, Usage, or another channel after the directory is quiescent, a later ReportInput construction reads the edited value. The Sample itself stores core data and its denominator only.

## Core data relationships

```text
Run expected slots
        ↓
Member: executed | carried | accepted
        ↓
Attempt and its named channels
```

- A Run's `expectedSlots` define the denominator.
- A slot has at most one Member. `executed` means this Run ran the Attempt; `carried` and `accepted` adopt an existing Attempt.
- An Attempt retains the `origin` where it actually ran. Adoption does not copy Verdict, Usage, or diagnostics.
- Reasons for carrying and accepting belong to the Run's `niceeval.actions` channel and link the slot and Attempt.

Record validation of structure, paths, identities, and references rejects contradictory data. It does not retain edit history.

## Channel read states

Business values live in named channels, such as Verdict, Eligibility, Usage, and diagnostics. A channel's durable collection completeness and its current decoding completeness are separate facts.

| State | Meaning | Caller behavior |
| --- | --- | --- |
| `read` | A value was read; collection or decoding can still be partial. | Preserve completeness and issue information. |
| `unavailable` | It was declared but not collected, or it does not apply. | Show the reason. |
| `unsupported` | The current reader does not support the channel. | Affect only content that depends on it. |
| `invalid` | A requested channel file or value is invalid. | Fail with its named issues. |

An unknown or retired channel is `unsupported` at that channel only. `unavailable`, `unsupported`, and `invalid` cannot replace one another. An unrequested channel does not block an unrelated read.

## From Sample to ReportInput

A `Sample` is an explicit in-memory selection and does not write back to the Record. It preserves every expected slot and represents scope with these states:

| Sample state | Meaning |
| --- | --- |
| `included` | It has a valid Member and can read that Member's adopted Attempt. |
| `not-recorded` | The expected slot has no Member. |
| `invalid` | The Member, Attempt, or core reference has a problem. |
| `excluded` | A caller excluded it from an existing Sample. |

Reports turn a Sample into `ReportInput` through the facts they require. ReportInput is an ordinary in-process value that retains the denominator, membership states, channel read states, and issues. A Report consumes it; it never reads a path or interprets files itself.
