Result viewing starts with published Runs. NiceEval first forms a `Sample`, then provides it only through `ctx.scope` while a Page or composite component executes. Application code cannot construct a Sample, open a result directory, or hold a reader.

## A Sample retains the selected scope

A Sample fixes the Runs, logical Slots, and denominator of this selection. Each position retains one of the states `included`, `not-recorded`, `core-invalid`, or `excluded`.

`--run` retains the full planned scope of the selected Run. `project-current` retains only the scope that still matches the current project identity. Neither selection shrinks its denominator because a Measure lacks input.

The unit of membership for `project-current` is a matching Run slot occurrence, not a deduplicated `(experiment, eval, ordinal)`. When the same position appears in multiple matching Runs, every occurrence contributes to `MetricValue.total`. Repeated runs or accepting entries one by one can therefore increase the denominator.

A Sample can only be passed to the Report facade during `load()`, Page, or composite-component execution. Once the callback ends, the page retains only values that have already been closed and cannot read results again.

## Get rows with `aggregate()`

`niceeval/report` re-exports the Analysis facade required by Reports. `aggregate()` returns `ClosedRows` with stable identity, issues, refs, and complete `MetricValue` values.

```tsx
import {
  aggregate,
  defineComponent,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const ResultTable = defineComponent(async (_props: {}, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { experiment },
    values: { passRate },
  });

  return <Table rows={rows} />;
});
```

`Table` uses rows, charts use points, and `Stat` uses a formatted complete metric. A display layer can sort, limit, or filter rows, but it cannot recalculate a value from the displayed array or reduce `MetricValue.total`.

## Get closed domain data

Attempt Evidence, Observability, File Changes, Sources, and Sandbox history each have a named Report facade. They respectively use `toAttemptEvidence()`, `toAttemptObservability()`, `toFileChanges()`, `toSources()`, and `toSandboxHistory()`. These facades accept only a fixed Sample and an optional Attempt locator, then return a closed `DomainView`.

A parameter Page uses `context.evidence(locator)` to obtain the closed Evidence for its detail target. The Host verifies that the locator belongs to the current Sample; it does not give the page a path, raw Record payload, or arbitrary query capability.

## Understand `MetricValue`

| Field | Meaning |
| --- | --- |
| `value` | The current value; `0` is valid. |
| `samples` | The number of members that actually contributed. |
| `total` | The denominator determined in advance by the Measure. |
| `state` and `issues` | Why a value is incomplete, unavailable, or failed. |
| `refs` | Evidence locations that can be reviewed. |

`available`, `partial`, `empty`, `unsupported`, and `failed` are distinct states. Do not treat `null` as zero, or replace the total denominator with the count of remaining visible rows.

For example, the `2 / 4 slot · partial` produced by `formatMetricValue()` means that only two of four selected occurrences supplied input for that Measure. Those counts describe coverage only; they are not an earned score, pass rate, or proportion of work completed. The Measure's own `value` is the reading.

The default Overview does not append this count to every metric cell. It displays pass rate or earned score by evaluation kind, then uses a separate `Result coverage` area to show the number of available results when data is incomplete. The terminal renders that area in a titled border; the underlying `MetricValue` fields do not change.
