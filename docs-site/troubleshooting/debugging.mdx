---

Start by reading a problem through an explicit Run. Do not guess the target from a directory name or time.

```sh
pnpm exec niceeval show --run <run-id>
pnpm exec niceeval view --run <run-id> --no-open
```

These commands form a Sample from the same scope and execute the same Report. First confirm the selection, then inspect Measures and problems on the page.

## Results cannot be found or opened

| Visible error | Meaning | Next step |
| --- | --- | --- |
| `record-root-missing` | The selected result set does not exist. | Check the project directory or `--record` parameter. |
| `record-migration-required` | Published results need migration. | Run `niceeval migrate`. |
| `record-format-unsupported` | The current NiceEval does not recognize this result format. | Install a NiceEval version that supports the format. |
| `core-invalid` | A position's identity or reference cannot be read reliably. | Read the named problem; do not treat it as a missing result. |

Published results have no manual-edit repair path. Create a new Run when you need different facts. Run `niceeval clean` to clean up incomplete remnants.

## An expected result is missing from the Sample

A Sample retains a Run's expected denominator. Check the state of every position on the page:

| State | Meaning | Next step |
| --- | --- | --- |
| `included` | An analyzable Attempt exists. | Check the Measure or evidence displayed by the Report. |
| `not-recorded` | A planned position has no result. | Check whether the Invocation finished, or rerun that scope. |
| `core-invalid` | This position has an identity or reference problem. | Address the named problem; do not treat it as not collected. |
| `excluded` | This selection excludes the item. | Check `--experiment`, `--eval`, or other selection conditions. |

To determine what the next run will do, first run:

```sh
npx niceeval exp checkout --dry
```

The output shows whether each position will execute or reuse an existing Attempt, and lists why reuse conditions are not met.

## A Measure or detail is incomplete

Measures and domain views bring their own state and problems onto the page:

| State | Meaning | Next step |
| --- | --- | --- |
| `partial` | A displayable result exists, but some denominator members did not contribute. | Check the problems and denominator; do not treat it as a complete result. |
| `empty` | Inputs are complete and the domain result is validly empty. | Confirm whether this empty result fits the task. |
| `unsupported` | The current environment does not support the required input. | Use an environment that supports the capability, or view a page that does not depend on it. |
| `failed` | Reading, joining, or aggregation failed. | Read the named problem and fix the cause. |

Run `niceeval migrate` before reading historical results that need migration. A Measure problem does not change the Sample's fixed denominator or stop unrelated pages from appearing.

## view does not show new results

`view` publishes a new complete site only after a successful rebuild. If Report, configuration, theme, or result changes make a rebuild fail, the page continues to display the previous usable site and shows the current problem.

Fix the rebuild problem, then wait for the next successful rebuild. Refreshing the page cannot bypass this boundary or make an old site read results again.

## JSON has no receipt

`npx niceeval exp <experiment> --json` outputs a receipt only at the end, after it successfully creates an Invocation. If an input error makes the command exit before it creates the Invocation, there are no `runIds` to read.

Correct the Experiment, Eval selection, or command argument, then run it again. On success, use the receipt's `runIds` with `show`, `view`, or `view --out`.

## A static Report site cannot export

`view --out` exports only a completed, complete site. Analysis problems can appear in the exported site and remain visible. An author callback that throws, an invalid parameter instance, a route conflict, or a resource conflict stops the export.

The target directory must not exist. After a failure or interruption, use a new output directory, then export again.

For more operational steps, see [Viewing results](/tutorials/viewing-results) and [Publish a static Report](/tutorials/publish-report).
