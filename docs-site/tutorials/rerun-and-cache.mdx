When you repeat the same command, NiceEval carries completed results forward instead of paying for the same Agent and Sandbox work again. Only missing or invalidated Attempts are dispatched.

```text
╭─ PLAN ──────────────────────────────────────────╮
│ 36 attempts · 36 evals × 1 configs              │
│ 24 of 36 reused · 12 to run                     │
╰─────────────────────────────────────────────────╯
```

Use `--dry` to inspect the attempt-level plan before dispatch. Human output keeps the Verdict of every carried result:

```text
compare/codex  memory/passed       carried (passed)
compare/codex  memory/failed       carried (failed)
compare/codex  memory/mixed        carried (2 passed · 1 failed)
compare/codex  memory/partial      carried 2/3 (1 passed · 1 failed) · errored 1/3
```

For a row with multiple Attempts, each dispatched reason uses the same `N/total` form. The default policy carries matching `passed` and `failed` Verdicts, while `errored` and `skipped` Attempts run again. Bare `--rerun` actively reruns `failed` Attempts; `--rerun all` reruns every selected Attempt.

## Understand the invalidation scope

The scope follows the input that changed:

| Change | What runs |
| --- | --- |
| Prompt, assertion, comment, or formatting in one `.eval.ts` file | That eval reruns |
| A shared source file imported by 30 evals | Those 30 evals rerun |
| Experiment `model`, `reasoningEffort`, or any `flags` key | Every selected eval reruns |
| `labels`, description, comments, or experiment-field order | Nothing reruns |
| `attempts` from 3 to 5 | The existing 3 carry forward; the missing 2 run |
| A larger `timeoutMs` | Completed results carry forward |
| A smaller `timeoutMs` | Results whose execution exceeded the new limit rerun |
| A different Sandbox `template`, `image`, or `snapshotId` | Every affected eval reruns |
| A rebuilt image under the same name, an Agent CLI upgrade, or a changed external service | The fingerprint cannot see it; use `--rerun all` |

Write stable experimental conditions in `flags`. Put values that are known only after execution, such as a tunnel URL, in `ctx.fact()`. Keep report-only grouping coordinates in `labels`.

## A cached Attempt must pass every gate

The fingerprint is only one gate:

| Gate | Requirement |
| --- | --- |
| Terminal state | The verdict is `passed` or `failed`; `errored` and `skipped` always rerun |
| Fingerprint | The eval fingerprint matches the current config's fingerprint |
| Eligibility | Its execution time does not exceed the currently resolved `timeoutMs` |
| Rerun policy | The current `--rerun` mode still trusts that verdict |
| Execution mode | The Attempt is outside the current `--keep-sandbox` band |

Carry-forward works per Attempt. Increasing `attempts` therefore fills only the missing ordinals, and an interrupted Run can contribute every completed terminal Attempt even when the Run itself was never finalized.

## Know which files enter the fingerprint

For each eval, NiceEval fingerprints:

- The complete bytes of its `.eval.ts` file.
- Every project-local module in its static import graph, recursively.
- Files registered by `loadYaml`, `loadJson`, `loadText`, or `loadCriteria`.
- The resolved experiment configuration and the eval's Sandbox case identity.

Packages under `node_modules`, dynamic `import()`, and files read directly with `fs` are outside this closure. Use NiceEval's loaders for criteria files. When an external input changes outside the fingerprint, explicitly revalidate with `--rerun`.

## Move runtime coordinates out of flags

A tunnel address changes every time the service starts. Putting it in `flags` invalidates every completed result whenever the address changes. Record it as an execution fact instead:

```ts
sandboxSetup(): SandboxHook {
  return async (sandbox, ctx) => {
    ctx.fact("nowledge.endpoint", env.url);
    await sandbox.writeText(".nowledge/env", `NMEM_URL=${env.url}\n`);
  };
}
```

Carried results retain the address they actually used. A newly started Attempt records its new address.

## Move a key without rerunning the previous batch

If a runtime coordinate was already stored in `flags`, moving it to `ctx.fact()` changes the flags bag and invalidates the earlier results. Run `--dry` first to see why the whole batch would rerun:

```bash
npx niceeval exp compare --dry
```

```text
plan: 36 attempts · 36 evals × 1 configs · attempts 1
0 carried in from cache · 36 to run

compare/baseline  01  previous-result passed: config:flags.tunnelUrl changed (https://a1b2.trycloudflare.com → https://c3d4.trycloudflare.com)
  prior:  @2VRHPQ4D2KG9EFW5TB8167MXJ3 (passed)
  accept: niceeval accept @2VRHPQ4D2KG9EFW5TB8167MXJ3
```

`previous-result passed` means that the historical verdict passed, but the current fingerprint has changed, so the result cannot be carried from cache yet. The difference explanation and execution evidence are separate: `fingerprint version changed` only means that the input difference cannot be expanded from the current manifest. It does not mean that execution, diff, or timing evidence is gone. Open the locator, verify that the verdict still holds, and then accept it:

```bash
npx niceeval show @2VRHPQ4D2KG9EFW5TB8167MXJ3 --timing
npx niceeval accept @2VRHPQ4D2KG9EFW5TB8167MXJ3
npx niceeval accept @2VRHPQ4D2KG9EFW5TB8167MXJ3 @67MXJ30SYZCNAVRHPQ4D2KG9EF
```

```text
╭─ PLAN ─────────────────────────────────────────────╮
│ Accepted @2VRHPQ4D2KG9EFW5TB8167MXJ3 · mode: accepted                       │
│ Current fingerprint: 5f3b…                      │
╰──────────────────────────────────────────────────╯
```

`accept` runs an atomic precheck over all explicit locators and writes nothing when any of them fails. On success it groups them by experiment, opens a new Run per experiment, and writes one accept Claim per explicit member (saving the current config identity, the adopted Attempt ref, and a readable difference audit) plus a `mode: "accepted"` RunContribution whose `basisClaims` point at that Claim. The Contribution adopts the original Attempt's explicit revision — it never copies or reparents the Attempt, Verdict, evidence, or Provenance, and it never produces another locator; the Run's immutable `RecordGraphRef` and receipt are returned. The command never accepts unlisted results merely because they share the same difference, and there is no bulk-accept option.

Differences that cannot be proven equivalent appear as `previous-result` and require an explicit `accept` or a rerun. The output does not use the ambiguous phrase `details unavailable`.

A locator that is missing `@`, is not 26 characters, contains illegal letters, or has an invalid high bit returns `malformed-locator` instead of suggesting a command that must fail. Copy the full canonical locator, or rerun that eval to produce one that can be accepted.

Historical `passed` and `failed` results can be accepted. Whether a result came from Sandbox reuse, or whether the current experiment declares `sandboxReuse: true`, does not affect eligibility. Results with `errored` or `skipped` verdicts cannot be accepted, and neither can execution modes that require a real Sandbox to remain available. The command explains the reason instead of silently running the experiment.

## Force revalidation outside the fingerprint

`--rerun` has three modes:

| Form | Results still trusted | What runs |
| --- | --- | --- |
| Omitted | `passed` and `failed` | Missing, `errored`, and `skipped` Attempts |
| `--rerun` or `--rerun failed` | `passed` only | The above, plus every `failed` Attempt |
| `--rerun all` | None | Every selected Attempt |

```bash
npx niceeval exp compare --rerun
npx niceeval exp compare --rerun all
```

Acceptance is a standalone `niceeval accept @locator...` command, not an `exp` flag. With `--rerun failed`, an accepted historical `failed` result still reruns, while an accepted `passed` result may carry forward. `--rerun all` rejects all cached results.

## Resume an interrupted Run

An Attempt commits its facts after its cleanup chain completes. Their trustworthiness does not depend on the enclosing Run reaching a normal end. After Ctrl-C, `kill -9`, or a CI timeout, repeat the same command: committed terminal Attempts carry forward and only the missing work runs.

Concurrent invocations use the same rule. Before dispatch, each eval takes a lease and checks the records again; work completed by another invocation carries forward, while still-missing Attempts run locally.

## Execution modes and carry

- An experiment with `sandboxReuse: true` follows the same carry rule as a regular experiment. Terminal Attempts with a matching fingerprint carry forward; only Attempts that are not carried run in the invocation's shared Sandbox. `--rerun` can still require those Attempts to execute again.
- `--keep-sandbox` requires a real execution to leave a live debugging environment. Attempts inside the requested keep band rerun because a carried result has no Sandbox to keep.
