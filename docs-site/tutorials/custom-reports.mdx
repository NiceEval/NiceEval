title: "Write Custom Reports"
description: "Define Analysis statistics first, then use standard React JSX to write a Report that can be read in the terminal, web, and static site."
---

A custom Report is responsible only for pages and presentation. The Record stores published facts, Analysis defines population, denominator, and missing-data meaning, and the Report organizes `ClosedRows`, `MetricValue`, and closed `DomainView` values.

```text
Record → Sample → Analysis
                    ↓
          ClosedRows / MetricValue / DomainView
                    ↓
              Report Pages and components
             ↙                    ↘
  show: one target Page       view / --out: every Page
```

## Start with a Measure

Define business statistical meaning outside the Report module. A Measure decides the denominator, missing-data behavior, and Evidence. A Page must not recalculate a pass rate or cost from array length.

```ts
// reports/quality-measures.ts
import {
  allLogicalSlots,
  attemptPassed,
  defineDimension,
  defineMeasure,
  latestCompletedAttempt,
  logicalSlots,
  oneValue,
  partial,
  ratio,
  retainContributingEvidence,
} from "niceeval/analysis";

export const experiment = defineDimension({
  id: "quality.experiment",
  population: logicalSlots,
  value: slot => slot.experimentId,
});

export const passRate = defineMeasure({
  id: "quality.pass-rate",
  population: logicalSlots,
  input: attemptPassed,
  withinAttempt: oneValue<boolean>(),
  withinSlot: latestCompletedAttempt<boolean>(),
  acrossSlots: ratio(),
  denominator: allLogicalSlots(),
  missing: partial(),
  evidence: retainContributingEvidence(),
  unit: "ratio",
  format: "percent",
  better: "higher",
});
```

## Organize a Page

A Report module is a `.tsx` file and uses TypeScript's `"jsx": "react-jsx"`. Composite components obtain the Sample fixed for this selection through `ctx.scope`. Components and Pages do not receive a Record reader, file paths, or browser-request capability.

```tsx
// reports/quality.tsx
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const QualityComparison = defineComponent(async (_props: {}, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { experiment },
    values: { passRate },
  });

  return (
    <Grid>
      <Bars points={rows} x="experiment" y="passRate" />
      <Table rows={rows} caption="Experiment pass rate" />
    </Grid>
  );
});

export default defineReport({
  title: { en: "Quality", "zh-CN": "质量" },
  pages: [{
    id: "overview",
    path: "/",
    title: { en: "Overview", "zh-CN": "概览" },
    render: () => <QualityComparison />,
  }],
});
```

`ctx.scope` is the component's only way to obtain a Sample. `ctx.report` provides the read-only Report title, navigation Page summaries, and verified `PricingProfile` or `null` `pricing`; it is not Config, the Runner price table, or a second price input.

`Table` and charts use the same rows. Every Measure cell retains its full `MetricValue`: `samples` is the number that actually contributes, `total` is the predetermined denominator, and `partial`, `empty`, `unsupported`, and `failed` must not be hidden or changed to zero.

## Declare a Profile for cost

Cost does not derive from Config. When you need a cost Measure, explicitly declare a USD Profile in the same Report module, then pass that same value to `defineReport({ pricing })`:

```tsx
import { definePricingProfile } from "niceeval/report";

const pricing = definePricingProfile({
  currency: "USD",
  display: { decimalPlaces: 2, rounding: "half-away-from-zero" },
  provenance: {
    kind: "declared-rate-card",
    source: "https://platform.openai.com/pricing",
    asOf: 1785542400000,
  },
  coverage: [{
    coverageId: "openai-gpt-5-6-2026-08",
    state: "priced",
    selector: { provider: "openai", model: "gpt-5.6" },
    effective: { startsAt: 1785542400000, endsAt: null },
    charges: [
      { kind: "token", bucket: "input", perMillionTokens: "1.25" },
      { kind: "token", bucket: "output", perMillionTokens: "10" },
      { kind: "token", bucket: "cache-read", perMillionTokens: "0.125" },
      { kind: "token", bucket: "cache-write", perMillionTokens: "1.25" },
      { kind: "request", requestKind: "model", ratePerRequest: "0" },
    ],
  }],
});
```

In a component, call only `costUSD(pricing)` or `totalCostUSD(pricing)`; neither has a zero-argument form. Analysis computes the slot-provider ledger, exact total, and `numerator / denominator` mean. The Report Host only validates the Profile, captures the closure, and presents the result. The Runner calculates `estimatedCostUSD` independently even when observed cost exists, and uses it only for `maxCost`; the Report does not read it.

The `cost` cell from `aggregate(ctx.scope, { values: { cost: costUSD(pricing) } })` is observable `CostMetricValue`, whose `cell.projection` is a `CostProjectionValue`. Both types, plus the projection's state, basis, ledger, and reason-data types, are exported type-only from `niceeval/report`.

Codex sealed Usage contains a `requestKind: "model"` observation. Therefore, even when a model request is free, token-priced coverage must declare `{ kind: "request", requestKind: "model", ratePerRequest: "0" }` explicitly.
The four token charges plus that zero request charge form a complete rate card. Missing it does not imply free: strict coverage makes the relevant slot-provider `unavailable` and records `pricing-charge-not-found`.

Without a Profile, Summary displays English `Cost unavailable — this report does not declare a PricingProfile.` or Chinese `成本不可用——此报告未声明 PricingProfile。`; a cost × pass-rate scatter displays English `Cost × pass rate scatter unavailable — this report does not declare a PricingProfile.` or Chinese `成本 × 通过率散点图不可用——此报告未声明 PricingProfile。`. Neither component requests a cost Measure, captures a projection, or displays a number.

## Add detail pages and display primitives

When you need several detail addresses, define a parameterized Page. `pages` is the sole page collection, so detail pages must be explicitly declared there. `params.enumerate(sample)` lists every instance only for `view` or static export; the Host does not build additional detail routes. `show --page <route>` executes only one requested instance and checks that `decode()` followed by `encode()` produces the same canonical key.

A new display primitive uses two surfaces through `defineComponent()`: `resolve()` obtains closed input at most once, then `text()` and `web()` read the same value. The two surfaces must not separately call Analysis again or substitute web-only content for terminal text.

## Set it as the project default

Load the Report in `niceeval.config.ts`. Current-project `show` and `view` without an explicit `--report` use it:

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality.tsx";

export default defineConfig({
  report: quality,
});
```

## Run, read, and publish

```sh
pnpm exec niceeval show --run <run-id> --report ./reports/quality.tsx
pnpm exec niceeval show --run <run-id> --report ./reports/quality.tsx --json
pnpm exec niceeval view --run <run-id> --report ./reports/quality.tsx --no-open
pnpm exec niceeval view --run <run-id> --report ./reports/quality.tsx --out ./quality-site
```

All commands form a Sample from the same selection, but their scope differs: `show` and `show --json` execute one Page and capture only that Page's projection closure; `view` and `view --out` enumerate every Page, then form a complete site and `_niceeval/data/projections.json`. The bytes of that file are part of revision identity. A successful `view` rebuild atomically replaces the current site; failure retains the previous usable site. `--out` must point to a directory that does not exist.
