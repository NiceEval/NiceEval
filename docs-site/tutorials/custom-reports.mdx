Write custom Reports with the 0.12 classic facade. `defineReport({ title, pages })` declares pages, and `render(sample)` reads a closed Sample and returns controlled JSX. It never receives a Record path or looks up data while a page renders. Import the `Sample` type from `niceeval/record`.

Existing React Reports can keep `"jsx": "react-jsx"`. A new Report can avoid a React runtime by also setting `"jsxImportSource": "niceeval/report"` in its `tsconfig.json`. The component code stays the same.

```text
Record
    ↓ fixed projection plan (evaluation plan, verdict, kind-gated score, usage, timing)
frozen Sample
    ↓ page.render(sample) expands controlled JSX
immutable ReportExecution
          ↙       ↓       ↘
        show     view    export
```

## Declare pages

Place this Report in `reports/quality.tsx`. The page function receives the frozen `Sample` that the host creates after one projection. Use `aggregate` to group data and calculate `passRate` and `costUSD`:

```tsx
import type { Sample } from "niceeval/record";
import {
  Bars,
  Col,
  ExperimentScatter,
  ExperimentTable,
  Hero,
  SampleSummary,
  Section,
  aggregate,
  costUSD,
  defineReport,
  experiment,
  passRate,
} from "niceeval/report";

async function overview(sample: Sample) {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate, costUSD },
  });

  return (
    <Col>
      <Hero
        title="Memory condition comparison"
        description="Compare pass rates across memory conditions for the same set of tasks."
        links={[{
          label: "Project repository",
          href: "https://github.com/example/memorybench",
        }]}
      />
      <SampleSummary />
      <Section title="Leaderboard">
        <Bars
          points={rows}
          x="experiment"
          y="passRate"
          layout="horizontal"
        />
      </Section>
      <ExperimentScatter input={sample} />
      <ExperimentTable input={sample} />
    </Col>
  );
}

export default defineReport({
  title: "Memory condition comparison",
  pages: [{
    id: "overview",
    title: "Overview",
    render: overview,
  }],
});
```

`aggregate` groups at Eval granularity, so it does not split Attempts for the same task. `passRate` uses a strict two-level denominator: it first averages Attempts in each `(experiment, eval)` unit, then averages those unit values equally across Evals. Skipped and missing values do not enter the numerator, and coverage shows the gap.

Controlled JSX is not raw React or DOM. Native tags, unwrapped components, `head`, scripts, styles, fonts, workers, WASM, and raw HTML are rejected during loading or validation. `Hero` links must use absolute HTTPS URLs; NiceEval serializes the URL without requesting it.

## Set it as the project default

Import the Report in `niceeval.config.ts`. Afterward, `show` and `view` use it when `--report` is absent:

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality";

export default defineConfig({
  report: quality,
});
```

## Handle incomplete data and failures

Recorded-data problems do not change the Sample denominator:

- `unavailable` means the owner did not provide the requested Attachment.
- `migration-required`, `migration-unavailable`, and `unsupported` mean a historical schema cannot be read for the current request.
- `invalid` or partial collection means the recorded data is incomplete.

The built-in problems surface shows these conditions. Missing cost and timing stay missing instead of becoming zero. When an aggregation field is absent, `aggregate` uses `unknown` rather than reading the current project declaration to fill historical data.

A projector, Calculation, or Page callback that throws is an execution problem. So are an invalid document and a route conflict. `show` and `view` show the problem while retaining other pages. Static export does not publish that execution.

## Run and publish

```sh
npx niceeval show --report ./reports/quality.tsx
npx niceeval view --report ./reports/quality.tsx --no-open
npx niceeval view --report ./reports/quality.tsx --out ./quality-site
```

`show`, `view`, and `--out` all select a Sample, execute the same Report, and produce a fixed `ReportExecution`. Each successful `view` rebuild produces the next execution. A failed rebuild keeps the last good execution.

`--out` must name a directory that does not exist. See [Publish a Static Report](/tutorials/publish-report) for the export workflow.

## Use the lower-level projection API

Use the lower-level projection API when you need custom projections or Calculations. Declare data with `RecordProjection`, then use `defineCalculation`, `definePage`, `definePageFamily`, and `defineDownload` to package results. Both authoring paths share the same `ReportExecution`. See [Report API](/reference/report-components) and [Results Data API](/reference/results-data).
