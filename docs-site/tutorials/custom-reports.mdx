A custom report receives the Sample the host selected and returns a component tree:

```text
Sample
  → plain TypeScript functions
  → serializable result values
  → components
  → text / web
```

Computation happens in the page render.
Components only display concrete values such as `rows`, `points`, `items`, `nodes`, or `attempt`.

## Create your first report

Create `reports/quality.tsx`:

```tsx
import {
  Page,
  Scatter,
  Table,
  agent,
  aggregate,
  costUSD,
  defineReport,
  passRate,
} from "niceeval/report";

export default defineReport(async (sample) => {
  const performance = await aggregate(sample, {
    by: { agent },
    values: { passRate, costUSD },
  });

  return (
    <Col>
      <Scatter
        points={performance}
        x="costUSD"
        y="passRate"
        point="agent"
      />
      <Table rows={performance} />
    </Col>
  );
});
```

Run:

```bash
niceeval show --report ./reports/quality.tsx
niceeval view --report ./reports/quality.tsx
```

Both hosts run the same page render.
The same result tree is handed to the text and web renderers.

## Set it as the project default

Import the definition directly in `niceeval.config.ts`:

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality";

export default defineConfig({
  report: quality,
});
```

After that, run `niceeval show` or `niceeval view` directly.
Pass `--report standard` to switch back to the built-in report for one run.

## Narrow the Sample

The host applies `--record`, `--exp`, eval positional arguments, and `--fresh` first,
then hands the Sample to the report.

Keep using Sample methods inside the report:

```ts
const security = sample.scope({ evals: "security/" });

const reliable = security.filter((attempt) =>
  attempt.result.verdict !== "errored"
);
```

`scope()` changes the comparison population and coverage denominator.
`filter()` removes untrusted or inapplicable observations.

When a set of charts shares a scope, create one named Sample first:

```ts
const production = sample
  .scope({ experiments: "production/" })
  .filter(isReliableAttempt);
```

Then pass the same `production` into every computation.

## Use `aggregate()`

`aggregate()` takes grouping functions and Calculations:

```tsx
const rows = await aggregate(sample, {
  by: {
    experiment,
    agent,
  },
  values: {
    passRate,
    costUSD,
  },
});
```

Object keys become result field names.
Each metric field is a `MetricValue` with `value`, `unit`, `samples`, `total`, `basis`, and `refs`.

The result is a plain array you can keep using in JavaScript:

```ts
const ranked = rows
  .toSorted((a, b) =>
    (b.passRate.value ?? -Infinity) -
    (a.passRate.value ?? -Infinity)
  )
  .slice(0, 10);
```

Do not pass an aggregated result back into `aggregate()`.
To add metrics, go back to the same Sample and add Calculations to the original `values`.

## Define your own Calculation

`rollup()` turns a per-Attempt value function into a Calculation:

```ts
import {
  mean,
  min,
  rollup,
} from "niceeval/report";

export const changedLines = rollup(
  async (attempt) => {
    if (attempt.result.verdict !== "passed") {
      return null;
    }

    const diff = await attempt.diff();
    return diff ? countChangedLines(diff) : null;
  },
  {
    withinEval: min,
    acrossEvals: mean,
    unit: "lines",
    better: "lower",
  },
);
```

Built-in and user Calculations both use `rollup()`.
Empty sets stay `null` and are never disguised as zero.

## Show entity lists

The Sample already exposes materialized `attempts`:

```tsx
export default defineReport((sample) => {
  const failures = sample
    .filter((attempt) =>
      attempt.result.verdict === "failed" ||
      attempt.result.verdict === "errored"
    )
    .attempts
    .toSorted((a, b) =>
      (attemptCostUSD(b.result) ?? 0) -
      (attemptCostUSD(a.result) ?? 0)
    )
    .slice(0, 50);

  return <AttemptList attempts={failures} />;
});
```

For a generic table, convert first:

```tsx
const rows = toAttemptRows(failures);
return <Table rows={rows} />;
```

## Reuse dynamic blocks

Reuse is ordinary functions:

```tsx
export async function overview(sample: Sample) {
  const performance = await aggregate(sample, {
    by: { agent },
    values: { passRate, costUSD },
  });

  return (
    <>
      <Scatter
        points={performance}
        x="costUSD"
        y="passRate"
        point="agent"
      />
      <Table rows={performance} />
    </>
  );
}
```

Call it directly in the page render:

```tsx
render: async (sample) => (
  <Col>
    {await overview(sample)}
  </Col>
)
```

Use ordinary `Promise.all()` for independent computations.

## Create a multi-page report

```tsx
export default defineReport({
  title: "Team evals",
  pages: [
    {
      id: "overview",
      title: "Overview",
      render: async (sample) => (
        <Col>
          {await overview(sample)}
        </Col>
      ),
    },
    {
      id: "failures",
      title: "Failures",
      render: failuresPage,
    },
    standardAttemptPage,
  ],
});
```

Array order in `pages` is navigation order.
The host runs only the requested page render.
`standardAttemptPage` provides the official Attempt detail page and locator drill-down.

## Custom Attempt detail

```tsx
{
  id: "attempt",
  title: "Attempt",
  input: "attempt",
  navigation: false,
  render: async (attempt) => {
    const [turns, files] = await Promise.all([
      toConversationTurns(attempt),
      toDiffFiles(attempt),
    ]);

    return (
      <Col>
        <Conversation turns={turns} />
        <DiffView files={files} />
      </Col>
    );
  },
}
```

A report has at most one Attempt page.
Without it, locators render as plain text only.

## Connect external business snapshots

Write external data as a frozen snapshot module first:

```tsx
// budget-snapshot.ts — generated by a script before the run, versioned with the report
export const budgets = {
  checkout: { monthlyUSD: 40 },
  search: { monthlyUSD: 25 },
};
```

Import it directly in the report file:

```tsx
import { budgets } from "./budget-snapshot";

export default defineReport(async (sample) => {
  const performance = await aggregate(sample, {
    by: { experiment },
    values: { passRate, costUSD },
  });

  return <Table rows={joinBudgets(performance, budgets)} />;
});
```

The page render does not call the network and does not read environment variables, clocks, or randomness. Regenerate the snapshot module to refresh data.
Snapshots belong to the report import graph; the dev server rebuilds the report when they change.

## Author a new display shape

When existing components cannot compose the target display, use the extension entry:

```tsx
import { defineRenderer } from "niceeval/report/extension";

const ConfusionMatrix = defineRenderer({
  text(value, options, context) {
    return renderTextMatrix(value, options, context);
  },
  web(value, options, context) {
    return <WebMatrix value={value} options={options} />;
  },
});
```

Both renderers only accept already-computed plain values.
Custom computation stays in ordinary functions; no registration protocol is required.

## Pin a value to a color

In the report shell's `dimensionPins`, fix visual identity by grouping field and full value.
For example, the same Agent can keep the same colors, line styles, and markers on every page.

Display labels are not identity keys. Do not truncate Experiment path suffixes or assign colors by array index.
See [Report theming](/tutorials/theming) for full theme fields.

## Make your components follow any theme

Custom renderers use `--niceeval-*` theme tokens.
Do not copy Basalt or Chalk hex values into components.
Use semantic tokens such as positive, negative, and warning for state,
and runtime-assigned visual identity for nominal series.

## Embed in your own React page

Compute on the server or during the build:

```ts
const points = await aggregate(sample, {
  by: { agent },
  values: { passRate, costUSD },
});
```

Use `niceeval/report/react` in the browser:

```tsx
<Scatter
  points={points}
  x="costUSD"
  y="passRate"
  point="agent"
/>
```

The React entry does not read Record, Sample, or artifacts.
When the record root is not in the product runtime, write the Result as JSON at build time.
