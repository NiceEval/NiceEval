A custom Report has three clear responsibilities. Published run results preserve what happened. Analysis defines statistical meaning. Report organizes pages and display. You neither need nor can read result files from a page or register extra data types.

```text
Published run results
        ↓
Analysis: Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report: Page + component
        ↓
ReportExecution → show / view / export
```

## Define a Measure

Define reusable statistical meaning outside the Report module. This Measure groups by Experiment and aggregates the latest completed Attempt for each logical position into a pass rate.

```ts
// reports/quality-measures.ts
import {
  allLogicalSlots,
  attemptPassed,
  defineDimension,
  defineMeasure,
  latestCompletedAttempt,
  logicalSlots,
  oneValue,
  partial,
  ratio,
  retainContributingEvidence,
} from "niceeval/analysis";

export const experiment = defineDimension({
  id: "quality.experiment",
  population: logicalSlots,
  value: slot => slot.experimentId,
});

export const passRate = defineMeasure({
  id: "quality.pass-rate",
  population: logicalSlots,
  input: attemptPassed,
  withinAttempt: oneValue<boolean>(),
  withinSlot: latestCompletedAttempt<boolean>(),
  acrossSlots: ratio(),
  denominator: allLogicalSlots(),
  missing: partial(),
  evidence: retainContributingEvidence(),
  unit: "ratio",
  format: "percent",
  better: "higher",
});
```

`defineMeasure()` fixes the input, denominator, and missing-data semantics together. Do not infer a pass rate from an array length in a Page, or unwrap a number and wrap it again for display.

## Let a component obtain closed rows

A composite component receives a `Sample` while it executes. Use `aggregate()` to obtain rows, then pass them directly to neutral table and chart components.

```ts
// reports/quality.ts
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const QualityComparison = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });

  return Grid({
    children: [
      Bars({ points: rows, x: "experiment", y: "passRate" }),
      Table({ rows, caption: "Experiment pass rate" }),
    ],
  });
});

export default defineReport({
  title: "Quality report",
  pages: [
    {
      id: "overview",
      path: "/",
      title: "Overview",
      render: () => QualityComparison({}),
    },
  ],
});
```

`rows` retain each row's identity, problems, and complete `MetricValue`. `Table` consumes rows, charts consume points, and `Stat` consumes a complete value. Terminal, web, and static sites therefore display the same statistical meaning.

## Add detail pages or a custom primitive

For a family of detail addresses, declare `params`, `load`, and `render` on the same Page. `params.enumerate(sample)` lists every instance for static export. `load` can use `context.evidence(locator)` to obtain a closed evidence view. Instance routes come only from the selected scope and closed values; opening a page in a browser never reads results again.

For a new display primitive, `defineComponent()` provides both `text` and `web`. Its optional `resolve()` computes one closed value before both renderers. The two surfaces then read that same result. Do not replace the terminal surface with raw HTML or content that exists only on the web.

## Set it as the project default

Import the Report in `niceeval.config.ts`. Later `show` and `view` commands use it when `--report` is absent:

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality.ts";

export default defineConfig({
  report: quality,
});
```

## Handle partial data and failures

Analysis problems travel with `MetricValue`, `ClosedRows`, and domain views into a page. `partial` retains a displayable result and its complete denominator. `unsupported` and `failed` retain their reason instead of becoming zero or silently disappearing from a table.

An author callback that throws, invalid parameters, an invalid semantic tree, or a route conflict is an execution problem. `show` and `view` display other successful pages. Static export does not publish a site with an execution problem.

## Run and publish

```sh
npx niceeval show --run <run-id> --report ./reports/quality.ts
npx niceeval view --run <run-id> --report ./reports/quality.ts --no-open
npx niceeval view --run <run-id> --report ./reports/quality.ts --out ./quality-site
```

All three commands select the same scope, execute the same Report, and produce a fixed `ReportExecution`. A later successful `view` rebuild produces the next execution. A failure keeps the previous usable result.

`--out` must point to a directory that does not exist. See [Publish a Static Report](/tutorials/publish-report) and [Report API](/reference/report-components) for details.
