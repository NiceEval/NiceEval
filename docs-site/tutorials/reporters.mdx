A Reporter belongs to the current Invocation. It can send results from that run to an external observability or analysis system. It does not own published results and cannot replace later `show`, `view`, or Report use.

```text
Current Invocation
    ├─ terminal and --json feedback
    ├─ Reporter → external system
    ├─ --junit → CI-platform file
    └─ receipt → invocationId and runIds

Published results
    └─ Run, Member, Attempt, and inspectable run facts
```

## What a Reporter is for

Configure a Reporter for the run you want to observe. It handles results visible to the current process. An external system can receive a run summary, Attempt results, or links. To read complete business facts, use the receipt's `runIds` to reopen the published Record.

A Reporter cannot:

- Treat external-system data as a business value in the Record.
- Replace Verdicts, Usage, assertions, or diagnostics with external reporting.
- Make later `show`, `view`, or a static Report read from the external system.
- Write results back into the Record from the external system.

## Use JUnit in CI

JUnit is the most direct external integration:

```sh
npx niceeval exp ci --junit ./artifacts/niceeval-junit.xml
```

NiceEval writes that file atomically. A CI platform reads it to show annotations and test results. It is an output format for this Invocation, not an owner of Record facts.

## Use JSON and the receipt

```sh
npx niceeval exp checkout --json
```

`--json` emits NDJSON for the current process. Its final receipt includes `invocationId`, `runIds`, start time, end time, and completion. External automation can retain the receipt, then use its `runIds` to select a Report to inspect.

```sh
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY
```

Do not treat progress or diagnostic records as a long-lived result format. They serve the current Invocation. Complete business facts belong to the published Record.

## Principles for external integration

1. Let external reporting consume only information known to the current Invocation.
2. Keep credentials in runtime variables, not in output.
3. Use the exit status for a CI gate.
4. Use a receipt's `runIds` to connect external workflows with inspectable results.
5. Use `view --out` to share a report page.

For CI commands and JUnit, see [CI Integration](/tutorials/ci-integration).
