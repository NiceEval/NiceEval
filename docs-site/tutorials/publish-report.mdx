`niceeval view --out <directory>` forms a fixed Sample from published results, then builds the complete report site. It does not save the current browser page as files: every ordinary Page, parameterized Page instance, asset, and download explicitly declared in `pages` must be closed and validated first. The Host does not add detail pages.

```sh
pnpm exec niceeval view --experiment checkout \
  --out ./report-site \
  --no-open
```

To pin the export to this run, get the Run ID from the receipt's `runIds`:

```sh
pnpm exec niceeval view --run <run-id> \
  --out ./report-site \
  --no-open
```

## What builds before export

The full build enumerates every ordinary Page and every parameterized Page instance. The Host validates routes, links, downloads, author assets, Source, Diff, `_niceeval/data/projections.json`, and the resource budget, then forms a closed site revision.

That site revision is also the source of local view and static export. The HTTP body for a route and the page body in the export directory are byte-for-byte identical. `--out` does not accept `--page`, because a static directory always contains the whole site.

Analysis states `partial`, `empty`, `unsupported`, and `failed` are displayable data states. They are written into pages with their samples, total, issues, and refs. A failing Page callback, invalid parameter instance, route conflict, resource conflict, or budget overflow blocks export; none produces a directory with pages missing.

## What the export directory includes

A successful directory contains:

- Every HTML page and parameterized detail page.
- Report CSS, theme tokens, the reload client, and closed assets declared by the author.
- Closed Source and Diff assets, downloads, and `_niceeval/data/projections.json`.
- The navigation, body, completeness, and problem content needed to read the site.

The directory needs no source Record, NiceEval installation, or network. The bytes of `_niceeval/data/projections.json` enter the revision identity together with pages and assets. It carries the same reload client as view; when a static directory has no view endpoint, the client disables itself quietly, shows no error, and starts no new Analysis read.

Open the home page and at least one parameterized page in an offline browser with JavaScript disabled. The body, navigation, details, completeness, problems, and downloads must still be readable.

## Protect the destination directory

The directory passed to `--out` must not exist. The command never replaces, deletes, or merges an existing directory. To update a site, export to a new directory and let the hosting service switch versions.

```sh
# A successful export writes a new directory.
pnpm exec niceeval view --run <run-id> --out ./report-site-2026-08-15
```

## Generate it in CI

```sh
npx niceeval exp ci --json
pnpm exec niceeval view --experiment ci --out ./report-site --no-open
```

When CI must publish the run it just completed, read the `runIds` from the final receipt line of the first command and use `view --run <run-id>`. Do not let the hosting platform read the source Record; it should deploy only the generated directory.
