`niceeval view --latest --out <directory>`, or an explicit `niceeval view --run <id> --out <directory>`, selects a core-only Sample from a quiescent Record, builds ReportInput as planned, executes the Report once, and writes a self-contained static site. It is the only export path for sharing results.

```sh
npx niceeval view --latest --experiment checkout \
  --out ./report-site \
  --no-open
```

You can also export one explicit Run:

```sh
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY \
  --out ./report-site \
  --no-open
```

## Select the scope before exporting

`--run` and `--latest` form the Sample first. A Sample preserves the full expected-slot denominator and its `included`, `not-recorded`, `invalid`, and `excluded` states.

The Report requests the facts it needs through its plan and uses them to build one fixed `ReportInput`. An unrequested channel does not affect the export. A requested invalid channel shows its named issue and fails that export.

## What the export directory contains

A successful directory includes:

- Every planned page and parameterized page.
- The current host data each page needs.
- The exporter's exact built-in runtime, base styles, and fonts.
- Already-produced downloads.
- A `StaticAssetManifest` that exhaustively lists those files.

The browser reads only the export directory. It does not access the network or source Record, and it does not need a later NiceEval installation. Before sharing the directory with a colleague or static host, open it in an offline browser to confirm its pages and downloads work.

The target directory must not exist. The command never replaces or deletes an existing directory. To update a deployment, export to a new directory and let the hosting platform switch versions.

## Generate it in CI

Run evals, then export in the same job:

```sh
npx niceeval exp ci --json
npx niceeval view --latest --experiment ci --out ./report-site --no-open
```

The final JSON line from the first command is its receipt. To pin the export to that Invocation, read its `runIds` and use `view --run <runId>` instead.

## Publish the directory

Give `./report-site` to your hosting provider as the static-site directory. Do not point the platform build at a source Record; it only needs to deploy the already generated directory.

Deploy that directory with your hosting provider's normal static-site workflow.
