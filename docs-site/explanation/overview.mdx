NiceEval gives evaluation definitions, execution, published results, and reports distinct responsibilities. You define Evals and Experiments, and the Runner executes them. Complete Runs are published to a Record. When you view or share results, Analysis creates closed values from the selected results, then Report organizes those values into pages.

```text
Eval and Experiment
        ↓
Runner
        ↓
Record: published results
        ↓  select a scope
Analysis: Sample + Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report → immutable ReportExecution
              ├─ show
              ├─ view
              └─ static export
```

## How an eval runs

An Eval defines a task, assertions, and needed Fixtures. An Experiment selects Evals and declares the Agent, model, concurrency, budget, and other run conditions. An Adapter connects the system under test. A Sandbox provides an isolated place to execute work.

The Runner creates one Run for every selected Experiment. A Run lists its expected positions, which define the denominator for result calculation. Each position has at most one Member.

A Member identifies the Attempt occupying a position. An Attempt is `origin` when its `origin` matches the current position. It is `reference` when a Member adopts an Attempt from another Run. Adoption reuses a completed result; it does not execute that Attempt again.

## Record stores published results

A Record is a portable collection of published results that you can copy or put in Git. Application code does not parse or write it. Use `show`, `view`, `clean`, and `migrate` instead.

A Run is available for viewing or later selection only after it is fully published. Run a new Invocation to produce a different result. Historical results are never overwritten.

## Sample determines comparison scope

Without a locator or `--run`, commands select results that still match the current project. A locator or `--run` selects named historical results. NiceEval forms a `Sample` from that selection. It retains the complete expected scope and denominator, but does not let a page select again or reopen results.

`project-current` scans every published Run. It keeps positions whose Experiment, Eval, and execution identity still match the current project. It does not keep only one Run by time.

`--run` retains the complete expected scope of each named Run. Every selected position is `included`, `not-recorded`, `core-invalid`, or `excluded`. Once selection establishes that framework, missing analysis input cannot silently shrink the denominator.

## What Analysis and Report do

Analysis interprets results. Authors use `defineMeasure()` to declare a population, grouping, denominator, and missing-data rule. They use `aggregate()` or `query()` to produce `ClosedRows`, `MetricValue`, or a domain view.

Report organizes pages and display. Pages and components consume only those closed values: tables read rows, charts read points, and statistic cards read a complete value. For detail routes, a Page uses `params`, `load`, and `render` to enumerate instances. A Report does not recalculate measures or read result storage.

One Report produces one immutable `ReportExecution`. It has no capability to read results again. `show`, `view`, and static export consume that execution only.

When `view` detects a change, it builds the next execution. Only a complete rebuild replaces the result on screen. A failed rebuild keeps the previous usable result and shows the problem.

## Deliver a Report

`niceeval show` presents a Report in the terminal. `niceeval view` presents it locally in a browser. `niceeval view --out <directory>` produces a self-contained static report site. Pass one or more explicit `--run` values when you need a fixed historical scope.

A static report site consumes only the `ReportExecution` completed at export time. Its browser does not read source results. See [Publish a Static Report](/tutorials/publish-report) for publishing steps.
