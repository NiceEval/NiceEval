NiceEval gives clear responsibilities to eval definitions, execution, published results, and reports. You define Evals and Experiments, then the Runner executes them. Complete Runs are published to a Record. When you view or share results, Analysis forms closed values from the selected results, and Report organizes those values into pages.

```text
Eval and Experiment
        ↓
Runner
        ↓
Record: published results
        ↓  select a scope
Analysis: Sample + Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report
        ├─ show: one selected Page
        └─ view / static export: a complete site
```

## How evals run

An Eval defines a task, assertions, and required Fixtures. An Experiment selects Evals and declares the Agent, model, concurrency, budget, and other run conditions. An Adapter connects the subject under test, and a Sandbox provides an isolated place to execute work.

The Runner creates a Run for each selected Experiment. A Run lists the positions expected for that run, so it defines the denominator for result calculation. Each position has at most one Member.

A Member says which Attempt occupies that position. An Attempt is `origin` when its `origin` matches the current position; it is `reference` when it adopts an Attempt from another Run. Adoption reuses an existing result and does not execute that Attempt again.

## Record stores published results

A Record is a portable set of published results that you can copy, put in Git, and work with through `show`, `view`, `clean`, and `migrate`. Application code does not parse or write it.

A Run is available for viewing or subsequent selection only after it is fully published. To get different results, run a new Invocation and produce a new Run. Historical results are never overwritten.

## Sample determines the comparison scope

Commands without a locator or `--run` select results that still match the current project. A locator or `--run` selects historical facts. NiceEval forms a `Sample` from that selection. It keeps the complete expected scope and denominator, but does not let pages select again or reopen results.

`project-current` scans every published Run. It keeps positions whose Experiment, Eval, and execution identity still match the current project. It does not retain only one Run by time.

`--run` retains the complete expected scope of a named Run. Every selected position is `included`, `not-recorded`, `core-invalid`, or `excluded`. Once selection establishes the framework, missing Analysis input cannot silently reduce the denominator.

## What Analysis and Report do

Analysis interprets results. Authors use `defineMeasure()` to declare the population, grouping, denominator, and missing-data rule, then use `aggregate()` or `query()` to produce `ClosedRows`, `MetricValue`, or a domain view.

Report handles pages and display. Pages and components consume only closed values: tables read rows, charts read points, and statistic cards read complete values. When it needs detail routes, a Page uses `params`, `load`, and `render` to enumerate instances. A Report does not recalculate measures or read result storage.

While the Sample is alive, `show` executes only the selected Page, then delivers that page's text or machine document. `view` and static export enumerate every Page and parameter instance to form a complete closed version of the site. Neither path lets pages read results again.

When `view` changes, it builds the next complete site. Only a complete rebuild replaces the result currently displayed; a failed rebuild keeps the previous usable site and shows the problem.

## Deliver a Report

`niceeval show` displays a Report in the terminal. `niceeval view` displays it locally in a browser. `niceeval view --out <directory>` exports a self-contained static report site. Pass one or more explicit `--run` values when you need a fixed historical scope.

A static report site consumes only the complete site version at export time. The browser does not read source results. See [Publish a Static Report](/tutorials/publish-report) for publishing steps.
