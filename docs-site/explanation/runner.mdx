The Runner schedules selected Experiments and Evals as one Invocation. It executes work in the current process, shows progress, and publishes completed results to a Record.

## Invocation, Run, and Attempt

An Invocation has one `invocationId`. Each selected Experiment creates a Run. Its expected slots define the denominator for that run.

Each slot has at most one Member. A Member says which Attempt occupies the slot. An Attempt is `origin` when its origin matches the current slot. It is `reference` when the Member adopts an Attempt from another Run.

How a position was filled—by execution, automatic carry, or manual acceptance—is saved with the target Run as inspectable provenance. An Attempt always retains the origin that actually executed it. Adoption does not copy Verdicts, Usage, events, or other business facts.

## Plan before execution

`niceeval exp --dry` uses published results to list the plan for every position, then decides whether to execute or adopt an existing Attempt.

```sh
npx niceeval exp checkout --dry
```

Carry happens only when terminal state, input identity, timeout, and `--rerun` conditions all allow it. Eligibility, identity, and the adoption reason are saved with the target Run. Analysis selection and reuse planning are separate: selection establishes a viewing denominator, while planning decides which positions to execute.

The Runner starts the Attempts that need execution only after planning. See [Rerun and Carry Results](/tutorials/rerun-and-cache) for details.

## Feedback from the current process

Progress, active Attempts, and short diagnostics serve only the current process. The terminal can render them, and `--json` writes the same machine-readable feedback.

```sh
npx niceeval exp checkout --json
```

`exp --json` emits NDJSON. Progress and diagnostic records describe the current Invocation; they are not a Record decoding format. Exactly one final record is a lightweight `InvocationReceipt`:

```json
{
  "type": "receipt",
  "receipt": {
    "invocationId": "01J8ZK3M6P4T7V9X2C5N8QW0RY",
    "runIds": ["01J9ZK3M6P4T7V9X2C5N8QW0RY"],
    "startedAt": "2026-08-09T10:00:00.000Z",
    "completedAt": "2026-08-09T10:01:00.000Z",
    "completion": "completed"
  }
}
```

The receipt identifies this Invocation, its Runs, timing, and completion only. To inspect Verdicts, Usage, diagnostics, or report aggregates, reread the published Record with its `runIds`.

## How a Run is published

The Runner makes a Run available for later viewing and adoption only after its results are fully published. If the run exits, I/O fails, or it is interrupted before then, those results do not enter a Sample or reuse. Use `niceeval clean` to remove incomplete remnants.

## Reporter

A Reporter connects only to the current Invocation. It can send information already known to the process to an external system, and `--junit` writes a file for a CI platform to consume.

Those outputs do not own the Record. Verdicts, Usage, assertions, and diagnostics remain part of published results. To inspect complete results later, use the receipt's `runIds` to select a Sample, then run `show`, `view`, or `view --out`.

## Inspect after the run

After the Runner ends, inspect a historical result with an explicit Run selection:

```sh
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY --no-open
```

Without a locator or `--run`, `show` and `view` read every result whose identity still matches the current project. A locator or `--run` reads named historical results. NiceEval forms a `Sample`, obtains the closed values for the Measures or domain views a Report uses, and produces a fixed `ReportExecution`. Published Runs are immutable. Another view creates a new selection and execution.

## Completion status

The process exit status reflects the Verdicts, execution errors, and Invocation completion known to the Runner. CI can use that status as its gate. A machine caller can read the final receipt, then use `runIds` to select what to show or export.

Input errors that prevent an Invocation from being created have no receipt. Correct the command, Experiment, or selection condition before trying again.
