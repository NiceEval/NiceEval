一个实验条件经常不只是一项配置。例如，记忆条件可能同时需要 flags、Sandbox 内的
安装检查、Agent Skill、生命周期 Hook 和缓存身份。分别导出这些片段时，调用方很容易漏掉
其中一项。NiceEval Plugin 把同一个 owner 的这些片段组合成不可变条件，再显式挂到评估用例、实验或评估组。

一次挂载只应用当前位置的 owner callback，不会同时修改其它 owner。同一个 Plugin family 可以支持多个位置，表示它们共享命名和选项，不表示一次挂载会跨位置自动展开。

NiceEval Plugin 与 Agent 原生 Plugin 是两层概念：前者组合评估条件；后者是 Codex 或
Claude Code 从 Marketplace 安装的扩展包。NiceEval Plugin 可以通过 Agent Extension
贡献原生 Plugin 配置，但两者不共用定义格式。

## 定义一个 Plugin

所有 Plugin API 都从 `niceeval/plugin` 导入。下面的 `remem` 只支持实验，因为它声明的
条件属于 Agent 与模型配置，而不是某一道题：

```ts
// experiments/shared/remem.ts
import { definePlugin } from "niceeval/plugin";

type RememOptions = {
  readonly memoryModel: string;
};

export const remem = definePlugin<RememOptions>({
  name: "acme.remem",
  behaviorRevision: "1",
  instanceKey: ({ memoryModel }) => memoryModel,
  experiment: ({ memoryModel }) => ({
    identity: {
      memory: "remem",
      memoryModel,
    },
    flags: {
      memory: "remem",
      memoryModel,
    },
  }),
});
```

三个身份字段各管一件事：

| 字段 | 用途 |
| --- | --- |
| `name` | Plugin family 的稳定命名空间；跨文件也应保持唯一 |
| `behaviorRevision` | 实现语义变化时递增，让旧结果不再沿用 |
| `instanceKey(options)` | 区分同一 family 的不同配置，例如两个 memory model |

导出的 factory 按条件本身命名，例如 `remem`、`repositoryCheckout` 或
`typescriptToolchain`。不要写成 `rememPlugin`：调用点的 `plugins` 字段已经说明它是
Plugin，重复后缀只会掩盖实验真正增加了什么条件。`name` 则使用稳定的命名空间字符串，
不要求与 TypeScript 标识符相同。

## 在 owner 上显式挂载

```ts
// experiments/codex-remem.ts
import { defineExperiment } from "niceeval";
import { codexAgent } from "niceeval/adapter";
import { dockerSandbox } from "niceeval/sandbox";
import { remem } from "./shared/remem.ts";

export default defineExperiment({
  agent: codexAgent(),
  model: "gpt-5.6-luna",
  plugins: [remem({ memoryModel: "gpt-5.6-luna" })],
  sandbox: dockerSandbox({
    source: { type: "image", image: "acme/codex-remem:1" },
  }),
});
```

Plugin 不会按目录、Config 或命名空间隐式继承。每个 occurrence 都必须出现在 owner 的
`plugins` 数组里。同一个评估用例 × 实验 pair 如果得到重复的 `(name, instanceKey)`，
NiceEval 会在创建 Provider 资源前报错。

一个 `definePlugin()` 可以声明一个或多个 owner callback。返回的 occurrence 只能挂到它
支持的位置：

| callback | 可贡献内容 |
| --- | --- |
| `eval(options)` | identity、resource demand、只含命令的 `SandboxLayer` |
| `experiment(options)` | identity、flags、labels、只含命令的 `SandboxLayer`、实验生命周期、Agent Extension |
| `group(options)` | identity |

把条件放在最窄且完整的 owner 上。只属于一道题的仓库准备放在评估用例；同一实验的记忆
安装、Agent 扩展与 flags 放在实验；只用于声明整组兼容性的身份或要求才放在评估组。

## 组合 Sandbox 准备与 Agent 扩展

Plugin 可以贡献只含命令的 `SandboxLayer`。它不能选择 Docker image、E2B template 或
其它 Provider 起点；这些仍由评估用例、评估组或实验的 `sandbox` 字段明确声明。

```ts
import { codexAgentExtension, definePlugin } from "niceeval/plugin";
import { sandboxLayer, shell } from "niceeval/sandbox";

type ToolOptions = {
  readonly version: string;
};

export const projectMemory = definePlugin<ToolOptions>({
  name: "acme.project-memory",
  behaviorRevision: "2",
  instanceKey: ({ version }) => version,
  experiment: ({ version }) => ({
    identity: { projectMemoryVersion: version },
    sandbox: sandboxLayer().prepare(
      shell(`project-memory --version | grep -Fx '${version}'`),
    ),
    agentExtensions: [
      codexAgentExtension({
        skills: [{ kind: "local", path: ".agents/skills/project-memory" }],
        configFile: "configs/codex/project-memory.toml",
      }),
    ],
  }),
});
```

`shell()`、`command()` 与 `defineSandboxCommand()` 会把稳定命令身份带进结果指纹。
自定义命令的实现语义变化时提高 `revision`，动态输入写进 `inputs`。Plugin callback 在
配置构造时执行，只返回声明；不要在 callback 里联网、读取凭证或启动进程。

Agent Extension 的 `env` 是私有运行时通道，行为投影只保留变量名，不保存变量值。API key、
token 或私有代理凭据可以放在这里；单独轮换凭据不会让旧结果失效。功能开关、记忆模型和工具
版本等会改变被测行为的值，必须同时写入 Plugin `identity` 或 `instanceKey`，也可以在变化时
提高 `behaviorRevision`。不要只把这类值藏进 `env`，否则 carry 身份无法知道行为已经变化。

## 与评估组一起复用 Docker Sandbox

评估组负责同组串行和物理 Sandbox 复用，Plugin 负责条件组合。两者可以同时使用：

- Experiment 继续用 `dockerSandbox(...)` 选择 image。
- 同组真实运行的 Attempt 依次使用同一台 Docker Sandbox，不同组仍可并行。
- Eval Plugin 的 resource 在物理 Sandbox 中 materialize 一次，并为每条真实
  Attempt 执行 prepare。
- Group Plugin 只贡献 identity，不拥有 runtime resource。
- Plugin 不会把评估组的数组位置解释成业务依赖。当前组内按规范化 Eval ID 稳定派发，
  `evals` 数组只声明成员；业务顺序仍未提供，不能靠调整数组位置表达前后依赖。

`SandboxResource` 的一次 materialize 只覆盖它自己的下载。Agent Extension 中的远端
Skill 或 Agent 原生 Plugin 仍可能按 Attempt 安装；它们不会因为使用同一台 Docker Sandbox
就自动变成共享资源。固定版本的文档型 Skill 可以随项目 vendored，并用 `kind: "local"`
上传，避免每题重复 clone；同时把上游 commit 写进 Plugin identity，更新内容时再提高
`behaviorRevision`。真正必须在 Sandbox 内联网获取的文件或安装包，应建模成对应 receiver 的
`SandboxResource`，由 Group 的物理生命周期持有。

完整的分组方式见[用评估组复用 Sandbox](/zh/tutorials/eval-groups)。

## 先看计划，再运行最小切片

先确认 Plugin occurrence、命令与选中的评估用例，再产生模型费用：

```bash
npx niceeval exp codex-remem --dry --commands
npx niceeval exp codex-remem memory/smoke
```

修改 Plugin 行为后，检查 `behaviorRevision`、`instanceKey` 和命令 identity 是否反映了这次
变化。它们没有变化时，NiceEval 可能继续沿用旧结果；已经用错误身份产出的结果需要在修正
声明后，对受影响的选择执行一次 `--rerun all`。
