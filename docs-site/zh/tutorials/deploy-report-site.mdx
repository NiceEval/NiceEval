先生成完整报告站，再部署输出目录。托管平台不读取源 Record，也不需要安装或运行 NiceEval。

```sh
npx niceeval view --experiment checkout \
  --out ./report-site \
  --no-open
```

要部署一次明确运行，请从 receipt 读取 Run ID：

```sh
npx niceeval view --run <run-id> --out ./report-site --no-open
```

## CI 流程

一个静态托管流程有三步：

1. 运行 Experiment，并保留最后一条 receipt。
2. 用 `view --out` 构建完整站点。
3. 上传输出目录，而不是源 Record。

GitHub Actions 的构建任务示例：

```yaml
- name: 生成报告站
  run: npx niceeval view --experiment checkout --out ./report-site --no-open

- name: 上传静态站点目录
  uses: actions/upload-pages-artifact@v3
  with:
    path: ./report-site
```

## 发布前检查

导出前，NiceEval 已验证 `pages` 中全部显式声明的普通 Page、参数 Page 实例、链接、资源、下载、`_niceeval/data/projections.json` 和预算；Host 不补建详情 route。成功目录包含 HTML、Report CSS、reload client、作者 asset、下载文件与 projections 文件，后者的 bytes 属于 revision identity；静态目录缺少 reload 端点时，client 安静停用。

在部署前断开网络并禁用 JavaScript，打开首页和至少一个参数详情页。正文、导航、完整度、问题和下载仍应可读。若本机 `view` 使用同一选择和 Report，同一路由的 HTTP body 与目录页面 body 应逐字节一致。

`--out` 必须指向不存在的目录。更新内容时，选择新的 Sample、导出到新目录，再切换托管平台的发布版本；不要覆盖旧目录。
