---

自定义报告用 0.12 经典面编写：`defineReport({ title, pages })` 声明页面，`render(sample)` 读取闭合样本并返回受控 JSX。它不接收 Record 路径，也不在页面 render 时临时查数据。`Sample` 类型从 `niceeval/record` 导入。

迁移旧 React 报告时可以继续使用 `jsx: "react-jsx"`。新报告若不想依赖 React runtime，可再设置 `jsxImportSource: "niceeval/report"`，使用 NiceEval 随包的受控 JSX runtime；下面的组件写法无需改变。

```text
Record
    ↓ 固定 projection plan（evaluation plan / verdict / usage / timing）
深冻结 Sample
    ↓ page.render(sample) 展开受控 JSX
immutable ReportExecution
          ↙       ↓       ↘
        show     view    export
```

## 声明页面

页面函数接收 host 一次投影后形成的深冻结 `Sample`。用 `aggregate` 分组并计算 `passRate` 与 `costUSD`：

```tsx
import type { Sample } from "niceeval/record";
import {
  Bars,
  Col,
  ExperimentScatter,
  ExperimentTable,
  Hero,
  SampleSummary,
  Section,
  aggregate,
  costUSD,
  defineReport,
  experiment,
  passRate,
} from "niceeval/report";

async function overview(sample: Sample) {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate, costUSD },
  });

  return (
    <Col>
      <Hero
        title="Memory 条件对比"
        description="对比不同 memory 条件在同一批题目上的通过率。"
        links={[{
          label: "项目仓库",
          href: "https://github.com/example/memorybench",
        }]}
      />
      <SampleSummary />
      <Section title="排行榜">
        <Bars
          points={rows}
          x="experiment"
          y="passRate"
          layout="horizontal"
        />
      </Section>
      <ExperimentScatter input={sample} />
      <ExperimentTable input={sample} />
    </Col>
  );
}

export default defineReport({
  title: "Memory 条件对比",
  pages: [{
    id: "overview",
    title: "总览",
    render: overview,
  }],
});
```

`aggregate` 的 `by` 在 Eval 级分组，不会把同一道题的 attempts 拆开。`passRate` 是严格两级分母：每个 (experiment, eval) 单元先对 attempts 取均值，再把单元值跨 Eval 等权平均；skipped 与 missing 不进入分子，coverage 显式显示缺口。

受控 JSX 不是 raw React 或 DOM。原生 tag、未包装组件、`head`、script、style、font、worker、WASM 与 raw HTML 都会在装载或校验阶段被拒绝。`Hero` 的外链只接受绝对 https 地址；NiceEval 只把 href 序列化进页面，不代为请求。

## 设成项目默认

在 `niceeval.config.ts` 中导入 Report。以后不带 `--report` 的 `show` 与 `view` 使用它：

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality";

export default defineConfig({
  report: quality,
});
```

## 处理不完整与失败

recorded-data problem 不会改变 Sample 分母：

- `unavailable` 表示 owner 没有请求的 Attachment；
- `migration-required`、`migration-unavailable` 与 `unsupported` 表示历史 schema 不能按当前需要读取；
- `invalid` 或 partial collection 表示记录的数据不完整。

这些问题由内建 problems surface 显示。缺失的 cost 与 timing 保持缺失，不会补成 0。`aggregate` 分组缺少字段时按 unknown 处理，不读取当前项目声明来填充历史数据。

projector、Calculation 或页面 callback 抛错，以及非法 document 或 route conflict，属于 execution problem。`show` 与 `view` 显示问题并保留其它页面；静态导出不会发布这一份 execution。

## 运行和发布

```sh
npx niceeval show --report ./reports/quality.ts
npx niceeval view --report ./reports/quality.ts --no-open
npx niceeval view --report ./reports/quality.ts --out ./quality-site
```

`show`、`view` 与 `--out` 都选择 Sample、执行同一个 Report，并得到固定 `ReportExecution`。`view` 后续的成功 rebuild 会产生下一份 execution；失败时保留 last-good execution。

`--out` 必须指向不存在的目录。详情见[发布静态报告](/zh/tutorials/publish-report)。

## 低层 projection API

需要自定义投影或计算时，低层 projection API 继续存在：用 `RecordProjection` 声明数据，用 `defineCalculation`、`definePage`、`definePageFamily` 与 `defineDownload` 包装结果。两条路径共享同一个 `ReportExecution`。见[报告 API](/zh/reference/report-components)与[结果数据 API](/zh/reference/results-data)。
