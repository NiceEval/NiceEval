自定义 Report 不接收 Record 路径，也不在页面 render 时临时查数据。固定流程是：

```text
core-only Sample → ReportScope → ReportPlan
                                  ↓
                              ReportInput
                                  ↓
                         ReportExecution（一次）
                           ↙       ↓       ↘
                         show     view    export
```

## 定义所需 fact

优先使用 NiceEval 导出的内建 requirement。自定义 JSON fact 使用 `defineJsonFact()`，并明确 owner：

```ts
import { defineJsonFact } from "niceeval/report";

const attemptEnergy = defineJsonFact({
  id: "attempt-energy",
  owner: "attempt",
  name: "com.example.energy",
  parse(document) {
    if (typeof document.value !== "number") {
      throw new Error("energy must be a number");
    }
    return document.value;
  },
});
```

自定义 name 使用反向域 namespace，不能以 `niceeval.` 开头。parser 只接收已验证的 `{ observedAt, value }`，不会收到 bytes、descriptor、路径或 blob。它在 execute 阶段对每个 owner 与 requirement 组合执行一次，必须同步返回 JSON 值。

## 先计划页面

`plan(scope)` 只看 core-only slots。它可以按 Run、slot、Attempt ID 和 locator 穷尽详情 route，但不能读取 Verdict、Usage 或其它业务值。

```ts
import {
  defineReport,
  verdict,
} from "niceeval/report";

export default defineReport({
  id: "quality",
  plan(scope) {
    return {
      calculations: [qualitySummary],
      pages: [
        {
          id: "overview",
          route: { pathname: "/", parameters: {} },
          title: "Overview",
          inputs: [verdict, attemptEnergy],
          calculations: [qualitySummary],
          render(input) {
            return overviewPage(input);
          },
        },
      ],
      downloads: [],
    };
  },
});
```

页面、Calculation 和 Download 各自声明 `inputs`。未声明的 fact 不能在执行时补读；宿主会把这种调用报告为 plan invalid。

## 设成项目默认

在 `niceeval.config.ts` 中直接导入定义：

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality";

export default defineConfig({
  report: quality,
});
```

以后不带 `--report` 的 `show` 与 `view` 使用它。按次切回内建报告时使用 `--report standard`。

## 定义 Calculation

```ts
const qualitySummary = defineCalculation({
  id: "quality-summary",
  inputs: [verdict, attemptEnergy],
  completeness: "allowPartial",
  evaluate(input) {
    return calculateQuality(input);
  },
});
```

`allowPartial` 可以使用成功读到的部分，但结果必须保留完整 Sample 分母、observed 数与 partial 标记。`requireComplete` 只有 durable collection 与 decoding 都 complete 时才可用。

## 页面怎样读取

页面只能读取自己的 inputs 和 calculations：

```ts
render(input) {
  const rows = input.report.sample.included.map((slot) => ({
    locator: slot.locator,
    verdict: input.readAttempt(slot, verdict),
    energy: input.readAttempt(slot, attemptEnergy),
  }));

  return {
    title: "Overview",
    body: { rows },
    textAlternative: renderRowsAsText(rows),
  };
}
```

页面返回结构化 JSON 与文字等价内容，不返回 React 组件、脚本、CSS 或文件路径。浏览器宿主由 NiceEval 内建 runtime 提供。

## 失败隔离

如果页面 A 只请求合法 Verdict，而页面 B 请求损坏的 Usage：

- A 正常 render；
- B 形成带 channel 与 issues 的 `input-invalid`，本机 view 显示具名错误页；
- 其它页面不会重新读取 Record；
- 静态 export 因计划内存在失败 consumer 而整体不发布。

用户 render、Calculation 或 Download 抛错时状态是 `execution-failed`，不会冒充输入无效。

## 下载项

Download 也是具名 consumer。它声明 inputs 和 calculations，以 `defineReportDownloadPath("downloads/...")` 取得受约束路径，并在唯一执行阶段返回完整 `Uint8Array`。静态 export 只写已经生成的 bytes，不再次运行用户代码。

## 能力边界

自定义 Report 不提供：

- 任意浏览器 script、style、font、worker 或 WASM；
- 运行时网络请求；
- 从 Report 读取文件路径或 blob；
- generic `ctx.fact()` 的 JSONL、追加或超过 65,536 UTF-8 bytes 的 document。

大文本和二进制运行事实使用 NiceEval 认可的具名专用 Attempt channel 与 blob，由内建 decoder 交付普通值。

## 运行与发布

```sh
npx niceeval show --run <run-id> --report ./reports/quality.ts
npx niceeval view --run <run-id> --report ./reports/quality.ts --no-open
npx niceeval view --run <run-id> --report ./reports/quality.ts --out ./quality-site
```

`--out` 必须指向不存在的目录。详情见[发布静态报告](/zh/tutorials/publish-report)和[报告组件 API](/zh/reference/report-components)。
