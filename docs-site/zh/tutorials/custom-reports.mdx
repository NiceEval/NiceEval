---
title: "编写自定义报告"
description: "先定义 Measure，再用 Page 和组件把闭合分析结果组织成可查看、可导出的 Report。"
---

自定义 Report 有三层清楚的职责：已发布运行结果保存已经发生的事；Analysis 定义统计口径；Report 只组织页面和显示。你不需要也不能从页面读取结果文件或注册额外的数据类型。

```text
已发布的运行结果
        ↓
Analysis：Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report：Page + component
        ↓
ReportExecution → show / view / export
```

## 定义一个 Measure

先在报告模块之外定义可复用的统计口径。下面的度量按实验分组，并将每个逻辑位置的最新完成 Attempt 汇总为通过率。

```ts
// reports/quality-measures.ts
import {
  allLogicalSlots,
  attemptPassed,
  defineDimension,
  defineMeasure,
  latestCompletedAttempt,
  logicalSlots,
  oneValue,
  partial,
  ratio,
  retainContributingEvidence,
} from "niceeval/analysis";

export const experiment = defineDimension({
  id: "quality.experiment",
  population: logicalSlots,
  value: slot => slot.experimentId,
});

export const passRate = defineMeasure({
  id: "quality.pass-rate",
  population: logicalSlots,
  input: attemptPassed,
  withinAttempt: oneValue<boolean>(),
  withinSlot: latestCompletedAttempt<boolean>(),
  acrossSlots: ratio(),
  denominator: allLogicalSlots(),
  missing: partial(),
  evidence: retainContributingEvidence(),
  unit: "ratio",
  format: "percent",
  better: "higher",
});
```

`defineMeasure()` 同时固定输入、分母和缺失语义。不要在页面里从数组长度猜测通过率，也不要先取出未包装的 number 后重新包装成显示值。

## 让组件取得闭合行

复合组件在执行时拿到 `Sample`。用 `aggregate()` 取得 rows 后，直接交给中立的表格和图表组件。

```ts
// reports/quality.ts
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const QualityComparison = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });

  return Grid({
    children: [
      Bars({ points: rows, x: "experiment", y: "passRate" }),
      Table({ rows, caption: "实验通过率" }),
    ],
  });
});

export default defineReport({
  title: "质量报告",
  pages: [
    {
      id: "overview",
      path: "/",
      title: "概览",
      render: () => QualityComparison({}),
    },
  ],
});
```

`rows` 保留每行的身份、问题和完整 `MetricValue`。`Table` 使用 rows，图表使用 points，`Stat` 使用完整 value。这样终端、网页和静态站显示同一份统计含义。

## 增加详情页或自定义原语

需要一组详情地址时，在同一个 Page 上声明 `params`、`load` 和 `render`。`params.enumerate(sample)` 列出静态导出的全部实例；`load` 可以用 `context.evidence(locator)` 取得一个闭合证据视图。实例的路由只来自已选范围和已关闭的值，不会在浏览器打开页面时重新读取结果。

需要新的显示原语时，`defineComponent()` 同时提供 `text` 和 `web`。可选的 `resolve()` 在两种呈现前计算一次闭合值；两种面随后读取同一个结果。不要用原始 HTML 或只存在于网页的内容替代终端面。

## 设成项目默认

在 `niceeval.config.ts` 中导入 Report。以后不带 `--report` 的 `show` 与 `view` 使用它：

```ts
import { defineConfig } from "niceeval";
import quality from "./reports/quality.ts";

export default defineConfig({
  report: quality,
});
```

## 处理不完整与失败

Analysis 问题跟随 `MetricValue`、`ClosedRows` 和领域视图进入页面。`partial` 保留可显示的结果及完整分母；`unsupported` 和 `failed` 也保留原因，而不是被当成零或从表格中静默删除。

作者 callback 抛错、参数不合法、语义树不合法或路由冲突属于 execution problem。`show` 与 `view` 显示其它成功页面；静态导出不会发布包含 execution problem 的站点。

## 运行和发布

```sh
npx niceeval show --run <run-id> --report ./reports/quality.ts
npx niceeval view --run <run-id> --report ./reports/quality.ts --no-open
npx niceeval view --run <run-id> --report ./reports/quality.ts --out ./quality-site
```

三条命令都选择同一范围，执行同一份 Report，并得到固定 `ReportExecution`。`view` 后续成功 rebuild 会产生下一份 execution；失败时保留上一份可用结果。

`--out` 必须指向不存在的目录。详情见[发布静态报告](/zh/tutorials/publish-report)和[报告 API](/zh/reference/report-components)。
