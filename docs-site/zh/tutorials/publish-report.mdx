`niceeval view --latest --out <目录>` 或显式 `niceeval view --run <id> --out <目录>` 从停稳的 Record 选择 core-only Sample，按计划形成 `ReportInput` 并执行一次 Report，再写出自包含静态站。它是分享结果的唯一导出路径。

```sh
npx niceeval view --latest --experiment checkout \
  --out ./report-site \
  --no-open
```

也可以导出明确 Run：

```sh
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY \
  --out ./report-site \
  --no-open
```

## 导出前选择范围

`--run` 与 `--latest` 先形成 Sample。Sample 保留完整 expected-slot 分母，以及 `included`、`not-recorded`、`invalid` 和 `excluded` 状态。

Report 根据计划请求所需的 facts，并用这些值构造固定的 `ReportInput`。未请求的通道不会影响导出；被请求的无效通道会显示具名问题并使这次导出失败。

## 导出目录包含什么

成功的目录包括：

- 全部已计划页面和参数化页面；
- 页面所需的当前宿主数据；
- exporter 内建的精确 runtime、基础样式和字体；
- 已经生成的下载项；
- 穷尽列出这些文件的 `StaticAssetManifest`。

浏览器只读取导出目录。它不访问网络、不读取源 Record，也不需要之后安装 NiceEval。把目录交给同事或静态托管服务前，可以在断网浏览器中打开它确认页面与下载项可用。

目标目录必须不存在。命令不会替换或删除已有目录；需要更新时请导出到一个新目录，再让部署平台切换版本。

## 在 CI 中生成

先运行评估，再在同一任务中导出：

```sh
npx niceeval exp ci --json
npx niceeval view --latest --experiment ci --out ./report-site --no-open
```

第一条命令的最后一条 JSON 是 receipt。需要固定到本次运行时，读取 receipt 的 `runIds`，并改用 `view --run <runId>`。

## 发布目录

将 `./report-site` 作为静态站点目录交给你的托管平台。不要把平台构建步骤指向源 Record；平台只需要部署已经生成的目录。

部署方式见[部署报告站](/zh/tutorials/deploy-report-site)。
