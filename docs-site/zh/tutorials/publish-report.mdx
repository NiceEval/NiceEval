`niceeval view --out <目录>` 或显式 `niceeval view --run <id> --out <目录>`
选择已发布的 Run。NiceEval 形成 `Sample`，按 Report 实际使用的 Measure 或领域视图得到闭合值，并导出一次完成的 `ReportExecution`。这是分享结果的导出路径。

```sh
npx niceeval view --experiment checkout \
  --out ./report-site \
  --no-open
```

也可以导出明确 Run：

```sh
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY \
  --out ./report-site \
  --no-open
```

## 导出前选择范围

不带 locator 或 `--run` 的命令以当前项目身份选择全部匹配结果；`--run` 选择具名历史 Run。两者都会先形成 Sample。Sample 保留选中 slot 的分母，以及 `included`、`not-recorded`、`core-invalid` 和 `excluded` 状态。

Report 只读取它实际使用的 Analysis 输入。未使用的数据问题不影响导出。已经进入 Measure 或领域视图的问题会显示在报告中，而不是悄悄从分母中删除。

## 什么会阻止导出

`partial`、`unsupported` 与 `failed` 等 Analysis 状态可以被导出，但页面必须显示完整度和问题。需要迁移的历史结果先运行 `niceeval migrate`，再重新查看或导出。

作者 callback 抛错、非法语义树或路由冲突等是 execution problem。只要存在 execution problem，静态导出就停止，不发布半份成功报告。

## 导出目录包含什么

成功的目录包括：

- 全部普通页面和参数化 Page 展开的页面；
- 页面所需的 host-data；
- 已经生成的下载项；
- manifest 与 exporter 内建 runtime；
- 导出所需的完成信息。

浏览器只读取导出目录。它不访问网络、不读取源 Record，也不需要之后安装 NiceEval。把目录交给同事或静态托管服务前，可以在断网浏览器中打开它确认页面与下载项可用。

目标目录必须不存在。命令不会替换或删除已有目录；需要更新时请导出到一个新目录，再让部署平台切换版本。

## 在 CI 中生成

先运行评估，再在同一任务中导出：

```sh
npx niceeval exp ci --json
npx niceeval view --experiment ci --out ./report-site --no-open
```

第一条命令的最后一条 JSON 是 receipt。需要固定到本次运行时，读取 receipt 的 `runIds`，并改用 `view --run <runId>`。

## 发布目录

将 `./report-site` 作为静态站点目录交给托管平台。不要把平台构建步骤指向源 Record；平台只需要部署已经生成的目录。

部署方式见[部署报告站](/zh/tutorials/deploy-report-site)。
