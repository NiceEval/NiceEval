`niceeval view --latest --out <目录>` 或显式 `niceeval view --run <id> --out <目录>`
选择已发布的 Run。内部 host 形成纯 `AnalysisSample`，按 Report 声明投影所需事实，并导出
一次完成的 `ReportExecution`。这是分享结果的导出路径。

```sh
npx niceeval view --latest --experiment checkout \
  --out ./report-site \
  --no-open
```

也可以导出明确 Run：

```sh
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY \
  --out ./report-site \
  --no-open
```

## 导出前选择范围

`--run` 与 `--latest` 先形成 Sample。Sample 保留完整 expected-slot 分母，以及 `included`、`not-recorded`、`core-invalid` 和 `excluded` 状态。

Report 只读取它声明的 `RecordProjection`。未请求的坏 Attachment 不影响导出。请求到的 recorded-data problem 会写进内建 problems surface，而不是悄悄从分母中删除。

## 什么会阻止导出

`unavailable`、`migration-required`、`migration-unavailable`、`unsupported`、`invalid` 与 partial collection 都是 recorded-data problem。它们可以被导出，但页面必须显示问题。

projector 或作者 callback defect、非法 semantic document、route conflict 等是 execution problem。只要存在 execution problem，静态导出就停止，不发布半份成功报告。

## 导出目录包含什么

成功的目录包括：

- 全部 fixed 和 PageFamily 展开的页面；
- 页面所需的 host-data；
- 已经生成的下载项；
- manifest 与 exporter 内建 runtime；
- 最后写入的 `complete` marker。

浏览器只读取导出目录。它不访问网络、不读取源 Record，也不需要之后安装 NiceEval。把目录交给同事或静态托管服务前，可以在断网浏览器中打开它确认页面与下载项可用。

目标目录必须不存在。命令不会替换或删除已有目录；需要更新时请导出到一个新目录，再让部署平台切换版本。

## 在 CI 中生成

先运行评估，再在同一任务中导出：

```sh
npx niceeval exp ci --json
npx niceeval view --latest --experiment ci --out ./report-site --no-open
```

第一条命令的最后一条 JSON 是 receipt。需要固定到本次运行时，读取 receipt 的 `runIds`，并改用 `view --run <runId>`。

## 发布目录

将 `./report-site` 作为静态站点目录交给托管平台。不要把平台构建步骤指向源 Record；平台只需要部署已经生成的目录。

部署方式见[部署报告站](/zh/tutorials/deploy-report-site)。
