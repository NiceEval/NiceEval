`niceeval view --out <目录>` 从已发布结果形成固定 Sample，再构建完整报告站。它不是把当前浏览器页面保存为文件：`pages` 中显式声明的所有普通 Page、参数 Page 实例、资源和下载都必须先关闭并通过校验；Host 不补建详情页。

```sh
pnpm exec niceeval view --experiment checkout \
  --out ./report-site \
  --no-open
```

需要固定到本次运行时，从 receipt 的 `runIds` 取得 Run ID：

```sh
pnpm exec niceeval view --run <run-id> \
  --out ./report-site \
  --no-open
```

## 导出前会构建什么

完整构建会枚举每个普通 Page 和每个参数 Page 实例。Host 校验 route、链接、下载、作者 asset、Source、Diff、`_niceeval/data/projections.json` 与资源预算，然后形成一个关闭站点版本。

这个站点版本同时是本机 view 与静态导出的来源。同一路由的 HTTP body 和导出目录中的页面 body 逐字节相同。`--out` 不接受 `--page`，因为静态目录始终包含整个站点。

Analysis 的 `partial`、`empty`、`unsupported` 与 `failed` 是可显示的数据状态，会带着 samples、total、issues 和 refs 一起写入页面。固定 Sample 零选中结果时，导出以 `report-sample-empty` 失败且不创建目录。Page callback 失败、参数实例不合法、路径冲突、资源冲突或预算超限也会阻止导出；它们不会产生一份缺页的目录。

## 导出目录的边界

成功目录包含：

- 全部 HTML 页面和参数化详情页；
- Report CSS、theme token、reload client 与作者声明的关闭 asset；
- 已关闭的 Source / Diff asset、下载文件和 `_niceeval/data/projections.json`；
- 站点阅读所需的导航、正文、完整度和问题内容。

目录不需要源 Record、NiceEval 安装或网络。`_niceeval/data/projections.json` 的 bytes 与页面、资源一起进入 revision identity。它携带和 view 相同的 reload client；静态目录不存在 view 端点时，client 安静停用，不显示错误，也不发起新的 Analysis 读取。

在断网浏览器中关闭 JavaScript 后打开首页和至少一个参数页。正文、导航、详情、完整度、问题和下载仍应可读。

## 目标目录保护

`--out` 的目录必须不存在。命令不会替换、删除或合并已有目录；更新站点时导出到新目录，再让托管服务切换版本。

```sh
# 成功时写入全新目录
pnpm exec niceeval view --run <run-id> --out ./report-site-2026-08-15
```

## 在 CI 中生成

```sh
npx niceeval exp ci --json
pnpm exec niceeval view --experiment ci --out ./report-site --no-open
```

若 CI 必须发布刚完成的那次运行，读取第一条命令最后一行 receipt 的 `runIds`，并使用 `view --run <run-id>`。不要让托管平台读取源 Record；它只应部署生成目录。
