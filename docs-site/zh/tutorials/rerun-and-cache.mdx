跑过一轮之后再跑同一条命令，已经判定完的评估用例默认不重花 Agent 与 Sandbox 的钱：NiceEval 沿用上一轮的结果，这次只派发真正缺的那些 Attempt。

```text
╭─ PLAN ──────────────────────────────────────────╮
│ 36 attempts · 36 evals × 1 configs              │
│ 24 of 36 reused · 12 to run                     │
╰─────────────────────────────────────────────────╯
```

先用 `--dry` 查看派发计划。人读输出会保留每条携入结果的 Verdict：

```text
compare/codex  memory/passed       carried (passed)
compare/codex  memory/failed       carried (failed)
compare/codex  memory/mixed        carried (2 passed · 1 failed)
compare/codex  memory/partial      carried 2/3 (1 passed · 1 failed) · errored 1/3
```

一行有多个 Attempt 时，每个派发原因都使用 `N/total`。
默认规则携入指纹匹配的 `passed` 与 `failed`，`errored` 和 `skipped` Attempt 自动重跑。
裸写 `--rerun` 主动重跑 `failed`，`--rerun all` 重跑选中矩阵的全部 Attempt。

这一页回答两个问题：我刚改的这一处会让多少条重跑，以及改的东西 NiceEval 看不见时怎么让它复验。

## 沿用要过的门

指纹只是其中一道。一条已经落盘的 Attempt 要被这次运行沿用，下面每一道都要过：

| 门 | 判据 | 不过会怎样 |
| --- | --- | --- |
| 终态 | 判定是 `passed` 或 `failed` | `errored` / `skipped` 永不沿用，总会重试 |
| 指纹 | 这条评估用例的指纹等于本次配置算出的指纹 | 这条评估用例的全部 Attempt 重跑 |
| 资格 | 执行耗时不超过当前解析后的 `timeoutMs` | 这一条重跑 |
| 口径 | `--rerun` 这次仍采信这个判定 | 该判定的 Attempt 重跑 |
| 模式 | 这条不落在 `--keep-sandbox` 的留存档内 | 这一条真派发 |

`passed` 与 `failed` 都是「跑完了、判定确定」的终态，没理由重花一次钱去复现同一个已知结果。`errored` 是超时、Sandbox 失败这类环境层面的不确定失败，判定本身不可信，所以从不沿用。

## 指纹读得到哪些文件

判定逻辑常常不住在 `.eval.ts` 里：断言抽进 `share/assert-memory.ts`，数据行从 `evals/data/` 读进来。指纹因此认的不是单个文件：

- **源码**：评估用例文件的字节，加上它的导入图里解析后落在项目根内的每个模块，递归展开。相对路径和 `tsconfig` 的 `paths` 别名都算数。
- **数据**：经 `loadYaml` / `loadJson` / `loadText` 读入的文件，内容哈希算进读它的那条评估用例。隐藏测试脚本、参考实现、shell 模板都是判据文件，改一字节就重跑引用它的那条，写法见[隐藏测试判分](/zh/tutorials/criteria-files)。

三处读不到，是明确的缺口：`node_modules` 里的包、动态 `import()`，以及你自己用 `fs.readFile` 读进来的文件——NiceEval 不知道那次读发生过。判据文件一律走 loader 读入，loader 只能写在模块顶层，写进 `test(t)` 会直接报错。

## 每轮换一次的地址不要写进 flags

`flags` 写的是实验条件，它整袋参与指纹判定。隧道地址每次重启换一个 URL，写进 `flags` 就等于每次重启都作废全部已完成结果。

这个地址是 `setup` 跑起来才拿到的，用 `ctx.fact()` 把它记进结果：

```ts
sandboxSetup(): SandboxHook {
  return async (sandbox, ctx) => {
    ctx.fact("nowledge.endpoint", env.url);   // 这条 Attempt 实际连的实例
    await sandbox.writeText(".nowledge/env", `NMEM_URL=${env.url}\n`);
  };
}
```

记录一样不少：`niceeval show` 的 `facts:` 行会列出这条 Attempt 连的地址，报告也能按它分组。沿用进来的结果带的是它当初那一轮的地址，不会被这一轮的新 URL 顶替。

判据是**谁写下这个值**：你在实验里声明的是条件，写 `flags`；跑起来才知道的是观测，用 `ctx.fact()`；Adapter 和评估用例都不需要读、只给报告分组用的标注写 `labels`。

## 搬走一个键，不赔上一轮重烧

地址已经写进 `flags`、现在要搬去 `ctx.fact()` 时，删掉这个键会让 flags 袋变化、上一轮全废。先跑 `--dry` 看这次为什么全要重跑：

```bash
npx niceeval exp compare --dry
```

```text
plan: 36 attempts · 36 evals × 1 configs · attempts 1
0 carried in from cache · 36 to run

compare/baseline  01  stale passed: config:flags.tunnelUrl changed (https://a1b2.trycloudflare.com → https://c3d4.trycloudflare.com)
  prior:  @1A1B2C3D4E5F (passed)
  accept: niceeval accept @1A1B2C3D4E5F
```

`stale passed` 说明历史结论是通过的、但当前指纹已变化；它还不能被缓存直接携带。差异解释与执行证据是两条轴：`fingerprint version changed` 只说明输入差异无法按当前 manifest 展开，不表示 execution、diff 或 timing 丢失。先用 locator 打开证据，确认结论仍然成立后接受它：

```bash
npx niceeval show @1A1B2C3D4E5F --timing
npx niceeval accept @1A1B2C3D4E5F
npx niceeval accept @1A1B2C3D4E5F @5E6F7G8H9J0K
```

```text
╭─ PLAN ──────────────────────────────────────────╮
│ Accepted @1A1B2C3D4E5F as @1D4C3B2A1F5E          │
│ Current fingerprint: 5f3b…                      │
╰─────────────────────────────────────────────────╯
```

接受会写出使用当前指纹的新结果，并记下各自的来源 locator、旧/新指纹和差异摘要。多个显式 locator 先全部验证，任一条失败时零写入；全部通过后按 locator 各自所属的 experiment 分组，每组生成一个 snapshot——多个 experiment 可以在一条命令里一起接受。命令不会因为共同差异接受未列出的结果，也没有 `--all-stale`。

NiceEval 已知且能证明等价的 fingerprint 版本迁移会自动携带，并留下 `migratedFrom`；无法证明的迁移才显示 `stale` 并要求接受或重跑。输出不会使用含义不清的 `details unavailable`。

很早的落盘可能带有不符合当前 locator 格式的旧值。此时 `--dry` 会显示 `accept: unavailable (legacy locator …)`，不会给出一个必然失败的命令；重新运行该 eval 即可生成新的可接受 locator。

`passed` 和 `failed` 的历史结果可以接受。结果是否来自复用 Sandbox、当前实验是否声明 `sandboxReuse: true`，都不影响接受资格。`errored`、`skipped`，以及要求保留真实 Sandbox 现场的执行模式不能接受；命令会说明原因，不会自动改为运行实验。

## 指纹没得改但就是要重跑

`--rerun` 是一根轴三档，只作用于本次调用，不改变指纹定义：

| 写法 | 哪些算数 | 本次跑什么 |
| --- | --- | --- |
| 不带 | `passed` 与 `failed` | `errored`、`skipped` 与缺失的 Attempt 序号 |
| `--rerun` | 只有 `passed` | 上面那些，加所有 `failed` |
| `--rerun all` | 都不算数 | 选中矩阵的每一条 |

```bash
npx niceeval exp compare --rerun        # 改了 Agent 的 prompt，复验失败项
npx niceeval exp compare --rerun all    # Agent CLI 升级、镜像重建，全量重验
```

裸写的 `--rerun` 用于改了不在指纹里的东西之后复验失败项，不必自己去结果树里挖失败的评估用例 ID——失败面板的 `Retry:` 行给的就是这条命令。`--rerun all` 用于外部环境整个变了时的全量重验，也是收工前确认没有回归的那一步。

声明式 callback 漏改 identity 时，`--rerun all` 只能修复本次结果。先提高 `revision` 或把变化写进 `inputs`，再执行全量重验；否则下一轮仍可能沿用语义已经变化的旧结果。直接 callback 是 opaque，NiceEval 会禁用跨 Run carry，因此不需要用 `--rerun` 补偿函数体检测。

## 中断的运行重跑就是续跑

Attempt 的 `result.json` 在收尾链完成后一次写成，判定可信与否与这次运行有没有正常结束无关。被 Ctrl-C 或 `kill -9` 打断的运行，已经落盘的终态照常沿用。

所以长批次撞上 CI 时限或宿主超时之后，恢复路径就是重跑同一条命令：只花缺失 Attempt 的成本，重跑前不需要任何手工清理。完整的恢复流程见[被强杀之后接着跑](/zh/troubleshooting/recover-after-kill)。

这只说明 NiceEval 的结果与受管 Sandbox 能续上，不代表外部状态自动回滚。实验若把 `$HOME` checkpoint、远端 memory 服务或共享数据库跨 Attempt 累积，中断中的 Attempt 可能已经写入一半。正式比较必须恢复到最后一个终态 Attempt 的原子 checkpoint；做不到就换干净 cohort 从头重建。继续沿用旧 cohort 适合调试，不应和完整批次混作同一条实验轨迹。

多开一个终端跑同一条命令也是同一套规则：每条评估用例开跑前拿一把带心跳的锁，取到锁之后重新看一眼它当前的结果，别人已经跑完落盘的直接沿用，仍缺的自己跑。两边最后都拿到完整结果，交集部分只花一份钱。

## 留存现场要求真实执行

- **复用 Sandbox 的运行照常沿用结果。** 声明 `sandboxReuse: true` 的实验与普通实验一样，在 pair 具备稳定 carry identity 时沿用指纹匹配的终态 Attempt；未沿用的 Attempt 才在本次的共用 Sandbox 中执行。直接 callback 是 opaque，会明确禁用 carry。`--rerun` 仍可要求相应 Attempt 真实重跑。理由与写法见[复用 Sandbox](/zh/tutorials/sandbox-reuse)。
- **`--keep-sandbox` 要的是一次真实执行的现场。** 判定落在当前留存档内的 Attempt 不沿用、照常派发：沿用来的结果没有 Sandbox 可留。`failed` 档下 `failed` 重跑、`passed` 照常沿用，`all` 档下全部重跑。
