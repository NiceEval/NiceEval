Report 作者只组织已经关闭的 Analysis 值。作者文件使用标准 React JSX；它不读取 Record 路径、不会取得 reader，也不需要 NiceEval 专属 JSX runtime 或 `jsxImportSource`。

```text
已发布的 Record
        ↓ 选择
Sample → Analysis 的 ClosedRows / MetricValue / DomainView
        ↓
Report：Page + component
        ├─ show：一个选中的 Page → terminal text 或 JSON
        └─ view / view --out：全部 Page → 完整静态站
```

## 定义一个 Report

把 Report 写成 `.tsx` 模块，并在项目的 TypeScript 配置中启用 `"jsx": "react-jsx"`。组合组件通过 `ctx.scope` 取得这次命令固定的 `Sample`，再把 `aggregate()` 返回的 `ClosedRows` 交给标准组件。

```tsx
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  model,
  passRate,
  Section,
  Table,
} from "niceeval/report";

const Overview = defineComponent(async (_props: {}, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { model },
    values: { passRate },
  });

  return (
    <Section title={ctx.report.title}>
      <Grid>
        <Bars points={rows} x="model" y="passRate" />
        <Table rows={rows} />
      </Grid>
    </Section>
  );
});

export default defineReport({
  title: { en: "Quality", "zh-CN": "质量" },
  pages: [{
    id: "overview",
    path: "/",
    title: { en: "Overview", "zh-CN": "概览" },
    render: () => <Overview />,
  }],
});
```

`ctx.scope` 是组件取得 Sample 的唯一字段。`ctx.report` 提供 Report 标题、导航 Page 摘要和只读的 `pricing`；后者是已验证的
`PricingProfile` 或 `null`，与 `ReportDefinition.pricing` 是同一个值，不提供 Config、Runner price table 或第二份价格输入。`ctx.report`
不提供当前目录、Record、主题或其它 Page 的数据读取能力。

成本 Measure 必须显式调用 `costUSD(profile)` 或 `totalCostUSD(profile)`，其中 `profile` 就是该 Report 的已验证 `pricing`；没有零参数
或别名入口。Analysis 拥有 slot-provider ledger、exact total 与 `numerator / denominator` mean，Host 只闭合并呈现这些结果。

`MetricValue` 来自 Analysis，并完整保留 `value`、`state`、`samples`、`total`、`issues` 和 `refs`。`value: 0` 是有效读数。不要从可见行数重算分母，也不要把 `null` 写成零。

## 两种组件形态

上例是组合组件。它可以在 Page 执行期间异步读取固定 Sample 上的关闭值。

显示原语使用另一种 `defineComponent()` 形态。可选的 `resolve()` 只运行一次；同步的 `text()` 与 `web()` 读取同一个关闭结果。

```tsx
import {
  defineComponent,
  formatMetricValue,
  Stat,
  type MetricValue,
} from "niceeval/report";

const MetricCard = defineComponent<
  { readonly label: string; readonly value: MetricValue },
  { readonly label: string; readonly value: MetricValue }
>({
  resolve: props => props,
  text: data => `${data.label}: ${formatMetricValue(data.value)}`,
  web: data => <Stat label={data.label} value={formatMetricValue(data.value)} />,
});
```

`text()` 返回文字，`web()` 返回 React JSX。两面不能再次读取 Sample、发起网络请求或各自计算统计。不要从 HTML、文字或 React element 反推机器数据。

## Page、参数和页面选择

普通 Page 的 `render` 可以直接接收固定 Sample，或先用 `load(sample, params, context)` 关闭输入。参数 Page 还要声明 `navigation: false` 与 `params`：

- `encode(params)` 产生 canonical key；
- `decode(key)` 必须能把同一种 key 还原；
- `enumerate(sample)` 只为完整站点列出实例；
- `context.evidence(locator)` 只返回当前 Sample 内的关闭证据视图。

`pages` 是 Report 唯一的页面集合，详情必须作为 Page 或参数 Page 显式声明；Host 不补建任何 route。`niceeval show --page <route>` 只 decode、load 和 render 这个目标 Page。它不会调用 `enumerate()` 或执行其它 Page。`niceeval view` 与 `niceeval view --out` 才会枚举全部普通 Page 和参数实例，并在所有路径、链接、资源和预算通过校验后形成完整站点。

## JSON、网页和静态站

`show --json` 固定输出英语 JSON。内建 Report 输出 Host 拥有的具名领域文档；自定义 Report 输出一个 Page 的 route、标题、80-column rendered text、下载摘要和问题表。两种 v1 JSON 都在顶层以相同的 `projections` 对象携带该目标 Page 的闭合成本数据；它们不包含作者树、HTML、全站路由或站点 identity。

view 与静态导出使用同一份完整站点版本。同一路由的 HTTP body 与导出目录页面 body 逐字节相同。两者都携带同一个 reload client；静态目录找不到 view 的端点时，它会安静停用。禁用 JavaScript 或断开网络后，正文、导航、详情、完整度、问题和下载仍可读。

## 样式和资源边界

Report CSS 是唯一的产品样式 owner。它负责 reset、基础排版、theme token 与组件样式。View shell 只负责浏览器语言切换、reload 状态和 Host 提示，不重绘 Report 内容。

Report 可以在 `head` 中声明结构化 `meta`、`link`、`style` 和 `script`，也可以选择 theme。脚本只能做渐进增强，不能成为正文、导航、Evidence 或机器文档的唯一入口。自定义样式不能建立第二份 reset、theme 或 View shell。
