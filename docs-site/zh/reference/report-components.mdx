报告作者使用一条普通 TypeScript 数据流：

```text
Sample 或 AttemptEvidence
  → 普通函数
  → 可序列化结果值
  → 组件
  → text / web
```

公开 API 没有统一的惰性查询对象。
异步读取和计算在 page render 中完成，组件只显示已经算好的值。

## 定义报告

单页报告直接传 render 函数：

```tsx
export default defineReport(async (sample) => {
  const rows = toExperimentRows(sample);

  return (
    <Page title="Experiments">
      <Table rows={rows} />
    </Page>
  );
});
```

多页报告静态声明 `pages`：

```ts
interface SamplePage {
  id: string;
  title: LocalizedText;
  input?: "sample";
  navigation?: boolean;
  render: PageRender<Sample>;
}

interface AttemptPage {
  id: string;
  title: LocalizedText;
  input: "attempt";
  navigation: false;
  render: PageRender<AttemptEvidence>;
}
```

`pages` 是非空有序数组。`id` 必须唯一。
一份报告最多有一张 Attempt page，而且必须写 `navigation: false`。
宿主只执行当前请求的 page render。

外壳字段只有 `title`、`theme`、`dimensionPins`、`head` 与 `pages`。
页脚和页头链接用普通组件组合；组件脚本样式随自定义 renderer 声明。

## Calculation

Calculation 由 `rollup()` 产生：

```ts
const changedLines = rollup(
  async (attempt) => {
    const diff = await attempt.diff();
    return diff ? countChangedLines(diff) : null;
  },
  {
    withinEval: min,
    acrossEvals: mean,
    unit: "lines",
    better: "lower",
  },
);
```

Reducer 是函数值。内建入口提供：

```ts
mean;
sum;
min;
max;
percentile(0.95);
```

省略题内或跨题 reducer 时使用 `mean`。
`null` 不参与 reducer；空集合保持 `null`。

官方 Calculation 和用户 Calculation 使用相同的 `rollup()`。
常用官方值包括 `passRate`、`costUSD` 与 `durationMs`。

## `aggregate()`

`aggregate()` 按分组函数执行多个 Calculation：

```tsx
const performance = await aggregate(sample, {
  by: {
    agent,
    experiment,
  },
  values: {
    passRate,
    costUSD,
  },
});
```

结果是普通只读数组：

```ts
readonly {
  agent: string;
  experiment: string;
  passRate: MetricValue;
  costUSD: MetricValue;
  refs: readonly AttemptLocator[];
}[];
```

`by` 和 `values` 的键不能重名，也不能使用保留键 `refs`。
自定义分组可以是返回字符串的普通同步函数。

## `MetricValue`

```ts
interface MetricValue {
  value: number | null;
  unit?: string;
  format?: MetricFormat;
  better?: "higher" | "lower";
  bounds?: {
    min?: number;
    max?: number;
  };
  samples: number;
  total: number;
  basis: "attempt" | "eval" | "run" | "pair";
  refs: readonly AttemptLocator[];
}
```

`value: null` 表示缺数据或不适用，不等于零。
`samples`、`total` 与 `basis` 解释分母。
`refs` 让表格、图表和 Agent 下钻到原始 Attempt。

复杂算法使用 `metricValue()` 和 `evidenceRow()` 构造带证据结果：

```ts
const point = evidenceRow({
  eval: evalId,
  delta: metricValue({
    value,
    samples,
    total,
    basis: "pair",
    evidence,
    unit: "%",
  }),
});
```

成对差异、稳定性、固定题集成绩单和历史趋势保留在对应报告旁。
它们不共享一个没有稳定公式的公共函数。

## 实体转换

实体投影立即执行：

```ts
toAttemptRows(attempts);
toExperimentRows(sample);
toEvalRows(sample);
await toTraceNodes(sample);
toSampleNotices(sample);
```

函数返回精确结果形状，不返回统一包装。
普通数组可以继续 `filter()`、`toSorted()`、`slice()` 或 join。

高频实体提供薄组件：

```tsx
<AttemptList attempts={attempts} />
<ExperimentList sample={sample} />
<EvalList sample={sample} />
```

## 组件属性

| 组件 | 主要属性 |
|---|---|
| `Table` | `rows` |
| `Scatter` | `points`、`x`、`y`、`point` |
| `Line`、`Bars`、`Area` | `points`、`x`、`y` |
| `Stat` | `value` |
| `Grid` | `items` |
| `Callouts` | `items` |
| `Conversation` | `turns` |
| `Waterfall` | `nodes` |
| `SourceView` | `source` |
| `DiffView` | `files` |
| `AttemptDetails` | `attempt` |
| `Hero` | `logo`、`description`、`links` |

`SourceView` 的 `source` 表示待显示的源码值。
它不是惰性查询对象。

## 品牌标题区

`Hero` 可以直接显示产品 Logo、介绍和主要外链。
间距、响应式布局、链接体裁与深浅色适配由 NiceEval 提供：

```tsx
<Hero
  logo={{ src: memoryBenchLogo, alt: "MemoryBench" }}
  description={{
    en: "Does memory help coding agents ship better code?",
    "zh-CN": "记忆能否帮助 coding agent 交付更好的代码？",
  }}
  links={[
    {
      label: "GitHub",
      href: "https://github.com/acme/memorybench",
    },
  ]}
/>
```

`logo.src` 使用浏览器可读取的图片 URL。
`description` 与 `links[].label` 支持 `LocalizedText`。
`show` 输出介绍与链接文字，但省略纯视觉 Logo；`view` 显示完整品牌标题区。

## 表格

```tsx
<Table
  rows={performance}
  columns={[
    "agent",
    { field: "costUSD", label: "Spend" },
    "passRate",
  ]}
/>
```

省略 `columns` 时按稳定字段顺序推导。
排序、过滤和 limit 只改变显示行，不重新聚合。

## 图表

```tsx
<Scatter
  points={performance}
  x="costUSD"
  y="passRate"
  point="agent"
/>
```

从 Sample 派生的 points 必须带行级 `refs`，
读数字段必须是 MetricValue。
纯外部数值序列要显式声明 `external`，并且不提供 Attempt 下钻。

`Line` 用于时间或有序数值，`Bars` 用于排行和堆叠，
`Area` 用于累计量或区间。
需要混合 mark 时使用 `ComposedChart`，每条 series 显式绑定字段和轴。

## Attempt 详情

Attempt 详情是一张参数化 page：

```tsx
{
  id: "attempt",
  title: "Attempt",
  input: "attempt",
  navigation: false,
  render: (attempt) => (
    <AttemptDetails attempt={attempt} />
  ),
}
```

自定义详情可以显式调用：

```ts
toConversationTurns(attempt);
toDiffFiles(attempt);
toTimelineNodes(attempt);
toAnnotatedEvalSource(attempt);
```

官方导出 `standardAttemptPage`。
把它放进自己的 `pages` 数组即可复用完整详情。

## 自定义 renderer

只有新增显示形状时才使用扩展入口：

```tsx
import { defineRenderer } from "niceeval/report/extension";

const ConfusionMatrix = defineRenderer({
  text(value, options, context) {
    return renderTextMatrix(value, options, context);
  },
  web(value, options, context) {
    return <WebMatrix value={value} options={options} />;
  },
});
```

`text` 与 `web` 都是必填项。
renderer 只接已经计算好的普通值，不读取 Sample、Record、artifact 或网络。

脚本和样式放在 `assets`。
初始 HTML 在没有 JavaScript 时仍必须完整可读。

## React 入口

`niceeval/report/react` 只导出纯 Web 组件与结果类型：

```tsx
const points = await aggregate(sample, {
  by: { agent },
  values: { passRate, costUSD },
});

<Scatter
  points={points}
  x="costUSD"
  y="passRate"
  point="agent"
/>
```

服务端或构建进程负责打开 Record、选择 Sample 和计算结果。
浏览器只接收序列化后的值。
