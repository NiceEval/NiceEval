Report 作者声明需要哪些 `RecordProjection`，再把投影结果和计算结果包装成页面或下载。作者不接收 `RecordReader`、路径或磁盘字段。

```text
AnalysisSampleHandle
        ↓  RecordProjection declarations
ProjectedSample
        ↓  Calculation / Page / PageFamily / Download
immutable ReportExecution
        ├─ show
        ├─ view revision
        └─ static export
```

## 声明 RecordProjection

`RecordAttachment projector` 固定解释一个明确 owner 的一个 Attachment family。Report 用三个 constructor 声明逻辑访问：

| constructor | 对齐方式 |
| --- | --- |
| `attemptSlotProjection(projector)` | 对 Sample 的每个 slot 形成 entry，并读取它精确引用的 Attempt Attachment。 |
| `attemptOriginRunProjection(projector)` | 对每个 slot 形成 entry，并读取该 Attempt 的 origin Run Attachment。 |
| `selectedRunProjection(projector)` | 对每个 selected Run 形成 entry，并读取该 Run Attachment。 |

前两种访问不会丢掉 `excluded`、`not-recorded` 或 `core-invalid` slot。相同 Attempt 被多个 slot 引用时，公开结果仍按 slot 对齐。

```ts
const verdicts = attemptSlotProjection(verdictProjector);
const evaluations = selectedRunProjection(evaluationsProjector);

const inputs = reportInputs({ verdicts, evaluations });
```

`reportInputs` 固定输入 key 与其 projection 的类型。host 在执行任何 Record I/O 前闭合这组依赖，并让每个 projection 至多执行一次。

## 定义 Calculation 和页面

Calculation 只从静态声明的 projection 派生业务值。它自己返回业务 `observed` 与 `denominator`；host 不会从 coverage 或 entry 数量猜测统计口径。

```ts
const passRate = defineCalculation({
  id: Either.getOrThrow(reportComponentId("pass-rate")),
  inputs,
  completeness: "allow-partial",
  calculate: ({ sample, inputs }) =>
    calculatePassRate(sample, inputs.verdicts, inputs.evaluations),
});
```

直接消费 projection 的 Calculation、Page、PageFamily 和 Download 必须选择完整度：

| 选择 | 行为 |
| --- | --- |
| `allow-partial` | callback 收到完整的 `ProjectedSample`、coverage 与 issues，可以显示部分结果。 |
| `require-complete` | 必需数据不完整时不调用 callback，result 是 `data-unavailable`。 |

`unavailable`、`migration-required`、`migration-unavailable`、`unsupported`、`invalid` 与 partial collection 都是 recorded-data problem。callback 的意外 throw 属于 execution problem，两者不能互相替代。

Page 返回闭合的 `ReportDocumentV1` 语义树。它不是 HTML、React element 或另一套文本输出。PageFamily 只能根据已投影或已计算的内存值展开 route，不能在展开时追加 Attachment I/O。

## 组合一个 Report

```ts
const overview = definePage({
  id: Either.getOrThrow(reportComponentId("overview")),
  route: Either.getOrThrow(reportRoute("/")),
  calculations: { passRate },
  render: ({ calculations }) =>
    reportDocument({
      title: "Summary",
      children: [
        reportMetric({
          label: "Pass rate",
          value:
            calculations.passRate.state === "available"
              ? calculations.passRate.value.rate
              : null,
        }),
      ],
    }),
});

export default defineReport({
  id: Either.getOrThrow(reportId("summary")),
  calculations: { passRate },
  pages: [overview],
});
```

`defineReport` 验证 ID 与组件引用。Page、PageFamily 和 Download 只能引用同一个 Report 已注册的 Calculation。页面 route 与下载路径必须通过对应 constructor 创建，避免输出冲突。

## 执行一次 Report

```ts
const execution = yield* executeReport({
  sampleHandle,
  report,
});
```

`ReportExecution` 是不可变、自包含的进程内值。它包含 Sample、projection 摘要、Calculation、family、页面、下载项与 problem table，但不包含 reader、路径、Scope、callback 或 projector token。

每个 projection、Calculation、PageFamily、页面实例与 Download 在同一 execution 中最多执行一次。`show`、`view` 与 `exportStaticReport` 只消费完成后的 execution。

| 情况 | `show` / `view` | 静态导出 |
| --- | --- | --- |
| recorded-data problem | 显示问题，并保留其它成功内容。 | 可以导出，问题必须可见。 |
| execution problem | 保留其它成功页面，并显示问题。 | 不导出。 |

## view 与静态导出

`view` 每次 rebuild 构造新的固定 `ReportExecution`。完整成功后才替换当前 revision；失败保留 last-good execution，并显示 bounded rebuild problem。

静态导出只写一份已经完成的 execution。它先验证 semantic tree、route、下载项与 execution problems，再写出页面、host-data、downloads、manifest 和内建 runtime。所有内容写完后，最后写入 `complete` marker。
