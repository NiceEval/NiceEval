Report 作者从 `niceeval/report` 导入公开入口，并从 `niceeval/record` 导入 `Sample` 类型。classic facade 是默认作者面：页面使用 `defineReport({ title, pages })` 与 `render(sample)`，可复用业务组件使用 `defineComponent((props, ctx) => ...)` 与 `ctx.scope`。低层 projection API 继续存在，供自定义投影与计算使用。作者不接收 reader、路径、raw Attachment 或磁盘字段。

```text
Record
    ↓ 固定 projection plan / RecordProjection declarations
深冻结 Sample / ProjectedSample
    ↓ page.render(sample) / Calculation / Page / PageFamily / Download
closed semantic validation
    ↓
immutable ReportExecution
        ├─ show
        ├─ view revision
        └─ static export
```

## Classic facade

### defineReport 与 render(sample)

```tsx
import type { Sample } from "niceeval/record";
import {
  aggregate,
  Bars,
  Col,
  defineReport,
  experiment,
  passRate,
} from "niceeval/report";

async function overview(sample: Sample) {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });
  return <Col><Bars points={rows} x="experiment" y="passRate" layout="horizontal" /></Col>;
}

export default defineReport({
  title: "Memory 条件对比",
  pages: [{
    id: "overview",
    title: "报告",
    render: overview,
  }],
});
```

`defineReport` 的 classic overload 只声明 `title` 与页面列表；页面 `render(sample)` 接收深冻结 `Sample` 并返回受控 JSX 树。

可复用业务组件沿用 0.12 的 compose 形态。`ctx.scope` 是当前页面的深冻结 Sample：

```tsx
import { Bars, aggregate, defineComponent, experiment, passRate } from "niceeval/report";

const Leaderboard = defineComponent(async (_props, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { experiment },
    values: { passRate },
  });
  return <Bars points={rows} x="experiment" y="passRate" layout="horizontal" />;
});
```

已有 React 报告可以保留 `jsx: "react-jsx"`；NiceEval 接收 React element，但仍只展开受控组件。不想引入 React runtime 时，在报告项目的 `tsconfig.json` 同时设置 `jsx: "react-jsx"` 与 `jsxImportSource: "niceeval/report"`，即可使用 NiceEval 随包 JSX runtime。两条路径生成同一棵 classic element tree。

### 受控 JSX 边界

组件树只接受内置组件与 `Fragment`。子节点可以是数组、string、number 或 null。它拒绝原生 tag、任意未包装组件、`head`、script、style、font、worker、WASM、raw HTML 与自定义 text / web 双面 renderer。

trusted module 本身不是沙箱。NiceEval 只保证组件拿不到 reader、Effect、Record root / path 与 append-I/O capability。

### 内置组件

| 组件 | 职责 |
| --- | --- |
| `Col` | 纵向布局容器，按声明顺序排列子块。 |
| `Section` | 带标题的块。 |
| `Hero` | 页首摘要块；可写 `title` 与 `logo`。链接只接受绝对 https，NiceEval 只序列化 href，不 fetch。 |
| `SampleSummary` | 当前 Sample 概况：实验、Eval、attempt 与 coverage。 |
| `Bars` | 柱状图；`layout="horizontal"` 呈现横向柱状图。 |
| `ExperimentScatter` | 按 Experiment 的散点；传入 `input={sample}`。当前 Report 展开对应 experiment 页时点可下钻，否则保持纯图形。 |
| `ExperimentTable` | 实验级读数表；传入 `input={sample}`。 |
| `SampleNotices` | 从闭合 Sample 呈现 partial selection warning。 |
| `RunNotices` | 保留 0.12 作者导入与组合位置。当前闭合 Sample 没有 Run diagnostics projection，因此组件不输出区块，也不伪造一份空诊断结果。 |

官方主题继续支持两个经典导入位置：

```ts
import { basalt, chalk } from "niceeval/report/built-in";
```

它们与 `niceeval/report` 根入口导出的同名 `ThemeDefinition` 是同一份值。

### aggregate 与 passRate

```ts
type AggregationSubject = {
  readonly experimentId: string;
  readonly evalId: string;
  readonly run: { readonly experiment?: {
    readonly labels?: Readonly<Record<string, string | number>>;
    readonly flags?: Readonly<Record<string, JsonValue>>;
  } };
};

type GroupFunction = (subject: AggregationSubject) => string;
```

`aggregate(sample, { by, values })` 在 Eval 级分组，返回带稳定身份的 `rows`。`experiment` 按 experimentId 分组。`passRate` 与 `costUSD` 使用严格两级分母：每个 (experiment, eval) 单元先对 attempts 取均值，passed = 1、failed / errored = 0；再把单元值跨 Eval 等权平均。skipped / missing 不进入分子，也不伪造值；coverage 显式显示缺口，缺失 cost / timing 不补 0。

### metadata 来源

`Sample` 的 metadata 标注来源，不读取当前项目声明填充历史数据。`project-current` 使用完整 current-declaration profile，并显示 `metadataOrigin: "current-declaration"`。`--run` 的 explicit-runs 在 Record 没有 durable profile 时，metadata 是 unknown / partial，experiment id 回退为 id / unknown，并给出一条结构化 notice。

## 低层 projection API

需要自定义投影与计算的作者继续使用低层 API。它与 classic facade 共享同一个 `ReportExecution` 路径。

### 声明 RecordProjection

NiceEval 提供的 opaque projector 固定形成一种 typed view。Report 用三个 constructor 声明逻辑访问；作者不能定义 raw family/projector：

| constructor | 对齐方式 |
| --- | --- |
| `attemptSlotProjection(projector)` | 对 Sample 的每个 slot 形成 entry，并读取它精确引用的 Attempt Attachment。 |
| `attemptOriginRunProjection(projector)` | 对每个 slot 形成 entry，并读取该 Attempt 的 origin Run Attachment。 |
| `selectedRunProjection(projector)` | 对每个 selected Run 形成 entry，并读取该 Run Attachment。 |

前两种访问不会丢掉 `excluded`、`not-recorded` 或 `core-invalid` slot。相同 Attempt 被多个 slot 引用时，公开结果仍按 slot 对齐。

```ts
const verdicts = attemptSlotProjection(verdictProjector);
const evaluations = selectedRunProjection(evaluationsProjector);

const inputs = reportInputs({ verdicts, evaluations });
```

`reportInputs` 固定输入 key 与其 projection 的类型。host 在执行任何 Record I/O 前闭合这组依赖，并让每个 projection 至多执行一次。

### 定义 Calculation 和页面

Calculation 只从静态声明的 projection 派生业务值。它自己返回业务 `observed` 与 `denominator`；host 不会从 coverage 或 entry 数量猜测统计口径。

```ts
const passRate = defineCalculation({
  id: Either.getOrThrow(reportComponentId("pass-rate")),
  inputs,
  completeness: "allow-partial",
  calculate: ({ sample, inputs }) =>
    calculatePassRate(sample, inputs.verdicts, inputs.evaluations),
});
```

直接消费 projection 的 Calculation、Page、PageFamily 和 Download 必须选择完整度：

| 选择 | 行为 |
| --- | --- |
| `allow-partial` | callback 收到完整的 `ProjectedSample`、coverage 与 issues，可以显示部分结果。 |
| `require-complete` | 必需数据不完整时不调用 callback，result 是 `data-unavailable`。 |

`unavailable`、`migration-required`、`migration-unavailable`、`unsupported`、`invalid` 与 partial collection 都是 recorded-data problem。callback 的意外 throw 属于 execution problem，两者不能互相替代。

Page 返回闭合的 `ReportDocument` 语义树，不是任意 HTML、DOM 或 React element。PageFamily 只能根据已投影或已计算的内存值展开 route，不能在展开时追加 Attachment I/O。

### 组合一个 Report

```ts
const overview = definePage({
  id: Either.getOrThrow(reportComponentId("overview")),
  route: Either.getOrThrow(reportRoute("/")),
  calculations: { passRate },
  render: ({ calculations }) =>
    reportDocument({
      title: "Summary",
      children: [
        reportMetric({
          label: "Pass rate",
          value:
            calculations.passRate.state === "available"
              ? calculations.passRate.value.rate
              : null,
        }),
      ],
    }),
});

export default defineReport({
  id: Either.getOrThrow(reportId("summary")),
  calculations: { passRate },
  pages: [overview],
});
```

`defineReport` 验证 ID 与组件引用。Page、PageFamily 和 Download 只能引用同一个 Report 已注册的 Calculation。页面 route 与下载路径必须通过对应 constructor 创建，避免输出冲突。

## 由 show / view 执行 Report

应用代码不调用 Report host。`niceeval show`、`niceeval view` 与 `view --out` 的内部 host
选择 Run、执行 projection 与作者 graph，并形成不可变、自包含的 `ReportExecution`。
包不导出 `niceeval/report/host`、`niceeval/report/host/node` 或 `executeReport()`。

`ReportExecution` 包含 Sample、projection 摘要、Calculation、family、页面、下载项与 problem table，但不包含 reader、路径、Scope、callback 或 projector token。classic facade 与低层 API 的页面都来自同一个 `ReportExecution`；terminal JSON、live view 与静态站消费同一份 execution。

每个 projection、Calculation、PageFamily、页面实例与 Download 在同一 execution 中最多执行一次。`show`、`view` 与 `exportStaticReport` 只消费完成后的 execution。

| 情况 | `show` / `view` | 静态导出 |
| --- | --- | --- |
| recorded-data problem | 显示问题，并保留其它成功内容。 | 可以导出，问题必须可见。 |
| execution problem | 保留其它成功页面，并显示问题。 | 不导出。 |

## 内建 source evidence Report

`sourceEvidenceReport()` 是一份普通 Report，只消费公开的 source-navigation projection。它不会拿到 Record reader、Record path 或文件系统访问能力。

```ts
import { sourceEvidenceReport } from "niceeval/report/built-in";

const compact = sourceEvidenceReport();
const expanded = sourceEvidenceReport({ mode: "full" });
const oneFile = sourceEvidenceReport({
  mode: "file",
  file: "evals/checkout.eval.ts",
});
```

`default` 显示入口文件与需要注意的调用。`full` 展开每个可显示的项目调用。`file` 只选择一份捕获的 source。`file` 不是 Record path，也不能读取当前工作区。

### 迁移 source options

把历史的 `{ path: "evals/checkout.eval.ts" }` 调用替换成 `{ mode: "file", file: "evals/checkout.eval.ts" }`。显式 mode 把文件筛选与 compact、full 呈现分开。

## view 与静态导出

`view` 每次 rebuild 构造新的固定 `ReportExecution`。完整成功后才替换当前 revision；失败保留 last-good execution，并显示 bounded rebuild problem。

静态导出只写一份已经完成的 execution。它先验证 semantic tree、route、下载项与 execution problems，再写出页面、host-data、downloads、manifest 和内建 runtime。所有内容写完后，最后写入 `complete` marker。
