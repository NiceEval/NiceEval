Report 只负责展示。先在 Analysis 定义统计口径，再在 Page 或组件中取得闭合结果。Report 作者不读取结果文件、不注册持久数据类型，也不处理迁移或存储路径。

```text
已发布的运行结果
        ↓
Analysis：Measure + aggregate() / query()
        ↓
ClosedRows / MetricValue / DomainView
        ↓
Report：Page + component
        ↓
ReportExecution → show / view / static export
```

## 先定义统计口径

`niceeval/analysis` 提供 NiceEval 已发布的输入。作者用 `defineMeasure()` 明确总体、归并方式、分母和缺失策略；不需要额外的输入注册步骤。

```ts
import {
  allLogicalSlots,
  attemptPassed,
  defineDimension,
  defineMeasure,
  latestCompletedAttempt,
  logicalSlots,
  oneValue,
  partial,
  ratio,
  retainContributingEvidence,
} from "niceeval/analysis";

export const experiment = defineDimension({
  id: "example.experiment",
  population: logicalSlots,
  value: slot => slot.experimentId,
});

export const passRate = defineMeasure({
  id: "example.pass-rate",
  population: logicalSlots,
  input: attemptPassed,
  withinAttempt: oneValue<boolean>(),
  withinSlot: latestCompletedAttempt<boolean>(),
  acrossSlots: ratio(),
  denominator: allLogicalSlots(),
  missing: partial(),
  evidence: retainContributingEvidence(),
  unit: "ratio",
  format: "percent",
  better: "higher",
});
```

`MetricValue` 会保留数值、状态、实际贡献数、固定分母、问题和证据引用。不要先取出未包装的 number，再在 Report 中重新计算或包装它。

## 在 Page 或组件中读取闭合值

`aggregate()` 适合按维度形成表格或图表行。它在 Page 或复合组件取得的 `Sample` 上运行，并返回可直接交给 `Table`、`Bars`、`Line` 或 `Scatter` 的 `ClosedRows`。

```ts
import {
  aggregate,
  Bars,
  defineComponent,
  defineReport,
  Grid,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const Comparison = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { experiment },
    values: { passRate },
  });

  return Grid({
    children: [
      Bars({ points: rows, x: "experiment", y: "passRate" }),
      Table({ rows, caption: "各实验的通过率" }),
    ],
  });
});

export default defineReport({
  title: "质量概览",
  pages: [
    {
      id: "overview",
      path: "/",
      title: "概览",
      render: () => Comparison({}),
    },
  ],
});
```

需要完整的表格请求或一个领域视图时，从 `niceeval/analysis` 导入 `query()`。例如，`attemptEvidenceView` 会返回已关闭的证据视图；它不会把读取器或原始运行数据交给组件。

## 组件的两种形态

复合组件在执行期间取得 `Sample`，再组合已有组件。上例的 `Comparison` 就是这种形态。

新显示原语同时提供文字面和网页面。可选的 `resolve()` 是唯一可以异步取得闭合值的阶段；`text` 与 `web` 读取同一个结果。

```ts
import {
  defineComponent,
  Stat,
  Text,
  type MetricValue,
} from "niceeval/report";

const PassRateState = defineComponent({
  text: ({ value }: { readonly value: MetricValue }) =>
    Text({ value: `通过率状态：${value.state}` }),
  web: ({ value }) => Stat({ label: "通过率", value }),
});
```

两个面都只能返回 NiceEval 的语义节点。不要返回 DOM、原始 HTML、浏览器副作用或另一套独立的文字结果。

## 页面、参数和路由

`defineReport({ pages })` 是唯一的报告定义入口。普通 Page 可直接在 `render(sample)` 中读取闭合结果；需要一组详情地址时，在同一个 Page 上提供 `params`、`load` 和 `render`。`params.enumerate(sample)` 给静态导出列出全部实例，`load` 可以通过 `context.evidence(locator)` 取得一个闭合证据视图。

Page 的 `id` 用于诊断和稳定顺序，`path` 是用户访问的基础地址。参数化 Page 必须设置 `navigation: false`，并让 `encode()` 与 `decode()` 规范往返。Report 在调用作者回调前检查页面定义、ID 与普通路径；实例化后再检查参数路由和下载路径冲突。

## 执行与问题

`show`、`view` 和静态导出在 Sample 仍可用时执行 Page 与组件，随后只保留不可变的 `ReportExecution`。它包含已完成的页面、下载项和问题；不包含可以再次读取结果的能力。

Analysis 问题会保留在 `MetricValue`、`ClosedRows` 和领域视图中。回调抛错、参数不合法、语义树不合法或路由冲突则成为 execution problem。`show` 和 `view` 继续显示其它成功页面；静态导出遇到 execution problem 不发布站点。
