`niceeval/report` 把报告能力分成三层：

| 层 | 定义方式 | 职责 |
| --- | --- | --- |
| Source | `sources.*` / `defineSource(...)` | 从 Sample 或 AttemptEvidence 计算 Content |
| Composition | `defineComposition(...)` | 协调多个 Source、加工 Content、装配组件树 |
| Component | 内建原语 / `defineComponent(...)` | 把 Content 同步显示成 text 与 web |

Component 不读取 Sample、Record 或 artifact。数据读取、聚合、排序和证据关联属于 Source；
动态编排和跨来源连接属于 Composition。

## 数据绑定

数据原语接收互斥的 `source` 与 `data` 两种形态：

```ts
type DataProps<Input extends SourceInput, Content> =
  | { source: Source<Input, Content>; input?: Input; data?: never }
  | { data: Content; source?: never; input?: never };
```

```tsx
<Table source={sources.entity.experiments} />
<Table data={content} />
```

- `source`：管线在 resolve 阶段调用 `compute(input)`；省略 `input` 时使用当前 page input。
- `data`：使用已经计算好的可序列化 Content；组件不会再次取数。
- 同时传入 `source` 与 `data` 会报错。

同一 page 实例内，相同 Source 对象和相同 input 引用只计算一次。两个配置相同但分别创建的 Source
是两个值，因此会分别计算。

## 官方 Source

官方 Source 统一从 `sources` 对象发现：

| Source | 产出 |
| --- | --- |
| `sources.entity.experiments` | Experiment 行，包含 Eval 与 Attempt 下钻 |
| `sources.entity.evals` | Eval 行，包含 Attempt 下钻 |
| `sources.entity.attempts` | Attempt 行 |
| `sources.measure.rows(options)` | Dimension 与 Measure 组成的 Dataset |
| `sources.measure.matrix(options)` | 两个维度的交叉格 |
| `sources.measure.scoreboard(options)` | 固定题集的总分与分科得分 |
| `sources.measure.delta(options)` | 相同 Eval 在多个条件上的值与差异 |
| `sources.measure.stability(options)` | Eval 跨 Run 的稳定性 |
| `sources.sample.snapshot` | Sample 范围、判定、覆盖、来源与读取期 Issue |
| `sources.sample.traces` | Sample 中各 Attempt 的执行瀑布 |
| `sources.run.diagnostics` | 已持久化的 Run 诊断 |
| `sources.attempt.snapshot` | Attempt 身份、判定、耗时、用量、成本与错误 |
| `sources.attempt.diagnostics` | Attempt lifecycle 诊断 |
| `sources.attempt.assertions` | 断言与给分记录 |
| `sources.attempt.source` | 带证据标注的评估源码 |
| `sources.attempt.conversation` | 分轮事件流与失败命令 |
| `sources.attempt.timeline` | runner phases 与关联 spans |
| `sources.attempt.trace` | 原始 OTel span 树 |
| `sources.attempt.diff` | 文件变化与 patch |

范围级 Source 接收 `Sample`。Attempt Source 接收 `AttemptEvidence`，只能用于 attempt-input page。

## TableContent

表格 Source 返回统一的 `TableContent`：

```ts
interface TableContent<RowValue extends Row = Row> {
  columns: readonly ColumnSpec[];
  rows: readonly RowValue[];
}

interface ColumnSpec {
  key: string;
  unit?: string;
  better?: "higher" | "lower";
}

interface Row {
  key: string;
  cells: Readonly<Record<string, Cell>>;
  subRows?: readonly Row[];
  variant?: "normal" | "placeholder";
}
```

`columns` 声明稳定字段身份和默认顺序。`rows[].cells` 通过字段 key 关联列；
数组位置不是字段身份。

## Table

`Table` 显示任何 `TableContent`：

```tsx
const byAgent = sources.measure.rows({
  dimensions: ["agent"],
  measures: [passRate, costUSD],
  sort: passRate,
});

<Table source={byAgent} filter />
```

需要覆盖默认列时使用 `Column`：

```tsx
<Table source={byAgent}>
  <Column dataKey="agent" header="Agent" />
  <Column dataKey="pass-rate" header="通过率" />
  <Column dataKey="cost-usd" header="成本" />
</Table>
```

`Column` 是结构节点，只选择和呈现已经计算好的字段，不取数、不聚合。

web 面使用真实 `<table>`，排序与过滤属于渐进增强。text 面按终端显示宽度计算列宽；
中文与全角字符按两列处理。`null` 显示为 `—`，不会被改成 0。

## Chart

`Chart` 是唯一图表原语。它消费 `sources.measure.rows(...)` 返回的 Dataset，
再由 `Series` 把字段映射成 line、bar、area 或 scatter：

```tsx
const qualityCost = sources.measure.rows({
  dimensions: ["experiment", "agent"],
  measures: [costUSD, passRate],
});

<Chart source={qualityCost} x="costUSD" y="passRate" legend tooltip>
  <Series id="frontier" mark="scatter" points="experiment" by="agent" />
</Chart>
```

`Series` 是结构节点。它不计算 Dataset，也不能独立出现在报告树中。

```ts
interface SeriesProps {
  id: string;
  mark: "line" | "bar" | "area" | "scatter";
  x?: string;
  y?: string;
  points?: string;
  by?: string;
  value?: string;
  stack?: string;
  connect?: boolean;
  hidden?: boolean;
  label?: LocalizedText;
}
```

同一 Dataset 可以同时交给 `Table` 和多个 `Chart`。改变 mark、轴或 series 不会触发第二套聚合。

## 排版原语

| 原语 | 作用 |
| --- | --- |
| `Col` | 纵向堆叠 |
| `Row` | web 横排；text 空间足够时分栏 |
| `Grid` | 多列网格；列数由格数和可用宽度决定，不用声明 |
| `Section` | 带标题的内容区 |
| `Stat` | label、value、detail 与 tone |
| `Text` | 不解析标记的普通文本 |
| `Markdown` | CommonMark 正文，两面共享同一棵 AST |
| `Table` | 表格 |
| `Tabs` / `Tab` | 页内并列内容 |

报告树不能直接放 `<div>`、`<table>` 或其它 HTML intrinsic，因为它们没有 text 面。
HTML 只能出现在自定义 Component 的 web renderer 内。

## 官方 Composition

Composition 只装配公开 Source 和 Component，不实现 renderer：

| Composition | 回答的问题 |
| --- | --- |
| `SampleOverview` | 当前 Sample 的摘要、质量成本图与 Experiment 层级行 |
| `SampleSummary` | Sample 范围、判定构成、主读数与成本 |
| `SampleNotices` | Sample 选择和读取过程发现的问题 |
| `RunNotices` | 已持久化的 Run 诊断 |
| `SampleFixPrompt` | Sample 中失败事实对应的批量修复 prompt |
| `FailureList` | 最近的 failed / errored Attempt |
| `AttemptDetail` | 一次 Attempt 的全部证据区块 |
| `AttemptAssessment` | source 或 assertions 的评估说明 |
| `AttemptNotices` | Attempt 错误与诊断 |
| `AttemptFixPrompt` | 单个 Attempt 的修复 prompt |

```tsx
<SampleOverview />
<FailureList limit={20} />
```

需要改变官方 Composition 的区块顺序或取舍时，直接用 Source 和原语重新装配。

## 自定义 Composition

```ts
interface CompositionContext<Input extends SourceInput> {
  readonly input: Input;
  readonly data: Readonly<Record<string, JsonValue>>;
  readonly page: NormalizedPage;
  readonly signal: AbortSignal;
  resolve<Content>(source: Source<Input, Content>, input?: Input): Promise<Content>;
}
```

```tsx
const FailingEvals = defineComposition(async (_props: {}, ctx) => {
  const content = await ctx.resolve(sources.entity.evals);
  const rows = content.rows.filter(
    (row) => row.cells.verdict.verdict !== "passed",
  );
  return <Table data={{ ...content, rows }} />;
});
```

Composition 内必须使用 `ctx.resolve()`，不能调用 `source.compute()`。后者会绕过 page 缓存。

## 自定义 Component

```ts
interface ComponentFaces<Data, Options, D extends DimensionDeclarations> {
  dimensions(data: Data, options: Readonly<Options>): D;
  text(data: Data, options: Readonly<Options>, ctx: RenderContext<D>): string;
  web(data: Data, options: Readonly<Options>, ctx: RenderContext<D>): ReactNode;
  enhance?: readonly EnhanceCapability[];
  styles?: readonly ComponentStyle[];
}
```

三个函数都同步执行：

- `dimensions()` 声明组件消费的维度值和编码；不消费维度时返回 `{}`。
- `text()` 生成终端文本。
- `web()` 生成 ReactNode。

Component 没有 `resolve`，也不能在 renderer 中读取 Source、Sample、Record、磁盘或网络。

## 页级维度身份

组件先在 `dimensions()` 中声明完整值集合，再通过 `ctx.dimension(handle).at(index)` 读取呈现：

```tsx
const AgentLegend = defineComponent<LegendData, {}>({
  dimensions: (data) => ({
    agents: {
      dimension: "agent",
      encoding: { kind: "series", mark: "line" },
      values: data.agentIds,
    },
  }),
  text(data, _options, ctx) {
    const agents = ctx.dimension("agents");
    return data.agentIds.map((_, index) => agents.at(index).label).join("  ");
  },
  web(data, _options, ctx) {
    const agents = ctx.dimension("agents");
    return (
      <ul>
        {data.agentIds.map((id, index) => (
          <li key={id} style={{ color: agents.at(index).stroke }}>
            {agents.at(index).label}
          </li>
        ))}
      </ul>
    );
  },
});
```

text 面只得到标签与文本身份；web 面还得到颜色、线型、点形或 pattern。
不要逐个截断 label，也不要按数组下标自行配色。

一个实验在同一页上恒定一个颜色，图例、表格和图上的点用的是同一次分配。
取颜色只有两个入口：报告树里的组件用 `ctx.dimension(handle)`，
自有 React 页面用 `presentDimension(declaration)`。库不导出色板、槽位号或取色函数，
自己按下标配色会和官方组件对不上。

## 显示值与格式化

读数格的显示字符串在计算时生成一次，写进 `MeasureCell.display`，两个渲染面直接输出它。
终端和网页上的同一个数字因此逐字相同。

`unit` 决定折成什么：

| `unit` | 显示 |
| --- | --- |
| `"%"` | `87.3%` |
| `"ms"` | `850ms` / `1.2s` / `4m 20s` |
| `"$"` | `$0.31` |
| 其它，如 `"tokens"` | `46.5k tokens` |
| 省略 | `1.2k` |

自定义 Source 生成读数格时调用 `measureDisplay(value, unit)`，不要自己拼字符串。
自己拼会让同一个读数在实验行和分组行显示成两种样子。

| 函数 | 用途 |
| --- | --- |
| `measureDisplay(value, unit?)` | 生成 `MeasureCell.display` |
| `formatMeasureValue(value, unit?)` | 按 unit 折一个数字 |
| `formatAxisTick(value, step, unit?)` | 图表轴刻度，精度跟随步长 |
| `formatCellText(cell, locale?)` | 把任意 Cell 折成一行文本 |
| `missingText(code, locale?)` | 缺数据格的原因文案 |

缺数据格带的是 code，不是文案。内建 code 有 `noSamples`、`notRun` 和 `unscorable`，
各有中英文案，`missingText()` 按当前语言取。自定义 code 未命中词表时原样显示。

## 文本排版

自定义组件的 text 面用这组函数对齐。不要用 JavaScript 自带的 `padEnd`：
它数的是码元不是显示列宽，一带中文就把表撕歪。

| 函数 | 用途 |
| --- | --- |
| `stringWidth(text)` | 显示宽度，中文与全角记 2 列 |
| `padEnd(text, width)` / `padStart(text, width)` | 按显示宽度补齐 |
| `wrapText(text, width)` | 按显示宽度折行 |
| `indent(block, prefix)` | 每行加缩进 |
| `bar(ratio, width)` | 字符条 |
| `columns(blocks, widths, separator?)` | 多块并排 |

## 共用呈现 props

数据原语按需支持以下呈现 props：

| Prop | 作用 |
| --- | --- |
| `attemptHref` | 把 AttemptLocator 映射到证据链接 |
| `locale` | 组件内建文案的语言 |
| `className` | web 根元素 class |
| `filter` | 只为 web 增加过滤输入框，不改变 Content |

排序、轴映射、图例和 tooltip 只能改变呈现，不能触发第二次聚合。

## `niceeval/report/react`

这个入口导出纯 web renderer、Content 类型，以及上面那套呈现工具箱：格式化、缺数据文案、
`presentDimension` 和 locale 解析。它不导出 Source、Composition，也不读取记录：

```tsx
import { sources } from "niceeval/report";
import { Table } from "niceeval/report/react";

const data = await sources.entity.experiments.compute(sample);
return <Table data={data} />;
```

在 report page 外直接调用 `compute()` 是正确的；那里没有 `ctx.resolve()` 和 page 缓存。
