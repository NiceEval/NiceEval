`niceeval/expect` 只提供纯 Match factory。Match 比较一个候选值，不记录结果，也不决定判定或分数。`t.check(...)`、`turn.*(...)` 与 `t.sandbox.*(...)` 负责生成 Fact；`t.assert(...)`、`t.require(...)` 与计分制的 `t.score(...)` 再消费 Fact。

```ts
import { and, excludes, includes, pattern } from "niceeval/expect";
```

## 使用方式

```ts
t.assert(t.check(t.reply, includes("confirmed")));
t.assert(t.check(t.reply, and(pattern(/order #\d+/i), excludes("cancelled"))));
const config = await t.require(t.check(t.sandbox.file("config.json"), pattern(/runtime/)));
```

| 入口 | 作用 |
|---|---|---|
| `t.check` | 把立即值或延迟 EvidenceSource 与 Match 组合成 Fact |
| `t.assert` | 把 Fact 用作通过制要求；失败不会中止后续代码 |
| `t.require` | 立即消费 `phase: "now"` Fact；失败时中止后续代码并保留结果 |
| `t.score` | 在计分制评估中把 Fact 计入分数 |

### 常见用法示例

```ts
t.assert(t.check(t.reply, includes("Paris")));
t.assert(t.check(t.reply, pattern(/order #\d+/i)));
t.assert(t.check(turn.data, equals({ intent: "refund" })));
t.assert(t.check(turn.data, matches(OrderSchema)));
t.assert(t.check(turn.data, satisfies("返回数组", Array.isArray)));
t.assert(t.check(t.reply, similarity("The answer explains the refund window")), { atLeast: 0.8 });
```

## 组合与三态

```ts
t.assert(t.check(t.reply, and(includes("required"), excludes("forbidden"))));
t.assert(t.check(t.reply, or(includes("approved"), includes("accepted"))));
```

同一 `and` / `or` 里的 Match 必须属于同一 domain（`value`、`tool` 或 `event`）。布尔 Match 的内部结果是 `matched`、`mismatched` 或 `unavailable`：`or` 只有在没有子项命中且至少一项证据不完整时才返回 `unavailable`，不会把未知当成否定。Match 自身没有 `.gate()`、`.points()` 或 `.atLeast()`；这些策略只属于 Fact 的消费位置。

## 自定义 matcher

```ts
import { defineValueMatch } from "niceeval/expect";

const validEmail = () =>
  defineValueMatch<string>({
    name: "valid email",
    evaluate(value) {
      return value.includes("@");
    },
  });

t.assert(t.check(t.reply, validEmail()));
```

布尔自定义 Match 用 `defineValueMatch`，连续分数用 `defineScoreMatch`。两者只实现单候选比较；读取文件、扫描事件、决定 coverage 或修改 Verdict 仍由各领域的 Fact producer 与 consumer 负责。
