`niceeval/expect` 只提供纯 Match factory。Match 比较一个候选值，不记录结果，也不决定判定或分数。Turn、Session 与 Sandbox producer 负责生成 Fact；`t.check(...)`、`t.require(...)` 与计分制的 `t.score(...)` 消费 Fact。值加 Match 的便利写法会原子创建并消费 Fact。

```ts
import { and, excludes, includes, pattern } from "niceeval/expect";
```

## 使用方式

```ts
t.check(t.reply, includes("confirmed"));
t.check(t.reply, and(pattern(/order #\d+/i), excludes("cancelled")));
const config = await t.require(rawConfig, pattern(/runtime/));
```

| 入口 | 作用 |
|---|---|---|
| `t.check` | 登记判定用途并同步返回已有或新建的 Fact；失败不会中止后续代码 |
| `t.require` | 立即消费 `phase: "now"` Fact；失败时中止后续代码并保留结果 |
| `t.score` | 在计分制评估中把 Fact 计入分数 |

### 匹配工具名称、参数与命令

`toolMatch("get_weather")` 只检查工具名称。第二个参数可以继续约束同一次调用的完整 JSON 输入和生命周期状态；`input` 接受 value Match，而不是直接接受一份参数对象：

```ts
import type { JsonValue } from "niceeval";
import { equals, satisfies, toolMatch } from "niceeval/expect";

const exactWeatherCall = toolMatch("get_weather", {
  input: equals<JsonValue>({ city: "Taipei", unit: "celsius" }),
  status: "completed",
});

const installCall = toolMatch("shell", {
  input: satisfies<JsonValue>("运行 pnpm install", (input) =>
    typeof input === "object" &&
    input !== null &&
    !Array.isArray(input) &&
    typeof input.command === "string" &&
    input.command.includes("pnpm install")
  ),
});
```

`equals(...)` 比较完整输入；`matches(...)`、`satisfies(...)` 与其它 value Match 可以表达结构或谓词条件。具体字段由 Agent 的工具协议决定，例如 shell 工具可能把命令文本放在 `command` 字段。只关心参数、不限制工具名称时，使用 `toolMatch({ input })`。

`toolMatch("shell")` 回答“调用的是哪类工具”，`commandMatch("niceeval", { argsStart: ["show"] })` 回答“这次调用运行了哪个可执行文件和哪些 argv token”。后者依赖 Adapter 提供的结构化 command projection；只有 shell source、截断文本或脱敏文本时，不会猜测 argv，结果会是 `unavailable`。需要两项同时成立时，把它们组合在同一笔调用上：

```ts
import { and, commandMatch, toolMatch } from "niceeval/expect";

t.check(turn.calledTool(
  and(
    toolMatch("shell", { status: "completed" }),
    commandMatch("niceeval", { argsStart: ["show"] }),
  ),
));
```

## 组合与三态

```ts
t.check(t.reply, and(includes("required"), excludes("forbidden")));
t.check(t.reply, or(includes("approved"), includes("accepted")));
```

同一 `and` / `or` 里的 Match 必须属于同一 domain（`value`、`tool` 或 `event`）。布尔 Match 的内部结果是 `matched`、`mismatched` 或 `unavailable`：`or` 只有在没有子项命中且至少一项证据不完整时才返回 `unavailable`，不会把未知当成否定。Match 自身没有 `.gate()`、`.points()` 或 `.atLeast()`；这些策略只属于 Fact 的消费位置。

## 自定义 matcher

```ts
import { defineValueMatch } from "niceeval/expect";

const validEmail = () =>
  defineValueMatch<string>({
    name: "valid email",
    evaluate(value) {
      return value.includes("@");
    },
  });

t.check(t.reply, validEmail());
```

布尔自定义 Match 用 `defineValueMatch`，连续分数用 `defineScoreMatch`。两者只实现单候选比较；读取文件、扫描事件、决定 coverage 或修改 Verdict 仍由各领域的 Fact producer 与 consumer 负责。
