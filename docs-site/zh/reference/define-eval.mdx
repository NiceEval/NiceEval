`defineEval` 是编写评估用例的主要入口。每个评估用例文件调用一次，传入描述和 `test(t)`，并默认导出结果。

```ts
import { defineEval } from "niceeval";

export default defineEval({
  description: "Brooklyn weather query",
  async test(t) {
    await t.send("What's the weather like in Brooklyn today?");
    t.succeeded();
  },
});
```

<Note>
  不要提供 `id` 或 `name`。[NiceEval](https://niceeval.com/) 从文件路径推导评估用例 ID。
</Note>

#### `description`

```ts
description?: string;
```

一句话描述,展示在 `niceeval list` 和 view 里;纯说明,不影响调度或打分。

#### `tags`

```ts
tags?: string[];
```

标签,供 CLI `--tag` 过滤和 view 分类;与 id 前缀过滤是两套独立的筛选维度。

#### `sandbox`

```ts
sandbox?: SandboxLayer;
```

这道题贡献的 Sandbox 声明层。省略等价于空 command-only layer，不提供隐式 template。
每个实际 Eval x Experiment 配对必须恰好一方提供 template-bearing layer。

#### `judge`

```ts
judge?: JudgeConfig;
```

覆盖项目级 Config.judge,只对这一条评估用例生效(如换个更贵的评审模型)。

#### `reporters`

```ts
reporters?: Reporter[];
```

覆盖 / 追加项目级 Config.reporters,只对这一条评估用例生效。

#### `timeoutMs`

```ts
timeoutMs?: number;
```

覆盖项目级 / CLI 的单次 attempt 超时(毫秒),只对这一条评估用例生效。

#### `metadata`

```ts
metadata?: globalThis.Record<string, JsonValue>;
```

任意附加元数据,作为 Attempt Provenance 保存,不参与调度或打分;供自定义 reporter 消费。

#### `diff`

```ts
diff?: { include?: string[]; ignore?: string[] };
```

调整 agent diff 的归因排除清单(仅 Sandbox 型;见 docs/feature/eval/README.md):两个数组都是
gitignore 风格 glob(workdir 相对)。默认排除 .git/node_modules/构建产物/包管理器缓存;
`ignore` 在默认清单上追加排除;`include` 优先级最高,把匹配路径显式加回。
合成规则固定为「默认 ∪ ignore,再被 include 打洞」,清单在分类账锚点时冻结。

#### `test`

```ts
test(t: TestContext): Promise<void> | void;
```

## Test context: `t`

`t`（`TestContext`）是评估用例作者拿到的高层上下文。运行器按 agent 的实际能力组装它——`t.sandbox` 这类字段只在 `defineSandboxAgent` 构造的 agent 上才有意义，完整规则见[能力位参考](/zh/reference/capabilities)。

下面签名里的 `H` 是断言句柄类型：`defineEval` 的 `t` 上 `H` 恒为 `AssertionHandle`。计分制 `defineScoreEval` 的 `t`（`ScoreTestContext`）换成 `ScoreAssertionHandle`——多出 `.points(n)` 这一个给分词。严重度三个词在两种题型里含义相同：`.gate()` 只声明「不过就 failed」，不改变 `test()` 的控制流。要「这步不成立就别往下跑了」再链 `.stopOnFailure()`，或者用值断言的简写 `t.require()`（两种题型都有）。跨两种题型复用的辅助函数把参数标注成 `BaseTestContext<H>`，两种 `t` 都能传进去。详见[计分制](/zh/tutorials/evaluation-kinds#走完三步也要记三分)。全部成员：

#### `send`

```ts
send(input: SendInput): Promise<TurnHandle<H>>;
```

向默认会话发一条消息(字符串或结构化消息),返回该轮的 TurnHandle。事件同时累加进默认会话的累计事件流,供下面的作用域断言使用。

#### `sendFile`

```ts
sendFile(path: string, text?: string): Promise<TurnHandle<H>>;
```

发一条带文件(图片等多模态输入)的消息。`path` 相对项目根;读出后 base64 随 TurnInput.files 交给 adapter。

#### `requireInputRequest`

```ts
requireInputRequest(filter?: InputRequestFilter): InputRequest;
```

取默认会话里等待中的 HITL 输入请求;不传 filter 要求恰好一条,拿不到就抛。

#### `respond`

```ts
respond(...responses: (string | RespondAnswer)[]): Promise<TurnHandle<H>>;
```

回答默认会话里等待中的输入请求,返回续接的 TurnHandle。字符串形式只在恰好一条待处理请求时
才能自动对位——命中该请求 `options` 里的某个 id 就是 `optionId`,否则整句落自由文本;
多个请求并停时字符串形式无法消歧,直接抛 `hitl.stringAmbiguous`,要求改用
`{ request, optionId }` / `{ request, text }` 对象形式(RespondAnswer,见其类型注释)显式指名。

#### `respondAll`

```ts
respondAll(optionId: string): Promise<TurnHandle<H>>;
```

用同一个 optionId 批量回答默认会话里全部等待中的输入请求。

#### `reply`

```ts
readonly reply: string;
```

默认会话最近一轮的助手回复文本。

#### `sessionId`

```ts
readonly sessionId: string | undefined;
```

adapter 侧的默认会话 id(有会话概念的 agent 才有)。

#### `events`

```ts
readonly events: readonly StreamEvent[];
```

默认会话累计的事件流(跨该会话所有轮次)。

#### `newSession`

```ts
newSession(): SessionHandle<H>;
```

另开一路独立会话,返回它的 SessionHandle——不是 void。多会话隔离的关键入口:
新会话的发送与断言都与默认会话及其它 newSession() 会话相互隔离,常用于「多用户
并行对话」「一条主线 + 一条旁支」这类场景。

#### `signal`

```ts
readonly signal: AbortSignal;
```

本次 attempt 的中止信号;超时 / 首过即停 / 用户 Ctrl-C 时触发,传给 adapter 的长耗时调用做取消。

#### `model`

```ts
readonly model?: string;
```

本次 attempt 使用的模型名(由 experiment/CLI flag 决定);省略即 agent 原生默认,不代表「无模型」。

#### `reasoningEffort`

```ts
readonly reasoningEffort?: string;
```

本次 attempt 的推理努力程度(如 "low"/"medium"/"high",取值由 adapter/模型决定)。

#### `flags`

```ts
readonly flags: Readonly<globalThis.Record<string, JsonValue>>;
```

本次 attempt 生效的实验 flags(experiment.flags 的只读视图;实验条件,非命令行开关)。

#### `progress`

```ts
progress(update: ProgressUpdate): void;
```

作用域反馈:报告评估用例自己执行的长步骤(上传 Fixture、跑构建……)。短命状态,scope 固定
为 `eval.run`;只报告不断言(见 docs/feature/eval/library/context.md「向运行反馈长步骤」)。

#### `diagnostic`

```ts
diagnostic(input: DiagnosticInput): void;
```

作用域反馈:报告运行结束后仍需保留的问题(永久事件,落 attempt diagnostics)。
即使 level 为 "error" 也不自动改变 verdict——测试结论仍由断言决定。

#### `log`

```ts
log(msg: string): void;
```

`progress({ message: msg })` 的别名(调试日志),不出现在最终结果里。

#### `skip`

```ts
skip(reason: string): never;
```

立即中止本评估用例,形成 `skipped` Verdict Claim;`reason` 不能为空。

#### `check`

```ts
check(value: unknown, assertion: ValueAssertion): H;
```

对任意值跑一个 ValueAssertion,返回可链 `.gate()` / `.atLeast()` 的 AssertionHandle。
打分延迟到评估用例结束后统一 finalize,调用本身同步、不抛错——不通过只是记一条失败断言,
不会中止后续代码。要「不满足就立即中止评估用例」用 require。

#### `require`

```ts
require<T>(value: T, assertion: ValueAssertion): Promise<T>;
```

`t.check(value, assertion).gate().stopOnFailure()` 的值断言简写。立即求值；失败时保留
AssertionResult 并中止后续 test，成功时透传原 value。两种题型语义相同。

#### `group`

```ts
group<T>(title: string, fn: () => Promise<T> | T): Promise<T>;
```

把一组断言归到一个有标题的分组下(对照 vitest 的 test('title', ...))。纯组织/报告用,
不改打分:组里每条断言仍独立计分。可嵌套(标题用 › 连接)。

#### `succeeded`

```ts
succeeded(): H;
```

断言默认会话累计状态为 "completed"(跨该会话所有轮次,不止最后一轮)。

#### `parked`

```ts
parked(): H;
```

断言默认会话当前卡在 HITL 输入请求上。

#### `messageIncludes`

```ts
messageIncludes(token: string | RegExp): H;
```

断言默认会话累计的助手回复包含 token(跨该会话所有轮次,不止最后一轮)。

#### `calledTool`

```ts
calledTool(name: string, match?: ToolMatch): H;
```

断言默认会话累计调用过指定名字的工具;match 可约束入参 / 次数 / 状态。

#### `notCalledTool`

```ts
notCalledTool(name: string, match?: Omit<ToolMatch, "count">): H;
```

断言默认会话累计未调用指定工具(或未按 match 条件调用)。

#### `toolOrder`

```ts
toolOrder(names: string[]): H;
```

断言默认会话累计工具调用按给定顺序出现(允许中间夹杂其它调用)。

#### `usedNoTools`

```ts
usedNoTools(): H;
```

断言默认会话至今未调用任何工具。

#### `maxToolCalls`

```ts
maxToolCalls(max: number): H;
```

断言默认会话累计工具调用总数不超过 max。

#### `loadedSkill`

```ts
loadedSkill(skill: string): H;
```

断言默认会话累计加载过指定 skill。

#### `noFailedActions`

```ts
noFailedActions(): H;
```

断言默认会话累计没有失败的工具调用 / 命令。

#### `event`

```ts
event(type: StreamEvent["type"], opts?: { count?: number | ((n: number) => boolean) }): H;
```

断言默认会话累计出现过指定类型的事件;opts.count 可约束出现次数。

#### `notEvent`

```ts
notEvent(type: StreamEvent["type"]): H;
```

断言默认会话累计未出现指定类型的事件。

#### `calledSubagent`

```ts
calledSubagent(name: string, match?: SubagentMatch): H;
```

断言默认会话累计调用过指定名字的子 agent;match 可约束次数 / 状态 / remoteUrl。

#### `eventOrder`

```ts
eventOrder(types: StreamEvent["type"][]): H;
```

断言默认会话累计事件按给定类型顺序出现(允许中间夹杂其它事件)。

#### `eventsSatisfy`

```ts
eventsSatisfy(label: string, predicate: (events: readonly StreamEvent[]) => boolean): H;
```

用自定义谓词对默认会话累计的整段事件流断言;label 必填、进断言标题。

#### `sandbox`

```ts
readonly sandbox: EvalSandbox<H>;
```

受限 Sandbox 视图:能执行命令 / 读写文件 / 看最终 diff,不能 stop Sandbox 本身(见 EvalSandbox)。

#### `o11y`

```ts
readonly o11y: O11ySummary;
```

本 attempt 至今的行为摘要:工具调用计数、读/改的文件、shell 命令、web 请求、思考块数等。
每次读取都从已累积的标准事件流现算,多轮之间读到的是截至最近一次已返回 `send()` 的行为;
direct 与 sandbox Agent 同一行为。摘要住在宿主侧——沙箱里没有任何框架文件、也没有任何框架
环境变量,行为证据因此在被测 agent 够不着的地方。用它把「过程正确性」写进断言:

```ts
await t.send("用脚手架初始化项目");
t.check(t.o11y.shellCommands.map((c) => c.command).join("\n"), includes("create-next-app"));
t.check(t.o11y.filesRead.join("\n"), excludes(".env"));
```

token 用量、估算成本与耗时不在其中:那三样分别以结果的 `usage`、`estimatedCostUSD`、
`durationMs` 为准,同一事实不落第二份。

#### `usage`

```ts
readonly usage: Usage;
```

默认会话累计的 token 用量与估算成本。

#### `maxTokens`

```ts
maxTokens(max: number): H;
```

断言默认会话累计 token 用量不超过 max。

#### `maxCost`

```ts
maxCost(usd: number): H;
```

断言默认会话累计花费(USD)不超过 usd。

#### `judge`

```ts
readonly judge: JudgeNamespace<H>;
```

可用的 judge 命名空间(t.judge.autoevals.*)。

## Judge 断言

```ts
t.judge.autoevals.factuality(expected, { on: t.reply }).atLeast(0.8);
t.judge.autoevals.closedQA(question, { on: t.reply }).atLeast(0.7);
t.judge.autoevals.closedQA(rubric, { on: t.reply }).atLeast(0.75);
t.judge.autoevals.summarizes(sourceText, { on: t.reply }).atLeast(0.7);
```

`t.judge.autoevals` 有三个方法：`factuality`（回复与 `expected` 事实是否一致）、`closedQA`（回复是否满足给定问题或 rubric）、`summarizes`（回复是否是给定原文 `source` 的合格摘要）。三者都直接用 [autoevals](https://github.com/braintrustdata/autoevals)（braintrust）库的评分器，`{ on: t.reply }` 指定被评的文本。

## 测试集导出

```ts
export default rows.map((row) =>
  defineEval({
    description: row.task,
    async test(t) {
      await t.send(row.prompt);
    },
  }),
);
```

数组导出会生成稳定 ID：`file/0000`、`file/0001` 等。

已有稳定业务 key 时也可以默认导出 `Record<string, EvalDef>`。例如 key `15193` 在 `swelancer.eval.ts` 中生成 `swelancer/15193`。key 必须是非空单一路径片段，不能是 `.` / `..`，不能含 `/`、`\\` 或控制字符。发现顺序按 key 字典序固定。
