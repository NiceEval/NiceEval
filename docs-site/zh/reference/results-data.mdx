`Record` 是 `.niceeval/record/` 下的持久事实集，只包含完整发布的 Run。Core 保存 Run、Member 与 Attempt 的关系；业务事实保存为 owner-local 的 `RecordAttachment`。

这页说明数据边界。要在终端或浏览器中查看结果，请阅读[查看结果](/zh/tutorials/viewing-results)。要定义页面和计算，请阅读[报告 API](/zh/reference/report-components)。

## 用 AnalysisSelectionRequest 选择 Run

打开 reader 后，把纯 `AnalysisSelectionRequest` 单独传给 `selectAnalysisSample`。请求不携带路径、callback 或 I/O capability。

```ts
const sampleHandle = yield* selectAnalysisSample(reader, {
  policy: "explicit-runs/v1",
  input: {
    runIds: [runId],
  },
});

const sample = sampleHandle.sample;
```

`explicit-runs/v1` 选择精确 Run。`latest-runs/v1` 使用 Run-owned Evaluations Attachment，为目标 Experiment 选择最后完成的 Run：

```ts
const sampleHandle = yield* selectAnalysisSample(reader, {
  policy: "latest-runs/v1",
  input: {
    experimentIds: ["checkout"],
  },
});
```

两种选择都只使用传入 reader 的 frozen 视图。之后完成的 Run 不会混进既有 Sample。未完成的 Run 也不会进入候选集合。

## AnalysisSampleHandle 与 AnalysisSample

`AnalysisSampleHandle` 是 live capability，绑定创建它的 reader。它的 `.sample` 是纯 `AnalysisSample`；reader 关闭后仍可显示或收窄它，但不能从 pure Sample 恢复 Attachment I/O。

```text
AnalysisSampleHandle
  ├─ .sample → AnalysisSample（纯值）
  └─ projectAnalysisSample(...) → ProjectedSample（reader 存活时）
```

Sample 保存每个 expected slot，并保留完整分母：

| 状态 | 含义 |
| --- | --- |
| `included` | 有合法 Member，且能读取它精确引用的 Attempt。 |
| `not-recorded` | expected slot 没有 Member。 |
| `core-invalid` | Member、Attempt 或核心引用不能可靠读取。 |
| `excluded` | 调用方在既有 Sample 上排除了该项。 |

## 用 projector 读取 Attachment

`RecordAttachment projector` 固定解释一个 owner 类型和一个 Attachment family。Projection 把这个 typed view 与 Sample 对齐：

```ts
const projected = yield* projectAnalysisSample({
  sampleHandle,
  projection: attemptSlotProjection(verdictProjector),
});
```

`attemptSlotProjection` 对每个 slot 形成 entry。`attemptOriginRunProjection` 仍对每个 slot 形成 entry，但读取其 Attempt 的 origin Run Attachment。`selectedRunProjection` 对每个 selected Run 形成 entry。

前两种 entry 保留 `excluded`、`not-recorded`、`core-invalid` 与 `attachment-result`。因此十个 slot 引用同一个 Attempt 时，结果仍有十条按 slot 对齐的 entry。

## Attachment 读取状态

Attachment 读取状态是成功数据，不会改变 Sample 的 Core 状态：

| 状态 | 含义 |
| --- | --- |
| `available` | payload 已由 family 解码，并可被 projector 解释。 |
| `unavailable` | owner 没有这个 Attachment。 |
| `migration-required` | 已知旧 schema 有完整相邻 converter 链。 |
| `migration-unavailable` | 已知 schema 不能无损形成当前值。 |
| `unsupported` | family 或 schema 不被当前功能认识。 |
| `invalid` | envelope、payload、blob 或 schema decode 无效。 |

真实 I/O、权限和关闭的 reader 仍是 Effect failure。projector callback 的意外 throw 是 defect，不会伪装成 `invalid`。
