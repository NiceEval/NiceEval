结果查看从已发布 Run 开始。NiceEval 先形成 `Sample`，再只在 Page 或组合组件执行期间通过 `ctx.scope` 提供它。应用代码不能构造 Sample、打开结果目录或持有 reader。

## Sample 保留已选范围

Sample 固定本次选择的 Run、logical Slot 与分母。每个位置保留 `included`、`not-recorded`、`core-invalid` 或 `excluded` 状态。

`--run` 保留指定 Run 的完整计划范围。`project-current` 只保留仍与当前项目身份匹配的范围。两种选择都不会因为某个度量缺少输入而缩小分母。

`project-current` 的成员单位是匹配的 Run slot occurrence，不是去重后的 `(experiment, eval, ordinal)`。同一位置出现在多个匹配 Run 中时，每个 occurrence 都进入 `MetricValue.total`。重复运行或逐条 `accept` 因此可能增加分母。

Sample 只能在 `load()`、Page 或组合组件执行期间传给 Report facade。回调结束后，页面只保留已经关闭的值，不能再次读取结果。

## 用 `aggregate()` 取得 rows

`niceeval/report` 重新导出 Report 所需的 Analysis facade。`aggregate()` 返回带稳定 identity、issues、refs 和完整 `MetricValue` 的 `ClosedRows`。

```tsx
import {
  aggregate,
  defineComponent,
  Table,
} from "niceeval/report";
import { experiment, passRate } from "./quality-measures.ts";

const ResultTable = defineComponent(async (_props: {}, ctx) => {
  const rows = await aggregate(ctx.scope, {
    by: { experiment },
    values: { passRate },
  });

  return <Table rows={rows} />;
});
```

`Table` 使用 rows，图表使用 points，`Stat` 使用格式化后的完整度量。显示层可以排序、限制或过滤行，但不能用显示后的数组重算数值或减少 `MetricValue.total`。

## 取得关闭领域数据

Attempt Evidence、Observability、File Changes、Sources 和 Sandbox history 都有具名 Report facade。
它们分别使用 `toAttemptEvidence()`、`toAttemptObservability()`、`toFileChanges()`、`toSources()` 和 `toSandboxHistory()`。
这些 facade 只接收固定 Sample 和可选的 Attempt locator，并返回关闭 DomainView。

参数 Page 使用 `context.evidence(locator)` 取得目标详情的关闭 Evidence。Host 验证 locator 属于当前 Sample；它不会把路径、原始 Record payload 或任意查询能力交给页面。

## 读懂 `MetricValue`

| 字段 | 含义 |
| --- | --- |
| `value` | 当前数值；`0` 是有效值。 |
| `samples` | 实际贡献成员数。 |
| `total` | Measure 预先确定的分母。 |
| `state` 与 `issues` | 缺口、不可用或失败的原因。 |
| `refs` | 可复核的 Evidence 定位。 |

`available`、`partial`、`empty`、`unsupported` 和 `failed` 都是不同状态。不要把 `null` 当成零，也不要用只剩下的可见行数替换总分母。

例如 `formatMetricValue()` 输出的 `2 / 4 slot · partial` 表示四个已选 occurrence 中只有两个提供该 Measure 的输入。这组计数只描述覆盖率；它不是 earned score、通过率或工作完成比例。Measure 自己的 `value` 才是读数。

默认 Overview 不把这组计数重复追加到每个指标单元格。它按题型显示通过率或 earned score，并在结果不完整时用独立的 `Result coverage` 区域显示可用结果数。终端把这个区域渲染成有标题的边框；底层 `MetricValue` 的字段保持不变。
