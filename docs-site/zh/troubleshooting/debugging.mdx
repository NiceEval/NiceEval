先让 Runner、active reader 和人工编辑停止，再检查停稳的 Record。导出的 Sample 选择与 ReportInput 构造阶段也必须结束；后续 Report 执行和写站不访问 Record。随后用明确 Run 查询，不要从目录名或时间猜测目标。

```sh
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY --page attempt-01J8ZK3M6P4T7V9X2C5N8QW0RY
```

## 找不到或无法打开 Record

| 可见错误 | 含义 | 下一步 |
| --- | --- | --- |
| `record-root-missing` | 指定的 Record 根目录不存在。 | 检查项目目录或 `--record` 参数。 |
| `record-format-invalid` | 根目录不是 `niceeval.record` 格式。 | 指向正确的 `.niceeval/record/` 目录。 |
| `record-core-invalid` | 根级 `record.json` 或保留布局无效。 | 按错误中的根文件与问题修复。 |
| `CoreRead.invalid` | 已选 Run、Member 或 Attempt 的核心无效。 | 按 Sample 或 slot 中的具名问题修复。 |

不要在这些错误出现时用空值代替结果。先修复明确指出的路径或文件，再重新读取。

## Sample 中缺少预期结果

Sample 会保留 Run 的 expected-slot 分母。查看页面上每个 slot 的状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `included` | Member 和 Attempt 可读。 | 检查所需业务通道。 |
| `not-recorded` | expected slot 没有 Member。 | 检查 Invocation 是否完成，或重新运行该范围。 |
| `invalid` | Member、Attempt 或引用存在问题。 | 修复具名问题，不要把它当作未采集。 |
| `excluded` | 本次选择排除了该项。 | 检查 `--experiment`、`--eval` 或其他选择条件。 |

需要判断下一次运行会做什么时，先执行：

```sh
npx niceeval exp checkout --dry
```

输出会显示每个 slot 是执行、`carried` 还是等待明确 `accepted`，并列出采用条件不满足的原因。

## 通道显示不可用或失败

通道状态只影响请求它的页面或 Calculation：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `unavailable` | 未采集或不适用。 | 检查该运行是否应采集此通道。 |
| `unsupported` | 当前 reader 不支持该通道。 | 查看不依赖该通道的页面，或使用支持它的 reader。 |
| `invalid` | 被请求的通道文件或内容无效。 | 修复错误列出的 descriptor、文件或内容。 |
| partial | 采集或解码不完整。 | 阅读 observed、分母和问题，不要把读数视为完整。 |

`unavailable` 不表示 `unsupported`，`unsupported` 也不表示 `invalid`。被请求的 `invalid` 通道会使该请求失败；未请求的通道不会阻止无关页面或导出。

## 编辑后没有看到新值

`show` 和 `view` 会为一次调用形成固定的 `ReportInput`。如果你在 Record 停稳后修改 Verdict、Usage 或其他通道，结束当前查看命令并重新运行：

```sh
npx niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY --no-open
```

不要在编辑时同时运行 Runner 或 active reader。导出命令只在选择 Sample 和构造 ReportInput 时持有 reader；随后执行 Report 与写站不再访问 Record。

## JSON 中没有 receipt

`npx niceeval exp <experiment> --json` 只有在成功建立 Invocation 后，最后才会输出 receipt。命令在建立 Invocation 前就因输入错误退出时，没有 `runIds` 可读取。

先修正 Experiment、Eval 选择或命令参数，再重新运行。成功时，使用 receipt 的 `runIds` 运行 `show`、`view` 或 `view --out`。

## 静态报告站无法导出

`view --out` 只能导出已计划的页面、下载项和资源。被请求的无效通道、缺失资源、网络 URL、路径问题或符号链接都会让导出失败。

修复错误后重新执行导出。成功的静态目录包含 `StaticAssetManifest`，并能在断网浏览器中打开；它不读取源 Record。

更多操作步骤见[查看结果](/zh/tutorials/viewing-results)和[发布静态报告](/zh/tutorials/publish-report)。
