先用明确 Run 读取问题，不要从目录名或时间猜测目标。

```sh
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY
npx niceeval show --run 01J9ZK3M6P4T7V9X2C5N8QW0RY --page /
```

Record reader 只看已经带 `complete` 的 Run。它冻结本次可见的集合；正在写入的目录不会混进 Sample。

## 找不到或无法打开 Record

| 可见错误 | 含义 | 下一步 |
| --- | --- | --- |
| `record-root-missing` | 指定的 Record 根目录不存在。 | 检查项目目录或 `--record` 参数。 |
| `record-migration-required` | Core 是已知旧 major。 | 运行 `niceeval migrate`。 |
| `record-format-unsupported` | 当前 NiceEval 不认识该 Core major。 | 安装支持该格式的 NiceEval。 |
| `core-invalid` | 已完成 Run 的 Core 或引用不能可靠读取。 | 查看具名 issue；不要把它当成缺失结果。 |

不要用空值替代这些结果。已发布的 Record 不提供手工编辑修复路径；需要不同事实时创建新的 Run。格式迁移使用 `niceeval migrate`，未完成目录使用 `niceeval clean`。

## Sample 中缺少预期结果

Sample 会保留 Run 的 expected-slot 分母。查看页面上每个 slot 的状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `included` | Member 和 Attempt 可读。 | 检查需要的 Attachment。 |
| `not-recorded` | expected slot 没有 Member。 | 检查 Invocation 是否完成，或重新运行该范围。 |
| `core-invalid` | Member、Attempt 或引用有问题。 | 处理具名 issue，不要把它当成未采集。 |
| `excluded` | 本次选择排除了该项。 | 检查 `--experiment`、`--eval` 或其他选择条件。 |

需要判断下一次运行会做什么时，先执行：

```sh
npx niceeval exp checkout --dry
```

输出会显示每个 slot 会执行还是沿用已有 Attempt，并列出沿用条件不满足的原因。

## Attachment 显示不可用

一个 RecordAttachment 的状态只影响请求它的 Page、PageFamily、Calculation 或 Download：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `unavailable` | owner 没有这个 Attachment。 | 确认它是否适用于这次运行。 |
| `migration-required` | 有完整相邻 converter 链。 | 运行 `niceeval migrate`。 |
| `migration-unavailable` | 不能从历史事实无损形成当前值。 | 使用能读取历史值的功能，或发布新的 Run。 |
| `unsupported` | 当前功能不认识该 schema。 | 安装 owning plugin，或查看不依赖它的页面。 |
| `invalid` | envelope、payload 或 blob 无效。 | 阅读具名 issue；其它 Attachment 仍可读取。 |

未请求的坏 Attachment 不会阻止无关页面。`require-complete` consumer 显示 data-unavailable；`allow-partial` consumer 可显示完整分母与问题。

## view 没有显示新的结果

`view` 每次成功 rebuild 才发布一份新的 `ReportExecution`。如果 Report、配置、主题或 Record 的变化导致 rebuild 失败，页面继续显示 last-good execution，并显示本次问题。

先修复 rebuild problem，再等待下一次成功 rebuild。页面刷新本身不会绕过这个边界，也不会让旧 execution 重新读取 Record。

## JSON 中没有 receipt

`npx niceeval exp <experiment> --json` 只有在成功建立 Invocation 后，最后才会输出 receipt。命令在建立 Invocation 前就因输入错误退出时，没有 `runIds` 可读取。

先修正 Experiment、Eval 选择或命令参数，再重新运行。成功时，使用 receipt 的 `runIds` 运行 `show`、`view` 或 `view --out`。

## 静态报告站无法导出

`view --out` 只导出一个已经完成的 `ReportExecution`。recorded-data problem 可以进入导出站并保持可见；projector 或作者 callback defect、非法 semantic tree 和 route conflict 会让导出停止。

目标目录必须不存在。写入在最后留下 `complete` marker；失败或中断可能留下没有 marker 的目录。删除那个未完成目录后重试。

更多操作步骤见[查看结果](/zh/tutorials/viewing-results)和[发布静态报告](/zh/tutorials/publish-report)。
