NiceEval 把评估定义、运行、当前结果和报告分成清楚的职责。你定义评估用例与 Experiment，Runner 执行它们；停稳后的结果进入可编辑的 Record；查看和分享从 Record 选择 Sample，再形成 ReportInput。

```text
Eval 与 Experiment
        ↓
Runner
        ↓
Record
        ↓
Sample
        ↓
ReportInput
        ↓
show、view 或静态报告站
```

## 评估如何运行

Eval 定义任务、断言和需要的 Fixture。Experiment 选择 Eval，并声明 Agent、模型、并发、预算与其他运行条件。Adapter 连接被测系统；Sandbox 提供隔离的执行位置。

Runner 为每个选中的 Experiment 建立一个 Run。Run 列出本次应有的 slots，因此它定义结果计算的分母。每个 slot 最多采用一个 Attempt。

| Member | 含义 |
| --- | --- |
| `executed` | 本 Run 实际执行了这个 Attempt。 |
| `carried` | 规划器采用了符合条件的已有 Attempt。 |
| `accepted` | 操作者明确采用了已有 Attempt。 |

Attempt 始终保存实际执行它的 `origin`。采用操作不复制业务值；下一次读取会看到该 Attempt 通道中的当前值。

## Record 是当前数据集

Record 位于 `.niceeval/record/`。人和工具只在目录停稳时读写它。Verdict、Usage、断言与诊断等业务值都在 owner-local 的具名通道中，因此可以按通道读取，也可以在停稳后由用户编辑。

Record 不保存编辑历史。结构、路径、身份和引用校验只用于发现相互矛盾的数据。

读取时，未知或退役通道只局部成为 `unsupported`。被请求的无效通道会失败；未采集的 `unavailable` 不是 `unsupported` 或 `invalid`。采集完整度与本次解码完整度分别保留。

## Sample 决定比较范围

查看者必须明确选择 Run，或使用具名 `latest` policy。Sample 从 Run 的 expected slots 建立分母，并把每项标为 `included`、`not-recorded`、`invalid` 或 `excluded`。

这让报告能够诚实显示缺少成员、核心问题和被排除项目，而不是只统计有值的部分。更多选择规则见[查看结果](/zh/tutorials/viewing-results)。

## Report 只接收 ReportInput

Reports runtime 不读取磁盘。Sample 先只选择核心与分母，ReportPlan 再列出 facts；唯一 composition adapter 按计划形成 `ReportInput`，Report 随后只执行一次计算和页面生成。

每个页面和 Calculation 都声明自己需要的 facts 与完整度要求。partial 值显示实际观察到的数量和完整分母；`unavailable`、`unsupported` 与 `invalid` 也保持可见。

## 交付报告

`niceeval show --latest` 在终端显示一份 `ReportExecution`。`niceeval view --latest` 在本机显示同一数据流的网页。`niceeval view --latest --out <目录>` 生成自包含的静态报告站，其中包括精确内建 runtime、全部页面、宿主数据、下载项和 manifest；也可以把 `--latest` 换成一个或多个明确 `--run`。

静态报告站可离线打开。浏览器只读取导出目录，不访问网络或源 Record。发布步骤见[发布静态报告](/zh/tutorials/publish-report)。
