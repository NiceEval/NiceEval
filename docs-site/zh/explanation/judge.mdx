Judge 用独立裁判模型评估难以用精确 Match 表达的质量，例如事实一致性、摘要忠实度和说明是否清楚。
它的三个 recipe 都返回 `ScoreFact<"now">`，分数是 `[0, 1]` 内的有限数字。Judge 与其他 ScoreFact 使用同一套 Fact/use 规则。

```ts
const turn = await t.send("用两句话说明这项变更的风险。");
const quality = turn.judge.autoevals.closedQA("回答是否清楚说明了风险？");

t.assert(quality, { atLeast: 0.8, label: "风险说明质量" });
```

## 三个 recipe

| Recipe | 用途 |
|---|---|
| `closedQA(question, material)` | 判断输出是否满足一条开放式标准 |
| `factuality(reference, material)` | 判断输出是否与参考文本一致 |
| `summarizes(source, material)` | 判断输出是否忠实总结原文 |

`turn.judge.autoevals.*` 已经绑定该 Turn 的原始用户输入和助手输出，因此只传标准：

```ts
const fact = turn.judge.autoevals.factuality("退款期限是 30 天。");
t.assert(fact, { atLeast: 0.9, label: "退款事实" });
```

根级 `t.judge.autoevals.*` 用于跨轮、文件或其他自定义材料，必须显式传入两个字符串：

```ts
const notes = await t.sandbox.readText("NOTES.md");
const explanation = t.judge.autoevals.closedQA("文档是否说明了安装和回滚？", {
  input: "安装服务并在 NOTES.md 中说明安装和回滚。",
  output: notes,
});
t.assert(explanation, { atLeast: 0.8, label: "操作说明" });
```

文件先经公开 Sandbox API 读取成字符串。Judge API 不接收路径、`{ on }`、隐式最后一条输入或单次模型覆盖。`session.judge` 也不是公开 API；跨 session 的材料由作者显式组合。

## 声明 capability 和配置

只有 eval 声明了 `judge` 才能创建 Judge Fact：

```ts
export default defineEval({
  judge: true,
  async test(t) {
    const turn = await t.send("总结需求。");
    t.assert(turn.judge.autoevals.summarizes("原始需求"), { atLeast: 0.8 });
  },
});
```

- `judge: true` 声明 capability，并从 Experiment 与项目配置继承字段。
- `judge: { ... }` 同时声明 capability，并按字段覆盖 Experiment 与项目配置。
- 没有 `judge` 声明时创建 Judge Fact 会立即报告作者错误。

```ts
// niceeval.config.ts
export default defineConfig({
  judge: {
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
  },
});
```

字段优先级是 Eval 对象、Experiment、项目配置。未指定时，`baseUrl` 为 OpenAI 兼容端点，`apiKeyEnv` 为 `OPENAI_API_KEY`，`timeoutMs` 为 180000 毫秒。
运行器把解析结果冻结一次，并将同一份配置用于指纹、预检和实际 evaluator。

## 使用 Judge ScoreFact

Fact 只在消费时求值。选择用途时写在 `t` 上：

```ts
const quality = turn.judge.autoevals.closedQA("回答是否准确且完整？");

t.assert(quality, { atLeast: 0.8, label: "回答质量" });
await t.require(quality, { atLeast: 0.8, label: "下一步前的质量检查" });
// defineScoreEval 中：t.score("回答质量", quality, { max: 20 });
```

`assert` 记录 verdict use 并继续执行。`require` 在当前位置立即开始求值，低于阈值、不可用或 evaluator error 时停止依赖该结果的后续代码。`score` 只在 `defineScoreEval` 中可用，按归一化分数比例计分。

同一个 Fact 最多有一个 verdict use 和一个 score use，evaluator 只运行一次。未被 `assert`、`require` 或 `score` 消费的 Judge Fact 是作者错误，不会请求模型。一个 Attempt 中的 Judge evaluator 按声明顺序串行执行。

## 配置、预检与失败

没有模型或 key 时，NiceEval 不发网络预检。消费后的 Judge Fact 为 `unavailable`，并保留 `judge-model-unresolved` 或 `judge-key-unresolved` 原因；通过制 Attempt 因此为 `errored`。

模型和 key 都存在时，运行器在派发前检查端点。真实预检失败是 setup error，不伪造 Judge Fact。模型请求开始后发生的传输失败是普通 `unavailable` Fact。无效响应、非有限分数和区间外分数是 evaluator error，NiceEval 不把它们裁剪成可用分数。

Judge 给出的理由写入通用 `explanation`。`evidence` 只保存裁剪、脱敏后的判分材料。

## 结果读取

记录使用 schema 17，直接保存 `factResults` 和 `factUses`。`niceeval show`、网页报告和失败反馈从同一张图生成摘要：失败或不可用 use 优先显示，成功的已消费 ScoreFact 显示归一化分数。

成功、已消费且没有 score use 的 ScoreFact 各计一次 `examScore`。有 score use 的 Fact 只进入 `totalScore`。Judge 没有专用的断言结果或展示分支。
