Judge 用独立裁判模型评估难以用精确 Match 表达的质量，例如事实一致性、摘要忠实度和说明是否清楚。
它的三个 recipe 都直接登记 measurement Assertion，分数是 `[0, 1]` 内的有限数字。调用即登记；handle 只配置同一条 Assertion。

```ts
const turn = await t.send("用两句话说明这项变更的风险。");
turn.judge.autoevals.closedQA("回答是否清楚说明了风险？")
  .atLeast(0.8)
  .label("风险说明质量");
```

## 三个 recipe

| Recipe | 用途 |
|---|---|
| `closedQA(question, material)` | 判断输出是否满足一条开放式标准 |
| `factuality(reference, material)` | 判断输出是否与参考文本一致 |
| `summarizes(source, material)` | 判断输出是否忠实总结原文 |

`turn.judge.autoevals.*` 已经绑定该 Turn 的原始用户输入和助手输出，因此只传标准：

```ts
turn.judge.autoevals.factuality("退款期限是 30 天。")
  .atLeast(0.9)
  .label("退款事实");
```

根级 `t.judge.autoevals.*` 用于跨轮、文件或其他自定义材料，必须显式传入两个字符串：

```ts
const notes = await t.sandbox.readText("NOTES.md");
t.judge.autoevals.closedQA("文档是否说明了安装和回滚？", {
  input: "安装服务并在 NOTES.md 中说明安装和回滚。",
  output: notes,
}).atLeast(0.8).label("操作说明");
```

文件先经公开 Sandbox API 读取成字符串。Judge API 不接收路径、`{ on }`、隐式最后一条输入或单次模型覆盖。`session.judge` 也不是公开 API；跨 session 的材料由作者显式组合。

## 声明 capability 和配置

只有 eval 声明了 `judge` 才能创建 Judge Assertion：

```ts
export default defineEval({
  judge: true,
  async test(t) {
    const turn = await t.send("总结需求。");
    turn.judge.autoevals.summarizes("原始需求").atLeast(0.8).label("总结质量");
  },
});
```

- `judge: true` 声明 capability，并从 Experiment 与项目配置继承字段。
- `judge: { ... }` 同时声明 capability，并按字段覆盖 Experiment 与项目配置。
- 没有 `judge` 声明时创建 Judge Assertion 会立即报告作者错误。

```ts
// niceeval.config.ts
export default defineConfig({
  judge: {
    model: "judge-model",
    baseUrl: "https://gateway.example.com/v1",
    apiKeyEnv: "JUDGE_GATEWAY_KEY",
    timeoutMs: 180_000,
  },
});
```

字段优先级是 Eval 对象、Experiment、项目配置。未指定时，`baseUrl` 为 OpenAI 兼容端点，`apiKeyEnv` 为 `OPENAI_API_KEY`，`timeoutMs` 为 180000 毫秒。
运行器把解析结果冻结一次，并将同一份配置用于指纹、预检和实际 evaluator。

## 阈值与分数

Pass Eval 必须用 `.atLeast(n)` 把 Judge measurement 封口成 Boolean condition。measurement 低于阈值时 Attempt 为 `failed`。

```ts
const quality = turn.judge.autoevals.closedQA("回答是否准确且完整？")
  .atLeast(0.8)
  .label("回答质量");
await quality.orStop();
```

`.orStop()` 是同一 handle 的 async barrier。低于阈值时它停止当前 continuation；正常 stop 后 Attempt 仍得到 `failed` Verdict。

Score Eval 直接调用 `.score(n)`：measurement `m` 贡献 `m * n`。`.atLeast(n)` 只增加局部 condition，可以单独配置，也可以与 `.score(n)` 同一条 Assertion 共存。

```ts
turn.judge.autoevals.closedQA("回答质量如何？").score(20).atLeast(0.5);
```

两种配置都只运行一次 Judge evaluator，写一条 AssertionResult。没有配置 `.score()` 的 Judge Assertion 默认只保存 evaluation。

## 配置、预检与失败

没有模型或 key 时，NiceEval 不发网络预检。Judge Assertion 为 `unavailable`，并保留 `judge-model-unresolved` 或 `judge-key-unresolved` 原因。配置了 score 或 `.orStop()` 的 Assertion 不可用时，Score grading 不可排名；Pass Attempt 为 `errored`。

模型和 key 都存在时，运行器在派发前检查端点。真实预检失败是 setup error，不伪造 AssertionResult。模型请求开始后发生的传输失败是普通 `unavailable`。无效响应、非有限分数和区间外分数是 `errored`，NiceEval 不把它们裁剪成可用分数。

Judge 给出的理由写入通用 `explanation`。`evidence` 只保存裁剪、脱敏后的判分材料。

## 结果读取

`niceeval show`、网页报告和失败反馈从同一份已封口的断言结果生成摘要：失败或不可用项优先显示，已配置的 measurement 显示实际值与 required threshold。Judge 没有专用的断言结果或展示分支。
