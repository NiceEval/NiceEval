NiceEval 的评估单位是 Assertion。作者调用 `t.check(value, match)`、`turn.succeeded()`、`calledTool(...)` 或 Judge recipe 时，NiceEval 立即登记一条 Assertion；不存在先创建中间对象、再由另一条 API 消费它的流程。返回的 handle 只配置这一条 entry。

```ts
import { includes } from "niceeval/expect";

t.check(turn.message, includes("完成")).label("回复说明完成");
turn.succeeded().label("Turn 完成");
turn.calledTool("get_weather", { count: 1 }).label("查询天气");
turn.judge.autoevals.closedQA("回答是否具体且礼貌？").atLeast(0.8).label("回答质量");
```

每条 Assertion 的 `key` 与 `label` 最多各配置一次。重复配置即使写入同一个值也是作者错误。

## Match 只比较值

`niceeval/expect` 导出纯 Match factory。Match 是可复用、不可变、确定性且无副作用的比较规则；它没有身份、调用位置、阈值、分值或控制流。`t.check(value, match)` 严格接收两个参数，在调用时读取 `value` 并登记 Assertion。

```ts
import { equals, includes, matches, satisfies } from "niceeval/expect";

t.check(turn.message, includes("订单已确认"));
t.check(turn.data, equals({ status: "refund", amount: 42 }));
t.check(turn.data, matches(OrderSchema));
t.check(turn.message.length, satisfies("回复不是空文本", (length) => length > 0));
```

## 作用域 Assertion

作用域方法在调用时直接登记 Boolean Assertion。接收者决定证据范围：`turn.*` 只看该不可变 Turn，`session.*` 看该 Session 调用点之前的前缀，根 `t.*` 看调用点时所有已启动 Session 的 vector cut。

```ts
const turn = await t.send("运行检查并修复问题。");
turn.succeeded().label("Turn 成功");
turn.calledTool("shell").label("使用 shell");
turn.calledTool("read_file", { count: 2 }).label("读取两次");
```

`calledTool(name, options)` 的选项包括 `input` 与 `count`。输入使用递归 JSON 匹配：对象部分匹配、数组逐项匹配，任意层可用 `RegExp` 或动态谓词。

## 两种 Eval

`defineEval` 创建 Pass Eval。Boolean `matched` 进入 Attempt Verdict；`mismatched` 使最终 Verdict 为 `failed`，但不会阻止后续检查继续登记。连续 evaluator 与 Judge recipe 给出 `[0,1]` measurement；Pass Eval 必须用 `.atLeast(n)` 把它封口成 Boolean condition，未设 threshold 的 measurement 是作者错误。

```ts
turn.judge.autoevals.closedQA("回答是否给出可执行步骤？")
  .atLeast(0.8)
  .label("步骤可执行");
```

`defineScoreEval` 创建 Score Eval。它只有累计 `score`，没有 Attempt Verdict、总分、百分比或另一种数值单位。Assertion 默认只保存 evaluation，不计分；用 `.score(n)` 才让已有 Assertion 贡献 score。Boolean matched 贡献 `n`，mismatched 贡献 `0`；measurement `m` 贡献 `m * n`。`t.score(n)` 直接登记 contribution，返回的 handle 只能配置 `key` 与 `label`。

```ts
turn.calledTool("search");                       // 只保存 evaluation
turn.calledTool("search").score(2);              // matched 时 +2
turn.judge.autoevals.closedQA("回答完整").score(5); // measurement 0.8 时 +4
t.score(5);                                      // 直接 +5
```

Score Eval 的 measurement 不必 threshold 就能封口。`.atLeast(n)` 只增加局部 `met` / `below` condition，不改变 contribution。没有 `.score()` 的 Assertion 不显示 `+0`；正常没有计分项的 Score Eval 得到正式且可排名的 `score: 0`。

## 控制流

`.orStop()` 是同一 Assertion handle 的 async barrier，必须 `await`。Boolean mismatch，或 thresholded measurement below 时，它设置 authoring stop latch 并拒绝私有控制信号。它只停止当前被 await 的 continuation，不撤销普通 JavaScript 副作用，也不取消此前启动的并发任务；尚未执行的源码不生成结果。

```ts
const turn = await t.send("搜索资料并说明结论。");
await turn.succeeded().orStop();
const search = await t.check(turn.message, includes("结论")).orStop();
```

正常 stop 后，Pass Eval 仍按触发 Assertion 得到 `failed` Verdict；Score Eval 仍是 `scored`，保留正式 score 和 stop cause，因此可以排名。

## Judge

Judge recipe 调用时直接登记 measurement Assertion。Pass Eval 对同一 handle 用 `.atLeast(n)`，Score Eval 用 `.score(n)`；两种配置都只运行一次 Judge evaluator。材料、配置和失败语义见 [Judge](/zh/explanation/judge)。

## 不可用与读取

缺少 evidence 不能伪装成普通 mismatch。`unavailable` 与 `errored` 保留原因与脱敏 evidence。

AssertionResult 也不是只保存成功或失败。每条结果都保存 Assertion identity、subject 或 scope snapshot ref、明确版本的 evaluator、完整安全 config、evaluation、policy 和 projection。它还保存 versioned evidence，其中包含最小判定见证、coverage、结构化 payload、refs，以及 redacted / truncated / unavailable limitations。

这组数据称为 **Assertion 可解释闭包**。它让 `show`、`view`、JSON、export 与 source 可以离线重新组织文案和界面，不必重新运行 Match 或调用 Judge。`expected` / `received` 是读取面从结构化数据生成的文案，不是 Record 中仅存的两个字符串。

可解释闭包不要求把完整 stdout、events 或源码全部内联进 AssertionResult。Assertion 只规定自己必须产出什么结构化数据和证据引用；Record 决定这些数据怎样落盘。判定依赖的最小结构化依据称为**判定见证**。如果安全持久化后连这份最小依据都无法保留，结果必须是 `unavailable`，不能只留下 `matched` 或 `mismatched`。
