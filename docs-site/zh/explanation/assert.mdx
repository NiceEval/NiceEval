NiceEval 把“观察到什么”和“如何使用观察”分开。Match 只比较一个候选值；`t.check(...)`、Turn、Session 和 Sandbox producer 创建 Fact；`t.assert(...)`、`t.require(...)` 与 `t.score(...)` 才让 Fact 影响结果。

```ts
import { includes, similarity } from "niceeval/expect";

const containsResult = t.check(turn.message, includes("完成"));
const answerQuality = t.check(turn.message, similarity(expected));

t.assert(containsResult, { label: "回复说明完成" });
t.assert(answerQuality, { atLeast: 0.8, label: "回复质量" });
```

创建 Fact 不会隐式改变 Attempt。每条需要检查的规则都在消费位置明确登记，因此本地、CI 和重跑使用同一套判定。

## 三种 Fact use

| 入口 | 用途 | 控制流 |
|---|---|---|
| `t.assert(fact)` | Boolean Fact 的 verdict use | 继续执行，收集独立结果 |
| `t.assert(scoreFact, { atLeast })` | ScoreFact 的阈值 verdict use | 继续执行 |
| `await t.require(fact, options)` | 即时 Fact 的 verdict use，并取得通过结果 | 未通过或不可用时停止依赖路径 |

`defineScoreEval` 还提供 `t.score(label, fact, { max })`。它登记 score use：Boolean Fact 通过获得 `max`，ScoreFact 按归一化分数比例获得分数。

一个 Fact 最多有一个 verdict use 和一个 score use。两种用途共享一次 evaluator 求值。无人消费的 Fact 是作者错误；它不会在后台自行运行。

## 通过制与计分制终态

通过制按已消费 Fact/use 折叠：

```text
任一已消费 Fact 或 verdict use unavailable / errored  → errored
任一 verdict use failed                               → failed
显式 t.skip(reason)                                   → skipped
否则                                                   → passed
```

计分制保留更细的 score terminal。成功为 `scored`，失败的 verdict use 为 `invalid`，不可用为 `unavailable`，evaluator 或执行错误为 `errored`。只有 `scored` 才有可计入的 credit；不可用和错误不伪装为 0 分。

## 值 Fact

`niceeval/expect` 导出纯 Match factory。Boolean Match 产生通过、失败或证据不可用；Score Match 产生 `[0, 1]` 内的连续分数。

```ts
import { equals, includes, matches, satisfies, similarity } from "niceeval/expect";

t.assert(t.check(turn.message, includes("订单已确认")));
t.assert(t.check(turn.data, equals({ status: "refund", amount: 42 })));
t.assert(t.check(turn.data, matches(OrderSchema)));
t.assert(t.check(turn.message.length, satisfies("回复不是空文本", (length) => length > 0)));

const quality = t.check(turn.message, similarity("期望答案"));
t.assert(quality, { atLeast: 0.8 });
```

Match 不携带阈值、分值、可选性或控制流。Score Match 返回无效结构、非有限数或区间外数值时，Fact 为 evaluator error，不会被裁剪。

## 作用域 Fact

接收者决定证据范围。`turn.*` 只看该 Turn，`session.*` 看那条 session 的前缀，根 `t.*` 在 `test(t)` 返回后看整个 Attempt。

```ts
import { toolMatch } from "niceeval/expect";

const turn = await t.send("运行检查并修复问题。");
t.assert(turn.succeeded(), { label: "Turn 成功" });
t.assert(turn.calledTool(toolMatch("shell")), { label: "使用 shell" });
t.assert(turn.calledTool(toolMatch("read_file"), { count: 2 }), { label: "读取两次" });
```

否定检查和精确次数依赖完整证据。证据不足时，Fact 为 `unavailable`；普通消费会让 Attempt `errored`，而不是把空事件当作通过。

## Sandbox Fact 与真实命令

最终文件变化是 `phase: "final"` Fact。Sandbox 命令先返回普通结果，再用 `t.check` 生成即时 Fact：

```ts
import { commandSucceeded, includes } from "niceeval/expect";

t.assert(t.sandbox.fileChanged("src/Button.tsx"), { label: "修改 Button" });
t.assert(t.check(t.sandbox.file("src/Button.tsx"), includes("export function Button")));

const testResult = await t.sandbox.runCommand("pnpm", ["test"]);
t.assert(t.check(testResult, commandSucceeded()), { label: "项目测试通过" });
```

文件缺失是确定失败；权限、传输或超时导致的证据问题是 `unavailable`，不会把空字符串当内容继续匹配。

## 计分 Fact

```ts
const changed = t.sandbox.fileChanged("experiments/local.ts");
t.assert(changed, { label: "配置有效" });
t.score("配置修复", changed, { max: 2 });

const quality = t.check(turn.message, similarity(expectedAnswer));
t.score("回答质量", quality, { max: 20 });
t.score("代码精简", { earned: tierPoints });
return t.finishScore();
```

成功、已消费且没有 score use 的 ScoreFact 可进入 `examScore`。有 score use 的同一 Fact 只进入 `totalScore`。这个规则也适用于 Judge。

## Judge 是普通 ScoreFact

Judge recipe 返回 ScoreFact，因此使用方式与其他连续 Fact 相同：

```ts
const quality = turn.judge.autoevals.closedQA("回答是否具体且礼貌？");
t.assert(quality, { atLeast: 0.7, label: "回答质量" });
```

Judge 没有链式阈值、可选消费、观察消费或计分 API。材料、配置和失败语义见 [Judge](/zh/explanation/judge)。
