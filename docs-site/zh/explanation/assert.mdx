NiceEval 把“观察到什么”与“怎样使用这项观察”分开。Match 只比较一个候选值；`t.check(...)`、Turn、Session 与 Sandbox API 生成 Fact；`t.assert(...)`、`t.require(...)` 和计分制的 `t.score(...)` 再决定 Fact 用于判定还是计分。

```ts
import { includes, similarity } from "niceeval/expect";

const containsResult = t.check(turn.message, includes("完成"));
const answerQuality = t.check(turn.message, similarity(expected));

t.assert(containsResult, { label: "回复说明已经完成" });
t.assert(answerQuality, { atLeast: 0.8, label: "回复接近期望内容" });
```

创建 Fact 不会隐式改变 Attempt。每项必须成立的条件都要在消费位置明确登记，因此同一个评估用例在本地、CI 和重跑时不会切换判定标准。

## 三个普通 Fact 消费入口

| 入口 | 用途 | 控制流 |
|---|---|---|
| `t.assert(fact)` | 把 Boolean Fact 登记为硬要求 | 继续执行，收集其它独立事实 |
| `t.assert(scoreFact, { atLeast })` | 把 Score Fact 登记为带阈值的硬要求 | 继续执行 |
| `await t.require(fact)` | 登记硬要求，并取得通过后的收窄值 | 未通过或无法求值时结束依赖路径 |

`t.require(value, match)` 是立即值检查的简写：

```ts
const config = await t.require(
  JSON.parse(await t.sandbox.readText("config.json")),
  matches(ConfigSchema),
  { label: "配置符合 schema" },
);
```

`require` 只接受即时的 `phase: "now"` Fact。最终 diff 与整个 Attempt 的聚合事实要等 `test(t)` 返回后才能求值，因此它们使用 `t.assert(...)`，不能拿来控制中途路径。

## 判定结果

通过制 `defineEval` 按以下顺序形成终态：

```text
执行、作者或 evaluator 错误，或必需证据无法取得 → errored
任一 assert / require 要求失败，或 Judge gate 失败 → failed
显式 t.skip(reason)                                  → skipped
否则                                                 → passed
```

`errored` 表示这次执行无法形成可信判断，不伪装成 agent 没做到。多个独立 `t.assert(...)` 会全部求值，报告可一次显示完整失败信息。

## 值 Match 先生成 Fact

`niceeval/expect` 导出纯 Match factory。Boolean Match 产生通过、失败或证据不可用三态；Score Match 产生 `[0, 1]` 的连续分数或证据不可用。

```ts
import {
  equals,
  includes,
  matches,
  satisfies,
  similarity,
} from "niceeval/expect";

t.assert(t.check(turn.message, includes("订单已确认")));
t.assert(t.check(turn.data, equals({ status: "refund", amount: 42 })));
t.assert(t.check(turn.data, matches(OrderSchema)));
t.assert(t.check(turn.message.length, satisfies("回复不是空文本", (length) => length > 0)));

const quality = t.check(turn.message, similarity("期望答案"));
t.assert(quality, { atLeast: 0.8 });
```

Match 本身不携带判定或计分策略。同一个 Match 可以复用到多个候选值，不会因为某个调用点的用途改变自身。

## Turn、Session 与 Attempt Fact

接收者决定事实范围。`turn.*` 只看这一轮，`session.*` 看一条 Session 的前缀，`t.*` 在 `test(t)` 返回后看整个 Attempt。

```ts
import { commandMatch, eventMatch, toolMatch } from "niceeval/expect";

const turn = await t.send("运行检查并修复问题。");

t.assert(turn.succeeded());
t.assert(turn.calledTool(toolMatch("shell", { status: "completed" })));
t.assert(turn.event(eventMatch("message", { role: "assistant" })));

t.assert(t.calledTool(commandMatch("niceeval", {
  argsStart: ["show"],
  status: "completed",
})));
```

次数写在 Fact producer 的 `{ count }` 里，不写成阈值：

```ts
t.assert(turn.calledTool(toolMatch("read_file"), { count: 2 }));
```

`commandMatch(...)` 只读取 Adapter 提供的 logical command projection。证据不完整或命令投影 opaque 时，没找到匹配不能冒充确定失败。

## Sandbox Fact 与真实命令

最终文件变化是 `phase: "final"` Fact。Sandbox 命令先返回普通结果，再由值 Match 生成即时 Fact。

```ts
import { commandSucceeded, includes } from "niceeval/expect";

t.assert(t.sandbox.fileChanged("src/Button.tsx"));
t.assert(t.sandbox.fileDeleted("src/old.ts"));
t.assert(t.check(
  t.sandbox.file("src/Button.tsx"),
  includes("export function Button"),
));

const testResult = await t.sandbox.runCommand("pnpm", ["test"]);
t.assert(t.check(testResult, commandSucceeded()), { label: "项目测试通过" });
```

一个延迟文件 EvidenceSource 在一项 Fact 内只读取一次。文件缺失是确定失败；权限、传输或超时问题是证据不可用，不能把空字符串当文件内容继续匹配。

## 效率与成本

用量值也先变成 Fact，再明确登记预算要求：

```ts
const outputBudget = t.check(
  t.usage.outputTokens,
  satisfies("有用量且 output tokens 不超过 10000", (tokens) =>
    typeof tokens === "number" && tokens <= 10_000
  ),
);
t.assert(outputBudget, { label: "输出 token 预算" });
```

这项 Match 同时要求用量存在，因此缺失不会被当成 0。只有 core 标记的 usage Fact 才能交给 `t.assertIfCovered(...)` 表达“Agent 声明不支持时不适用”。

## 计分制复用同一个 Fact

`defineScoreEval` 的 `t.score(...)` 把 Fact 用于分数。一个 Fact 可以同时用于判定和计分，而且 evaluator 只运行一次。

```ts
const changed = t.sandbox.fileChanged("experiments/local.ts");
t.assert(changed, { label: "runtime 配置有效" });
t.score("runtime 配置修复", changed, { max: 2 });

const quality = t.check(turn.message, similarity(expectedAnswer));
t.score("回答质量", quality, { max: 20 });

t.score("代码精简", { earned: tierPoints });
return t.finishScore();
```

Boolean Fact 通过挣得 `max`，失败挣 0；Score Fact 按 `max × normalizedScore` 计分。作者直接给分使用 `{ earned }`，正常路径最后返回 `t.finishScore()`。

## 自定义 Match

Boolean Match 用 `defineValueMatch`，连续分数 Match 用 `defineScoreMatch`：

```ts
import { defineScoreMatch, defineValueMatch } from "niceeval/expect";

const jsonValid = () => defineValueMatch<string>({
  name: "valid JSON",
  evaluate(value) {
    try {
      JSON.parse(value);
      return true;
    } catch {
      return false;
    }
  },
});

const concise = () => defineScoreMatch<string>({
  name: "concise answer",
  score(value) {
    return Math.max(0, 1 - value.length / 1000);
  },
});

t.assert(t.check(turn.message, jsonValid()));
t.assert(t.check(turn.message, concise()), { atLeast: 0.7 });
```

自定义 Match 只实现单个候选值的比较。读取文件、扫描事件、判断证据完整度以及决定 Verdict 仍由对应的 Fact producer 与 consumer 负责。

## Judge 保留兼容句柄

Judge 尚未迁移成普通 Fact producer，因此继续支持 `.atLeast(...)`、`.gate(...)`、`.optional()`、`.stopOnFailure()`，以及计分制的 `.points(...)`。这些链式方法不属于普通 Match 或 Fact。

```ts
t.judge.autoevals.closedQA("回答是否具体、礼貌?").atLeast(0.7);
t.judge.autoevals.closedQA("不得编造账户信息").gate(0.9);
```
