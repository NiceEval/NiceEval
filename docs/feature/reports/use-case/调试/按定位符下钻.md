# `@locator`：从默认报告下钻到一次 Attempt 的证据

## 解决什么问题

默认报告的一行失败摘要足够分诊，但不足以定位断言、执行、耗时或文件差异。`@<locator>` 在固定 Graph 中识别完整 AttemptRef；后续命令用它选择同一次 Attempt 的内建 target。

## 全流程

1. 从默认报告复制 locator：

   ```text
   ✗ 失败    memory/swelancer-manager-proposals
     └─ @01J4C6N8PQRS2TVWXY9ZABCD3E    assertion unavailable / limited / failed
   ```

2. 打开诊断首页：

   ```bash
   niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E
   ```

   show 生成含该成员的固定 Sample，标准 Plan 列出详情 Projector 和 Calculation。详情按 identity、读数、unavailable 原因、facts、notice、源码、执行、时间线和 diff 的稳定顺序显示。

3. 只在需要某个证据切面时选择相应 target：

   - `niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E --source` —— 已计划的源码或断言投影。
   - `niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E --execution` —— 已计划的对话与工具调用投影。
   - `niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E --timing` —— 已计划的生命周期阶段与 spans。
   - `niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E --diff` —— 已计划的文件差异投影。

   每种 target 均通过 executor 形成 ReportData；text 只显示既有数据。

## 边界

- locator 必须带 `@`，不是数组下标或文件路径；同一 locator 在不同 Graph 或 adopted revision 中不是同一 identity。
- flag 选择内建 target，不会绕过 Sample、plan 或 Projector 边界。
- `--diff=<path>`、`--timing=<mode>` 等参数必须符合对应 target 的 schema；无效输入非零退出。
- 源 Record 中已有却不能复制或验证的依据使导出失败，不能显示为普通 unavailable。
