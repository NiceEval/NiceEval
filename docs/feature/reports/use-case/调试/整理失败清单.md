# 从失败清单到可修复任务

## 解决什么问题

一批 Eval 跑完后,你要的不是又一张总分图,而是「现在先修哪些,每条的证据在哪里」。

## 全流程

1. 不写报告文件就能开台:`niceeval view --report failures`(终端 `niceeval show --report failures`)
   装载[内建失败视图](../../library/built-in.md#failures-与-stability),内容就是下面这套装配。
2. 自定义清单时在 plan 中声明失败 summary data，再用 `FailureList` 显示需要处理的 Attempt、全部 unavailable causes 和 locator。
3. 需要把整批交给 coding agent 时加 `SampleFixPrompt`;只修一条时复制 locator 跑 `niceeval show @<locator>`。
4. locator 打开由固定 Sample 枚举的 `AttemptDetails` 参数化 instance，再按已计划的判定、源码、对话、时间树、trace 和 diff 定位。
5. 修复并重跑后回到同一清单;不用报告保存任务状态。

可复制的报告树见[修失败示例](../../library/examples.md#失败清单),locator 证据路径见[下钻用例](../调试/按定位符下钻.md)。

## 边界

- 想比较 Experiment 整体水平时回内建首页的实验列表与散点,不要从失败列表反推总体读数。
- 自定义清单在 plan 中声明失败 summary data；要回答「有哪些失败」优先用已组装好的 `FailureList`。
