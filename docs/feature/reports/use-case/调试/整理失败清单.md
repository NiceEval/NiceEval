# 从失败清单到可修复任务

## 解决什么问题

一批 Eval 跑完后,你要的不是又一张总分图,而是「现在先修哪些,每条的证据在哪里」。

## 全流程

1. 用 `FailureList` 只投影需要处理的 Attempt,保留主失败原因和 locator。
2. 需要把整批交给 coding agent 时加 `SampleFixPrompt`;只修一条时复制 locator 跑 `niceeval show @<locator>`。
3. locator 打开 `AttemptDetail` 参数化 page,再按判定、源码、对话、时间树、trace 和 diff 定位。
4. 修复并重跑后回到同一清单;不用报告保存任务状态。

可复制的报告树见[修失败示例](../../library/examples.md#修失败待处理失败清单),locator 证据路径见[下钻用例](../调试/按定位符下钻.md)。

## 边界

- 想比较 Experiment 整体水平时用 `SampleOverview`,不要从失败列表反推总体读数。
- `sources.entity.attempts` 适合自定义子集;要回答「现在有哪些失败」优先用已组装好的 `FailureList`。
