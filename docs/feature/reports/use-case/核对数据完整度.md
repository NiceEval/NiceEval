# 核对数据完整度

团队要知道报告是否基于完整的命令检查数据，而不是把有值的 Attempt 当成全部 Attempt。

## 选择固定范围

```sh
niceeval show --run <run-id> --report ./reports/command-checks.ts --page /
```

--run 固定一个 Run 的 Sample。Analysis 在读取可用值前固定该度量的 expected member，因此 total 不会因数据缺口而改变。

## 显示完整度

```tsx
import { aggregate, defineReport, Grid, Stat, Table } from "niceeval/report";
import { commandCheckCount } from "niceeval/analysis";

export default defineReport({
  title: "Command checks",
  pages: [
    {
      id: "coverage",
      path: "/",
      title: "Coverage",
      render: async sample => {
        const [summary] = await aggregate(sample, {
          by: {},
          values: { commandCheckCount },
        });

        return (
          <Grid>
            <Stat label="Command checks" value={summary.commandCheckCount} />
            <Table rows={[summary]} />
          </Grid>
        );
      },
    },
  ],
});
```

by: {} 对同一个固定总体产生恰好一行。假设 100 个成员应参加检查，只有 20 个成员贡献数值：

```text
value:   20
samples: 20
total:   100
state:   partial
```

页面写 20 / 100 · partial。Stat 和 Table 都接收同一个完整 MetricValue，因此不会把 20 改写成 20 / 20。

## 分清状态

| state | 页面必须说明什么 |
|---|---|
| available | 全部分母成员都贡献了值。 |
| partial | 已贡献数、既定分母和每个缺口 issue。 |
| empty | 输入完整但领域结果合法为空，不等于缺失。 |
| unsupported | 当前 host 不能提供所需输入。 |
| failed | 输入读取或归并失败，以及可复核 refs。 |

状态不依赖组件。任何使用 commandCheckCount 的 Page、文字面、网页面和静态站都显示相同的 samples、total、issues 和 refs。

## 局部影响

问题只影响使用该度量的单元。质量页可以只读取 passRate，并在命令检查数据 unavailable 时继续呈现。反过来，Report 不能通过隐藏 coverage Page、过滤 rows 或把 null 设为零来消除问题面。

如果 Page 自己的 load、render 或组件失败，Host 把它记为 execution problem。它与 MetricValue 的 partial、unsupported 或 failed 不同：show 和 view 隔离失败 Page，static export 则拒绝发布完整站点。
