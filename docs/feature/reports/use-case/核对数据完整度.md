# 核对数据完整度

自动化需要先发现有哪些固定问题可问，再按小而稳定的 machine document 检查结果是否完整。

```sh
niceeval query discover
niceeval query discover --request operation.json
niceeval query run --request summary.json
niceeval query explain --request comparison.json
```

Discovery 先给出 compact bootstrap；只在选择一个 operation 后返回其 schema、合法 selector 和最小 follow-up request。列表与重 payload 结果使用 bounded domain page；继续读取时原样传回 opaque continuation token。

每个 result 明确保留 denominator、missing、issues、basis 与 Evidence。token 不泄露或接受 DB cursor、rowid、文件位置或调用方指定的 page size。
`run.summary` 同时交付已封口的 usage totals；conversation 子通道的 limitation
不得把完整 usage 改写为 partial 或 missing。

Record 内容、sealed cutoff、request 或 operation behavior 改变时，命令返回完整 restart correction。它不拼接不同 frozen view 的页。

`query explain` 让调用方在读重 payload 前审计会读取的 handle、selection、comparison mode 与 fact kinds。它不能成为任意存储查询接口。
