# 从终端做跨条件归因

## 解决什么问题

同批 Eval 跑了 baseline 与一个或多个处理条件时，你要回答三层递进的问题：整体差多少、哪些题翻转、以及翻转的 Attempt 中发生了什么。全程使用 `niceeval show` 的公开 target，不翻存储布局。

## 全流程

1. 用多个 `--exp` 形成固定 Sample selection：

   ```bash
   niceeval show --exp memory/claude-baseline --exp memory/claude-mempal
   ```

   compare target 的 plan 声明成对 Calculation，首个条件是 baseline。矩阵显示每格的 EvidenceValue、coverage 与 refs；available 显示 verification，unavailable 显示 causes / basedOn，不把缺口压成零。

2. 通过计划好的 Experiment provenance 核对 agent、model、flags 与 labels。需要运行事实时，打开对应 Attempt 的详情 target；facts 由 Projector 读取，不由终端字段推断。
3. 用 `--usage` 选择 usage target，逐题比较 uncached input、cache read、输出、请求和成本。聚合的 unavailable policy 和不完整 coverage 由该 target 明确显示。
4. 对翻转的成员复制完整 locator，并选择 `--source`、`--execution`、`--timing` 或 `--diff`：

   ```bash
   niceeval show @01J4C6N8PQRS2TVWXY9ZABCD3E --execution
   ```

   每个 flag 都形成自己的固定 Sample、ReportPlan 和数据入口；renderer 不直接扫描 event 或文件。

5. 需要把历史波动与条件差异分开时，使用 `niceeval show --stats` 或 `--history`，并明确提供历史 Sample 或 `unionSamples()` 输入。
6. 要交给脚本或后续 Agent 时，用 `--json` 读取同一 target 的结构化 ReportData；要交付自定义报告时，用 `exportReport()`。

## 边界

- 单点翻转先看固定成员集合中的整体位移与 coverage；不要由一个 locator 推断条件总体。
- 可分享的网页或静态交付使用报告定义的 plan 与 `view` / `exportReport()`；终端 target 不需要复制另一套 Calculation。
- 跨 Record 只能先合并 materialized Sample，并显式选择 conflict policy。
