# 分数低时区分任务失败与执行失败

## 解决什么问题

端到端通过率下降,但可能是 Agent 做错,也可能是沙箱、限流或 Adapter 没形成可信判定。

## 全流程

1. 用 `aggregate()` 并排 `passRate`、`taskPassRate` 和 `executionReliability`。
2. 先看端到端值作默认读数,再用后两列解释损失出处。
3. 按 Experiment 排后，在 plan 中声明 Eval 行 Calculation，找出集中产生 errored 的题。
4. 从 locator 下钻已计划的 Timeline 与 Notice target，查看错误属于哪个生命周期阶段。

## 边界

- `taskPassRate` 是「已形成判定的样本中」的条件诊断,不能替代默认成功率。
- 样本缺失与执行失败是两件事;前者先看 Sample 完整性。
- 想快速找出「从来没通过过」的题,用 show 的 [`--stats`](../../show/stats.md)。
  网页版是[内建稳定性页面](../../library/built-in.md#failures-与-stability)（标准 plan 的 stability Calculation）。
  本页诊断的是已形成判定后 task 与 execution 失败的归因, 是稳定性问题之后的下一步。
