# 把报告嵌入自己的产品页

## 解决什么问题

你不想发布独立 `niceeval view` 站点,而是要把评测概览嵌入内部门户、产品后台或现有 React 应用。

## 先回答:记录根在哪台机器上

`openRecord()` 读的是本地文件系统上的 `.niceeval/`。部署出去的产品进程通常看不见这份目录——
它躺在跑 eval 的那台机器或 CI 的工作区里。所以这条流程的分界不是「服务端 vs 浏览器」,是
**执行这段代码的进程能不能打开记录根**。两种落点:

| 形态 | 什么时候用 | 数据怎么到页面 |
|---|---|---|
| 一:页面与记录根同机 | 本地 dev、跑 eval 那台机器上的看板、内网工具 | 请求时现算 |
| 二:构建期算好 JSON | 结果随发布走,产品运行时看不见记录根 | 数据源 `.compute()` 得到的 Content 写成 JSON,与站点一起部署 |

两种形态使用同一批数据源,区别只在什么时候调用 `.compute()`;两份可复制的代码在
[Library · 嵌入自己的 React 页面](../../library.md#嵌入自己的-react-页面)。记录根不随产品部署时选形态二。

## 全流程

1. 在能打开记录根的进程里用 `openRecord()` 选 Sample,明确使用 `latestRunSample()` 还是 `currentSample()`。
2. 用 `Promise.all` 计算 `sources.sample.snapshot.compute(sample)`、
   `sources.measure.rows(options).compute(sample)` 等数据源，产出可序列化 JSON。
3. 把 data 传给 `niceeval/report/react` 的纯 web 组件;该入口不读文件,也不运行 report resolve。
4. 传入产品自己的 `attemptHref`,让 locator 下钻进入你的路由。
5. 引入官方样式与渐进增强脚本,或只消费 data 类型完全自绘。

## 边界

- 不要在浏览器组件中调用 `source.compute()`;它可能懒加载本地 artifact。
- 证据下钻要跟着走:`attemptHref` 指向的路由同样需要证据文件。形态二下记录根不在产品那边,用
  [`publish()`](../../../record/library.md#发布publish) 把要展示的那批结果物化进产品能读到的目录。
- 形态二的 JSON 只代表算它那一刻的 Sample。记录根有了新 Run 要重跑构建脚本,页面不会自己变新。
- 只需要可分享的独立报告时用 `view --out`,不需要嵌入应用。
