# 把报告嵌入自己的产品页

在服务端或构建进程中打开固定 `RecordHandle`、materialize 一份单 source Sample，再由该 handle 构造 `RecordSourceSet` 并运行 ReportDefinition 的 plan/executor：

```ts
const report = await loadReportDefinition(
  new URL("./product-report.tsx", import.meta.url),
);
const ref = await exportReport(report, {
  sample,
  sources,
  parameters: {},
  target: { store: productReportStore, pages: "all" },
});

const artifact = await openReportArtifact(productReportStore, ref);
```

产品页面直接托管 artifact 已生成的 HTML 与资产，或把其中的最终 text 交给自己的文本面。
artifact 的 `data` 是只读的 canonical JSON 审计快照，不是可重新执行 renderer 的 branded
`ReportData`。需要把已计划 data 交给 `niceeval/report/react` 时，应在同一次内存执行阶段组合纯组件，
而不是从持久化 artifact 反序列化函数或 `ReportNode`。

React 入口与重开的 artifact 都不读取 Record、Sample、Projection 或 Store。
需要 evidence 下钻时，产品托管同一 artifact 的 `RecordEvidenceProofIndexV1` 与 inert archive；它不把源 Record 复制成活动数据源。

构建服务按 `ReportArtifactError.failure` 处理导出失败。source reader 与 proof closure 都使用
`report-evidence-closure-failed`。
typed `cause` 分别完整保留 `RecordSourceFailure` 或 `RecordEvidenceProofFailure`，适合按 owner code
决定重试或提示。

源 Record 有新 Graph 时，重新 materialize 一份带新 source 的 Sample 并导出新的 artifact。
