# 分享静态报告站

团队要把固定比较结果交给没有 Record、没有网络且不会安装 NiceEval 的读者。一个完整 ClosedSiteRevision 同时服务
`niceeval view` 和 `niceeval view --out`；两者对同一路由交付相同页面 body bytes。

## 定义详情 Page

Attempt 详情使用参数化 Page。`params` 是页面作者维护的稳定 key codec；它以 durable Attempt locator 枚举实例，
不能使用数组下标或显示 label。

```tsx
import {
  aggregate,
  costUSD,
  defineComponent,
  defineReport,
  Grid,
  model,
  passRate,
  Table,
  type PageEvidence,
} from "niceeval/report";
import { attemptParams } from "./attempt-params.ts";
import { releasePricing } from "./pricing.ts";

const EvidenceSummary = defineComponent(
  ({ evidence }: { readonly evidence: PageEvidence }) =>
    <Table
      caption="Evidence"
      rows={evidence.entries.map(entry => ({
        attempt: entry.attempt.locator,
        state: entry.state,
      }))}
    />,
);

export default defineReport({
  title: "Release report",
  pricing: releasePricing,
  pages: [
    {
      id: "overview",
      title: "Overview",
      render: async sample => {
        const rows = await aggregate(sample, {
          by: { model },
          values: { passRate, costUSD: costUSD(releasePricing) },
        });

        return (
          <Grid>
            <Table rows={rows} />
          </Grid>
        );
      },
    },
    {
      id: "attempt",
      path: "/attempt",
      title: "Attempt",
      navigation: false,
      params: attemptParams,
      load: async (_sample, params, context) =>
        await context.evidence(params.locator),
      render: evidence => <EvidenceSummary evidence={evidence} />,
    },
  ],
});
```

`pages` 是该 Report 唯一的页面集合：Overview 与 Attempt 都由作者明确声明，Host 不补建其它详情 route。`enumerate(sample)` 返回每个
可公开详情的 locator。Host 对每个值验证 encode、decode、再 encode 的往返，不接受重复、大小写冲突或不规范 key。

## 构建完整站点

```sh
niceeval view \
  --report ./reports/release-summary.ts \
  --out ./release-report
```

这条命令先形成固定 Sample。Host 构建完整站点时运行 Overview，恰好调用 Attempt Page 的
`enumerate(sample)` 一次，并对所有 locator 分别运行 `load` 与 `render`。每个详情 route 都是 revision 的固定内容；
浏览器地址不能生成新参数、重新选择 Sample 或再次读取事实。

Host 在构建期收集全部 route、下载文件、静态文件、`_niceeval/data/projections.json` 和 manifest。
一个冲突集合检查 exact path、ASCII case-fold、file/directory prefix、Windows device name、尾点、尾空格和长度冲突。

Source、Trace 和 Diff 也必须在这一阶段成为详情 Page 或静态文件。读者点击链接时只读取 revision 中已经存在的 bytes。

## 写出和本机查看

全站关闭和验证成功后，exporter 才准备此前不存在的 `release-report` 目录，并原样写出 revision 的 HTML、静态文件、
`_niceeval/data/projections.json` 和 downloads。该 projections 文件的 bytes 属于 revision identity。已有目标目录返回
`report-export-target-exists`；Host 不删除或替换其中的文件。

```sh
niceeval view --report ./reports/release-summary.ts --port 4400
```

本机 view 构建同一种 ClosedSiteRevision，并原样托管其 bytes。若 `http://127.0.0.1:4400/attempt/<key>` 与
`release-report/attempt/<key>/index.html` 指向同一路由，两份页面 body bytes 相同。view 的 watcher、HTTP header 和
刷新通知不改变正文。

## 断网读取

浏览器只消费目录中的页面、静态文件和 downloads。禁用 JavaScript 并断开网络后，正文、导航、参数化详情、
MetricValue 的完整度、问题和下载仍可读。

`partial`、`empty`、`unsupported` 和 `failed` 随关闭页面内容写出。任何 Page 回调、枚举、路径或全站验证错误都会阻止
形成 revision，因此不会发布一个只包含部分详情的网站。
