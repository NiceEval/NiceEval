# 用 artifact 定义业务读数

## 解决什么问题

内置读数能回答通过率、成本和耗时,但你要问「通过的方案改了多少行」或「某类工具调用多少次」。

## 全流程

1. 用 `rollup()` 声明 Attempt 取值函数、两级 reducer、`unit` 与 `better`。
2. 取值函数只保留读数真正适用的 Attempt;测不了返回 `null`,不返回 0。
3. 需要 diff、events、trace 或 o11y 时在 page render 里 `await attempt.diff()` 等,在计算层做一次。
4. 把 Calculation 放进 `aggregate()` 的 `values`,与官方读数并排。
5. 需要新分组而不是新数值时写 `aggregate().by` 里的分组函数,不滥用 Calculation。

可复制代码见[自定义读数示例](../../library/examples.md#自定义读数)。

## 边界

- 读数是消费方观点,不回写 Record,不改 verdict。
- 自定义计算在 page render 或报告旁的普通函数里运行,不放进纯 React renderer。
