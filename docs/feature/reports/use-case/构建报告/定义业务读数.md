# 用 Projector 定义业务读数

## 解决什么问题

内置读数能回答通过率、成本和耗时，但业务报告还会问「通过方案改了多少行」或「某类工具调用多少次」。

## 全流程

1. 用 `defineAttemptProjector()` 声明 snapshot evidence、参数 schema、完整规范化 defaults、实际 Projector object dependencies 与 identity。`projectNormalized()` 只返回 raw `T`。
2. 用 `defineCalculation()` 静态列出 Projector dependency，并在纯 `evaluate()` 中转换 EvidenceValue。
3. 用 `rollup()` 明确题内、题间 reducer 与 unavailable policy。
4. 把 Calculation 放进 plan 中 `aggregate(...).measures`，与官方读数并排。
5. 需要新 group 时，声明只读取固定 membership provenance 的 group key。

Projector 通过 `ProjectionReadContext` 自动形成 basedOn。
省略可选 input 时 runtime 从空对象开始规范化，并冻结 defaults、规范化 Params、dependencies 与 raw result；作者不能手写 available/unavailable。
Calculation 不读取 Store，也不把 unavailable 改成 `null` 或零。

## 边界

- 读数是消费方的确定性推导，不回写 Record 或改写 Claim。
- 外部业务事实先 snapshot 进 Record，再由 Projector 读取。
- renderer 只显示 ReportData，不能触发业务读数计算。
