# 从单页报告升级为多页站点

## 解决什么问题

一份报告同时包含管理层总览、评测工程分析和 Attempt 证据时，把它们塞在 Tabs 中会让终端和网页都难读。多页报告把这些问题分成稳定的 page instance，同时仍共享一份 Sample 和一次 executor 输出。

## 全流程

1. 用 `defineReport({ plan })` 定义报告；`plan({ sample, parameters })` 一次列出全部页面、Calculation 与 Projector request。
2. 总览页组合 `Hero`、`SampleNotices`、`RunNotices`、`SampleSummary` 与前沿散点；失败页组合 `FailureList`；分析页组合已计划的读数图。
3. 用 `attemptDetailPages(sample, { projector: attemptDetails })` 在 plan 中枚举详情 instance。该构造函数
   为每项显式生成同一个 page id、由完整 Sample member identity 确定的 instanceId，以及只编码该
   已计划 instance 的 route。参数化页不能省略 instanceId / route。要自定义详情，改写它的 data 与
   `render(data)`，不在 URL 或 render 时读取 Attempt。
4. 用 `ReportDefinition` 的 title、theme、dimensionPins 与 head 声明静态外壳；换外观走[主题](../交付报告/主题/)。
5. 同一份定义分别用 `show --page` 和 `view` 验证 text/web 两面；两面只消费一次生成的页面树。

## 边界

- Tabs 是页内局部视角；不同受众、不同 URL 或终端需分段阅读时用 pages。
- 只有普通 singleton page 可同时省略 instanceId / route；executor 按 Library 的唯一 shorthand
  补全。提供其中一个却遗漏另一个、重复 target 或重复 route 都在 request 执行前失败。
- 参数化详情是固定 Sample membership 上的已计划 instance，不是可借 locator 任意取数的路由。
- 任何数据相关分支只能改变既有 data 的显示，不能新增 Projector、Calculation 或 Store 读取。
