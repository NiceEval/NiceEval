# 核对通道完整度

团队要知道一个 Report 是否基于完整的命令检查数据，而不是把有值的 Attempt 当成全部 Attempt。

## 选择固定分母

    niceeval show --latest --report ./reports/command-checks.ts --page coverage

`--latest` 先由 `latest/v1` analysis projector 选择每个 Experiment 的完成 Run。`AnalysisSample` 随后保留每个 expected slot，因此这张页的分母在 Calculation 开始前已经固定为 100。

## 声明 `commands.checked`

Report 为 `commands.checked` 声明一个 Attempt-owned fact requirement，并把它列进 Calculation 的 `inputs`。composition adapter 按 plan 交付每个 included Attempt 的 `ChannelRead`，其中持久采集完整度和解码完整度分别保留。

```ts
const commandChecks = defineCalculation({
  id: "command-checks",
  inputs: [commandsChecked],
  completeness: "allowPartial",
  evaluate(input) {
    return checkedCommands(input);
  },
});
```

当只有 20 个 slot 提供可用检查数据时，`checkedCommands` 返回：

    {
      state: "available",
      value: 20,
      completeness: {
        state: "partial",
        observed: 20,
        denominator: 100,
        issues: [],
      },
    }

页面写 `20 / 100 · partial`。它不把 20 显示成完整数量，也不把 20 当成新的分母。

## 需要完整读数时

若业务读数不能使用缺口数据，使用 `requireComplete`。

```ts
const releaseGate = defineCalculation({
  id: "release-gate",
  inputs: [commandsChecked],
  completeness: "requireComplete",
  evaluate(input) {
    return gateFromChecks(input);
  },
});
```

同样的 20 / 100 输入使 `releaseGate` 返回 unavailable。页面显示 20、100、partial 和原因，但不给出通过或失败的数值。

## 分清三种不足

| 输入状态 | 页面文本 |
|---|---|
| `unavailable` | 写明未采集或不适用。 |
| `unsupported` | 写明当前 reader 不支持 `commands.checked`。 |
| `invalid` | 显示该通道的具名 issue。 |

这些状态只影响请求 `commands.checked` 的 Calculation 和页面。例如只使用 verdict 的质量页保持可读。
