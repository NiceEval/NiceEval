# `--report` / `--page`：show 与 view 共用一份自定义报告

## 解决什么问题

内建报告提供通用口径；项目可用自己的 `ReportDefinition` 提供固定题集成绩单或带品牌的多页站。`--report` 选择这份定义，`view` 输出网页，`show` 输出终端；两面共享同一份 Sample、ReportPlan、ReportData 与页面树。

## 全流程

1. 编写默认导出为 `defineReport({ plan })` 的报告文件。在 plan 中静态列出 pages、Calculation 和 Projector request，外壳字段见 [Library](../../library/shell.md)。
2. 在浏览器中打开定义：

   ```bash
   niceeval view --report ./reports/exam.tsx
   niceeval view --report ./reports/site.tsx --page exam
   ```

3. 把同一份文件交给终端：

   ```bash
   niceeval show --report ./reports/site.tsx
   niceeval show --report ./reports/site.tsx --page exam
   ```

   `--page` 只能选择该 Plan 已枚举的 instance；show 的页索引保留 `--record`、`--report`、范围和参数。

4. 位置参数、`--exp` 与 `--run` 只形成 Sample selection，`--page` 只选 target：

   ```bash
   niceeval show memory/swelancer --report ./reports/site.tsx --page exam
   ```

5. 在 plan 中用 `attemptDetailPages(sample, …)` 枚举 Attempt 详情。随后 view 深链和带 `--report` 的 `show @<locator>` 可指向同一 instance。
6. 定型后可把定义放进项目配置的 `report` 字段：

   ```ts
   import { defineConfig } from "niceeval";
   import site from "./reports/site";

   export default defineConfig({ report: site });
   ```

   不带 `--report` 的 `show` 与 `view` 随即使用它；`--report standard` 可按次选择内建定义。

## 边界

- 未知 page、不可达 instance 或无效参数会得到明确错误，不会临时查询其它 Store。
- 配置的 `report` 只影响读面；它不改变 Run、Attempt、Sample 或 RecordGraphRef。
- 显式 `--report` 的定义若未枚举某详情 instance，locator 不会悄悄切换到标准详情。
- `--history` 与 `--report` 互斥，因为二者选择不同主 target。
- 主题、head 与静态资产不改变计划数据；`--theme` 属于 `view` 的 web 面。
