# 比较质量与成本

用户需要比较多个已封口 Run 时，必须同时看清成员、分母、missing 与 Evidence，而不是把两个数字相减。

```json
{
  "protocol": "niceeval.query/v1",
  "operation": {
    "kind": "runs.compare",
    "request": { "mode": "paired", "left": { "runs": ["<left>"] }, "right": { "runs": ["<right>"] } }
  }
}
```

`side-by-side` 分别交付集合结果，不产生 delta。`exact` 只在 member domain 与 exact member set 都相同后成立。`paired` 只使用 NiceEval 第一方 pairing key，并在同一个 result 中交付 left、right、pair 的三份 denominator，以及 pairs、unmatched、excluded、missing 与 Evidence。

只有 Inspection operation 可以决定成员是否匹配、分母是否相同或结果是否可比。machine consumer 与 View 只能呈现同一闭合 result；它们不能补配、删掉 unmatched，或用未包装 scalar 再算排名、趋势或聚合。
