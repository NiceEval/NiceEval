# 比较质量与成本

团队要比较两个或多个完成 Run 的质量与成本，并看清每个读数的分母和缺口。

## 选择范围

先显式选择要比较的 Run。

    niceeval show \
      --run 01H7A0A0A0A0A0A0A0A0A0A0A0 \
      --run 01H7B0B0B0B0B0B0B0B0B0B0B0 \
      --report ./reports/quality-cost.ts

`AnalysisSample` 以每个 Run 的 expected slots 形成分母。没有 Member 的 slot 保持 `not-recorded`；核心引用有误的 slot 保持 `core-invalid`。比较页不能因为某个 Attempt 没有数值而把它从分母移走。

## 声明读数

该 Report 的质量 Calculation 声明 evaluations 与 verdicts inputs，成本 Calculation 声明 usage input。两项各自声明 policy：

```ts
const evaluations = selectedRunProjection(evaluationsProjector);
const verdicts = attemptSlotProjection(verdictProjector);
const usage = attemptSlotProjection(usageProjector);

const quality = defineCalculation({
  id: Either.getOrThrow(reportComponentId("quality")),
  inputs: reportInputs({ evaluations, verdicts }),
  completeness: "require-complete",
  calculate({ sample, inputs }) {
    return passRateFrom(sample, inputs.evaluations, inputs.verdicts);
  },
});

const cost = defineCalculation({
  id: Either.getOrThrow(reportComponentId("cost")),
  inputs: reportInputs({ usage }),
  completeness: "allow-partial",
  calculate({ sample, inputs }) {
    return costFrom(sample, inputs.usage);
  },
});
```

两个 callback 只读 Sample 与 projected inputs，不按路径、时间或 locator 打开其它 Attempt。

## 读页面

质量 Calculation 用 `evaluationKind: "pass"` 的 slots 形成通过率分母；Score Eval 另由 score Calculation 聚合。所有 Attempt 的 terminal state 都来自 Verdict，但两种 evaluation kind 的质量数值不相加。成本 Calculation 可以显示 partial，例如 `$3.20 · 20 / 100 · partial`，并给出未参与公式的 slots 与原因。`observed`、`denominator` 与 `state` 都由 Calculation value 返回。

如果 `niceeval.usage` unsupported，成本卡片写明 reader 不支持该 Attachment。质量卡片仍可使用 Verdict 计算。若 `niceeval.verdict` 被请求且 invalid，质量卡片显示具名 issue；不读取 Verdict 的页面与另一个 Report 保持可用。

## 交付

同一 Report 可由终端或网页呈现。

    niceeval view \
      --run 01H7A0A0A0A0A0A0A0A0A0A0A0 \
      --run 01H7B0B0B0B0B0B0B0B0B0B0B0 \
      --report ./reports/quality-cost.ts

散点图必须给出同一批行的文字表。每一行展示 Run、质量、成本、observed、denominator 和状态，不能只靠点的位置或颜色传达 partial。
