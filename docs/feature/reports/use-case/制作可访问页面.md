# 制作可访问页面

团队要让键盘、屏幕阅读器和纯文本读者取得相同的质量、成本和完整度信息。

## 从页面数据开始

页面从已计算的 ReportInput 和 CalculationValue 生成宿主数据。不要让一个视觉组件私下读取 facts，也不要让文字页另算一次。

    interface ReportPageModel {
      readonly title: string;
      readonly body: ReportJsonValue;
      readonly textAlternative: string;
    }

<code>body</code> 与 <code>textAlternative</code> 表达同一页的事实。<code>show</code> 使用文字等价内容；网页使用 body，并保留同样的标题、数值、分母和状态。

## 语义结构

每张网页按下列顺序组织：

1. 一个页面标题和有序标题层级；
2. 有名称的导航链接；
3. 带列标题的数值表；
4. 与每项读数相邻的 observed、denominator 和状态；
5. 具名 issue、unavailable 原因或 unsupported 通道名称。

错误和状态不能只通过颜色、图标、位置或悬停提示表达。页面更新状态时，辅助技术可以读取变化后的文字。

## 图表的文字等价内容

质量—成本散点图附带同一批数据的表。每行至少写 Run、质量、成本、observed、denominator 与 partial 或 unavailable 状态。

柱状图、趋势图和时间分布同样提供逐项表或短文本摘要。图形可以帮助比较，但不能是得到数值或发现通道不足的唯一方式。

## 交互与静态站

参数化详情页的链接都指向已计划的静态 route。键盘用户可以按导航顺序抵达页面、下载项和详情链接；客户端不以鼠标操作来生成新的 route 或读取新的 fact。

    niceeval view --latest --report ./reports/accessible-summary.ts
    niceeval view --latest --report ./reports/accessible-summary.ts --out ./accessible-site

本机页面和静态报告站使用同一预渲染数据。断网查看静态站时，页面仍显示完整分母与所有已经生成的文字等价内容。
