# 制作可访问页面

团队要让键盘、屏幕阅读器、terminal 读者和静态站读者取得同一份质量、成本和完整度信息。

## 从闭合值开始

Page 和复合组件先从 Sample 取得 rows 或领域视图，再组成 NiceEval 语义节点。显示原语不会私下读取事实，terminal renderer 也不另算一次。

```tsx
const QualitySummary = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { model, condition },
    values: { passRate, costUSD },
  });

  return (
    <Grid>
      <Scatter points={rows} x="costUSD" y="passRate" color="model" />
      <Table rows={rows} />
    </Grid>
  );
});
```

callback 完成后，Host 只保留 ClosedReportTree。树不含 Sample、Promise、回调或浏览器对象，因此 text、Web 和 static renderer 只能读取同一事实。

## 语义结构

每张页面按以下顺序组织：

1. 一个可读的页面标题和有序标题层级；
2. 有名称的导航与详情链接；
3. 带列标题的数值表；
4. 每项读数相邻的 value、samples、total 和 state；
5. 具名 issue、unsupported 原因或 failed 的可复核 refs。

错误和状态不能只通过颜色、图标、位置或悬停提示表达。页面更新状态时，辅助技术可读取新的文字。

## 图形的文字等价内容

Scatter、Bars、Line 和自定义双面原语都必须有同步 text face。质量—成本图的 text face 直接使用相同 rows 生成表或短摘要；每行至少写 model、condition、质量、成本、samples、total 和 state。

图形可以帮助比较，但不是取得数值、发现 partial 或进入 Evidence 的唯一方式。web face 的颜色、hover、缩放和筛选不能改变文字面已经声明的值或顺序语义。

## 键盘、详情与下载

参数化详情页的链接都指向当前 execution 已闭合的 route。键盘用户可以按文档顺序到达导航、表格、详情页和 Download；客户端不会因鼠标操作生成新 route 或读取新事实。

```sh
niceeval view --report ./reports/accessible-summary.ts
niceeval view --report ./reports/accessible-summary.ts --out ./accessible-site
```

本机 view 与静态站使用同一 ClosedReportTree 和不可关闭的问题面。断网且禁 JavaScript 查看静态站时，页面仍显示完整分母、状态、问题、下载和同一棵树派生的文字内容。

## 自定义显示原语

新原语必须采用双面 defineComponent()。`resolve()` 可以在呈现前求值得到闭合数据对象；`text()` 和 `web()` 都同步读取该对象。实现不能让 `web()` 再发请求、让 `text()` 重新计算，或只在网页面藏住问题说明。

当原语无法提供同等的可访问 terminal 与静态语义时，它不能进入普通 Report module，应先作为 NiceEval core 的设计与实现工作。
