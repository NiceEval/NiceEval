# 制作可访问页面

团队要让键盘、屏幕阅读器和纯文本读者取得相同的质量、成本和完整度信息。

## 从页面数据开始

页面从 `ProjectedSample` 与 `ReportCalculationResult` 生成闭合语义树。不要让一个视觉组件私下读取 Channel，也不要让文字宿主另算一次。

    interface ReportDocumentV1 {
      readonly schema: "niceeval.report-document/v1";
      readonly title: string;
      readonly children: readonly ReportBlockV1[];
    }

`ReportBlockV1` 是 section、paragraph、list、table、metric、status、code 与 chart 的 closed discriminated union。`show`、网页与 static HTML 都从这棵树派生；页面不维护另一份可能漂移的 `textAlternative`。

## 语义结构

每张网页按下列顺序组织：

1. 一个页面标题和有序标题层级；
2. 有名称的导航链接；
3. 带列标题的数值表；
4. 与每项读数相邻的 observed、denominator 和状态；
5. 具名 issue、unavailable 原因或 unsupported 通道名称。

错误和状态不能只通过颜色、图标、位置或悬停提示表达。页面更新状态时，辅助技术可以读取变化后的文字。

## 图表的文字等价内容

质量—成本散点图节点保存同一批 structured series、axis、label、completeness 与可表格化数据。文字 renderer 从这些字段直接生成表；每行至少写 Run、质量、成本、observed、denominator 与 partial 或 unavailable 状态。

柱状图、趋势图和时间分布同样提供逐项表或短文本摘要。图形可以帮助比较，但不能是得到数值或发现通道不足的唯一方式。

## 交互与静态站

参数化详情页的链接都指向当前 execution 已经展开的 route。键盘用户可以按导航顺序抵达页面、下载项和详情链接；客户端不以鼠标操作来生成新的 route 或读取新的 Channel。

    niceeval view --latest --report ./reports/accessible-summary.ts
    niceeval view --latest --report ./reports/accessible-summary.ts --out ./accessible-site

本机页面和静态报告站使用同一 semantic tree 与host-owned problems surface。断网且禁JavaScript查看静态站时，页面仍显示完整分母、问题和同一棵树派生的文字内容。
