# 制作可访问的固定 View

维护者需要对一个精确 NiceEval candidate 的 pinned sealed synthetic Snapshot 制作可访问的固定 View，以在浏览器中审阅 Run overview，并按需查看 trace、diff、sources 或 artifacts。

```sh
niceeval view --run <run-id>
niceeval view @<attempt-locator> --no-open
```

未给 `--record` 时，View 从 Host 定位的 project operational Store 读取 sealed facts。它建立完整 revision 后才 ready；新 sealed Run 只提示更新，用户确认后才刷新。刷新失败保留 last-good，旧请求不会混入新 cutoff。

对 pinned sealed synthetic `RecordSnapshot`，固定 renderer 生成 immutable、byte-complete、多文件 `ViewRevision`。其中固定有 `overview`、`run`、`attempt`、`compare`、`sources` 与 `artifacts`。

超过 delivery limit 时，页面必须明确显示 `truncated`、边界与固定的继续读取方式。这不可以掩盖或改写 operation 的 `partial`、`missing`、`issues` 或 Evidence。

本地 loopback 与官方公开 Preview 服务同一份 revision bytes。两者仅 transport 不同：loopback 在文件外验证 session、Host 与 Origin；公开 Preview 的静态文件不含任何 session auth。

`NiceEval-Preview` 官方 `main` 以精确 candidate SHA 作为信任边界，并只部署 revision files 到 Netlify，作为部署与视觉 dogfood。

它不部署 SQLite、Inspection JSON、`.niceeval` 或 secrets，也没有 Functions 或长期 Node。

View 是 NiceEval 固定 UI，不是用户 static export 或可定制 Report。它不接收页面、样式、组件、路由、renderer 或任意 operation，也不允许把任意匿名 URL 当成第一方 Delivery。

新 Preview site/check 由 `NiceEval-Preview` 持有，不由 NiceEval 主仓 PR 持有。新站验活后旧 site/check 由外部 owner 解除。
