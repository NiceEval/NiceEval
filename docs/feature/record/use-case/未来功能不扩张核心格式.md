# 选择正确的演进边界

新增持久能力时，目标不是把 Record 设计成自由容器。目标是让每项变化停在自己的 owner，并在 Core 公理改变时显式迁移。

## 判断顺序

依次回答：

1. 能否从 plan 已声明的 projections 推导，只改 Calculation 或 Report？
2. consumer 所需 typed view 的类型与语义是什么？
3. payload bytes 的 shape、media type 与语义是什么？
4. recorded claim 的 ChannelName 与领域 owner 是谁？
5. owner、Core relationship、path safety 或 atomic publish unit 是否改变？
6. 可观察行为或 reuse gate 是否改变，需要更新 behavior identity 吗？

第 1 项决定 Report。第 2 项决定 projector。第 3、4 项决定 Channel schema 与 name。第 5 项决定 Record major。第 6 项独立决定执行安全身份。

## 动作表

| 变化落点 | 发布动作 | Record Core |
|---|---|---|
| 纯展示或聚合 | Calculation、Page 或 Report definition | 不变 |
| payload contract | `ChannelSchemaId` | 不变 |
| typed view contract | 新 projector export / Library API | 不变 |
| recorded claim 的业务语义 | ChannelName 与 schema | 不变 |
| 执行行为或 reuse gate | input、config 或 reuse identity | 不变 |
| owner、reference、path 或 publish unit | `RecordFormatId` 与相邻 converter | 发布新的 major |

正式 Channel schema 是长期契约。closed decoder、writer fixture、closure codec 和所需的标准 projector 由领域 owner 一起维护。

## 自定义 typed Channel

producer 先定义写入 contract：

```ts
const gpuEnergy = defineJsonChannel({
  owner: "attempt",
  name: "com.example.gpu-energy",
  schemaId: "com.example.gpu-energy/v1",
  schema: GpuEnergySchema,
});
```

consumer 再定义 typed view：

```ts
const gpuEnergyProjector = defineJsonChannelProjector({
  owner: "attempt",
  channel: gpuEnergy.name,
  cases: [
    {
      schema: gpuEnergy,
      project: (payload) => ({
        joules: payload.joules,
        limitations: payload.limitations,
      }),
    },
  ],
});
```

definition 的 `ChannelSchemaId` 是 durable identity；projector 只有进程内 private token。producer 不能传 raw JSON，projector 不能接触 path、其它 Channel 或外部服务。

## 测量口径

GPU 能耗的 payload shape 由 `ChannelSchemaId` 冻结。joules-only 与带误差区间的 typed view 由各自的 projector export 形成。

设备估算与机房电表实测是不同 recorded claim，应使用不同 ChannelName。consumer 不能只看字段相似就把两者当成同一指标。

这些定义都不修改 Attempt Core。

## 多模态附件

图片、音频和视频使用 origin Attempt-owned official blob-backed Channel。payload 保存 media type、角色、byte length、digest 与 owner-local blob ref。

对应 schema 带永久 storage closure codec，migration 可以穷尽验证和复制全部 blob。Channel projector 只在 closure 验证后形成 typed attachment view。

跨 Attempt 去重、远端 URL 或 root 外 path 会改变 owner 与 portable closure。这类能力属于新的 Record major，不属于 payload schema。

## Verdict、score 与质量信号

`niceeval.verdict/v1` 只保存 Pass Eval 的 `passed | failed | errored | skipped`。Score Eval grading 由独立 score Channel 保存。

附加质量信号使用自己的 Channel。终态、score 与质量信号不能靠一个开放对象混成同一 schema。

reuse planning 显式声明需要的 Verdict、score 与 Eligibility projection。展示可读不自动意味着 reuse 可接受。

## Behavior identity

fingerprint 算法或输入 closure 的语义由 identity domain 冻结。每个 reuse gate 也由 `reuseContract.domain` 表达。

reuse planning 对 schema、domain 与 equality token fail closed。不受当前 policy 接受的输入形成 gap。

Behavior identity 不写进 Core，也不能用 provenance Channel 代替。

## Record major migration

owner、path 或 publish invariant 改变时，format 通过相邻 converter 迁移到 current major：

```text
source root ── adjacent converter ── exact validate
            ── repeat until current major
            ── preservation inventory
            ── in-place cutover
```

普通 reader 只读取 current major。已知可迁移 major 返回 `record-migration-required`，用户执行 `niceeval migrate` 后重试原命令。

migration 保持 `recordId` 和全部业务 identity。它不升级 Channel payload、不补默认值，也不重算当前算法能得到的内容。

无法证明 recorded claims 一一等价时，converter 返回 `record-migration-not-lossless`。自由 JSON 不能绕过这项证明义务。

## 不能走的捷径

- 同一 schema ID 接受多个对象 shape；
- 用可选字段组合猜 payload 代际；
- 给 generic writer 增加 `writeAssertions2()` 一类业务方法；
- 为每个 Eval 暴露 raw `writeChannel`；
- 用 Channel schema 表达远端 URL、跨 owner ref 或新的 portable unit；
- 把 session、lock、migration history 或 cache 写进 Record；
- 普通 open 自动迁移，或提供跨 major compat reader；
- migration 运行 projector、重算业务值或更换 object identity；
- 为了避免 migration，把 Core 改成 `Record<string, unknown>`。

## 设计验收

每次增加持久能力时回答：

1. recorded claim 的领域 owner 是谁？
2. owner 是 Run 还是 Attempt，理由是什么？
3. ChannelName 与 ChannelSchemaId 分别冻结什么？
4. media type、closed schema 与完整 closure怎样验证？
5. projector export 返回的精确类型和语义是什么？
6. 多个 schema case 是否都能无损形成同一 view？
7. unsupported schema 是否只影响当前 projection？
8. 新行为怎样进入 input/config identity，新 gate 怎样形成 gap？
9. 是否改变 Core owner、reference、path 或 publish unit？
10. 需要新 major 时，相邻 converter 怎样证明 lossless preservation？

答不清其中任一项时，不得以“只是加一个 optional 字段”为理由发布持久契约。
