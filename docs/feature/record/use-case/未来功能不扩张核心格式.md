# 选择正确的持久边界

新增能力先判断它是派生结果、新的不可恢复事实、family semantic change、physical storage change，还是所有 reader 都必须理解的
Core identity。

| need | owner and action |
|---|---|
| 重新计算、筛选、展示 | 固定 Inspection / Delivery；使用 bounded read 或 Stream |
| 新 Attempt plain-data items | 新 `Record.attemptCollection()` family |
| 新 rich 或 Run-owned fact | 新 `Record.attempt()` / `Record.run()` family |
| family fields、units、cardinality、Content/reference meaning 改变 | typed adjacent family/data migration |
| table/index/trigger 改变，logical facts 不变 | checked-in physical schema migration，保留 `LogicalSealIdentity` |
| Run/Attempt/owner/reference/Seal identity 改变 | 新 Record format 与显式 import |
| OS-user first-party Service durable state | static namespaced module in `~/.niceeval/state.sqlite` |
| cache、secret、claim、mailbox、lease | 各自独立 store，不进入 Record/Service state |

Family 定义不能提供 SQL、table、column、index、pragma、transaction 或 chunk size。第三方 family 通过 Host composition 参与 generic
rows，但不能注册 Service state module；Service v1 只允许 application 静态列举的第一方 namespace 与 fixed operations。

unknown family 不是修改 Core schema 的理由。generic rows 允许它被 Snapshot 与 physical migration 原样保留；无关局部读取继续，
direct/reference/full operation 才要求 definition。

## 不能走的捷径

- 为 family 新增专属 SQLite table 或 raw SQL hook；
- 把完整数组读取当作大 collection 的唯一 API；
- 把 operational `record.sqlite` 复制、提交或交给 `--record`；
- 用 cache、current worktree 或 provider 重写历史事实；
- 让 physical schema migration 改变 Logical Seal，却仍声称只是 storage change；
- 让 Service module 取得 connection、跨 namespace transaction、authorizer 或 maintenance；
- 引入 Drizzle 代替 checked-in SQL、prepared statements、typed decoder 与 Host ownership。
