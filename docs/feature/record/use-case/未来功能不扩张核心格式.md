# 选择正确的持久边界

新增能力先判断它是已保存事实的读取、一个新的不可恢复事实，还是所有 reader 都必须理解的 Core
公理。migration 不是把业务字段写入 Core 的理由；新的 Attachment family 也不升级 Core。

## 判断顺序

1. 这只是从已保存事实重新计算、展示或下载吗？
2. consumer 需要的 typed view、Measure 或 Report component 是否改变？
3. 是否出现了无法从现有事实恢复的新事实？
4. 该事实属于 Run 还是 Attempt？
5. 是否改变了现有 family 的字段、单位、基数或 blob closure 语义？
6. 是否改变了 Run、Slot、Member、Attempt、owner、reference、目录或原子发布边界？

| 答案 | 正确动作 |
|---|---|
| 只重新计算或展示 | Analysis、Calculation 或 Report |
| 只改变 typed view | 发布新的读取 API，不改 Record |
| 此前未保存的不可恢复事实 | 由拥有该语义的 package 定义或扩展 Attachment family；不改 Core |
| family 持久语义改变 | 提高 durable interpretation revision，并同批提供相邻 private migration |
| Core 公理改变 | 发布新的 Record format identity 与显式 conversion；不增加全局 revision |

## Attachment family 是显式 composition，不是全局注册

第三方 package 与 Plugin 可以通过 `defineRecordAttachment()` 定义 GPU 能耗、私有 trace 或额外 evidence 等
durable family。Record 附件定义必须声明 owner、family、exact current Schema、invariant、content / reference closure
与预算。matching persistence 绑定 current revision 与严格相邻的 private migration 链。它们都不能打开 Record root、取得文件系统能力或决定 capture 时机。

Host 或 Plugin composition 显式提供 immutable catalog，没有全局 registry、动态注册或后写替换。reader 遇到未贡献
family 时仍可读取不依赖它的已知 family；direct/reference closure 与 `requireComplete()` fail closed。

## 事实、行为和派生结果不能互换

`niceeval.assertions` 保存 sealed check result，五个 source receipt family 保存各 capture authority 的安全运行观察，
`niceeval.sources` 保存当时源码。它们不能替代当前 matcher、input identity 或 reuse policy。

反过来，平均值、通过率、P95、成本汇总、trace tree、图表点位和页面布局都能从固定事实及显式
Calculation 形成，不应变成 Attachment 字段。能展示一个 Attempt 不等于当前 Experiment 可以 reuse 它；
reuse gate 明确声明所需 facts 和 behavior identity。

## Attachment persistence revision 的边界

current root 的领域值固定为 `{ format: "niceeval.record.attachments", recordId }`，没有 revision。所有 contributed family
都处于各自 current 时，`niceeval migrate` 才返回 `already-current`。root format / Core 不相容时返回
`unsupported-format`。

已知 family 的旧 revision 也只能经 maintenance 迁移。未贡献独立 family 不阻塞无关局部读取；已知 future
revision 或 migration chain 缺口仍是 unsupported。
未发布的带 `/vN` 后缀草案是 `unsupported-format`，不能借由这个规则伪装成 future family。

任一 persistence 升到下一 revision 时，private migration 以 storage-neutral tokenized document 形成 current bytes。相邻中间 revision 不写盘。历史 Attachment 在转换完成前不能
`openRead`，不会进入 Analysis 或 Report。

## 不能走的捷径

- 给 Record root 增加全局 numeric revision；
- 让 generic writer 接受任意 JSON、path、bytes 或手写 content ref；
- 把 session、claim、lease、migration history 或 cache 写进 Record；
- 在 ordinary read lease 内升级，或把另一 schema 伪装成 current 值；
- 为了少做 migration，把 Core 改成 `Record<string, unknown>`；
- 让当前 capture / Analysis 算法绕过 definition 的纯 migration 重写历史事实。
