# 选择正确的持久边界

新增能力先判断它是已保存事实的读取、一个新的不可恢复事实，还是所有 reader 都必须理解的 Core
公理。migration 不是把业务字段写入 Core 的理由；新的 NiceEval fixed family 也不升级 Core。

## 判断顺序

1. 这只是从已保存事实重新计算、展示或下载吗？
2. consumer 需要的 typed view、Measure 或 Report component 是否改变？
3. 是否出现了无法从现有事实恢复的新事实？
4. 该事实属于 Run 还是 Attempt？
5. 是否改变了现有 family 的字段、单位、基数或 blob closure 语义？
6. 是否改变了 Run、Slot、Member、Attempt、owner、reference、目录或原子发布边界？

| 答案 | 正确动作 |
|---|---|
| 只重新计算或展示 | Analysis、Calculation 或 Report |
| 只改变 typed view | 发布新的读取 API，不改 Record |
| 此前未保存的不可恢复事实 | NiceEval 评审后扩展既有 family，或加入独立 static fixed family；不改 Core |
| family 持久语义改变 | 提高 numeric schemaVersion，并同批提供相邻 migration |
| Core 公理改变 | 发布新的 Record format identity 与显式 conversion；不增加全局 schemaVersion |

## fixed family 不是调用方扩展点

Adapter、Plugin 和 Report 作者只能消费 NiceEval catalog 已发布的 family，不能把 GPU 能耗、私有 trace 或
额外 file evidence 写成第三方 durable identity。若一项不可恢复事实确实需要保存，NiceEval 可以定义
`niceeval.energy` 等新的 fixed family，并裁决其 owner、exact payload、cardinality、closure、collector 与
schemaVersion。这个新增 family 不改变 Core，也不改 Record root。

旧 reader 遇到未知 future family 时在 ordinary session 形成前拒绝整份 Record，不把部分 Core 或已知
family 交给 Analysis / Report。已知 family 的旧 schemaVersion 仅在存在完整固定 chain 时可 migration。

## 事实、行为和派生结果不能互换

`niceeval.assertions` 保存 sealed check result，`niceeval.observability` 保存安全运行观察，
`niceeval.sources` 保存当时源码。它们不能替代当前 matcher、input identity 或 reuse policy。

反过来，平均值、通过率、P95、成本汇总、trace tree、图表点位和页面布局都能从固定事实及显式
Calculation 形成，不应变成 Attachment 字段。能展示一个 Attempt 不等于当前 Experiment 可以 reuse 它；
reuse gate 明确声明所需 facts 和 behavior identity。

## Attachment schemaVersion 的版本边界

current root 的领域值固定为 `{ format: "niceeval.record", recordId }`，没有 schemaVersion。所有 fixed family
都处于各自 current 时，`niceeval migrate` 才返回 `already-current`。root format / Core 不相容时返回
`unsupported-format`。

已知 family 的旧 schemaVersion 也只能经 maintenance 迁移。未知独立 future family 与已知 future 版本都拒绝 ordinary open。
未发布的带 `/vN` 后缀草案是 `unsupported-format`，不能借由这个规则伪装成 future family。

任一 fixed family 升到下一 schemaVersion 时，NiceEval 同时交付固定相邻 maintenance step，且只从保存的
closure 形成新 bytes。历史 Attachment 在转换完成前不能
`openRead`，不会进入 Analysis 或 Report。

## 不能走的捷径

- 把 Attachment 版本重新提升成 Record 全局版本；
- 让 generic writer 接受任意 JSON、path、bytes 或手写 blob ref；
- 把 session、claim、lease、migration history 或 cache 写进 Record；
- 在 ordinary read lease 内升级，或把另一 schema 伪装成 current 值；
- 为了少做 migration，把 Core 改成 `Record<string, unknown>`；
- 让第三方 converter 或当前业务算法重写历史事实。
