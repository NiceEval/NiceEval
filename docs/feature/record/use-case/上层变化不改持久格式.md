# 上层变化不改持久格式

本用例说明 Assert-first API、执行算法与展示方式怎样独立演进。判断依据是持久事实的语义与 shape，而不是上层模块或函数名。

## 当前稳定模型

```text
Assert-first author API
        ↓
Assertion evaluator / Match / Plugin lifecycle
        ↓
producer-owned Channel payloads
        ├─ niceeval.assertions/v1
        ├─ niceeval.verdict/v1
        ├─ niceeval.score/v1
        ├─ niceeval.eligibility/v1
        └─ niceeval.evaluations/v1
        ↓
generic Record
```

作者调用 API 时直接登记 Assertion。Record 保存 sealed AssertionResult，不保存 handle、Match 对象、调用控制流或 evaluator 的运行时对象。

AssertionResult 的持久投影包含 subject、evaluator identity 与安全 config、evaluation、evidence、policy，以及 pass 或 score projection。

## 每层只拥有自己的变化

| 变化 | owner | 持久边界 |
|---|---|---|
| Assertion authoring、Match 实现、Plugin lifecycle | producer / behavior | 行为变化时更新 input、config 或 reuse identity |
| AssertionResult payload shape 与语义 | Assertions | `RecordChannelSchemaId` |
| consumer 所需 typed view | consumer | 新 projector export / Library API |
| 页面、聚合与下载 | Reports | Report definition 与 Calculation |
| owner、reference、path 与 publish unit | Record | `RecordFormatId` |

一次 fixture 产生相同 bytes 不能证明行为等价。运行条件或 reuse gate 可能改变时，behavior identity 仍要更新。

## Pass Eval 与 Score Eval

`niceeval.evaluations/v1` 是 Run-owned closed payload：

```ts
type EvaluationsDocumentV1 = {
  evaluations: readonly {
    evalId: EvalId;
    evaluationKind: "pass" | "score";
  }[];
};
```

它包含 expected slots 中的每个 distinct `evalId`。Report 在 composition 阶段读取它，不回到当前源码猜评估类型。

每个 origin Attempt（Pass 或 Score）的判定面都是完整四态 Verdict。Score Eval 的 origin Attempt 另有 score grading，由独立 score Channel 保存；Verdict 与 score 不互斥也不可互推。Pass 与 Score 都保留完整 AssertionResult 集合。

ExpectedSlot 保存 `evalId` 与 attempt ordinal，因为它们属于 Record v1 的分母和引用完整性。评估类型仍属于 Channel。

## Assertions Channel 与 projector

`niceeval.assertions/v1` 精确保存 AssertionResult 的稳定投影。它不保存未执行源码对应的虚构 entry，也不把 measurement 当成 Pass Eval score。

`assertionsProjector` 只读取 Attempt-owned Assertions Channel。它把已解码 payload 形成自包含 typed view，不读取当前源码、其它 Channel 或外部服务。

一个 projector 可以声明多个 schema case，但每个 case 都必须无损形成同一 typed view。同一 projector 的返回类型与语义保持不变。

## reuse 是独立边界

能显示一个 Attempt，不表示能把它用于当前目标。reuse planning 显式声明需要的 Verdict、score、Eligibility 与其它 projections。

每个 reuse gate 都进入 `reuseContract.domain` 或对应 behavior identity。不受当前 policy 接受的 schema、domain 或 equality token 一律形成 gap。

Record 只保存当时的 recorded claims。它不把某个 Attempt 持续认证为“当前仍可复用”。

## Record major migration

Channel payload 与 typed view 的变化不要求 Core migration。只有 owner、reference、path 或 atomic publish unit 改变时，才发布新的 Record major。

普通 reader 只打开 current major。已知可迁移 source major 返回 `record-migration-required`，用户执行 `niceeval migrate`。

migration 只转换 Core 表示并保留 Channel closure。它不运行 Assertion evaluator、Channel projector 或 reuse planning，也不产生新的业务值。

## 验收问题

每次上层重构都回答：

1. Channel payload 的 shape、顺序和语义是否逐项相同？
2. typed view 的精确类型与语义是否相同？
3. 相同输入的可观察行为是否可能改变？
4. reuse gate 或比较安全边界是否改变？
5. owner、reference、path 或 atomic publish unit 是否改变？

前两项决定 Channel schema 与 projector。第三、四项决定 behavior identity。只有第五项可能触发 Record major migration。
