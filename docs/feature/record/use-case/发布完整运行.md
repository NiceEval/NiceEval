# 发布一轮完整 Run

本用例面向 Runner 或受信任的第三方 producer。目标是在一个 `RecordWriteSession` 中读取 frozen history、执行 gaps，并用最后写入的完成标识发布 Run。

## 1. 昂贵工作前建立写边界

```ts
const program = Effect.scoped(
  Effect.gen(function* () {
    const session = yield* openRecordWriteSession({ root });
    return yield* produceRuns(session);
  }),
);
```

constructor 在模型、Sandbox、外部命令或付费调用前：

1. 打开或初始化 current Record；
2. 取得 shared maintenance lock；
3. 取得 exclusive writer lock；
4. 冻结 `session.view` 中已完成的历史 Run。

任一步失败都不启动昂贵工作。reader 可以与 writer 并发。

## 2. 形成 Evaluation plan 与 reuse plan

producer 用 expected SlotId 形成 Evaluation plan。reuse planning 只从 `session.view` 选择历史 Attempt，并把每个 Slot 判为 reference 或 gap。

本 session 后来完成的 Run 不反过来参与这次 planning。RecordAttachment missing、migration-required、migration-unavailable、unsupported、invalid 或当前 reuse domain 不匹配都可以形成 gap；这个判断属于 reuse planning，不属于 Record。

## 3. 形成 origin 与 reference intent

实际执行在 Evaluation plan 中形成 origin Attempt intent；历史沿用形成 reference intent。`frozenAttempt` 必须来自同一 `session.view`。reference Member 只保存 `{ originRunId, attemptId }`，不复制历史 Attempt。

Member 不保存 executed、reuse 或 manual adoption。形成原因写入 Run-owned Membership Provenance RecordAttachment。

## 4. EvaluationRecordContract 先验证业务事实

官方 Evaluation producer 先把本轮 producer 的领域组合交给 `EvaluationRecordContract`，通过后才调用 generic writer：

| 事实 | owner |
|---|---|
| AssertionResult | Attempt |
| Pass/Score Attempt 的四态 Verdict | Attempt |
| Score Eval 的 Score | Attempt |
| reuse Eligibility | Attempt |
| Conversation、Usage、Timing、Commands、Diff | Attempt |
| Evaluation 类型与 Slot 映射 | Run |
| Sources 与 Invocation provenance | Run |
| Member 采用原因 | Run |

通过 contract 后 producer 才能调用 `createRun`、`record`、`createAttempt`、`reference` 或 `publish`。generic writer 不理解这些领域名字；它只验证 typed RecordAttachment write、Core、owner、owner-local closure 与精确引用。

第三方 producer 使用 `defineJsonRecordAttachment` 与 `makeRecordAttachmentWrite`。它不能把 raw name、path 或任意 JSON 直接交给 writer。

## 5. 写入并创建完成标识

contract 通过后，producer 把已验证的 plan 写进 generic writer：

```ts
const draft = yield* session.createRun({ startedAt, expectedSlots });
const attempt = yield* draft.createAttempt({ slotId });
yield* attempt.record(makeRecordAttachmentWrite(verdictFamily, verdict));
yield* draft.reference({ slotId: reusedSlotId, attempt: frozenAttempt });
const receipt = yield* draft.publish({ completedAt });
```

`publish` 直接处理 `runs/<RunId>/`：

1. exact encode 最终 `run.json`；
2. 验证 expected slots、Member 与 origin Attempt；
3. 验证 typed RecordAttachment definition、owner 与 closure；
4. flush 并关闭已写文件；
5. 最后 exclusive create zero-byte `complete`；
6. 返回 receipt，并永久 consume draft。

`publish` 不验证 Evaluation 的领域组合；那是 `EvaluationRecordContract` 在 writer 之前完成的职责。

## 6. 中断与删除未完成 Run

完成标识之前发生 interruption、I/O failure 或进程退出时，Run 没有发布。目录留在 `runs/<RunId>/`，以后 reader 忽略并 warning。

用户运行：

```sh
niceeval clean
```

clean 取得 writer lock，重新检查完成标识，再删除仍未完成的目录。它不删除已完成但 Core invalid 的 Run。

完成标识之后发生 interruption 时，Run 已经发布。以后 reader 以磁盘标识为准；receipt 没有返回不等于撤销事实。

## 7. 重新读取

当前 reader snapshot 不自动看见刚完成的 Run。`show`、`view` 或下次 planning 重新打开 reader 后才看见它。

一次 Invocation 的多个 Run 分别完成，没有 Invocation 级事务。reader 可以只看见其中一部分，但每个显示出来的 Run 都带完成标识。

## 反例

| 错误做法 | 违反的边界 |
|---|---|
| 没有完成标识也把目录加入 candidates | 半成品进入分析与 reuse |
| 创建完成标识后继续补 `completedAt` 或 RecordAttachment | published Run 不再 immutable |
| clean 自动删除有完成标识的 invalid Run | 维护命令删除已发布事实 |
| 把 session、lock 或 cache 写进 Record | local 状态进入 portable boundary |
| 让 generic writer 判断 Verdict 或 reuse | Record 接管领域 contract |
| 给 producer 暴露 raw JSON/path writer | typed RecordAttachment 边界失效 |
| 把采用原因写成 Member kind | 当前 policy 被固化进 Core |
