# 发布一轮完整 Run

本用例面向 Runner 或第三方 producer。目标是在一个 `RecordWriteSession` 中读取 frozen history、执行 gaps，并把每个完整 Run 原子发布。

运行中状态只进入当前进程和 local session。portable Record 只包含已经封口的 Run。

## 1. 昂贵工作前建立写边界

```ts
const program = Effect.scoped(
  Effect.gen(function* () {
    const session = yield* openRecordWriteSession({
      root,
      createIfMissing: true,
    });

    return yield* produceRuns(session);
  }),
);
```

constructor 依次完成：

1. 求得 canonical root，并映射 local sidecar；
2. 检查未收敛的 migration state；
3. 读取或初始化 current Record major；
4. 取得 shared maintenance lease，再取得 exclusive writer lock；
5. 检查遗留 Run publish sessions；
6. preflight no-follow、file/dir `fsync` 与 no-replace directory rename；
7. 创建 local session，并冻结 `session.view`。

任一步失败都不能启动模型、Sandbox、外部命令或付费调用。reader 可以在正常 writer session 期间并发。

## 2. 形成 target 与 reuse planning

Invocation builder 在内存中为目标 Run 和 slot 分配 identity，绑定 `startedAt` 和完整 expected slots。它把当前 target 与 `session.view` 交给 reuse planning。

reuse planning 只从 frozen candidate set 选择 source，并沿已选 Member 建 dependency closure。每个 slot 穷尽形成 `reuse | gap`。

本 session 后来发布的 Run 不会反过来参与这次 planning。任何 required Channel unavailable、unsupported、invalid 或 domain mismatch 都形成 gap。

## 3. 内部 EvaluationRecordContract 先验证领域 aggregate

官方 Evaluation producer 用内部 `EvaluationRecordContract` 验证一次运行形成的事实：

| recorded claim | owner 与 schema |
|---|---|
| Assertion outcomes | Attempt / `niceeval.assertions/v1` |
| Pass Eval terminal Verdict | Attempt / `niceeval.verdict/v1` |
| Score Eval grading | Attempt / `niceeval.score/v1` |
| reuse eligibility | Attempt / `niceeval.eligibility/v1` |
| usage、timing、conversation、commands、diff | 对应 Attempt schema |
| diagnostics | Attempt 或 Run / `niceeval.diagnostics/v1` |
| Eval source closure | origin Run / `niceeval.sources/v1` |
| 每个 distinct Eval 的 `pass | score` | Run / `niceeval.evaluations/v1` |
| Member 形成原因与 gap | Run / `niceeval.membership-provenance/v1` |
| Invocation provenance | Run / `niceeval.run-provenance/v1` |

contract 验证这些 Channel 的 required 集合和交叉关系。通过后才把 aggregate 转成 generic `StagedRunInput`。

generic writer 只验证 Core、固定 envelope、closure、references 与 crash safety。它不评估 Assertion、Verdict 或 reuse policy。

custom producer 通过自己持有的 `JsonChannelDefinition` 写入。它不能传 raw ChannelName、path 或任意 `JsonValue` 绕过 typed boundary。

## 4. Core 只保存占位关系

实际执行产生的 Attempt 住在当前 origin Run，并由唯一 origin Member 锚定。其它 Member 只保存精确 `{ originRunId, attemptId }` reference。

Member 不保存 executed、reuse 或 manual adoption。形成原因只进入 `niceeval.membership-provenance/v1`；未来沿用资格由 eligibility 与当前 reuse planning 决定。

当前进度、心跳、尚未完成的 event 和 Sandbox handle 不进入 portable Record。崩溃后的 building session 不能继续外部执行，只能显式 abandon。

## 5. seal 整个 Run

producer 先形成最终 `completedAt`、expected membership、已有 Member 与全部 Channel。没有 outcome 的 expected slot 保持无 Member。

`stageRun()` 和 `sealRun()` 依次完成：

1. 验证 Core identity、origin 与 reference；
2. 验证 `ChannelEnvelopeV1`、单文件或官方 closure、schema 与 collection；
3. 拒绝 link、越界 path、重叠 closure 和未声明文件；
4. `fsync` 并关闭普通文件；
5. 把完整 Run 放进 local `publish/<runId>`，随后禁止修改；
6. 持久化位于被移动目录之外的 recovery manifest。

第 6 步完成后才返回 opaque `SealedRun`。它只可由创建它的 session 发布一次。

## 6. publish 与 recovery

`publishRun()` 重新验证 source 与 destination，再执行 no-replace directory rename。成功后对 parent directory 执行 `fsync`，并从 destination 重验 manifest。

一次 Invocation 的多个 Run 逐个发布，没有 Invocation 级事务。reader 可以只看见其中一部分，但每个可见 Run 都完整。

Scope finalizer 只删除本 session 尚未 seal 的 staging directory。它不能删除 sealed、visible、durable 或 cleanup-pending 现场。

遗留 sealed session 使用：

```text
niceeval record recover --session <sessionId> --commit-only
```

用户明确不要 building session 时使用：

```text
niceeval record abandon --session <sessionId>
```

commit-only recovery 不调用 producer、projector、模型或 Sandbox。

## 7. 返回 receipt，再重新读取

Runner 返回窄 `InvocationReceipt`：Invocation identity、Run identities、起止时间与 completion。receipt 不复制 Verdict、usage、locator 或聚合读数。

`show` 或 `view` 可以在 writer 仍工作时打开另一个 reader。它们取得 shared maintenance lease，并可能看见已经发布的完整 Run。

## 反例

| 错误做法 | 违反的边界 |
|---|---|
| 在 final Run 目录逐文件追加 | reader 可能看见半个提交单位 |
| 把 session、lock、migration state 或 cache 写进 Record | local 状态进入 portable boundary |
| publish 后补 `completedAt` 或 Channel | 已发布 Run 不再 immutable |
| 给新业务增加 `RecordWriter.writeX2()` | generic storage API 跟随业务代际扩张 |
| 让 generic writer 评估 Assertions 或 Verdict | Record 接管了 EvaluationRecordContract 的职责 |
| 给每个 Eval 暴露 raw `writeChannel` | 任意 payload 绕过 typed producer capability |
| 把 reuse 原因写成 Member kind | 业务 policy 被固定进 Core |
