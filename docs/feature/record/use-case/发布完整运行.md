# 发布一轮完整 Run

本用例面向 NiceEval Runner 与官方内部 producer。目标是在一个
`RecordWriteSession` 中读取 frozen history、执行 gaps，并以最后写入的完成标识发布
Run。

契约单源始终在 [Record Library](../library.md) 与
[Record 架构](../architecture.md)。本页只串起 producer 的调用顺序。

## 1. 昂贵工作前建立写边界

```ts
const program = Effect.scoped(
  Effect.gen(function* () {
    const session = yield* openRecordWriteSession({ root });
    return yield* produceRuns(session);
  }),
);
```

constructor 在模型、Sandbox、外部命令或付费调用前：

1. 打开或初始化 current Record；
2. 取得 shared maintenance lock；
3. 取得 exclusive writer lock；
4. 冻结 `session.view` 中已完成的历史 Run。

任一步失败都不启动昂贵工作。reader 可以与 writer 并发。`session.view` 是完整
`FrozenRecordView`，所以 reuse planning 与普通 reader 使用相同的 snapshot contract。

## 2. 形成 Evaluation plan 与 reuse plan

producer 用 expected SlotId 形成 Evaluation plan。reuse planning 只从 `session.view`
选择历史 Attempt，并把每个 Slot 判为 reference 或 gap。

本 session 后来完成的 Run 不反过来参与这次 planning。Attachment `unavailable`、
`migration-required`、`migration-unavailable`、`unsupported`、`invalid` 或当前 reuse
domain 不匹配都可以形成 gap；这个判断属于 reuse planning，不属于 Record。

## 3. 形成 origin 与 reference intent

实际执行在 Evaluation plan 中形成 origin Attempt intent；历史沿用形成 reference intent。
`FrozenRecordAttempt` 必须来自同一 `session.view`。reference Member 只保存
`{ originRunId, attemptId }`，不复制历史 Attempt。

Member 不保存 executed、reuse 或 manual adoption。形成原因写入 Run-owned Membership
Provenance Attachment。

## 4. EvaluationRecordContract 先验证业务事实

官方 Evaluation producer 先把本轮 producer 的领域组合交给
`EvaluationRecordContract`，通过后才调用 generic writer：

| 事实 | owner |
|---|---|
| AssertionResult | Attempt |
| Pass/Score Attempt 的四态 Verdict | Attempt |
| Score Eval 的 Score | Attempt |
| reuse Eligibility | Attempt |
| Conversation、Usage、Timing、Commands、Diff | Attempt |
| Evaluation 类型与 Slot 映射 | Run |
| Sources 与 Invocation provenance | Run |
| Member 采用原因 | Run |

通过 contract 后 producer 才能调用 `createRun`、`record`、`createAttempt`、
`reference` 或 `publish`。generic writer 不理解这些领域名字；它只验证 typed Attachment
write、Core、owner、完整 owner-local closure 与精确引用。

内部 producer 通过 definition、family 与 `makeRecordAttachmentWrite` 形成 write。
builder 为每个 `RecordBlobSource<E, R>` mint ref，并同时捕获 payload、ref 与 blob Stream。
它不能把 raw name、path、bytes 或手写 ref 直接交给 writer。

## 5. 写入、等待与创建完成标识

contract 通过后，producer 把已验证的 plan 写进 generic writer：

```ts
const draft = yield* session.createRun({ startedAt, expectedSlots });
const attempt = yield* draft.createAttempt({ slotId });
yield* attempt.record(verdictWrite);
yield* draft.reference({ slotId: reusedSlotId, attempt: frozenAttempt });
const receipt = yield* draft.publish({ completedAt });
```

`record<E, R>` 在 `open` state 消费 blob Stream，exact encode payload，并验证 refs 与完整
closure。它返回 `RecordWriteError | E`，且把 service requirements 保留在 `R`。

`publish` 立即把 draft 变为 `publishing`。此后不接受新的 mutation，却会等待已经在飞的
mutation 停稳。它在 marker 前完成 Core、Member、Attachment、reference 与 closure
validation，并构造 receipt。

最后的短暂 `Effect.uninterruptibleMask` 只做：

1. final flush 并 close Run 的全部 durable handles；
2. exclusive create zero-byte `complete`；
3. 同步把 draft consume 为 `published`。

`complete` 之后没有可失败的业务步骤。`published` 或 `failed` draft 都不可重用。

## 6. 中断、失败与删除未完成 Run

完成标识之前发生 interruption、I/O failure、typed write failure 或进程退出时，Run
没有发布。draft 进入 `failed`，directory 留在 `runs/<RunId>/`，以后 reader 忽略并
warning。

用户运行：

```sh
niceeval clean
```

clean 取得 writer lock，重新检查完成标识，再删除仍未完成的 directory。它不删除已完成
但 Core invalid 的 Run。Scope finalizer 也不做这项删除。

完成标识之后发生 interruption 时，Run 已经发布。以后 reader 以磁盘标识为准；receipt
没有返回不等于撤销事实。release finalizer failure 是 diagnostic defect，不是 typed
business failure。

## 7. 重新读取

当前 reader snapshot 不自动看见刚完成的 Run。`show`、`view` 或下次 planning 重新打开
reader 后才看见它。

一次 Invocation 的多个 Run 分别完成，没有 Invocation 级事务。reader 可以只看见其中一
部分，但每个显示出来的 Run 都带完成标识。

## 反例

| 错误做法 | 违反的边界 |
|---|---|
| 没有完成标识也把 directory 加入 candidates | 半成品进入分析与 reuse |
| 创建完成标识后继续补 `completedAt` 或 Attachment | published Run 不再 immutable |
| clean 自动删除有完成标识的 invalid Run | 维护命令删除已发布事实 |
| 把 session、lock 或 cache 写进 Record | local state 进入 portable boundary |
| 让 generic writer 判断 Verdict 或 reuse | Record 接管领域 contract |
| 给 producer 暴露 raw JSON、path 或 bytes writer | typed Attachment closure 边界失效 |
| 把 old blob ref 放进新 Attachment | 旧 closure 冒充新 closure |
| 把采用原因写成 Member kind | 当前 policy 被固化进 Core |
