# 发布一轮完整 Run

Experiment Host 要让一次运行成为可读事实，必须完成 Attempt backlog fence 与 Run final Seal transaction；append admission、
中间 batch commit 与 `sealing` 都不是 publication。

## 1. 创建 open Run

```ts
const run = yield* host.createRun({ store, core });
const attempt = yield* run.createAttempt({ slotId });
```

Host 在昂贵工作前验证 database header、format identity、storage revision 与 fixed schema allowlist。create transaction 写入
`open` Run、Slot 与 writer generation。predecessor 要求显式 migration；ordinary execution 不自动维护。

## 2. 接纳 facts

rich family 通过 `records.write()` 提交一次完整 closure。collection 通过 `append` / `appendAll(Stream)` 增量进入同时有 count
与 byte limit 的 mailbox，并通过 `close(complete | partial)` 显式表达领域 completion。

append 成功只确认 immutable command 已取得 sequence。dedicated storage worker 把 commands 组成 bounded batch，先取得
per-root writer admission ticket，再运行 short transaction。provider、Sandbox、builder 与 Stream backpressure 不持有
transaction。

pre-enqueue cancellation 不留 sequence；post-enqueue cancellation 只停止调用方等待，command 留在 backlog。commit 后 ack 前
崩溃以冻结 command identity 重读 committed success；identity/digest conflict poison writer。

## 3. Attempt completion fence

```ts
yield* attempt.records.close(turnMetrics, { state: "complete" });
yield* attempt.complete("completed");
```

`attempt.complete()` 关闭新 admission，等待所有已接纳 sequence durable，并传播后台 Schema/storage failure。仍有 active 但未
close 的 collection 时它必须失败；Host 不能从 Stream 正常结束、outcome 或 interruption 猜测 complete/partial。

## 4. Final Seal transaction

```ts
const receipt = yield* run.seal({ completedAt });
```

全部 Attempt fence 成功后，finalizer 把 Run 切到 `sealing`，在 transaction 外流式验证 Core、Attachment、items、references、
Content、unknown inventory 与候选 Seal。最终短 transaction 重新验证 writer generation、counts、digests 与 inventory identity，
插入全部 Seal rows 并切到 `sealed`。

Seal commit 前崩溃会整体 rollback，ordinary reader 仍不可见；recovery finalizer 重验后只 seal 一次。Commit 后 receipt 丢失
不撤销事实。reader 始终只选择 `sealed` status。

## 5. 分享

新 sealed Run 已在 operational `<project>/.niceeval/record.sqlite` 中可读，但 database 仍不能直接 copy、Git 或作为 `--record`。
用户需要可搬运结果时调用 Host Snapshot：barrier 固定 source，target 删除 unpublished closure并 `VACUUM INTO` sealed-only
database，通过 exact validation 后才返回 `RecordSnapshot`。
