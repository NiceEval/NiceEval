# 核对数据完整度

自动化先发现可问的固定 operation，再审计某个已封存结果是否完整。命令与输出契约单源始终在
[Inspection CLI](../cli.md)。

```sh
niceeval query discover
niceeval query explain --request operation.json
niceeval query run --request operation.json
```

discovery 先给 compact bootstrap。选择 operation 后，调用方取得 schema、合法 selector 与
最小 follow-up request。`explain` 在读取重 payload 前交付 source、selection、comparison
mode 与 fact kinds，随后 `run` 返回对应的闭合 document。

列表与重 payload 使用 bounded domain page。继续读取时，调用方原样传回 opaque continuation
token，而不传递 DB cursor、rowid、文件位置或 page size。token 所绑定的 Record、sealed cutoff、
request 或 `behaviorVersion` 变化时，调用方接受 restart correction，不拼接不同 document 的页。

结果中的 denominator、missing、limits、issues、basis 与 Evidence 共同说明完整度。
`run.summary` 交付 sealed usage totals；conversation 子通道的 limitation 不会把完整 usage
改写为 partial 或 missing。需要快速的终端人读审阅时使用 `niceeval show`；需要浏览器
连续审阅时进入 [Insight](../../insight/README.md)。两者执行相同 operation，都不读取或转换这次 CLI
的 protocol document。

原子选择失败不猜测相邻 execution 项，也不输出已成功 section 的半张结果：

```text
$ niceeval show @ATTEMPT-NEXT --execution --expand tool_unknown
error: execution item "tool_unknown" is not available for @ATTEMPT-NEXT
```

命令写 stderr 并以非零状态退出。`tool_unknown` 不是 stable identity index 暴露的 `itemId`、`toolOccurrenceId` 或
`commandId`，因此不能按显示位置、文本或相邻项补配。
