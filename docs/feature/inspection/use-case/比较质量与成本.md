# 比较质量与成本

用户先检查当前评估的可用结果，再比较质量与成本。当前结果的分母来自当前 Experiment、Eval 和 Attempt 数量；
固定 Run 保留当时的范围与证据。命令与指标规则单源在 [Inspection CLI](../cli.md) 和 [Inspection 架构](../architecture.md)。

## 先看当前结果可用性

三条 Eval 已有完整结果。修改其中一条的判据，再新增第四条，随后执行：

```sh
niceeval show
niceeval show --experiment harness/canary
```

```text
Current results
  Covered 2/4
  Gaps 2

Experiment harness/canary
  Covered 2/4
  Gaps 2

  Eval changed-case
  Gap identity-mismatch
  Previous result @1K1P0VJAPVJ12

  Eval new-case
  Gap no-result

Next: niceeval exp harness/canary --dry
```

历史三条结果不能被显示成当前 `3/3`，变更前的分数也不能填入缺口。旧 locator 只提供下钻入口。
默认当前摘要和 `--experiment` 都来自 `project.get`，收窄时不能换成历史成员集合。

```sh
niceeval show @1K1P0VJAPVJ12 --source
niceeval exp harness/canary --dry
```

dry plan 应只执行两个缺口，其它位置沿用。判据已经变化的结果不能 accept；
符合[有限采用规则](../../experiments/cache.md#显式采用的资格)的配置变化，才可以先预览并明确采用。
相同目标下，采用后当前结果可用性与后续沿用应一致。

## 按题型解释指标

Pass 与 Score 使用不同的质量读数，Coverage 只表示当前可用结果的数量。
例如三条当前 Pass 结果里两条 passed、一条 failed，另一个位置缺失：

```text
Covered 3/4
Gaps 1
Verdicts 2 passed; 1 failed
Pass rate 66.67% (partial)
```

失败但完整的 Pass 结果仍计为一个位置的可用结果。缺口不算 failed，不能把通过率算成 `2/4`。

计分题里一条完整零分、一条 partial score、两条没有结果时：

```text
Covered 1/4
Gaps 3
Outcomes 1 scored
Score 0 (partial)
```

完整零分贡献当前成绩；partial Attempt 的已知下界留在详情，不能混入完整结果均值。
同一 Eval 的完整 Attempt 取均值，跨 Eval 对已有贡献求和；不外推完整总分或虚构总满分。
Score 不显示 passed 或 Pass rate。缺少成本的结果也不按零成本处理。

路径分组与表格只负责呈现 operation 已关闭的指标。质量与成本部分可用时，保留各自样本分母，
不能仅凭一个总分给可用样本范围不同的 Experiment 排名。

## 用固定历史核对 origin

删除 Experiment 后，它退出当前分母，只在 History 留下旧结果入口。源码求值失败时，当前查看明确报错；
以下历史读取始终不依赖当前定义：

```sh
niceeval show --run <source-run-id>
niceeval show @1K1P0VJAPVJ12
```

机器读取当前结果使用：

```json
{
  "protocol": "niceeval.query/v1",
  "operation": { "kind": "project.get", "experimentIds": ["harness/canary"] }
}
```

读取整个 Record 的历史摘要则使用 `overview.get`；精确历史 Experiment 使用 `experiment.get`。
它们不声称旧结果仍适用于当前评估。只有 Record 的 source不能执行 `project.get`，应返回 `current-target-unavailable`，
不能悄悄改成历史汇总。

## 比较明确的两次运行

需要判断两组 Run 是否可比时，以两个明确 Run 集构造固定请求：

```json
{
  "protocol": "niceeval.query/v1",
  "operation": {
    "kind": "runs.compare",
    "mode": "paired",
    "leftRunIds": ["<left>"],
    "rightRunIds": ["<right>"]
  }
}
```

`side-by-side` 分别交付两组结果，不产生 delta。`exact` 要求 member domain 与 exact member set 相同。
`paired` 使用第一方 pairing key，保留两侧和配对分母、unmatched、excluded、missing、issues 与 Evidence。

消费者只读取 operation 的可比性与指标，不补配成员、不丢弃 unmatched，也不根据标量重新计算排名。
`--rerun all` 只改变下一次执行动作；新 Run 实际创建后，其 pending 位置才成为当前读取的新屏障。
当前可用结果不足也不等于 Invocation 未完成，early exit 与预算终态仍以固定 Run/receipt 为准。
