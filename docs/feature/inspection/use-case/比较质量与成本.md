# 比较质量与成本

用户先用默认 Results 查看各 Experiment × Eval 的成本、通过率、分数与完整度，再在需要严格对照时比较
多个持续可读 Run。两步都要一起审计成员、分母、missing 与 Evidence，而不是只相减两个数字。
命令行为与稳定布局规则单源始终在 [Inspection CLI](../cli.md) 与
[Inspection 架构](../architecture.md)。

## 查看 pass 制 Results

纯 pass 制评测的质量读数就是 Verdicts 与 Pass rate。Score 对它不适用，human renderer 不显示
`unsupported` 占位行或列：

```text
$ niceeval show
NiceEval results
  Totals

  Observed   180/180
  Verdicts   158 passed; 17 failed; 5 errored; 0 skipped
  Pass rate  87.78%

Experiments
  compare
  Experiment     Observed  Agent  Model         Pass rate
  -------------  --------  -----  ------------  ---------
  bub            36/36     bub    gpt-5.6-luna  88.89%
  codex          36/36     codex  gpt-5.6-luna  83.33%

Attempts · compare
  Experiment compare/bub
  Eval downshift/pr-1414
  Attempt         Verdict  Duration
  --------------  -------  --------
  @ATTEMPT-BUB-2  failed   20.12 s
  @ATTEMPT-BUB-3  errored  2.09 s

  34 passed Attempts hidden
  See more  niceeval show --experiment compare/bub --all
```

Attempt 表用缩进保留 Experiment → Eval → Attempt 的一对多关系：Eval ID 只显示一次，
同一 Eval 的每个可见 Attempt 各占一行，并显示各自的 Verdict 与 Duration。默认隐藏 passed Attempt，
但 failed、errored、skipped、pending 与 absent 始终可见；复制 `See more` 命令可展开该 Experiment 的全部 Attempt。
machine `overview.get` 仍保留 score metric 的 typed `unsupported`；
省略 Score 只是人读布局，不改变事实。

## 查看 score 制 Results 并收窄到 Experiment

下面的 locator、Run 与 Experiment ID 都是文档专用的 adopted target 示例，不是用户运行的实际值。

```text
$ niceeval show
NiceEval results
  Totals

  Observed   6/6
  Verdicts   6 passed
  Pass rate  100%
  Score      74

Experiments
  harness
  Experiment  Observed  Pass rate  Score
  ----------  --------  ---------  -----
  canary      3/3       100%       32
  v-next      2/2       100%       32

  install
  Experiment  Observed  Pass rate  Score
  ----------  --------  ---------  -----
  canary      1/1       100%       10

Attempts · harness
  Experiment harness/canary
  3 passed Attempts hidden
  See more  niceeval show --experiment harness/canary --all

  Experiment harness/v-next
  2 passed Attempts hidden
  See more  niceeval show --experiment harness/v-next --all

Attempts · install
  Experiment install/canary
  1 passed Attempts hidden
  See more  niceeval show --experiment install/canary --all
```

每个新 Experiment 标题都在上一张表结束后另起一段，标题后立即接其表头；标题后的空行会把它视觉上归到上一表，
因此不属于稳定布局。没有 `/` 的 Experiment 使用完整 ID，且不进入路径分组；Eval 只有在首段与显示分组相同时才使用
相对标签。身份在窄终端也不截断，只能折行。

要审阅一个 cell 而非 Results 的残片时，使用 exact selector：

```text
$ niceeval show --experiment harness/v-next
Experiment harness/v-next
  Summary

  Observed   2/2
  Verdicts   2 passed
  Pass rate  100%
  Score      32

  Attempts
  2 passed Attempts hidden
  See more  niceeval show --experiment harness/v-next --all
```

这组 Summary 与 Attempts 来自 `experiment.get`，不是 renderer 对默认 Results 的二次筛选或补值。
需要逐项核查成功结果时运行上面的 `--all` 命令，展开后仍按 Eval 缩进列出 Attempt、Verdict、Duration 与适用的 Score。

默认 Results 回答“canonical Record 中每个逻辑 slot 最新发布了什么”。当 Eval 内容、Experiment 配置、
Sandbox identity 或当前安装的候选变化时，已封口 Attempt 仍留在 Overview；因此无 selector `niceeval show` 不会仅因
当前 identity 与 Record 不同就返回 `Observed 0/0`。用户可以从 Overview 继续下钻 Run ID 或 locator，并根据
Run identity 判断结果属于哪次运行。

Overview 可见不等于当前 target 可复用。Experiment planning 仍以 execution identity 判断 `reuse | gap`；
`niceeval accept @<locator>` 只在用户确认旧证据适用时发布当前 target identity 的 reference Member，不作为查看已发布结果的前置条件。

```json
{
  "protocol": "niceeval.query/v1",
  "operation": { "kind": "overview.get" }
}
```

`overview.get` 的 cell 已经关闭 Experiment × Eval cost、pass rate、score 与 denominator。human renderer 按当前
投影的 evaluation kind 选择可用的质量列，不会把 pass rate 和 score 混成一个读数。用户从异常 cell 的
Attempt locator 进入 `attempt.get` 或 `attempt.trace`；machine consumer 不需要枚举 Run 后自己拼 board。
需要证明两组 Run 是否可比时，再使用 `runs.compare`：

```json
{
  "protocol": "niceeval.query/v1",
  "operation": {
    "kind": "runs.compare",
    "mode": "paired",
    "leftRunIds": ["<left>"],
    "rightRunIds": ["<right>"]
  }
}
```

`side-by-side` 分别交付两组结果，不产生 delta。`exact` 只在 member domain 与 exact member set 相同后成立。
`paired` 只使用 NiceEval 第一方 pairing key，并在同一个 `outcome: success` document 中交付 left、right、pair
的 denominator。pairs、unmatched、excluded、missing、issues 与 Evidence 一并保留。

只有 Inspection operation 决定成员是否匹配、分母是否相同与结果是否可比。machine consumer
与 [Insight](../../insight/README.md) 都使用同一 result meaning，不能补配、删掉 unmatched，或从
未包装 scalar 重算排名、趋势或聚合。Insight 不读取此 CLI document；它在自己的 `PublicationCutoff` 上经
sqlite-wasm 执行同一个固定 operation。
