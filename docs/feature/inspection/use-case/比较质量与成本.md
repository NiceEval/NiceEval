# 比较质量与成本

用户比较多个已封存 Run 时，需要一起审计成员、分母、missing 与 Evidence，而不是只相减两个
数字。命令与比较语义单源始终在 [Inspection CLI](../cli.md) 与
[Inspection 架构](../architecture.md)。

```json
{
  "protocol": "niceeval.query/v1",
  "operation": {
    "kind": "runs.compare",
    "request": {
      "mode": "paired",
      "left": { "runs": ["<left>"] },
      "right": { "runs": ["<right>"] }
    }
  }
}
```

`side-by-side` 分别交付两组结果，不产生 delta。`exact` 只在 member domain 与 exact member
set 相同后成立。`paired` 只使用 NiceEval 第一方 pairing key，并在同一个 document 中交付
left、right、pair 的 denominator，以及 pairs、unmatched、excluded、missing、issues 与 Evidence。

只有 Inspection operation 决定成员是否匹配、分母是否相同与结果是否可比。machine consumer
与 [Insight](../../insight/README.md) 都使用同一 result meaning，不能补配、删掉 unmatched，或从
未包装 scalar 重算排名、趋势或聚合。Insight 不读取此 CLI document；它在完整 Snapshot 上经
sqlite-wasm 执行同一个固定 operation。
