# 查看运行

## 用户目标

找到一次评测的 exact Run ID，查看已经发布的结果，并区分尚未运行的位置与已结束运行中的缺口。

## 起始状态

在保存 Record 的项目目录中操作。项目已有一个已创建的 Run；它可以仍在执行，也可以已经结束。
本篇命令未实际运行，以下均为预期输出说明。`<run-id>` 要替换为列表返回的完整 ID。

## 完整路径

1. 列出项目中的 Run，找到目标 Experiment 对应的 Run。 {#list}

   ```sh
   niceeval run list
   ```

   预期输出：每项包含 Run ID、state、Experiment、开始与结束时间、`published / expected` 和 invocationId。
   Run 一经创建即可出现，不必等全部 Attempt 完成。若只查看一次 Invocation，使用 `niceeval run list --invocation <invocation-id>`。

2. 复制完整 ID，打开这一次运行。 {#show}

   ```sh
   niceeval show run:<run-id>
   ```

   预期输出：该 Run 的状态、expected/published/missing、Planned attempt bindings、Attempt locators 与已发布结果。
   `active` 中尚未绑定的位置显示 pending；终态缺口显示 absence reason，不被算成虚构的 Attempt。

3. 需要把同一次查看交给脚本时，保留 exact ID 并请求机器输出。 {#json}

   ```sh
   niceeval show run:<run-id> --json
   ```

   预期输出：`operation: "run.get"` 的 machine document。字段契约由 Run CLI 与 Library 定义，不从人读文本拆字段。

## 结果

用户能定位并查看这一 Run 已发布的 Attempt。Run 仍为 `active` 或最终变为 `interrupted` / `failed`，都不撤销这些事实。
列表中的 `published / expected` 数量对应其读取时刻；之后再次查看时，活动 Run 可以新增已发布结果。

| 输入问题 | 处理 |
|---|---|
| 只提供前缀、`latest` 或省略 ID | 换成列表返回的 exact Run ID |
| Run 不存在或已删除 | 重新列出项目中的 Run，不用另一个 Run 冒充目标 |
