# 恢复中断运行

## 用户目标

评测进程已经终止，但 Run 仍显示 `active`。将它安全收口，同时保留此前发布的 Attempt。

## 起始状态

用户在原项目目录中。旧进程已终止；若 owner 仍活跃，本路径不能接管它。
本篇命令未实际运行，以下均为预期输出说明。`<run-id>` 替换为实际完整 ID。

## 完整路径

1. 找出遗留的 Run。 {#find}

   ```sh
   niceeval run list --state active
   ```

   预期输出：仍为 `active` 的 Run 按开始时间从新到旧列出，每项带 `owner alive`、`owner gone` 或 `owner unknown`。
   `owner gone` 的那些就是可以收口的遗留 Run。

2. 核对要恢复的 Run。 {#inspect}

   ```sh
   niceeval show run:<run-id>
   ```

   预期输出：目标 Run 为 `active`，并能看到已经发布的 Attempt 与尚为 pending 的位置。
   不用终端界面已经关闭来代替 owner 终止证明。

3. 对这个 exact Run 请求恢复，确认交互提示。 {#recover}

   ```sh
   niceeval run recover <run-id>
   ```

   预期输出：NiceEval 能证明旧 owner 已终止时，收口 Run 为 `interrupted`。
   证据不足则明确拒绝，不删除已发布的 Attempt。自动化场景确认目标无误后可用 `--yes --json`。
   遗留的 Run 不止一个时，用 `niceeval run recover --orphaned` 一次收口全部 `owner gone` 的 Run；它先列出目标再请求确认。

4. 再查看同一 Run，确认恢复结果。 {#verify}

   ```sh
   niceeval show run:<run-id>
   ```

   预期输出：成功恢复的 Run 显示 `interrupted`；已发布结果仍可查看，未绑定位置有终态 absence reason。
   若恢复过程被打断，按 [Run CLI](../cli.md) 的可重试恢复规则处理同一个 Run，不建立替代结果。

## 结果

遗留的活动 Run 已安全收口，原结果仍能复核。recover 不补跑缺失的 Attempt，也不恢复 Agent 执行。

| 情形 | 用户看到的结果与下一步 |
|---|---|
| owner 仍活跃或无法证明已终止 | 恢复拒绝；等待或核实旧进程状态，不强制接管 |
| Run 已是终态 | 领域拒绝；直接查看既有结果 |
| ID 无效或 Run 不存在 | 领域拒绝；从 `niceeval run list` 重新取得 exact ID |
| 列表显示 `owner unknown` | `--orphaned` 跳过它；确认 owner 所在机器上的进程已终止后，在那台机器上恢复 |
