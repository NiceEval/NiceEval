# `--reuse-sandbox`：本地冒烟一批 Eval

## 解决什么问题

改了公共 prompt、adapter 配置或共享 Fixture,想在本地把整组 eval 快速过一遍,看有没有明显挂。默认模式每个 attempt 一套全新沙箱:12 道题就是 12 次「起容器 + slim 镜像补系统依赖 + `npm install` + 装 agent CLI」。这批题共享同一套安装,重复付 12 次冷启动,总耗时被准备工作主导,真正跑题的时间只占零头。

## 全流程

1. 用 eval 前缀收窄选题,带上 flag:

   ```bash
   niceeval exp memory/commit0 onboarding --reuse-sandbox
   ```

2. PLAN 与启动反馈如实标注最多一个 Sandbox、有效宽度为 1、结果不进结果沿用与 CI：

   ```text
   Sandbox reuse: up to 1 sandbox · effective width 1
   Results excluded from carry-forward and CI: workdir-only reset
   ```

3. 第一题开跑前支付一次 `createSandbox` 与 SandboxSpec `setup`，然后建立
   复用 Sandbox 的题间重置点。
4. Agent 与 Eval `setup` / `teardown` 仍逐 Attempt 成对执行。稳定的 Agent 安装应在
   预制环境或 SandboxSpec Hook 中完成，不靠复用改变 Agent Hook 的次数。
5. 题间把 workdir reset 回题间重置点。Runner 每次派发前确认 Sandbox 复用寿命，
   不足时续期或轮换。
6. 结束反馈照常给判定汇总与 FAILED / NEXT；Attempt 记录 `sandbox.reused`，
   `show` / `view` 照常可查。

## 边界

- **结果只当冒烟信号。** 上一题写进 `$HOME`、全局安装或后台进程的东西会留给下一题;「串起来挂、单独跑过」出现时,用默认模式重跑那一题确认。
- **与结果沿用双向绝缘。** 复用 Attempt 永不被后续 Run 沿用；
  本次也不消费结果沿用，整批每一题都在共用的 Sandbox 中真实执行。
  要留下可供结果沿用的记录，去掉 CLI flag 再跑。
- **挂了想留现场?** `--keep-sandbox` 与 `--reuse-sandbox` 互斥(创建前报错)——换默认模式对那一题单独 `--keep-sandbox` 重跑,流程见 [keep-sandbox 用例](../留存现场/环境启动错误.md)。
