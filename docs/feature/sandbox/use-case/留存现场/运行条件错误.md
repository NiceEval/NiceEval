# `--keep-sandbox`:宿主运行条件类 errored,进现场手动重跑准备命令

## 解决什么问题

准备链装包失败、agent CLI 起不来——Attempt 的 Verdict Claim 为 `errored`,而这正是证据最薄的场景:agent 根本没跑,没有可用事件或 trace Observation，手里只有执行错误 Observation 与 timing Projection([为什么](../../cli.md))。
要定位「这条命令在那个现场里到底怎么失败的」,只能进活现场重跑一遍。

## 全流程

1. 收窄到挂的那条,带 flag 重跑(单独使用 `--keep-sandbox` 即 `failed` 档,含 `errored`):

   ```bash
   niceeval exp local onboarding/tool-first --keep-sandbox
   ```

2. run 收尾在摘要后给出留存面板(体裁见 [CLI · run 收尾输出](../../cli.md#run-收尾输出)),每条带 attempt 定位符、实例 id 和进入命令:

   ```text
   ╭─ KEPT SANDBOXES ─────────────────────────────────────────────────── 1 kept ─╮
   │ @6ZCNAVRHPQ4D2KG9EFW5TB8167  onboarding/tool-first #1  errored  docker · a3f9c2d1             │
   │            enter: niceeval sandbox enter a3f9c2d1                           │
   ╰─────────────────────────────────────────────── niceeval sandbox stop --all ─╯
   ```

3. 进现场。
   `enter` 自动唤醒休眠实例、落在 workdir:

   ```bash
   niceeval sandbox enter a3f9c2d1
   ```

4. 在现场手动重新执行失败的 prepare 命令(`npm install …`、装 agent CLI 的那一步),看真实报错:镜像缺系统依赖?registry 不通?版本冲突?配合 `niceeval show @6ZCNAVRHPQ4D2KG9EFW5TB8167` 的 phases 计时对照是哪一段挂的。
5. 退出 shell,现场自动回休眠,不烧资源;还要再看时重复 `enter`。
6. 定位后修 layer 声明——比如给 `dockerImageSandbox({ image })` 接一条 `.prepare(command("apt-get", ["install", "-y", "libfoo"], { user: "root" }))` 补依赖——正常重跑验证,然后销毁:

   ```bash
   niceeval sandbox stop a3f9c2d1
   ```

## 边界

- 被 Ctrl+C 中断的 run 不留存——留存授予发生在 verdict 定稿的收尾点。
- `defineSandbox` 自定义 provider 不支持 `--keep-sandbox`(创建前报错)。
- 与 Experiment 的 [`sandboxReuse: true`](../../reuse.md) 互斥：留存的现场必须只属于那一次 Attempt。
