# Sandbox 复用：批次包含多种环境

## 解决什么问题

选题范围一宽，批里就可能混进不同 sandbox spec 或 [`environment` profile](../../library/prebuilt-environments.md#按-environment-选预制产物)。
一个 Sandbox 只有一个题间重置点，不能同时代表两套环境。
Runner 按解析后的环境配置分组，每组各自建立可复用 Sandbox；`maxConcurrency` 限制整个实验同时存在的 Sandbox 数量，而不是给每组各分配一份并发额度。

## 全流程

1. 实验显式声明复用，并选择较宽的 Eval 范围：

   ```ts
   export default defineExperiment({
     evals: ["memory/commit0/"],
     sandboxReuse: true,
     maxConcurrency: 2,
     // ...
   });
   ```

2. Runner 在创建前给出环境分组：

   ```text
   Sandbox reuse groups:
     docker · node24        8 evals   onboarding/*, memory/*
     e2b · fasteval-agents  3 evals   research/*
   maxConcurrency: 2
   ```

3. 调度器最多同时运行两个 Sandbox。
   某一组没有空闲实例时，该组 Attempt 等待；不会借用另一组的 Sandbox，也不会越过实验的并发限制。

## 边界

- 环境配置相同才进入同一复用组；仅 provider 名相同不够。
- 单个 Sandbox 不会在环境组之间切换。
- 某个环境组的 Sandbox 创建失败，只影响该组；其余组按实验失败策略继续。
