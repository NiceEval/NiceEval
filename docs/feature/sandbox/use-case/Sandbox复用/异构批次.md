# Sandbox 复用：批次包含多种环境

## 解决什么问题

一个 command-only 的 Experiment 选题范围一宽，批里选中的 Eval 就可能各带不同 template——有的用 Docker image，有的用 E2B。
一个 Sandbox 只有一个题间重置点，不能同时代表两套环境。
Runner 按 `(CaseKey, templateOwner, layer identities, Agent ensure identity)` 分组，每组各自建立可复用 Sandbox 与自己的题间重置点。
`maxConcurrency` 限制整个实验同时存在的 Sandbox 数量，而不是给每组各分配一份并发额度。

## 全流程

1. 实验显式声明复用，并选择较宽的 Eval 范围：

   ```ts
   export default defineExperiment({
     evals: ["memory/commit0/"],
     sandboxReuse: true,
     maxConcurrency: 2,
     // ...
   });
   ```

2. Runner 在创建前给出复用池分组：

   ```text
   Sandbox reuse groups:
     docker · node24        8 evals   onboarding/*, memory/*
     e2b · fasteval-agents  3 evals   research/*
   maxConcurrency: 2
   ```

3. 调度器最多同时运行两个 Sandbox。
   某一组没有空闲实例时，该组 Attempt 等待；不会借用另一组的 Sandbox，也不会越过实验的并发限制。

## 边界

- 完整池键相同才进入同一复用组；仅 provider 名或物理 template 相同不够，规则见[复用池按完整身份分组](../../reuse.md#复用池按完整身份分组)。
- 不同组之间不共享 Sandbox，也不共享任何检查命中历史；单个 Sandbox 不会在组之间切换。
- 某一组的 Sandbox 创建失败，只影响该组；其余组按实验失败策略继续。
