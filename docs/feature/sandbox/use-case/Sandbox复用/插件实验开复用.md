# 声明了原生 Plugin 的实验开复用

## 解决什么问题

一个记忆插件实验：`plugins` 声明 marketplace 与插件，`postSetup` 跑插件自带的 setup 脚本，一批几十道题。
默认隔离下每条 Attempt 都要付一次 Sandbox 创建与公共准备，作者想声明 `sandboxReuse: true` 把这两段分摊掉。

插件安装落在 `$HOME`，而复用沙箱的 `$HOME` 活过题间重置。Adapter 把可验证的 marketplace 内容、Plugin 安装与声明式安装后命令编译成 Agent-owned before action。缓存命中恢复相同安装状态；不具备 exact provenance 的供应商 CLI 保守真实收敛。

```ts
export default defineExperiment({
  agent: codexAgent({
    plugins: [{
      marketplace: {
        name: "nowledge-community",
        source: "nowledge/codex-plugins",
        ref: "v0.9.4",
        sparse: ["plugins/nowledge-mem"],
      },
      name: "nowledge-mem",
      install: {
        after: command("python", ["scripts/install_hooks.py"]),
        changeFrequency: 30,
      },
    }],
  }),
  sandbox: e2bSandbox({ template: "niceeval-agents", lifetimeMs: 60 * 60_000 }),
  sandboxReuse: true,
  maxConcurrency: 2,
  timeoutMs: 20 * 60_000,
});
```

## 仍归作者的两件事

- **动态 `postSetup` 幂等**。
  secret、cohort、远端 Space 与租约仍由 callback 每条 Attempt 写入。它们在残留的 `$HOME` 上重跑时必须收敛，不能追加出第二份配置。
- **插件数据的存放路径**。
  插件安装目录每条 Attempt 被重装替换。
  插件运行期写下的数据要活过题间，只能存在安装目录之外；数据留不留得下、留下是否污染下一题，由实验设计裁决。

## 实际分摊多少

复用和准备缓存分别分摊 Sandbox 创建与固定 Plugin 安装；动态 overlay 仍按 Attempt 执行：

```text
默认隔离:Attempt 数 × (Sandbox 创建 + 完整公共准备 + Plugin restore/replay)
Sandbox 复用:实际 Sandbox 数 × (Sandbox 创建 + 完整公共准备)
           + 固定 Plugin 前缀 restore + Attempt 数 × 动态 overlay
```

marketplace 拉取是插件安装的大头，用 `sparse` 只拉插件所需路径能明显压低。Plugin 发布流程先查询移动 ref 当前指向的完整 commit，再交给 `gitCheckout()`；相同 commit 自动命中，推进后输入 commit 改变并自动 miss。NiceEval V1 不执行这项远端身份查找。Plugin 投影与第三方 Action 共用 [SandboxAction](../../layers.md#action-family-与-step) 和 [准备前缀验证边界](../../architecture.md#准备前缀的身份与验证边界)。
