# 声明了原生 Plugin 的实验开复用

## 解决什么问题

一个记忆插件实验：`plugins` 声明 marketplace 与插件，`postSetup` 跑插件自带的 setup 脚本，一批几十道题。
默认隔离下每条 Attempt 都要付一次 Sandbox 创建与公共准备，作者想声明 `sandboxReuse: true` 把这两段分摊掉。

插件安装落在 `$HOME`，而复用沙箱的 `$HOME` 活过题间重置。
作者不需要为此做任何事：Adapter 在每条 Attempt 开始前把安装收敛到声明——上一条 Attempt 留下的同名 marketplace 注册与插件安装，被替换成按声明来源与 ref 的全新安装（契约见[扩展边界](../../../adapters/architecture/coding-agent-extensions.md#安装收敛不假设沙箱空白)）。
插件自带脚本把注册改写成托管源这类生态行为，也被同一条规则吸收。

```ts
export default defineExperiment({
  agent: codexAgent({
    plugins: [{
      marketplace: {
        name: "nowledge-community",
        source: "nowledge/codex-plugins",
        ref: "v0.9.4",
        sparse: ["plugins/nowledge-mem"],
      },
      name: "nowledge-mem",
    }],
    postSetup: [async (sandbox) => {
      await sandbox.runShell("python ~/.codex/plugins/nowledge-mem/scripts/install_hooks.py");
    }],
  }),
  sandbox: e2bSandbox({ template: "niceeval-agents", lifetimeMs: 60 * 60_000 }),
  sandboxReuse: true,
  maxConcurrency: 2,
  timeoutMs: 20 * 60_000,
});
```

## 仍归作者的两件事

- **`postSetup` 幂等**。
  脚本每条 Attempt 都在残留的 `$HOME` 上重跑：往全局配置登记 hook 的脚本，重跑一遍必须收敛到同一份配置，不能追加出第二份。
  插件文档声称幂等的，开复用前先拿两三道题压一条泳道验证——第二题起才是真正的判据。
- **插件数据的存放路径**。
  插件安装目录每条 Attempt 被重装覆盖。
  插件运行期写下的数据要活过题间，只能存在安装目录之外；数据留不留得下、留下是否污染下一题，由实验设计裁决。

## 实际分摊多少

复用分摊的是 Sandbox 创建与检查命中前的那次昂贵公共准备；插件安装属于 Agent 侧安装，每条 Attempt 照付：

```text
默认隔离:Attempt 数 × (Sandbox 创建 + 完整公共准备 + 插件安装)
Sandbox 复用:实际 Sandbox 数 × (Sandbox 创建 + 完整公共准备)
           + 其余 Attempt × 检查命中 + Attempt 数 × 插件安装
```

marketplace 拉取是插件安装的大头，用 `sparse` 只拉插件所需路径能明显压低。
批次大到连这一段也要省时，把插件烘进 Provider 的 template 并从 `plugins` 里拿掉声明——代价是 manifest 里没有插件与解析版本的记录，可复现性凭证从 manifest 挪到 template 名。
