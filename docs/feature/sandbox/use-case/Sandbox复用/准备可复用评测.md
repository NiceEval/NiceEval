# 声明 Sandbox 复用：让一批 Eval 共用环境

拿一个真实 eval 仓库改:MemoryBench 的 `evals/toggl-cli/` 链,6 道题、同一个 repo、同一个 base commit、同一套 Rust 工具链。
它适合使用 Sandbox 复用，但现有准备逻辑需要分层。
先看改完之后代码长什么样——注释标的就是每一块落在哪一层、那一层只能放什么、在复用实验里怎么跑。
契约单源始终在 [Sandbox Layer](../../layers.md)、[三方准备时序](../../lifecycle.md)与 [Sandbox 复用](../../reuse.md),本页只做搭配叙事。

## 先看完整生命周期

一次 Invocation 先准备 Experiment，再按需创建 Sandbox。
每个 Sandbox 的 Case 就绪后建立题间重置点，然后串行承接多条 Attempt。
不同 Sandbox 可以在 `maxConcurrency` 限制内并行，但单个 Sandbox 同时只承接一条 Attempt。

![复用 Sandbox 的并行与生命周期](../../../../assets/sandbox-reuse-lanes.svg)

每条 Attempt 开始前,Runner 先把 workdir reset 回题间重置点,再按 owner 顺序重放两层 layer 的 `prepare()`,随后执行 agent.ensure 循环与 Agent runtime。
图中的 `git reset --hard` 和 `git clean` 由 Runner 自动执行,Eval 作者不写这两条命令。
无论 fresh 或 reuse,普通 command 都只有逐 Attempt 一种频次;各阶段的完整次数表见 [Sandbox 复用](../../reuse.md#各阶段次数)。

重放不等于每条 Attempt 付全价。
昂贵动作由真实检查把关:装在 workdir 之外的工具链活过 reset,第二条 Attempt 起检查命中、快速返回。
reset 删除了某个已安装内容时,当前 Attempt 的检查未命中并重新安装——这是正确性结果,不是缓存失败。

Codex CLI 这类稳定且每条 Attempt 相同的重依赖，优先烘进 provider 的 image / template / snapshot。
agent.ensure 循环每条 Attempt 重探:模板已预装 CLI 时 probe 命中即快速返回;鉴权、MCP、skills 和本 Attempt 的原生配置仍由 `agent.setup` 写入。
没有可发布的预制产物时,配对安装层在 `agent.ensure` 里安装,每条 Attempt 付一次探测或安装成本。

`clone` 和 `pnpm install` 的归属取决于 checkout 随什么变化：

- 整批 Eval 共用同一仓库、base commit 和 lockfile 时,checkout 归 Experiment layer 的 `prepare()`,和 template 声明写在一起。
- 某道 Eval 有自己的仓库、commit、lockfile 或额外依赖时,对应准备归该 Eval layer 的 `prepare()` 或 `test(t)`,不得污染其它 Eval 的起点。
- 只有与仓库无关、所有 Attempt 都相同的工具适合预装到 image / template / snapshot。
  不把会随 lockfile 变化的项目依赖烘进与它无关的公共基线。

题间 reset 只还原 workdir。
`$HOME`、`/tmp`、全局安装、后台进程和外部服务状态都可能继续存在。
单题资源由取得它的命令经 `context.onCleanup()` 登记收尾；无法容忍这些残留的 Eval 不能加入复用实验。

## Experiment layer 与 Agent layer:`experiments/compare/claude-dp-v4.ts`

```ts
import { defineExperiment } from "niceeval";
import { claudeCodeAgent } from "niceeval/adapter";
import { e2bSandbox } from "niceeval/sandbox";
import { NICEEVAL_CLAUDE_CODE_E2B_TEMPLATE } from "niceeval/sandbox/e2b-template";

import { ensureRustToolchain, ensureTogglCheckout } from "../../evals/toggl-cli/harness.ts";

export default defineExperiment({
  evals: ["toggl-cli/"],
  sandboxReuse: true,
  maxConcurrency: 1,

  // ── Agent layer(Adapter 的 ensure 声明 + 配对安装层,由 Runner 组装)──────
  // 只能放:怎么连上这个 agent——CLI probe 与安装、鉴权、agent 主配置、MCP、skills。
  // 不许放:任何读「当前是哪条 eval」的分支。这条不是建议,是配置归属不变量。
  // 每条 Attempt 重探:模板已预装 CLI,probe 命中即快速返回,只写本 Attempt 的鉴权与主配置。
  agent: claudeCodeAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseUrl: process.env.DEEPSEEK_BASE_URL,
  }),
  model: "deepseek-v4-flash",

  // ── template(构建期,factory 引用 provider 产物)──────────────────────────
  // 只能放:所有实验、所有 eval 都要的重依赖。装一次进模板,不进任何 prepare。
  // Experiment 带 template,它选中的 6 道 toggl eval 因此都必须是 command-only。
  sandbox: e2bSandbox({
    template: NICEEVAL_CLAUDE_CODE_E2B_TEMPLATE,
    lifetimeMs: 3_600_000,
  })
    // ── Experiment layer 的 prepare 命令链────────────────────────────────────
    // 只能放:不随 eval 变的环境准备——工具链、共享 checkout、预热。
    // 每条 Attempt 重放;昂贵动作自带真实检查,复用窗口内第二条起命中、秒级返回。
    .prepare(ensureRustToolchain)

    // 整批共用同一个 checkout,所以它也归 Experiment layer。
    // 网络 clone 只在检查未命中时发生;命中时从存活的 .git 本地恢复工作树。
    .prepare(ensureTogglCheckout),

  flags: { memory: "baseline" },
  attempts: 1,
  timeoutMs: 1_800_000,
});
```

## prepare 命令长什么样:`evals/toggl-cli/harness.ts`

prepare 命令的签名是 `(sandbox, context)`,不是 eval 的 `t`——它拿不到断言和 `t.send()`,因为这一层还不知道要跑哪条 eval。
跨文件共享的 helper 用 `defineSandboxCommand({ id, revision, inputs }, run)` 显式登记稳定 identity。直接传入的 callback 不阻断跨 Run 结果沿用，但它的实现与动态输入变化不会自动作废旧结果。

```ts
import { defineSandboxCommand } from "niceeval/sandbox";

const REPO_URL = "https://github.com/CorrectRoadH/toggl-cli.git";
export const BASE_COMMIT = "8646f29c87242b06eab974793a999d35b5a85b5e";
const RUST_VERSION = "1.88.0";

// Experiment layer:apt 依赖 + rustup + cargo,以 root 装进 /usr/local。装在 workdir 之外是
// 刻意的——workdir 之外的东西永不进 agent diff,题间 reset 也碰不到它,所以第二条 Attempt
// 起下面的检查就能命中。
export const ensureRustToolchain = defineSandboxCommand(
  { id: "toggl-cli/rust-toolchain", revision: "1", inputs: { rust: RUST_VERSION } },
  async (sandbox, context) => {
    // ensure 式检查:探真实版本,命中即快速返回。普通 runCommand 允许任意退出码，
    // 所以未命中的非零结果只是 probe 证据，不是执行异常。
    const probe = await sandbox.runCommand("/usr/local/cargo/bin/cargo", ["--version"]);
    if (probe.exitCode === 0 && probe.stdout.includes(RUST_VERSION)) return;

    context.progress({ message: "installing build deps + rust toolchain", current: 1, total: 1 });
    // checked 方法对非零退出抛 exit error:这条 attempt errored,归 sandbox.prepare.experiment。
    await sandbox.runShellOrThrow(TOOLCHAIN_SCRIPT, { user: "root" });
    await sandbox.runCommandOrThrow("/usr/local/cargo/bin/cargo", ["--version"]); // 装后复检
  },
);

// Experiment layer:把仓库恢复到 base commit。checkout 必须落在 workdir 根——嵌套子目录
// 会被分类账记成 gitlink,agent 的改动就从证据里消失了。
export const ensureTogglCheckout = defineSandboxCommand(
  { id: "toggl-cli/checkout", revision: "1", inputs: { repo: REPO_URL, commit: BASE_COMMIT } },
  async (sandbox, context) => {
    // 真实检查:上一条 Attempt 的 .git 活得过题间 clean(分类账在任意深度排除 .git)。
    // 它已指向 base commit 时不走网络,本地恢复工作树即可。
    const head = await sandbox.runShell("git rev-parse HEAD");
    if (head.exitCode === 0 && head.stdout.trim() === BASE_COMMIT) {
      await sandbox.runShell("git reset -q --hard && git clean -qfd");
    } else {
      context.progress({ message: "cloning toggl-cli @ base commit", current: 1, total: 1 });
      await sandbox.runShell(
        [
          "set -euo pipefail",
          // 半途死掉的上一次可能留下旧 .git 或临时目录,先删再 clone。临时目录名全实验
          // 统一一个,写进每条 eval 的 diff.ignore——分类账锚点按这份清单容忍它。
          "rm -rf .git .toggl-clone",
          `git clone -q -o origin ${REPO_URL} .toggl-clone`,
          "mv .toggl-clone/.git .git",
          "rm -rf .toggl-clone",
          `git reset -q --hard ${BASE_COMMIT}`,
          "git remote remove origin",
        ].join("\n"),
      );
    }

    // 冷依赖构建的预热也在这条命令里:构建树落在 /opt/cargo-target(workdir 之外),
    // 活过题间 reset,第二条 Attempt 起增量核对秒级完成。
    context.progress({ message: "warming cargo build cache", current: 1, total: 1 });
    await sandbox.runShell('export PATH="/usr/local/cargo/bin:$PATH"\ncargo build --tests --quiet');
  },
);
```

## Eval layer 与 `test(t)`:`evals/toggl-cli/01-entry-stats.eval.ts`

```ts
import { defineEval } from "niceeval";
import { commandSucceeded, equals } from "niceeval/expect";

import { runProbe } from "./harness.ts";

export default defineEval({
  description: "toggl-cli 01: add `toggl entry stats` (per-project totals)",
  tags: ["toggl-cli", "chain"],
  timeoutMs: 1_800_000,
  diff: { ignore: ["target", ".toggl-clone"] },
  // ↑ 以上都是定义期数据,不是生命周期回调:发现阶段就读得到,不在沙箱里执行。

  // ── Eval layer ────────────────────────────────────────────────────────────
  // 只能放:只有这条 eval 要的题目准备——它自己的起始文件、它自己那份数据、只为这一题
  // 装的依赖,写成 sandboxLayer().prepare(...) 或 test(t) 里的普通代码。
  // 这 6 道题的准备一模一样,一行都不该留在这一层,所以这条 eval 省略 sandbox 字段
  // (等价空的 command-only layer)。
  // 留在这里的症状:每道题各自声明一份,对照组实验也会被注入同一份东西。

  async test(t) {
    // ── test(t) ─────────────────────────────────────────────────────────────
    // 作者的代码,顺序与次数核心不插手。复用实验里每题重跑,进来时 workdir 刚被
    // reset 回题间重置点,两层 prepare 已重放完:base commit 的干净 checkout,依赖已就位。

    // send 之前写的文件 = eval 归因(Fixture),永不进 agent diff。
    // send 窗口内的 workdir 变化 = agent 归因。
    await (await t.send("…add `toggl entry stats`…")).succeeded().stopOnFailure();
    await (await t.send("…now give it `--json`…")).succeeded().stopOnFailure();

    // 这里只运行不含隐藏文件的公开 probe。需要本地测试文件时,
    // 在对应 send 返回后通过普通 API 上传、运行并断言。
    const probe = await runProbe(t, { cases: [{ name: "human", args: ["entry", "stats"] }] });

    // 断言读的是 agent 归因增量,不是「这个路径存不存在」——后者在共用的 Sandbox 中会被上一题
    // 的残留喂成假阳性。
    t.check(await t.sandbox.runShell("git diff --quiet -- Cargo.toml"), commandSucceeded());
    t.check(probe.human.exit, equals(0));
  },
});
```

起了后台进程或占了端口的题要自己收尾——题间的 `git reset` 不杀进程。
收尾跟着取得资源的那条命令走:Eval layer 的 prepare 命令起进程成功后用 `context.onCleanup()` 登记关闭动作,Runner 在 Agent teardown 之后按全局准备顺序逆序执行。
agent 自己起的进程不经作者命令取得,在 `test(t)` 末尾收:`await t.sandbox.runShell("pkill -f 'toggl serve' || true")`。

## 改之前坏在哪

现在的 `harness.ts` 把 clone 和冷构建放在 `prepareRepo(t)`、由每条 eval 在 `test(t)` 里调用,工具链安装则被 6 道题里的 5 道各自挂在自己的 eval 侧。
三处后果:

- **第二题撞库。**
  clone 脚本不检查现状,重放时 `mv .toggl-clone/.git .git` 撞上上一条 Attempt 留下的 `.git`——分类账在任意深度排除 `.git`,`git clean` 尊重这份清单,所以它活过题间重置。
  `mv` 把新 `.git` 放入旧目录里,接着 `git reset --hard` 作用在旧库上。
  同 repo 同 commit 碰巧不报错,换个 repo 就是找不到 commit。
  MemoryBench 里 31 道 eval 是这个 clone 形状。
- **省不下冷启动。**
  prepare 每条 Attempt 都重放,复用窗口内把 clone 与冷 `cargo build` 降成秒级的机制是真实检查命中。
  不带检查的写法每题付全价,复用只省掉了沙箱创建那一次。
- **分层错位。**
  `installRustToolchain` 同一个函数、同一份参数被 5 道题各自声明,一个字不随 eval 变。
  它自带 `if ! command -v cargo` 一类现状判断所以不会跑坏,但写在 eval 侧意味着对照组实验也会拿到它,失败还会归到 `sandbox.prepare.eval` 而不是 experiment。

## 一页速查:哪一层只能放什么

分工的单源是 [Library · 环境预置放哪](../../library.md#环境预置放哪);这里按「复用实验里跑几次」展开:

| 层 | 只能放 | 复用实验里跑几次 | 放错的症状 |
|---|---|---|---|
| 构建期(image / template / snapshot) | 所有实验都要的重依赖 | 跑之前就装好了,prepare 的检查因此秒级命中 | 写进 prepare 又不带检查 → 每条 Attempt 重装 |
| Experiment layer `prepare()` | 不随 eval 变的环境准备(工具链、共享 checkout、预热) | 每 Attempt 重放,昂贵动作检查命中、快速返回 | 放了随 eval 变的素材 → 换一批 eval 就不对,失败归因也记错 owner |
| Eval layer `prepare()` | 只有这条 eval 要的题目准备 | 每 Attempt 重放,顺序按 template owner 先、另一方后 | 放了公共安装 → 每道题各自声明、对照组被注入 |
| Agent layer(ensure 声明 + 配对安装层) | 怎么连上这个 agent:CLI probe 与安装、鉴权、主配置 | 每 Attempt 重探,命中快速返回 | 放了题目材料 → 同一 Eval 换不了 Agent |
| `test(t)` | 任务、判分材料、断言 | 每题重跑 | 放了公共安装 → 省不下冷启动 |
| `context.onCleanup()` | 命令成功取得资源后的对应清理 | 每 Attempt 按全局准备顺序逆序 | 不登记 → 后台进程、端口残留给下一题 |
| `SandboxLayer.setup()` / `teardown()` | 实际 Sandbox 的持久目录、守护进程或快照，以及跨 run checkpoint | 每个实际 Sandbox 成对一次 | 写进 prepare → 每题重放，错把物理寿命写成逐 Attempt 行为 |

`experiments/shared/nowledge.ts` 的 `nowledgeVerifyRemoteAlive()` 是收尾归属的现成例子:每条 attempt 收尾要探一次隧道还活着,cloudflare quick tunnel 的地址随进程重连就换。
这类检查写在 `test(t)` 末尾,或由起隧道的那条 prepare 命令用 `context.onCleanup()` 成对登记;两条路都是每 Attempt 一次,不存在被降频成每个 Sandbox 一次的档位。

## 改完之后

```bash
niceeval exp toggl
```

第一条 Attempt 付一次 e2b 沙箱创建、一次 apt + rustup、一次网络 clone、一次冷构建。
之后每道题 `git reset --hard` 回题间重置点,重放的两条 prepare 检查命中:工具链探一次版本、checkout 从存活的 `.git` 本地恢复、cargo 增量核对,整链秒级。
结果照常进 Run 供 `show` / `view` 看, 带 `sandbox.reused` 标记。
实验可以在 CI 中运行，结果按普通 Experiment 的终态、指纹、资格与 `--rerun` 判据沿用；携带条目不创建 Sandbox，未携带的 Attempt 才进入本次复用生命周期（见[结果与结果沿用](../../reuse.md#结果与结果沿用)）。

## 什么时候不要声明复用

`experiments/shared/mempal.ts` 把实际 Sandbox 中的 `$HOME/.mempal` 恢复为本实例的起点，并在它退休时打包收尾。
这对动作归 Experiment layer 的 `setup()` / `teardown()`，不写进 `prepare()`。它们的边界是一个物理 Sandbox；新的 run 也在 `setup()` 恢复、在 `teardown()` 回存 checkpoint。
声明复用后 `$HOME` 残留活过题间重置，正是 mempal 条件需要的连续物理实例；若实验要求每题完全独立，则不声明 `sandboxReuse`。

做不到可重复执行、或不能接受 workdir 之外的残留时,出路不是硬改,是**不声明、用并行**: 省略 `sandboxReuse` 时每条 Attempt 全新 Sandbox,并行照样由 `maxConcurrency` 与全局并发位给出。
复用省的是每个 Sandbox 一次的创建与检查命中前的那次昂贵准备;这段时间远小于单条 Attempt 时, 并行已经给出几乎全部墙钟收益,不必背复用的状态语义。
