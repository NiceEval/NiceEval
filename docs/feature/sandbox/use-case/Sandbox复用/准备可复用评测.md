# 声明 Sandbox 复用：让一批 Eval 共用环境

拿一个真实 eval 仓库改:MemoryBench 的 `evals/toggl-cli/` 链,6 道题、同一个 repo、同一个 base commit、同一套 Rust 工具链。
它适合使用 Sandbox 复用，但现有准备逻辑需要分层。
先看改完之后代码长什么样——注释标的就是每一块落在哪一层、那一层只能放什么、在复用实验里跑几次。

## 先看完整生命周期

一次 Invocation 先准备 Experiment，再按需创建 Sandbox。
每个 Sandbox 完成公共环境准备后建立题间重置点，然后串行承接多条 Attempt。
不同 Sandbox 可以在 `maxConcurrency` 限制内并行，但单个 Sandbox 同时只承接一条 Attempt。

![复用 Sandbox 的并行与生命周期](../../../../assets/sandbox-reuse-lanes.svg)

不复用时，每条 Attempt 都创建新 Sandbox，所以 `SandboxSpec.setup` 会随 Attempt 重放。
图中的复用 Sandbox 只在建立题间重置点前执行一次 `SandboxSpec.setup`。
它不知道当前是哪道 Eval，因此安全默认是只安装公共工具链，不 clone 任何题目仓库。
每道 Eval 在自己的 `Eval.setup` 中清理上一题可能残留的 `.git`，再 clone 自己的仓库和安装依赖。
Runner 自动执行图中的 `git reset --hard` 和 `git clean`，Eval 作者不写这两条命令。

Codex CLI 这类稳定且每条 Attempt 相同的重依赖，优先烘进 provider 的 image / template / snapshot。
`Agent.setup` 只负责检查 CLI 可用，并写入鉴权、MCP、skills 和本 Attempt 的原生配置。
如果 provider 没有可发布的预制产物，Adapter 可在 `Agent.setup` 回退安装它，但复用不会把 `Agent.setup` 提升为每个 Sandbox 一次，因此这条路径仍会每 Attempt 付一次安装或检查成本。

`clone` 和 `pnpm install` 的归属取决于 checkout 随什么变化：

- 整批 Eval 共用同一仓库、base commit 和 lockfile 时，两者放进 `SandboxSpec.setup`。
  它们每个 Sandbox 只跑一次，完成后的 workdir 成为题间重置点。
- 某道 Eval 有自己的仓库、commit、lockfile 或额外依赖时，对应的 clone / `pnpm install` 放进该 Eval 的 `setup`。
  它们在题间 reset 之后每 Attempt 重放，不得污染其它 Eval 的起点。
- 只有与仓库无关、所有 Attempt 都相同的 Node 工具适合预装到 image / template / snapshot。
  不把会随 lockfile 变化的项目依赖烘进与它无关的公共基线。

Eval 层 clone 的两条配套纪律。
临时 clone 目录全实验统一一个名字，写进每条 Eval 的 `diff.ignore`——分类账锚点按这份清单容忍上一条半途死掉留下的嵌套仓库；名字各写各的等于没写，接力的下一条既不清理也不 ignore 别人的名字。
clone 脚本第一条先 `rm -rf .git <临时目录>`：上一题的 `.git` 活得过题间 clean，不删就是把新 `.git` mv 进旧目录。

题间 reset 只还原 workdir。
`$HOME`、`/tmp`、全局安装、后台进程和外部服务状态都可能继续存在。
因此单题资源必须由 `Eval.teardown` 收尾；无法容忍这些残留的 Eval 不能加入复用实验。

## 沙箱层与 agent 层:`experiments/compare/claude-dp-v4.ts`

```ts
import { defineExperiment } from "niceeval";
import { claudeCodeAgent } from "niceeval/adapter";
import { e2bSandbox } from "niceeval/sandbox";
import { NICEEVAL_CLAUDE_CODE_E2B_TEMPLATE } from "niceeval/sandbox/e2b-template";

import { cloneTogglAtBaseCommit, installRustToolchain } from "../../evals/toggl-cli/harness.ts";

export default defineExperiment({
  evals: ["toggl-cli/"],
  sandboxReuse: true,
  maxConcurrency: 1,

  // ── agent 层(Agent.setup / .teardown,写在 adapter 内部)────────────────────
  // 只能放:怎么连上这个 agent——装 agent CLI、写鉴权、写 agent 主配置、MCP、skills。
  // 不许放:任何读「当前是哪条 eval」的分支。这条不是建议,是配置归属不变量。
  // 复用实验里仍逐 Attempt 成对执行。模板已经预装 CLI，这里只写本 Attempt 的鉴权与主配置。
  agent: claudeCodeAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseUrl: process.env.DEEPSEEK_BASE_URL,
  }),
  model: "deepseek-v4-flash",

  sandbox: e2bSandbox({
    template: NICEEVAL_CLAUDE_CODE_E2B_TEMPLATE,
    lifetimeMs: 3_600_000,
  })
    // ── 构建期(provider 的 image / template)──────────────────────────────────
    // 只能放:所有实验、所有 eval 都要的重依赖。装一次进模板,不进任何 setup。
    // 复用实验里:与复用无关——它在跑之前就已经装好了。

    // ── 沙箱层(SandboxSpec.setup 链)────────────────────────────────────────
    // 只能放:不知道跑哪条 eval 也能做完的环境准备——装二进制、预热、写 hook 文件、
    //         载入跨 attempt 状态。
    // Sandbox 复用时:每个 Sandbox 一次,落在重置点【之前】,所以它写出的东西题间重置抹不掉。
    .setup(installRustToolchain)

    // 整批共用同一个 checkout,所以 clone 也属于这一层。它跑在重置点之前,checkout
    // 因此成为重置点的一部分:每题的 git reset 直接回到 base commit 的干净状态,
    // 一次 clone、一次冷 cargo build 都不用重放。
    .setup(cloneTogglAtBaseCommit),

  flags: { memory: "baseline" },
  attempts: 1,
  timeoutMs: 1_800_000,
});
```

## 沙箱层 Hook 长什么样:`evals/toggl-cli/harness.ts`

沙箱层 Hook 的签名是 `(sandbox, ctx)`,不是 eval 的 `t`——它拿不到断言和 `t.send()`,因为这一层还不知道要跑哪条 eval。

```ts
import type { Sandbox, SandboxHook, SandboxHookContext } from "niceeval/sandbox";

const REPO_URL = "https://github.com/CorrectRoadH/toggl-cli.git";
export const BASE_COMMIT = "8646f29c87242b06eab974793a999d35b5a85b5e";

// 沙箱层:apt 依赖 + rustup + cargo,以 root 装进 /usr/local。装在 workdir 之外是
// 刻意的——workdir 之外的东西永不进 agent diff,题间重置也碰不到它。
export const installRustToolchain: SandboxHook = async (sandbox, ctx) => {
  ctx.progress({ message: "installing build deps + rust toolchain" });
  //          ↑ 沙箱层用 ctx.progress / ctx.diagnostic,不是 t.progress
  const installed = await sandbox.runCommand("bash", ["-lc", SCRIPT], { root: true });
  if (installed.exitCode !== 0) {
    // 沙箱层抛错 = 这条 attempt errored,phase 记成 sandbox.setup。
    throw new Error(`rust toolchain setup failed: ${installed.stderr.trim().slice(-500)}`);
  }
};

// 沙箱层:把仓库 clone 到 workdir 根,退到 base commit,抹掉之后的历史。
// checkout 必须落在 workdir 根——嵌套子目录会被分类账记成 gitlink,agent 的改动
// 就从证据里消失了。
export const cloneTogglAtBaseCommit: SandboxHook = async (sandbox, ctx) => {
  ctx.progress({ message: "cloning toggl-cli @ base commit" });
  const cloned = await sandbox.runShell(
    [
      "set -euo pipefail",
      // 幂等:这一层在 Sandbox 复用时每个 Sandbox 一次,默认档下每 Attempt 一次,而且以后有人把它
      // 搬回 eval 层也不该炸。上一次留下的 .git 活得过 git clean(分类账在任意深度
      // 排除 .git),所以先删。
      "rm -rf .git .toggl-clone",
      `git clone -q -o origin ${REPO_URL} .toggl-clone`,
      "mv .toggl-clone/.git .git",
      "rm -rf .toggl-clone",
      `git reset -q --hard ${BASE_COMMIT}`,
      "git remote remove origin",
      "git tag -l | xargs -r git tag -d >/dev/null",
      "git reflog expire --expire=now --all",
      "git gc -q --prune=now",
    ].join("\n"),
  );
  if (cloned.exitCode !== 0) throw new Error(`checkout failed: ${cloned.stderr.trim().slice(-500)}`);

  // 冷依赖构建也搬到这一层:不预热的话 agent 要从自己的时间预算里付一次数分钟的
  // cargo build。构建树落在 /opt/cargo-target(workdir 之外),Sandbox 复用时每个 Sandbox 只付一次。
  ctx.progress({ message: "warming cargo build cache" });
  const built = await sandbox.runShell('export PATH="/usr/local/cargo/bin:$PATH"\ncargo build --tests --quiet');
  if (built.exitCode !== 0) throw new Error(`baseline build failed: ${built.stderr.trim().slice(-800)}`);
};
```

## eval 层与 `test(t)`:`evals/toggl-cli/01-entry-stats.eval.ts`

```ts
import { defineEval } from "niceeval";
import { commandSucceeded, equals } from "niceeval/expect";

import { orderedLines, runProbe } from "./harness.ts";

export default defineEval({
  description: "toggl-cli 01: add `toggl entry stats` (per-project totals)",
  tags: ["toggl-cli", "chain"],
  timeoutMs: 1_800_000,
  diff: { ignore: ["target"] },
  // ↑ 以上都是定义期数据,不是生命周期回调:发现阶段就读得到,不在沙箱里执行。

  // ── eval 层(EvalDefinition.setup)────────────────────────────────────────────────
  // 只能放:只有这条 eval 要的任务素材——它自己的起始文件、它自己那份数据、
  //         只为这一题装的依赖。
  // 复用实验里:每题重置之后重放一次。所以放这里的东西必须是「重放一遍还对」的。
  // 这条 eval 现在【不声明 setup】:6 道题的准备一模一样,一行都不该留在这一层。
  // 留在这里的症状:每题重复付一次,而且对照组实验也会被注入同一份东西。

  async test(t) {
    // ── test(t) ─────────────────────────────────────────────────────────────
    // 作者的代码,顺序与次数核心不插手。复用实验里每题重跑,进来时 workdir 就是刚
    // reset 回重置点的样子:base commit 的干净 checkout,依赖已装好。

    // send 之前写的文件 = eval 归因(Fixture),永不进 agent diff。
    // send 窗口内的 workdir 变化 = agent 归因。
    await t.send("…add `toggl entry stats`…").then((turn) => turn.expectOk());
    await t.send("…now give it `--json`…").then((turn) => turn.expectOk());

    // 这里只运行不含隐藏文件的公开 probe。需要本地测试文件时，
    // 在对应 send 返回后通过普通 API 上传、运行并断言。
    const probe = await runProbe(t, { cases: [{ name: "human", args: ["entry", "stats"] }] });

    // 断言读的是 agent 归因增量,不是「这个路径存不存在」——后者在共用的 Sandbox 中会被上一题
    // 的残留喂成假阳性。
    t.check(await t.sandbox.runShell("git diff --quiet -- Cargo.toml"), commandSucceeded());
    t.check(probe.human.exit, equals(0));
  },

  // ── eval 层收尾(EvalDefinition.teardown)─────────────────────────────────────────
  // 只能放:这一条 attempt 自己的收尾与「这一条 attempt 怎么样」的核对。
  // 复用实验里:每题一次。所以按 attempt 判定的检查只能放这里,不能挂沙箱层。
  // 收尾发生在判定之后:只能追加 diagnostic,改不了 verdict。
  // 这条 eval 不需要收尾,写在这里只为标清位置:起了后台进程或占了端口的 eval 要在这
  // 一层自己收掉,题间的 git reset 不杀进程。
  async teardown(sandbox, ctx) {
    await sandbox.runShell("pkill -f 'toggl serve' || true");
  },
});
```

## 改之前坏在哪

现在的 `harness.ts` 把 clone 和冷构建放在 `prepareRepo(t)`、由每条 eval 在 `test(t)` 里调用,`installRustToolchain` 则挂成 `setup: installRustToolchain`(6 道题里 5 道)。
三处后果:

- **第二题撞库。**
  `mv .toggl-clone/.git .git` 遇到上一题留下的 `.git`——分类账在任意深度排除 `.git`,`git clean` 尊重这份清单,所以它活过题间重置。
  `mv` 把新 `.git` 放入旧目录里,接着 `git reset --hard` 作用在旧库上。
  同 repo 同 commit 碰巧不报错,换个 repo 就是找不到 commit。
  MemoryBench 里 31 道 eval 是这个 clone 形状。
- **省不下冷启动。**
  clone 与冷 `cargo build` 留在 `test(t)` 里就是每题重放,而它们正是这条链最贵的两段。
  复用只省掉了沙箱创建那一次。
- **分层错位。**
  `installRustToolchain` 同一个函数、同一份参数被 5 道题各自声明,一个字不随 eval 变。
  它自带 `if ! command -v cargo` 一类幂等判断所以不会跑坏,但重复付探测开销,而且写在 eval 层意味着对照组实验也会拿到它。

## 一页速查:哪一层只能放什么

| 层 | 只能放 | 复用实验里跑几次 | 放错的症状 |
|---|---|---|---|
| 构建期(image / template) | 所有实验都要的重依赖 | 跑之前就装好了 | 写进 `setup` 就每 attempt 重装 |
| 沙箱层 `.setup()` | 不知道跑哪条 eval 也能做完的环境准备 | 每个 Sandbox 一次,落在重置点之前 | 放了随 eval 变的素材 → 共用该 Sandbox 的 Attempt 都带着它 |
| agent 层 `Agent.setup` | 本 Attempt 怎么连上 agent | 每 Attempt 一次 | 放了稳定安装 → 每题重复付 |
| eval 层 `EvalDefinition.setup` | 只有这条 eval 要的任务素材 | 每题重置后重放 | 放了公共安装 → 每题重复付、对照组被注入 |
| `test(t)` | 任务、判分材料、断言 | 每题重跑 | 放了公共安装 → 省不下冷启动 |
| eval 层 `teardown` | 这一条 attempt 的收尾与核对 | 每题一次 | —— |
| agent 层 `Agent.teardown` | 本 Attempt 的 agent 收尾 | 每 Attempt 一次 | 与 setup 不成对 → 状态泄漏 |
| 沙箱层 `.teardown()` | 环境级收尾、回存跨 Attempt 状态 | 每个 Sandbox 一次 | 放了按 Attempt 判定的检查 → 静默降频 |

最后一行是 MemoryBench 里现存的一处。
`experiments/shared/nowledge.ts` 的 `nowledgeVerifyRemoteAlive()` 挂成沙箱层 `.teardown()`。
它要做的是每 attempt 收尾探一次隧道还活着——cloudflare quick tunnel 的地址随进程重连就换。
复用实验里前面每一题都失去自己的探针,隧道中途挂掉,坏结果会记在挂之前那几题上。
判据一句话:**这个 teardown 检查的是「这一条 attempt 怎么样」还是「这个环境怎么样」?** 前者归 eval 层。

## 改完之后

```bash
niceeval exp toggl
```

一次 e2b 沙箱创建、一次 apt + rustup、一次 clone、一次冷构建;之后 6 道题各自 `git reset --hard` 回重置点、重放自己的判分材料。
结果照常进 Run 供 `show` / `view` 看, 带 `sandbox.reused` 标记。
实验可以在 CI 中运行，但不参与结果沿用，因为跳过一条 Attempt 会改变后续 Attempt 继承的完整生命周期（见[结果与沿用](../../reuse.md#结果沿用与-ci)）。

## 什么时候不要声明复用

`experiments/shared/mempal.ts` 的 `mempalSetup` / `mempalTeardown` 是一对沙箱层 Hook: setup 把宿主机上的记忆状态恢复到 `$HOME/.mempal`,teardown 打包回宿主机。
复用实验里两个每个 Sandbox 各跑一次——共用该 Sandbox 的 Attempt 使用一份不断累积的记忆库；默认档是每 Attempt 恢复和回存。
对记忆条件来说这不是加速，是换了被测对象，所以那些实验不声明 `sandboxReuse`。

做不到幂等重放、或不能接受 workdir 之外的残留时,出路不是硬改,是**不声明、用并行**: 默认档每条 Attempt 全新 Sandbox,并行照样由 `maxConcurrency` 与全局并发位给出。
复用省的只有每个 Sandbox 一次的创建与公共准备;这段时间远小于单条 Attempt 时, 并行已经给出几乎全部墙钟收益,不必背复用的状态语义。
