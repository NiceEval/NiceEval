# 让一批 Eval 共用 Sandbox

## 解决什么问题

改了公共 prompt、adapter 配置或共享 Fixture，想在本地把整组 Eval 快速过一遍。
默认模式下，12 道题需要 12 次“起容器、补系统依赖、安装 Node 包和 Agent CLI”。
这批题共享同一套安装时，重复冷启动会让准备工作主导总耗时。

## 全流程

1. 在 Experiment 中声明复用，并按需要限制同时执行数：

   ```ts
   export default defineExperiment({
     // …
     sandboxReuse: true,
     maxConcurrency: 1,
   });
   ```

2. 用 Eval 前缀收窄选题：

   ```bash
   niceeval exp memory/commit0 onboarding
   ```

3. PLAN 与启动反馈如实标注 Sandbox 复用、同时执行数为 1；结果按普通携带判据沿用：

   ```text
   Sandbox reuse: up to 1 sandbox · effective width 1
   Carry-forward follows fingerprint gates · CI allowed
   ```

4. 第一题开跑前支付一次 Sandbox 创建；Case 就绪后建立复用 Sandbox 的题间重置点。
5. Runner 按 occurrence schedule 满足两层作者与 Agent 的 before action，再通过 agent.ensure 屏障并启动 Agent runtime。
   昂贵安装可以 restore 已验证前缀；稳定的 Agent CLI 仍适合进入预制实例。
6. 题间把 workdir reset 回题间重置点，再按 occurrence schedule 满足 attempt before。
   Runner 每次派发前确认 Sandbox 复用寿命，不足时续期或轮换。
7. 结束反馈照常给判定汇总与 FAILED / NEXT；每条真实派发 Attempt 的 prepare、命令、计时与诊断由 Observability 封口，`show` / `view` 通过 Analysis `query()` 照常可查。复用池编号与承接序号仍只用于运行调度，不进入 portable Record。

## 边界

- **生命周期是实验语义。**
  上一题写进 `$HOME`、全局安装或后台进程的东西会留给下一题。
   Experiment 作者必须确认这些状态不会意外改变结果。
- **与结果沿用使用同一判据。**
  复用 Attempt 与普通 Attempt 一样可被后续 Run 按指纹携带；携带条目不创建 Sandbox，未携带的题目才在本次共用 Sandbox 中真实执行。
  复用 Experiment 可以进入 CI，`--rerun` 仍可要求相应 Attempt 真实执行。
- **失败想留现场？**
  `--keep-sandbox` 与 `sandboxReuse: true` 互斥。
  用另一个不声明复用的 Experiment 对那一题单独重跑；流程见 [keep-sandbox 用例](../留存现场/运行条件错误.md)。
