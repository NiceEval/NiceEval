# 让一批 Eval 共用 Sandbox

## 解决什么问题

改了公共 prompt、adapter 配置或共享 Fixture，想在本地把整组 Eval 快速过一遍。
默认模式下，12 道题需要 12 次“起容器、补系统依赖、安装 Node 包和 Agent CLI”。
这批题共享同一套安装时，重复冷启动会让准备工作主导总耗时。

## 全流程

1. 在 Experiment 中声明复用，并按需要限制同时执行数：

   ```ts
   export default defineExperiment({
     // …
     sandboxReuse: true,
     maxConcurrency: 1,
   });
   ```

2. 用 Eval 前缀收窄选题：

   ```bash
   niceeval exp memory/commit0 onboarding
   ```

3. PLAN 与启动反馈如实标注 Sandbox 复用、同时执行数为 1、结果不进结果沿用：

   ```text
   Sandbox reuse: up to 1 sandbox · effective width 1
   Carry-forward disabled · CI allowed
   ```

4. 第一题开跑前支付一次 `createSandbox` 与 SandboxSpec `setup`，然后建立
   复用 Sandbox 的题间重置点。
5. Agent 与 Eval `setup` / `teardown` 仍逐 Attempt 成对执行。稳定的 Agent 安装应在
   预制环境或 SandboxSpec Hook 中完成，不靠复用改变 Agent Hook 的次数。
6. 题间把 workdir reset 回题间重置点。Runner 每次派发前确认 Sandbox 复用寿命，
   不足时续期或轮换。
7. 结束反馈照常给判定汇总与 FAILED / NEXT；Attempt 记录 `sandbox.reused`，
   `show` / `view` 照常可查。

## 边界

- **生命周期是实验语义。** 上一题写进 `$HOME`、全局安装或后台进程的东西会留给下一题。
  Experiment 作者必须确认这些状态不会意外改变结果。
- **与结果沿用双向绝缘。** 复用 Attempt 永不被后续 Run 沿用；
  本次也不消费结果沿用，整批每一题都在共用的 Sandbox 中真实执行。
  复用 Experiment 可以进入 CI，但每次都全量真实执行。
- **失败想留现场？** `--keep-sandbox` 与 `sandboxReuse: true` 互斥。
  用另一个不声明复用的 Experiment 对那一题单独重跑；
  流程见 [keep-sandbox 用例](../留存现场/环境启动错误.md)。
