# 比较同一接口的应用实现

## 用户目标

用户要用同一套任务与 Match 比较两个社交应用实现，不让实现专属方法悄悄改变评估内容。
共享接口的唯一类型与运行时配对规则见 [Application Library](../library.md#共享接口与选择实现)。

```ts
// application.ts
import { defineApplicationContract } from "niceeval";

interface SocialContext {
  post(text: string): Promise<{ id: string; text: string }>;
}

export const social = defineApplicationContract<SocialContext>({ name: "social/v1" });
export const baseline = social.implement({
  name: "baseline",
  behaviorRevision: "1",
  create: () => ({ post: async (text: string) => ({ id: "baseline-post", text }) }),
});
export const candidate = social.implement({
  name: "candidate",
  behaviorRevision: "1",
  create: () => ({ post: async (text: string) => ({ id: "candidate-post", text }) }),
});
```

评估只依赖共同接口。生产接入把两个 `create` 换成真实应用连接，接口与评估不变。

```ts
// evals/post.eval.ts
import { satisfies } from "niceeval/expect";
import { social } from "../application.ts";

export default social.defineEval({
  async test(t) {
    const post = await t.post("发起一个关于夜间公交的话题");
    t.check(post, satisfies<{ text: string }>("正文存在", p => p.text.length > 0));
  },
});
```

```ts
// experiments/compare/baseline.ts
import { defineExperiment } from "niceeval";
import { baseline } from "../../application.ts";

export default defineExperiment({ application: baseline, evals: ["post"] });
```

```ts
// experiments/compare/candidate.ts
import { defineExperiment } from "niceeval";
import { candidate } from "../../application.ts";

export default defineExperiment({ application: candidate, evals: ["post"] });
```

```sh
pnpm exec niceeval exp compare
pnpm exec niceeval view
```

两个配置各自执行相同评估，结果分别标记 baseline 与 candidate。
接口相容只授予执行同一任务的资格，不允许不同实现互相沿用结果。

## 不相容时停止

实现漏掉 `post` 或使用不相容参数时，TypeScript 报错。
实现可以提供额外成员，但共享评估无法调用它们。
两个独立创建但同名的契约没有配对资格；Experiment 选择错误契约时，在应用实例创建前拒绝执行。
要共享评估必须复用上面的同一个 `social`，不能只复制字符串 `social/v1`。
