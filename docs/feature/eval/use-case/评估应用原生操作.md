# 评估应用原生操作

## 用户目标

社交游戏已经提供发帖、回复与生图方法。用户希望直接评估这些方法返回的 Post，不把游戏动作伪装成 Agent 消息。
应用方法与通用评估能力的定义见 [Application Library](../library.md#自定义应用)，本篇只串联接入与查看结果。

## 定义应用连接

以下最小例子展示对象类型如何从应用进入评估。实际游戏可以把这些函数替换为自己的 LLM 请求。

```ts
// application.ts
import { defineApplication } from "niceeval";

export interface Post {
  id: string;
  text: string;
  replyToId: string | null;
}

export const social = defineApplication({
  name: "social",
  create(ctx) {
    const controller = new AbortController();
    ctx.onCleanup(() => controller.abort());
    const signal = AbortSignal.any([ctx.signal, controller.signal]);
    let nextId = 0;
    const posts: Post[] = [];
    return {
      async post(text: string): Promise<Post> {
        signal.throwIfAborted();
        const post = { id: String(++nextId), text, replyToId: null };
        posts.push(post);
        return post;
      },
      visitDiscoveryPage: () => [...posts],
    };
  },
});
```

每个实际 Attempt 从新的数组与序号开始。连接外部服务时，把同一个取消信号传给网络调用，并在取得资源后立即登记释放函数。
创建中途失败也会释放已登记资源；应用不需要在每个评估的 `finally` 中释放资源。

## 直接匹配 Post

```ts
// evals/publish.eval.ts
import { equals, satisfies } from "niceeval/expect";
import { social, type Post } from "../application.ts";

export default social.defineEval({
  async test(t) {
    const post = await t.post("邀请大家周末看流星雨");
    t.check(post, satisfies<Post>("Post 有正文", p => p.text.length > 0));
    t.check(t.visitDiscoveryPage().map(p => p.id), equals([post.id]));
  },
});
```

`t.post` 保留参数与返回类型，Match 收到的就是 Post。
应用可以增加 `reply`、`generateImage` 或其它方法；不需要全局 TypeScript 扩展或动作名称注册。
应用没有提供 `send` 时，评估调用 `t.send` 会产生类型错误。

```ts
// experiments/local.ts
import { defineExperiment } from "niceeval";
import { social } from "../application.ts";

export default defineExperiment({ application: social, evals: ["publish"], attempts: 2 });
```

```sh
pnpm exec niceeval check
pnpm exec niceeval exp local
pnpm exec niceeval view
```

这两个 Attempt 都通过，并分别保存自己的检查材料。View 显示应用身份，缺失的 token 与费用显示为 unavailable，而不是零。
完整的文字、生图与后续互动例子见 [LLM X](../../../../examples/zh/llm-x/README.md)。fixture 模式不请求真实模型，不能证明生成内容的质量。

## 失败与不支持的路径

方法参数不正确、核心名称冲突或评估调用未提供的方法，都应先通过 TypeScript 检查修正。
运行时创建失败会形成 errored Attempt；已登记 cleanup callback 按逆序执行，一项失败不会跳过其它资源。
超时先关闭作者调用入口，再发出取消；同步 abort listener 也不能追加 Assertion。
Assertion 封口后的慢 cleanup callback 不改变已确定的 Verdict，具体预算见 [生命周期](../architecture.md#应用实例生命周期)。

普通应用不自动获得 Agent 会话、Sandbox、生命周期 Plugin 或完整费用预算能力。
需要这些能力时使用相应 Agent 接入；需要内容质量时显式提供 Judge 材料，而不是从方法名称推断质量。

未声明 `behaviorRevision` 的应用默认重新执行。复用条件见 [外部行为变化后重验](../../experiments/use-case/缓存与沿用/外部行为发生变化.md)。
