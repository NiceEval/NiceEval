# Agent 或外部服务变化后重验

Agent CLI 升级、被测服务部署变化和 Agent 工厂内部参数通常不在 Eval 指纹中，默认运行仍可能采用旧 Attempt。
这时旧的 passed Verdict 可能已经不可信，应主动[全量重验](../重新运行/全量重验.md)。

能够长期声明的差异应进入 `model`、`flags` 或其它公开 Experiment 配置。
不要把影响行为的参数藏在工厂闭包里，否则规划无法判断历史 Attempt 是否仍可比。

## 自定义应用的行为版本

普通 Adapter 省略 `behaviorRevision` 时，每次实际运行重新执行。
确认可以跟踪远端行为版本后，才在应用定义中声明非空版本：

```ts
import { defineAdapter } from "niceeval";
import { connectSocialApp } from "./social-app.ts";

export const social = defineAdapter({
  name: "social",
  behaviorRevision: "release-1",
  create: ctx => connectSocialApp({ signal: ctx.signal }),
});
```

当远端部署改变时，把版本更新为 `release-2`。
相同源码与配置下，稳定版本可沿用历史 Attempt；版本改变后重新执行。
版本只是一项必要条件，不绕过源码、配置与其它复用检查，也不让不同实现共享结果。
可以用 `pnpm exec niceeval exp --dry --json` 查看计划；沿用数量见输出的 `reused`。
