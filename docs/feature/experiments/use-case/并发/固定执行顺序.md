# 让 Eval 按固定顺序执行

## 解决什么问题

跨 Eval 累积同一份状态时——逐题写入的记忆库、一步步搭起来的工程——后面的 Eval 要等前面的 Eval 跑完才有意义。
用文件名把顺序写进发现顺序,再把该实验的并发降到 1:

```text
evals/
  01-建立索引.eval.ts
  02-按索引检索.eval.ts
  10-全量回归.eval.ts
```

```ts
export default defineExperiment({
  maxConcurrency: 1,
  // ...
});
```

数字前缀零填充到同样位数。
发现顺序按字典序比较路径,不识别数字大小,`10-` 会排在 `2-` 前面。

两件事缺一不可:命名只决定串行队列怎么排,`maxConcurrency: 1` 才让队列真的一条接一条跑。

## 前提

- **一个实验一条 Invocation。**
  多开终端跑同一个实验时,两条 Invocation 各自有一条串行队列并认领 Eval,合起来的先后不再由命名决定(见[并行 Invocation 协作](并行Invocation协作.md))。
  `sharedState` 可以让两条状态区间不交错，但不会合并两边的选择集与发现顺序。
- **历史 Attempt 采用会跳过队列前面的 Eval。**
  上一次已判定的 Eval 这次通过 carried Contribution 采用、不再执行，它写入的外部状态也就不会重新产生。
  顺序依赖这份状态时用 [`--rerun all`](../重新运行/) 从头跑。
- **`attempts > 1` 时按轮次跑**:这批 Eval 各跑一遍算一轮,跑完再开下一轮。
  同一条 Eval 的多次 Attempt 不连在一起。

## 只要读起来有序,不要串行

只希望终端输出和报告按固定次序排列时不必动并发:结果始终按发现顺序输出,与本次并发多大无关。
命名前缀照样生效,吞吐不用付代价。
