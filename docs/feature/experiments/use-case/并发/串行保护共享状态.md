# 串行保护共享状态

先区分状态是只在本 Invocation 内累积，还是会被两条 Invocation 同时打开。

## 本 Invocation 内串行

多条 Attempt 在同一 Sandbox 内累积记忆，并且操作者只运行一条命令时，配置：

```ts
export default defineExperiment({
  sandboxReuse: true,
  maxConcurrency: 1,
});
```

`sandboxReuse` 保留同一条物理 Sandbox，`maxConcurrency: 1` 让本 Invocation 内上一条 Attempt 收尾后才开始下一条。

## 多个 Invocation 共享 checkpoint

实际 Sandbox 的 `$HOME`、服务或快照由 layer `setup()` 恢复、`teardown()` 回存，且多个进程指向同一份持久状态时，再声明共享状态身份：

```ts
export default defineExperiment({
  sandboxReuse: true,
  maxConcurrency: 1,
  sharedState: { key: "mempal/codex/cohort-a" },
});
```

这条租约从 Experiment 与 Sandbox setup 之前持有到 checkpoint save、Sandbox finalizer 与 Experiment teardown 之后。
所以等待方不会提前创建第二个 Sandbox，也不会把两次 restore/save 交错。

`sharedState` 不提供 checkpoint 存储和事务回滚。强杀可能留下半次外部写入；作者必须把 Attempt 终态设计成原子提交边界，否则需要换干净 cohort 和新 key 重建轨迹。

完整时序、重叠选择、Attempt 采用、强杀与跨机边界见 [Sandbox 复用 · 并行 Invocation 与状态边界](../../../sandbox/use-case/Sandbox复用/并行Invocation与状态边界.md)。

后一道 Eval 要读前一道的状态时，还要固定发现顺序与选择集，见 [固定执行顺序](固定执行顺序.md)。
