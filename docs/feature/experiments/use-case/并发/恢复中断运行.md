# 恢复中断运行留下的协调状态

## 解决什么问题

运行被强杀时可能留下仍被标记为占用的协调状态。下一次运行会等待上一位运行者停止活动，再自动接管过期状态；
用户不需要删除 `.niceeval/coordination/` 下的文件。

```bash
niceeval exp compare/codex
```

等待仍在活动的另一条 NiceEval 运行是运行状态，不是失败。Human 输出用 `i` 说明正在等待；对方结束或不再活动后，
当前运行继续派发。

```text
i Waiting for another NiceEval run before continuing compare/codex.
```

## 成功接管怎样显示

成功接管表示自愈已经完成，不形成 warning，也不写入 Run diagnostic。Human 只说明恢复完成并继续运行，不展示
协调器资源名称或内部计数：

```text
i Recovered interrupted-run state for compare/codex; this run continues.
```

`--json` 为每次接管追加结构化 notice。调用方只读取具名字段，不从 message 提取值：

```json
{"event":"notice","code":"coordination-recovered","level":"info","message":"recovered expired coordination state for compare/codex; this run continues. Further recoveries are summarized at completion.","resource":"concurrency-slot","experimentId":"compare/codex","slot":1,"previousPid":756156,"previousHost":"ctrdh-studio"}
{"event":"notice","code":"coordination-recovered","level":"info","message":"recovered expired coordination state for compare/codex; this run continues. Further recoveries are summarized at completion.","resource":"case-lock","experimentId":"compare/codex","evalId":"toggl-cli/01-entry-stats","previousPid":756156,"previousHost":"ctrdh-studio"}
```

只有有效 owner 持续占用、接管失败或协调状态无法解码时才形成 warning 或 error。成功接管不会改变 carry
资格、Attempt 身份或退出码；它只说明本次 Invocation 已取得继续派发所需的本地协调所有权。

## 与 Sandbox orphan 的边界

协调状态接管不等于 Sandbox cleanup。被强杀的运行还可能留下 orphan Sandbox；用户通过公开命令列出并终止它们：

```bash
niceeval sandbox list --orphans
niceeval sandbox prune
```

不需要 orphan cleanup 时，直接重新运行即可。Runner 会沿用仍符合资格的已发布 Attempt，只派发缺口。
