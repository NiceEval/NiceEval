# 查看活跃 Invocation

另一位同事已经启动几批长跑 Experiment。
你想知道哪些调用仍在执行、各自关联哪些 Run，以及另开终端是否能为剩余工作增加吞吐。

这不是结果读取。
`niceeval session` 保留为命令名，但它查询的是以 `invocationId` 为键的外部 Invocation 索引；索引与 Live 使用同一个 Reducer，完整契约见 [CLI · Session 查询](../../cli.md#session-查询)。

```sh
niceeval session list
niceeval session list compare/codex
niceeval session show inv_01ac42f0
```

输出按 Invocation 分组：

```text
ACTIVE INVOCATIONS (2)
inv_01ac42f0 · pid 41267 · 2m 14s
  compare/codex       run_01  2 running · 1 queued
  compare/claude      run_02  setup · 3 queued
inv_01ac439c · pid 41802 · 48s
  compare/bub         run_03  1 running · 2 elsewhere
```

`running` 是已派发但未结束的 Attempt。
`queued` 等待当前 Invocation 的条件，`elsewhere` 等待另一个 Invocation 的用例锁或共享状态租约。
`setup` 与 `teardown` 是 Experiment 的 Run 范围活动，不占 Attempt 并发位。

`--all --json` 还显示 terminal 或 `expired` 索引项。
`expired` 只表示外部索引心跳失效，不属于 active 计数，也不证明进程仍占用资源。

## 决定下一步

1. 有 `queued` 且本机、Provider、Agent 服务都有余量时，在新终端对同一选择器启动 `niceeval exp … --max-concurrency N`。
2. 只有 `elsewhere` 时，等待对方提交后重新规划，或选择不相交的 Experiment / Eval 范围。
3. 看见 `expired` 时，不把它当作正在执行的工作。重新运行原命令会按明确 GraphRef、用例锁与过期接管补齐缺失成员。

## 边界

- 索引的唯一身份是 `invocationId`。它不建立另一种 Session identity，也不进入 Record entity catalog。
- 索引不保存 Agent 消息、命令、密钥或完整执行证据。通过 receipt 的 GraphRef、`niceeval show` 或 Sample 读取 Record 事实。
- `session list` / `show` 不发现 Experiment 源码、不加载配置、不启动 Sandbox，也不修改 Record、锁或贡献关系。
