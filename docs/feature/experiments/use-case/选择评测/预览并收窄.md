# 选择器 + `--dry`:几十个实验里只跑要跑的,先看清计划再花钱

## 解决什么问题

对照仓库里 `experiments/` 攒到几十个配置、`evals/` 几百条题。
改完一个 adapter 只想验证 codex 那一族变体 × 一条 eval,直接 `niceeval exp` 全量既慢又烧钱;更怕的是选择器写错——以为选中 4 个实验,实际展开 200 个 attempt,钱花出去才发现。
位置参数负责把选择收窄到位,`--dry` 负责在派发前把矩阵摊开看清,一分钱不花。

## 全流程

1. 用「目录/文件名前缀」圈出一族,先 `--dry` 看计划。
   选择规则见 [CLI · 实验选择器怎样求值](../../cli.md#实验选择器怎样求值):

   ```sh
   niceeval exp compare/codex --dry
   ```

   ```text
   PLAN
   policy: attempts 1 · timeout 10m · reuse eligible
   compare/codex-gpt-5.6-luna             memory/commit0-cachetool  Attempt #1  will run
   compare/codex-gpt-5.6-luna--agents-md  memory/commit0-cachetool  Attempt #1  using result @1K1P0VJAPVJ12
   compare/codex-gpt-5.6-luna--mempal     memory/commit0-cachetool  Attempt #1  will run — configuration changed
   compare/codex-gpt-5.6-luna--nowledge   memory/commit0-cachetool  Attempt #1  will run
   4 targets · 1 reused · 3 to run
   ```

   `compare/codex` 不精确等于任何实验 id 或目录,按「目录段精确 + 文件名前缀」回退,把同一 agent 的功能变体(`--agents-md` / `--mempal` / `--nowledge`)当一族一起选中。
2. 只要对照版那一个时给精确 id——精确命中优先于前缀,即使它同时是其它文件名的前缀也不牵连变体:

   ```sh
   niceeval exp compare/codex-gpt-5.6-luna --dry
   ```

3. 参数精确等于目录路径(如 `compare`)则选中该目录下全部实验;再加尾随 eval id 前缀,把每个实验 `evals` 选出的题继续收窄到本次关心的:

   ```sh
   niceeval exp compare/codex memory/commit0 --dry
   ```

4. 计划与预期一致后去掉 `--dry` 实跑。
   `--dry` 只打印计划(人读文本或 `--json` 单文档),不运行、不落盘,也不写 JUnit(见 [CLI · 哪些参数改变什么](../../cli.md#哪些参数改变什么))。
   需要在花费前核对这个 Experiment 的 Sandbox 准备前缀时，使用 `niceeval debug <experiment> --json`；省略 Eval selector 会规划该 Experiment 选中的全部 Eval，`setupPrefixPlan` 按 prefix identity 去重消费者。这份静态计划固定标记 `lookup: "not-probed"`，不会把计划写成真实 cache hit。
   正式 `niceeval exp` 结束后，Human 摘要与机器 receipt 的 `setupPrefixes` 再按本次 Invocation 的唯一 prefix node 结算 `total / hit / prepared / failed`，不与历史结果沿用或物理 Sandbox 复用混算。
5. 选择器写错、第二个位置参数没有选中 Eval，或 argv 不能形成命令时，都在建立 Invocation 前以非零状态结束；没有 receipt。零命中只给可浏览的目录清单，不摊平打印每个已发现 id：

   ```sh
   niceeval exp dev-e3b
   ```

   ```text
   No experiment matched: dev-e3b. Available paths: agents/, suites/, stress/.
   Run `niceeval exp <path> --dry` to preview a plan.
   ```

   ```sh
   niceeval exp compare/codex no-such-eval
   niceeval exp compare/codex --attempts nope
   ```

   ```text
   error: No evals selected for compare/codex: no-such-eval.
   docs: niceeval exp compare/codex --dry

   error: --attempts must be a positive integer: nope
   usage: niceeval exp [<experiment-prefix>] [<eval-prefix>] [flags]
   ```

## 边界

- 位置参数只选「跑哪些」——experiment id / 路径与 eval id 前缀;agent 名、URL、运行配置不进位置参数,临时改 model 属于写一个新实验文件(见 [CLI · 用法错误](../../cli.md#用法错误))。
- 目录段永远要求精确匹配,`dev` 不会误中 `dev-e2b`;不存在跨目录的模糊匹配。
- 实验选中了、但 eval 前缀零命中(`total = 0`)是另一条报错(`No evals selected`,退出码非零),同样给 `--dry` 建议——两层选择分别校验,见 [CLI · 人看的结束反馈](../../cli.md#人看的结束反馈)。
