# 先列出 Experiment，再选择运行范围

仓库里有多组 agent、模型和条件变体时，先查看它们实际会选择多少 Eval，再决定运行哪一组。不要靠文件名猜 Experiment id，也不要为了查看配置启动一次 `exp --dry`。

```sh
niceeval exp list
niceeval exp list compare/codex
```

输出中的每一行是一个可签入的 Experiment 配置：id、description、agent、model、attempts、已选 Eval 数和 labels。`exp list` 会完成和运行前相同的发现与选择，因此「已选 Eval 数」就是随后 `niceeval exp <selector> --dry` 的候选范围；它不创建 Invocation、不取锁、不花 Sandbox 或模型成本。

确认 id 后，先预览成本和缓存，再开始执行：

```sh
niceeval exp list compare/codex
niceeval exp compare/codex --dry
niceeval exp compare/codex
```

需要给脚本传递完整 Eval 清单时使用 `niceeval exp list --json`。它是一次性 JSON 文档，不是运行期 NDJSON 流；运行中的 live 状态只由当前进程显示，结束后的持久事实用 `niceeval show --run <runId>` 或 `niceeval show` 查询。

## 边界

- `exp list` 发现的是**定义**；它不显示历史结果，也不表示某个 Experiment 当前在跑。
- 当前在跑的多个 Experiment 属于一个 Invocation，不属于一条 `exp list` 条目。运行中反馈只在启动命令的进程里显示。
- selector、零命中和 JSON 形状的精确契约单源在 [CLI](../../cli.md#niceeval-exp-list先看有哪些运行配置)。
