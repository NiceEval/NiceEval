# `--budget`:一批长跑实验,给烧钱装安全网

## 解决什么问题

夜间跑一批 `attempts: 5` 的长任务实验,单条 attempt 就要几十分钟、几美元;agent 一旦在某类题上反复兜圈,一晚上能烧掉一个月的预算。
实验文件里的 `budget` 字段是签入的**实验预算上限**;某次运行想临时收紧或放宽——比如换了更贵的模型先试探性跑一轮——用 `--budget` 替换它,不改签入配置。

## 全流程

1. 实验签入常规预算(`budget: 15`,见 [README · `defineExperiment` 的形状](../README.md#defineexperiment-的形状));本次回归想把每个选中配置的上限临时提到 25 美元——budget 按 experimentId 域各自计,`regression` 展开成几个配置就是几份 25,不是一次调用的全局总限制:

   ```sh
   niceeval exp regression --budget 25 --junit ./niceeval-regression.xml
   ```

2. 运行器只按**已完成 attempt 的 `estimatedCostUSD`** 判断：这个估算由 model、上报的 token 用量与 Config/runtime price table 计算；Provider / Adapter 上报的 observed `usage.costUSD` 不驱动 budget。同一 budget 域(experimentId)的累计估算到顶就停止派发新 attempt;已经在飞的照常跑完,不中途打断。
   到顶之前不做任何预测性节流,并发完全由并发参数决定(契约见 [Runner · 调度](../../../runner.md#调度))。
3. 到顶时 NiceEval 固定 Observability 的 diagnostic 说明 `budget_exhausted`。在飞 Attempt 闭合且没有 reserved / pending Attempt 后，Run 仍可正常 seal。
   `--json` 发送当前进程的反馈与最终 `InvocationReceipt`，不另立 budget 的结果文档。

4. 未派发的 Attempt 写作 `not-dispatched` Member。整次 Invocation 可以是 `completion: "completed"`，但 `budget_exhausted` 仍使退出码为 `1`——即使零 `failed` / `errored` 也不伪装全绿(见 [Runner · 完成状态](../../../runner.md#完成状态))。
5. 想补完分母时提高预算再次运行同一条命令：reuse planning 把合格的终态 Attempt 判为 reuse，本次只把 gaps 交给 planner（见 [Reuse planning](../cache.md#coordinatorplanner-与-writer)）：

   ```sh
   niceeval exp regression --budget 40 --junit ./niceeval-regression.xml
   ```

## 边界

- budget 是防止无限烧钱的安全网,不是精确计费上限:已花 + 在飞未结算的总花费可能短暂超出上限;要压吞吐用 [`--max-concurrency`](并发/限制全局并发.md)。
- 判断依据是 model、agent 报回的 token 用量与匹配的 price；observed `usage.costUSD` 不会补齐缺失的估算。连续多个已发起 agent turn 的 attempt 都拿不到可估算成本时,budget 对该域不可执行,运行器给一条去重后的 warning,而不是每个 attempt 重复提示。
  首个 agent turn 之前失败的 attempt 没有成本事实,不产生这条 warning。
- 配置优先级是 CLI flag → experiment → config(见 [Library · 与 config 的关系](../library.md#与-config-的关系));判断仍按每个实验自己的 budget 域分别计。
