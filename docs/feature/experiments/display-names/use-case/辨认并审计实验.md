# 用短名称辨认 Experiment，用完整 ID 审计 Run

团队把模型、Agent 和条件写进 Experiment 路径后，完整 ID 适合选择与审计，却不适合在长列表和运行面板中快速辨认。
作者在 `defineExperiment()` 上声明一行展示名称：

```ts
import { defineExperiment } from "niceeval";
import { codexAgent } from "niceeval/adapter";

export default defineExperiment({
  displayName: "Codex · RecallKit",
  description: "发布候选使用 RecallKit 的对照组。",
  agent: codexAgent(),
  model: "gpt-5.6",
});
```

若文件位于 `experiments/release/codex-recall.ts`，`niceeval exp list` 同时显示名称与完整 ID：

```text
Experiment          ID
Codex · RecallKit   release/codex-recall
```

用户仍以 `niceeval exp release/codex-recall` 运行。dry、运行面板和完成摘要都成对显示名称与 ID；
`show`、`view` 与 static 从 Run 保存的 presentation 读取同一名称。之后只修改源码中的 `displayName` 时，
历史 Run 继续显示旧名称，新 Run 显示新名称；已有 Attempt 只要其它 reuse 条件满足，仍可被新 Run 携带。

重复展示名称合法，两条 Experiment 仍按完整 ID 分开。按展示名称运行会以 usage error 拒绝，并提示复制列表中的 ID。
缺少展示名称时使用完整 ID。空值、首尾空白、控制字符、超过 160 UTF-8 bytes 或无效 Unicode 在 discovery
阶段失败，不建立 Invocation、Run 或 Sandbox。
