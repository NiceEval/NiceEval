# 错误助手 —— 架构

错误助手是既有错误交付链中的惰性增强能力。各功能拥有失败含义，CLI 或宿主拥有呈现，
Runner 继续拥有错误隔离和资源生命周期。它不引入全局异常监听器、运行中 agent 或模型调用。

## 边界与时序

1. 当前参数验证、模块加载、Provider 或 Host 边界取得真实失败，保留 typed cause 与已有归属。
2. 领域 owner 产生稳定 code、安全摘要、已知位置和可证明的下一步；基本反馈不依赖额外 I/O。
3. 交付层按需要和剩余预算定位 source map、读取说明；不支持或超限时保留明确缺失状态。
4. 既有 feedback sink 交付反馈；Scope 关闭时取消并收拢尚未完成的增强工作，关闭后不补写。

错误增强不能阻塞 Provider abort、Attempt 封口或 finalizer。运行中的定位工作经既有 feedback 生命周期管理，
不在每个 catch 里 await 一套 I/O；顶层 CLI 等 scoped 程序收尾后再交付自己的终局错误。
重试、停止派发和 Verdict 继续由 [执行失败分类](../error-classification/architecture.md) 及所属领域决定。

预期业务失败和未知 defect 都可以获得安全摘要，但两者不因此合并语义。取消不包装成未知异常；
错误渲染失败不能替换原失败、改变退出码或阻止资源释放。持久错误事实不从人读文本反向推导。

## 性能预算

成功路径只复用既有参数验证和失败分支，不做额外 Error 构造、stack 收集、Markdown I/O、源码语法 parse 或全项目扫描。
拒绝旧参数形状是现有校验中的有限判断；对已删除符号的源码识别只在模块加载已经失败后运行。
不存在每次合法调用都付费的通用迁移 preflight。

下列上限由当前 CLI 命令或 Invocation 共用，而非每条错误重新领取：

| 工作 | 上限与退化 |
| --- | --- |
| 源码定位 | 32 个不同位置；超限只显示已有位置或 unknown |
| 源码读取 | 单文件 256 KiB、累计 2 MiB；只读取当前已知模块或 source map 指向的受限文件 |
| 同步语法 parse | 每个文件最多 32,768 个节点；字节或节点超限不继续 parse |
| 增强并发与排队 | 并发 1、待处理最多 32 项；满队列跳过新增增强 |
| 可选增强耗时 | 单项 50 ms、累计主动工作预算 500 ms；取消或耗尽时停止准入 |
| 缓存 | 每命令或 Invocation 最多 2 MiB，按内容身份去重并驱逐；结束即释放 |
| 迁移指南资产 | 每篇不超过 32 KiB；只读取随包白名单路径，不接受用户拼接路径 |

时间预算不承诺抢占正在运行的同步语法 parse；必须同时执行字节和节点上限。
等待输出的背压不计作源码语法 parse 耗时，但输出仍由既有 sink 的有界队列和取消机制管理，不能无限积压。
错误风暴的合并只影响人读重复说明；每项原有领域事实和关联仍由原 owner 保存。

## 人读分组投影

分组发生在交付投影，不发生在领域错误、feedback sink 或 Record 存储层。
已知失败的 fingerprint 由 code、owner、repair target 和 guide ID 的 canonical 四元组构成。
这四项只由领域 owner 交付，投影不从 message、stack、路径字符串或异常类名推断。

同 fingerprint 的 occurrence 增加 count，并向有界 affected objects 和 source locations 样本追加去重值。
每条 occurrence 仍留在原 owner，包含原有 cause 关联、影响对象、位置和终态。
超过 32 组、每组 32 个对象或 32 个位置后，投影只保留 omitted 计数。
未知错误在没有 owner 稳定身份时使用单例组，避免把相似文字误当作同一修复目标。

第一条 occurrence 立即交付完整提示；终局边界交付组摘要。
指南去重独立使用 guide ID，因此同一指南即使横跨多组也只读取和输出一次。
终局摘要不替换首次提示，也不触发全历史或全项目源码扫描。

迁移指南是错误的正式说明，完整交付独立于可选源码增强预算。相同 guide ID 在一次命令内只读取并输出一次，
正文流经现有 sink，不随每个 occurrence 复制。位置增强失败不能阻止指南正文交付。
包内指南缺失、超限或损坏时保留迁移错误、guide ID、包版本和安全位置，显示 asset-unavailable；
不能改为执行旧功能或直接打印未经处理的 cause。

该设计承诺成功路径新增工作受控、失败密集时增强有界，不承诺零耗时或未经测量的性能百分比。
验收在相同候选和输入下比较无错误命令、首次错误、重复错误、不同错误密集发生与取消切片；
采集耗时、峰值内存、源码和指南读取次数、队列峰值与资源终态。

## DX 迁移定义

每项从初始版本 `0.15.0` 开始治理的 DX breaking change 都有稳定 ID 和一个功能 owner。
迁移条目声明旧形状首次适用版本、移除执行支持的准确发行版本、当前替代写法及可识别范围；
判定依据是观察到的 API/参数结构，不以项目 package.json 的版本推断用户已迁移。

版本在发布前绑定实际发行号，开发态可以明确标记 unreleased；不能编造尚未发生的发行号。
指南被保留到当前版本，替代示例始终指向当前可用 API；多次升级可以直接得到适用于当前包的修复步骤。

检测入口只有以下三种：

- 现有作者 API 的参数验证，识别已登记的旧结构而不执行 getter 或旧 callback。
- 只拒绝调用的旧导出或 CLI 参数入口；不出现在当前作者类型和正常 help 中，不实现旧行为。
- 模块加载已经失败后，依据可靠导入绑定识别已移除的 NiceEval 导入或调用；无法证明归属时保留普通加载错误。

字符串同名、注释、项目自己的同名函数和任意动态表达式不能作为迁移命中的证据。
没有可靠检测方法的 breaking change 必须设计有限拒绝入口和明确边界，不能只附网页链接就宣称完成迁移体验。
普通不合法输入仍为普通参数错误；不得把所有 unknown option 一律引导到某个 migration guide。

命中配置迁移时不创建 Invocation、不启动 setup、Sandbox 或模型请求。运行中命中时拒绝该调用并保留先前事实，
原 Scope 负责收尾。Library 不安装全局 exception handler；CLI 不承诺阻止或撤销用户模块顶层副作用。

## 英文指南与发布

`packages/niceeval/src/migrations/<id>.md` 是人读迁移内容的唯一 owner；文案、标题、说明与示例注释全部为英语。
每篇包含识别到的旧写法、变化原因、完整替代示例、模型/凭据等行为差异和迁移后的验证方法。
实际秘密和用户源码不插入静态 Markdown；位置与参数路径由独立诊断字段交付。

构建将这些受管文件复制到 `dist/migrations/`，并生成仅供安全定位的 ID → asset 映射。
package 发布检查证明每个已登记检测入口都有非空英文指南，且资产随 ESM、CJS 和 CLI 的同一候选包可离线读取。
维护者发布任何 DX 破坏性变化时，同批交付当前 API、拒绝旧入口、指南、源码位置与公开入口验收。

指南和拒绝型检测保存必要的旧写法知识，当前执行器不保留旧实现分支。
这条规则不修改 [Run](../run/README.md) 的历史读取、数据格式或迁移义务。

## 验收边界

使用安装后候选从真实 Library、CLI 和配置加载入口观察安全错误，不通过私有错误函数的单测替代用户结果。
确定性协议 fixture 只在 Provider 等外部边界制造失败。验收至少包含未知 thrown value、秘密脱敏、取消、
重复错误、增强超限、guide 资产缺失及 renderer 自身失败，证明原终态与 cleanup 保持成立。

迁移验收以带旧源码位置的真实消费项目进入：得到正确 ID、行列和完整英文指南，且被拒绝动作没有执行。
新写法正常运行；同名非 NiceEval 代码不误报；无法定位时显示 unknown；纯历史读取不因项目旧源码触发迁移。
