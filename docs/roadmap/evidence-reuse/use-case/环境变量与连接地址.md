# 环境变量与连接地址

`.env` 只决定值的加载位置，不决定值是否属于 Evidence 身份。
同一个 URL 变化可能需要沿用，也可能必须重跑，因此环境值必须先声明角色。

## Case A：新隧道仍通向同一资源

`NMEM_URL` 每次启动 cloudflared 都变化，但背后的服务与数据版本没变。
URL 是 connection，资源身份由 observer 回答：

```typescript
resources: [
  observeResource({
    id: "memory-corpus",
    async observe({ env, signal }) {
      return fetchVersion(env.connection("NMEM_URL"), signal);
    },
  }),
],

sandbox: e2bSandbox().env({
  NMEM_URL: fromConnection("NMEM_URL", { resource: "memory-corpus" }),
  NMEM_API_KEY: fromSecret("NMEM_API_KEY"),
}),
```

URL 与 API key 都不进 manifest；observer 返回的 resource identity 进入。
URL 变化而 resource identity 相同时，两套默认政策都沿用，不需要 ignore。

## Case B：URL 区分不同被测实现

`AGENT_ENDPOINT` 分别指向 production 与候选分支，endpoint 本身就是实验条件：

```typescript
sandbox: e2bSandbox().env({
  AGENT_ENDPOINT: fromEnvCondition("AGENT_ENDPOINT"),
}),
```

manifest 只保存安全摘要，不落 URL 明文。
摘要变化是 observed condition delta，两套默认政策都重跑。

用户确认两套地址对当前选中 Eval 等价时，可以承担风险：

```bash
niceeval exp compare/codex \
  --accept condition:env.AGENT_ENDPOINT
```

这次授权不会让未来第三个 endpoint 自动通过。

## Case C：URL 后面的资源身份无法观测

URL 被声明为 connection，但服务没有版本接口，也没有静态 epoch。
系统知道 Eval 依赖一个资源，却不能判断资源是否相同，因此状态是 opaque：

- 证明优先默认重跑；
- 复用优先默认沿用，并把 Evidence 标为 unverified。

两边分别可以用相反权限覆盖：

```bash
# 证明优先下，操作者确认资源没变
niceeval exp compare/codex --accept opaque:resource.memory-corpus

# 复用优先下，操作者怀疑资源变了
niceeval exp compare/codex --rerun resource:memory-corpus
```

每天都需要这类 flag，说明缺的是稳定 resource identity，不是更多 CLI 语法。

## Case D：Sandbox setup 中使用 URL

setup 里的 URL 仍按实际角色分类：

- npm mirror、代理或隧道只是 transport：connection；包版本或内容摘要另作身份。
- 下载地址决定拿到哪份工具或数据：condition，或为下载产物记录内容摘要。
- 带 token 的 signed URL 同时包含坐标和凭据：值本身不落盘，下载产物身份必须另行解析。

不能因为值来自 `.env` 就全部忽略，也不能因为字符串含 URL 就全部重跑。

## 审计

需要记录 Attempt 实际访问地址时，用 `ctx.fact()` 保存经脱敏的事实。
沿用 Evidence 保留原始执行时的地址，不被当前 Invocation 的 `.env` 覆盖。
