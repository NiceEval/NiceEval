# 同仓库多道题

这是该 API 的主要用户故事：同一题组共享一个 GitHub repository，但每道题从自己的 base commit 开始。

每道题只写自己的完整 base commit。无需共享 fixture、缓存路径或 clone 脚本：

```ts
// evals/project/issue-101/eval.ts
const BASE_COMMIT = "1111111111111111111111111111111111111111";

export default defineEval({
  sandbox: sandboxLayer().prepare(checkout({
    repository: "https://github.com/acme/project.git",
    commit: BASE_COMMIT,
  })),
  async test(t) {
    await t.send("修复 issue 101。");
  },
});
```

```ts
// evals/project/issue-205/eval.ts
const BASE_COMMIT = "2222222222222222222222222222222222222222";

export default defineEval({
  sandbox: sandboxLayer().prepare(checkout({
    repository: "https://github.com/acme/project.git",
    commit: BASE_COMMIT,
  })),
  async test(t) {
    await t.send("修复 issue 205。");
  },
});
```

第一次运行时，宿主为同一 repository 建立 SourcePool，只从 origin 补齐两个 commit 所缺的对象，并分别发布两个 SourceProjection。
后续运行只要投影仍在，同一健康 Domain 对这两个需求产生零 origin 请求；每道题仍取得独立、全新的 `.git`。

较早题只能看到它的 commit 和祖先。即使 Agent 知道第二题的 OID，`git cat-file -e <oid>` 也不能从第一题的 Sandbox 读到未来对象。
