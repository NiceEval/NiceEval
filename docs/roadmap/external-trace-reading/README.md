# 外部轨迹读取

被测应用常在自己的系统里保存完整原始录像，Record 中的执行轨迹只是规范化后的事件，或者只是其中一部分。
本方向让读者在 NiceEval 中显式读取这份外部存档的内容，并对取回的 bytes 做可验证的内容校验。
它建立在 Feature 的[外部存档出处](../../feature/adapters/library/README.md#外部存档出处)之上：出处只描述存档在哪里，本方向定义怎样经授权读到它。

## 谁会用

- 应用作者：Record 已保存足以导航的规范化事件，有时需要回看某段原始录像的逐帧细节，不想离开 NiceEval 另找工具。
- 诊断者：在另一台机器上读一份搬迁来的 Record，需要知道外部内容为什么读不到，而不是看到一份静默缩水的结果。

## 工作方式

外部读取是独立的显式入口，不替换 `show`、View 或任何现有 Inspection operation。
现有入口继续只读 Record 中已发布的事实，同一请求在任何机器、有无项目配置时得到同一结果，离线审计承诺不变。
读者主动选择外部读取时，结果另带外部可用性状态，与已发布事实分开呈现。

读取权限来自本机授权绑定，不来自 Record。
Record 中的出处只提供来源系统标识与纯数据 locator，不含凭据；凭据、租户与允许的对象范围保存在读者本机的绑定中。
已注册的 Adapter 只证明本地代码的来源，不证明这份 Record 获准使用本机对该来源的读取权限，因此注册本身不授权读取。

打开或导入 Record 时只校验出处的形状，绝不调用读取器。`--record`、`run import` 与所有现有 Inspection operation 都不触发外部访问。

## 不可用语义

外部内容读不到时返回明确的外部证据不可用状态，原因区分为：

| 原因 | 含义 |
|---|---|
| 缺少绑定 | 本机没有该来源系统的授权绑定，例如在另一台机器上读取 |
| 版本不兼容 | 存档的对象版本、来源或编码标识与本机读取器的兼容规则不符 |
| 已过期 | 来源系统已不再保存该对象 |
| 无权限 | 绑定存在，但不允许读取该对象 |
| 内容不符 | 取回的 bytes 与内容承诺不一致，该页被拒绝 |

任何不可用都不降级为部分内容冒充完整内容；离线可读的部分只来自 Record 中已发布的事实。

## 内容承诺与续读

每份可读取的外部存档在 Record 中带稳定的对象版本、来源与编码标识，以及能逐块验证的内容承诺。
逐块验证需要每块的预期摘要，或与根摘要配套的逐块证明；只有一个 Merkle 根不足以验证单块。
取回的块还要绑定块序号、长度、内容、格式，以及索引指向的规范化事件。

续读绑定同一逻辑对象与同一内容承诺。绑定恢复或重新授权后只能在相同承诺下继续；无法继续时返回 `restart-required`。

## 判定与身份

外部内容不进入历史判定。历史 Verdict 只折叠已发布的 Core outcome、Assertions 与显式 skip，读不到外部内容不改变它。
外部内容若决定一次新运行的判定，它的冻结版本或摘要是可观察输入，经受管输入、Adapter `behaviorRevision` 或有效配置进入当前目标身份。
读侧发现的摘要不符只改变该证据的可用性，不作为重跑触发依据。

## 复制进导出文件

把外部内容复制进导出文件时，不能以同一 Run 与 Attempt 身份改写已发布的内容闭包。
导出要么保持同一逻辑内容承诺的传输表示，使原版与复制版在同一库中不冲突；要么给复制产物独立身份并记录来源 Run 与 Attempt。

## 范围

本方向包含：

- 显式外部读取入口与它独立的可用性状态；
- 本机授权绑定、允许的数据域与对象范围；
- 对象版本、来源与编码标识的兼容规则，以及逐块内容承诺；
- 续读绑定与导出时的身份规则。

本方向不包含：

- 让 `show`、View 或现有 Inspection operation 隐式读取外部系统；
- 从 Record 中删除已保存的规范化事件或 Assertion 材料来节省空间；
- 读取时重新调用被测系统的业务 API；
- 在 Record 或 locator 中保存凭据。
