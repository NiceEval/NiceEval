# 内建子功能写入官方事实

Assertions、Verdict、Score、Eligibility、Observability、Sources 与 Sandbox facts 各自拥有私有官方
definition 和领域 adapter。它们没有另一条持久化管线。

以 Assertions 为例，包内 producer 把领域值先收束成其 durable payload，再通过与第三方相同的 owner-local
writer 写入：

```ts
// package-private: assertions/record.ts
import { assertionResults } from "./private-definition.js";

export const assertionOccurrence = {
  recordAttachments: { write: [assertionResults] },
};

export function writeAssertionResult(ctx, evaluation) {
  return ctx.recordEffect(
    assertionResults,
    assertionResultAdapter.toPayload(evaluation),
  );
}
```

`recordEffect()` 是 package-private 的 Effect adapter：它提交与公开 `ctx.record()` 完全相同的 command kernel，
不是第二条 writer 或额外 authority。这段内部接线表达的只有两件事：领域 adapter 决定业务事实，generic writer
验证 owner、schema 与 closure。它不向公共 API 暴露 `official: true`、namespace authority 或可写的
`niceeval.*` definition。

| 子功能 | 私有 definition 与 adapter 的职责 | owner |
| --- | --- | --- |
| Assertions、Verdict、Score、Eligibility | 将判定、得分与资格领域值编码为各自的事实 | Attempt |
| Evaluations、Membership Provenance、Sources | 将 Run 的分母、引用采用原因与源码 closure 编码为各自的事实 | Run |
| Observability | 将受限的对话、命令、usage、timing 与 diagnostic 输入收束为官方 family | Attempt 与 Run |
| Sandbox assignment | 将当前 Attempt 实际使用的 provider、实例与 reuse 坐标收束为事实 | Attempt |
| Plugin Provenance | 将成功 accepted contributions 与 linked occurrence identity 收束为审计事实 | Attempt 与 Run |

所有这些 producer 都通过内部 `recordAttachments: { write: [...] }` 获得自己的 exact definition-object grant。
外部作者既不能把官方 definition 放进 write grant，也不能绕过领域 adapter 调用 writer。当前 NiceEval package
固定安装自己的 official readers 与 migrations；应用的 `install` 只补充它选择信任的第三方 definitions。公共包只给
外部消费者 official family 的 `.reader` 与 projector capability；具体 durable shape 不由本用例复制。

官方无特权边界与 generic writer 的完整不变量见 [Architecture](../architecture.md)。
