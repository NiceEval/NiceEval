# Eval 写入 Attempt 自定义事实

一个 Eval 在执行时测得 GPU 能耗。这个观测属于当前 Attempt；它既不是运行配置，也不属于
Sandbox 或 Agent。

`record-attachments/gpu-energy.ts` 一次定义完整 family。这个版本没有 blob，因此 projection 明确返回空数组。

```ts
import { Schema } from "effect";
import { defineRecordAttachment } from "niceeval/record";

export const gpuEnergy = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: Schema.Struct({
        joules: Schema.Number,
        source: Schema.Literal("device-estimate"),
      }),
      blobRefs: () => [] as const,
    },
  },
  current: "v1",
  migrations: () => ({}),
});
```

`evals/gpu-energy.ts` 把这一个 definition-object 列入该 Eval occurrence 的 write grant，并在 Attempt
lifecycle 中调用同一个 `ctx.record()`。

```ts
import { defineEval } from "niceeval";
import { gpuEnergy } from "../record-attachments/gpu-energy.js";

export default defineEval({
  recordAttachments: { write: [gpuEnergy] },
  async test(ctx) {
    const joules = await measureGpuEnergy();

    await ctx.record(gpuEnergy, {
      joules,
      source: "device-estimate",
    });
  },
});
```

应用把读取与 migration trust 放在独立配置中。install 不会向这份 Eval 或任何其它 producer 授予 write。

```ts
import { defineConfig } from "niceeval";
import { gpuEnergy } from "./record-attachments/gpu-energy.js";

export default defineConfig({
  recordAttachments: { install: [gpuEnergy] },
});
```

这个 direct payload 只能用于零 blob 的 family。`record()` 调用立即占用当前 Attempt 的
`com.example.gpu-energy` family。漏 await 或捕获 rejection 都不会释放 reservation；host 仍跟踪 command 并在封口
前等待它。已接受 command 的 rejection 会 poison owner，不能再发布。重复与失败归属的精确语义见
[Lifecycle](../lifecycle.md)。blob 形态见 [写入 blob-backed
事实](Blob写入.md)，读取与 projector 形态见 [安装、读取与投影事实](读取投影.md)。
