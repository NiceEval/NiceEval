# 演进、迁移与保留历史事实

能耗事实用 `uncertainty` 区分已测得的不确定性与未知值。family 保留 v1 与 v2，并只声明 v1 到 v2 的相邻
converter。

```ts
import { Effect, Schema } from "effect";
import { defineRecordAttachment } from "niceeval/record";

export const gpuEnergy = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: Schema.Struct({
        joules: Schema.Number,
        source: Schema.Literal("device-estimate"),
      }),
      blobRefs: () => [] as const,
    },
    v2: {
      schema: Schema.Struct({
        joules: Schema.Number,
        source: Schema.Literal("device-estimate"),
        uncertainty: Schema.NullOr(Schema.Number),
      }),
      blobRefs: () => [] as const,
    },
  },
  current: "v2",
  migrations: ({ v1, v2 }) => ({
    v1: {
      to: v2,
      migrate: (source, target) =>
        Effect.succeed(target.value({
          ...source.payload,
          uncertainty: null,
        })),
    },
  }),
});
```

这里的 `null` 在 v2 schema 中明确表示“v1 facts 不含 uncertainty”；它不冒充数值 `0`。若 v2 语义不允许
表达未知值，就不能把历史值强行补成 current。

converter 收到 exact materialized source。它只通过 `target.value()` 或 `target.create()` 构造目标，不读取
当前 GPU、Record root 或运行时 context。此例 `Effect` 的 requirement 是 `never`；这不把 JavaScript callback
变成 sandbox。完整 callback 与 Cause 语义见 [Library](../library.md)。

如果业务改为要求 v2 的 `uncertainty` 必须是 calibrated number，而 v1 又没有足够事实，同一 edge 应使用
已定 unavailable 语义，而不是制造补值：

```ts
migrations: ({ v1, v2 }) => ({
  v1: {
    to: v2,
    unavailable: {
      reason: "v1 did not record a calibrated uncertainty",
    },
  },
})
```

这个形态使读取结果成为 `migration-unavailable`。它保留 v1 bytes，也不把失败伪装为可重跑的 converter。

producer module 与 definition module 可以独立部署。项目可以只保留 definition import 与项目配置，历史
Record 仍可读取与迁移：

```ts
import { defineConfig } from "niceeval";
import { gpuEnergy } from "./record-attachments/gpu-energy.js";

export default defineConfig({
  recordAttachments: { install: [gpuEnergy] },
});
```

`niceeval migrate --record /project/.niceeval/record` 只使用这份已安装的完整 family。它先检查 Git 恢复点并创建
sentinel；plan、恢复与中断反馈以 [CLI](../cli.md) 为单源。没有安装 definition 的历史 bytes 是 `unsupported`；
CLI 不按 name 发现 package、调用 producer 或执行 factory。
