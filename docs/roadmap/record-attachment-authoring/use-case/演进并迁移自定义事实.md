# 定义并显式迁移 GPU Attachment

这个机械切片只面向两种身份：领域 SDK 作者定义相邻 converter，application maintainer 规划并执行迁移。普通 Eval
作者仍只使用 `gpuEnergy({ meter })`，不接触本页 API。通用类型以 [Library](../library.md) 为单源；完整纵向消费见
[用户扩展 GPU 能耗领域 SDK](../../record-analysis-report/use-case/第三方事实扩展.md)。

## SDK 定义具体 Attachment 内容

这份 Attempt-owned family 的 durable identity 与 payload 是：

| 项目 | v1 | v2 |
|---|---|---|
| owner | `attempt` | `attempt` |
| name | `com.example.gpu-energy` | `com.example.gpu-energy` |
| schema identity | `com.example.gpu-energy/v1` | `com.example.gpu-energy/v2` |
| observed payload | `state + joules` | `state + joules + source + uncertaintyJoules` |
| unavailable payload | `state + reason` | `state + reason` |
| blobs | `[]` | `[]` |

v1 的版本语义规定 observed 值全部来自 `device-estimate`。因此 v2 可以无损补出 source；v1 没有持久化 uncertainty，
所以 v2 使用 `null`，不能写成 `0`。

```ts
import { Effect, Schema } from "effect";
import {
  defineRecordAttachmentAdapter,
  type RecordAttachmentInstallation,
} from "niceeval/record/adapter";
import type { GpuEnergy } from "./domain.js";

const finiteNonNegative = Schema.Number.pipe(
  Schema.finite(),
  Schema.nonNegative(),
);

const payloadV1Schema = Schema.Union(
  Schema.Struct({
    state: Schema.Literal("observed"),
    joules: finiteNonNegative,
  }),
  Schema.Struct({
    state: Schema.Literal("unavailable"),
    reason: Schema.Literal("not-supported", "not-readable"),
  }),
);

const payloadV2Schema = Schema.Union(
  Schema.Struct({
    state: Schema.Literal("observed"),
    joules: finiteNonNegative,
    source: Schema.Literal("device-estimate"),
    uncertaintyJoules: Schema.NullOr(finiteNonNegative),
  }),
  Schema.Struct({
    state: Schema.Literal("unavailable"),
    reason: Schema.Literal("not-supported", "not-readable"),
  }),
);

type PayloadV1 = Schema.Schema.Type<typeof payloadV1Schema>;
type PayloadV2 = Schema.Schema.Type<typeof payloadV2Schema>;

const gpuEnergyRecord = defineRecordAttachmentAdapter({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: payloadV1Schema,
      blobRefs: (_payload: PayloadV1) => [] as const,
    },
    v2: {
      schema: payloadV2Schema,
      blobRefs: (_payload: PayloadV2) => [] as const,
    },
  },
  current: "v2",
  migrations: ({ v1, v2 }) => ({
    v1: {
      to: v2,
      migrate: (source, target) =>
        Effect.succeed(
          target.value(
            source.payload.state === "observed"
              ? {
                  state: "observed",
                  joules: source.payload.joules,
                  source: "device-estimate",
                  uncertaintyJoules: null,
                }
              : source.payload,
          ),
        ),
    },
  }),
  adapt: (value: GpuEnergy, target) =>
    Effect.succeed(target.value(value)),
  project: ({ payload }) => payload,
});

export const gpuEnergyRecordInstallation:
  RecordAttachmentInstallation = gpuEnergyRecord.installation;
```

`source.payload` 是 exact decoded、package-owned、deep-frozen v1 plain data；`source.blobs` 只能访问这份 Attachment 的
own closure。`target.value()` 返回 opaque target result，不能选择 owner、name、schemaId、path 或提交时机。host 对结果
执行 v2 schema、plain-data 与 zero-blob closure validation。

若 v1 的版本语义没有保证 source，SDK 必须声明不可无损迁移：

```ts
migrations: ({ v1, v2 }) => ({
  v1: {
    to: v2,
    unavailable: {
      reason: "v1 did not record a source that can be derived losslessly",
    },
  },
}),
```

planner 遇到这条 edge 时不先执行前半条 chain。它保留 exact v1 bytes，并形成 `migration-unavailable`。

## Application 安装同一 capability

config 与 programmatic host 共用一个 installation 输入：

```ts
// record-attachments.ts
import {
  gpuEnergyRecordInstallation,
} from "@example/niceeval-gpu/record";

export const recordAttachments = {
  install: [gpuEnergyRecordInstallation],
} as const;

// niceeval.config.ts
import { defineConfig } from "niceeval";
import { recordAttachments } from "./record-attachments.js";

export default defineConfig({ recordAttachments });
```

installation 只授予读取与 migration trust。它不挂载 producer，也不能反推出 adapter、binding 或 writer。Plugin mount
同样不会自动安装它。

## Application 调用 migrate SDK

programmatic maintenance API 位于 host-only `niceeval/record/host`。它不是普通 Eval 或 Report 作者 API：

```ts
import { Console, Effect, Either } from "effect";
import {
  NodeRecordHostLive,
  makeRecordRoot,
  openRecordAccessRuntime,
  type RecordMigrationAuthorizationDecision,
} from "niceeval/record/host";
import { recordAttachments } from "./record-attachments.js";

export const migrateRecordHistory = (
  decision: RecordMigrationAuthorizationDecision,
) =>
  Effect.scoped(
    Effect.gen(function* () {
      const rootResult = makeRecordRoot("/project/.niceeval/record");
      if (Either.isLeft(rootResult)) {
        return yield* Effect.fail(rootResult.left);
      }
      const access = yield* openRecordAccessRuntime({
        root: rootResult.right,
        recordAttachments,
      });

      const plan = yield* access.maintenance.planMigration();
      yield* Console.log(JSON.stringify(plan.summary, null, 2));

      if (plan.state === "not-needed") {
        return yield* access.maintenance.migrate({ plan });
      }

      const authorizationResult =
        access.maintenance.authorizeMigration({ plan, decision });
      if (Either.isLeft(authorizationResult)) {
        return yield* Effect.fail(authorizationResult.left);
      }
      return yield* access.maintenance.migrate({
        plan,
        authorization: authorizationResult.right,
      });
    }),
  ).pipe(Effect.provide(NodeRecordHostLive));
```

`plan.summary` 穷尽列出 Core、每个 Attachment family、from/to、相邻 edges、实例数与 Git safety。

plan 本身是 package-minted opaque value。private state 绑定 exact runtime、root snapshot、installation identities、
source validation 与 Git inspection；复制 summary JSON 不能执行。

调用者显式选择 `{ state: "use-git-restore-point" }` 或 `{ state: "accept-data-loss" }`。
`authorizeMigration()` 才针对 exact plan mint nominal authorization。plan、registry、source bytes 或 Git 状态变化时，
执行返回 `record-migration-plan-stale`，且不会创建 sentinel。

成功 receipt 逐 family 区分：

- `migrated`：完整相邻 chain 已写成 current；
- `already-current`：原本已经是 current；
- `preserved-migration-unavailable`：已知但不可无损迁移，原 bytes 保留；
- `preserved-unsupported`：没有安装 owning family，原 bytes 保留。

## CLI 映射到同一个 facet

```sh
niceeval migrate \
  --record /project/.niceeval/record \
  --config /project/niceeval.config.ts
```

CLI 对 `--config` 做配置求值，得到同一个 `recordAttachments`。它调用 `planMigration()`，呈现 plan summary，再把交互
选择交给 `authorizeMigration()`。`--yes` 只形成 `accept-data-loss` decision，不能直接伪造或跨 plan 重用 authorization。

执行取得 exclusive maintenance lock，创建并 sync `migration.in-progress`，逐 adjacent edge 运行 converter，并复用
schema、plain-data 与 closure validators。target bytes 与最终 `record.json` sync 后，host 最后删除并 sync sentinel，
此时才返回 receipt。

converter、blob、durable I/O、defect、kill 或 interruption 失败时没有 receipt，sentinel 保留。后续 open、plan 与
migrate 都返回 `record-migration-interrupted`；用户必须从 plan 显示的 Git commit 或自己的备份恢复，不能直接重跑或
删除 sentinel。

成功后必须重新执行 Report。fresh snapshot 才形成 current value；迁移前的 `ReportExecution` 不会刷新。
