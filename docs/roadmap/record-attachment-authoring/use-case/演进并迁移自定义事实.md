# 演进并显式迁移

领域 SDK 在同一个 adapter 中增加相邻版本：

```ts
const adapter = defineRecordAttachmentAdapter({
  owner: "attempt",
  name: "com.example.measurement",
  versions: {
    v1: { schema: v1Schema, blobRefs: () => [] as const },
    v2: { schema: v2Schema, blobRefs: () => [] as const },
  },
  current: "v2",
  migrations: ({ v1, v2 }) => ({
    v1: {
      to: v2,
      migrate: (source, target) =>
        Effect.succeed(target.value(toV2(source.payload))),
    },
  }),
  adapt: adaptCurrent,
  project: projectCurrent,
});
```

converter 只读取 exact source payload 与 own blobs。它不重新采集、访问 clock／network／filesystem 或打开 producer
session。无法从 v1 事实无损得到 v2 时，edge 使用 `unavailable`，不能猜默认值。

application host 安装新 adapter 的 opaque installation 后，普通 read 仍只返回 `migration-required`。Report 先把这个
状态放进 projected row 与不可删除的 problems surface：

```sh
niceeval show --run 01H... --report ./reports/measurement.ts
```

它不会在读取期间运行 converter。用户显式执行：

```sh
niceeval migrate \
  --record /project/.niceeval/record \
  --config /project/niceeval.config.ts
```

CLI 先核对 installation registry、exact source、完整相邻 graph 与 Git restore point。确认后，它在 exclusive
maintenance lock 下创建 `migration.in-progress`，逐 adjacent edge 写入，并复用 schema、plain-data 与 closure validators。

成功删除 sentinel 后，用户重新执行 `niceeval show`。fresh snapshot 才能形成 current available value；旧
`ReportExecution` 不刷新。converter 或 durable write 失败会保留 sentinel，后续 open fail closed，用户从 Git 或备份
恢复。

Plugin mount 不自动执行 converter，也不从历史 bytes 动态 import SDK。`migration-unavailable` 保留旧 bytes，只显示
reason，不提示重复运行命令。完整 GPU 路径见[用户扩展 GPU 能耗领域 SDK](../../record-analysis-report/use-case/第三方事实扩展.md)。
