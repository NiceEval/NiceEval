# 演进并迁移自定义事实

能耗事实需要增加误差区间。作者在同一个 definition 中保留 v1、增加 v2，并声明唯一相邻 edge：

```ts
import { Effect, Schema } from "effect";
import { defineRecordAttachment } from "niceeval/record";

export const gpuEnergy = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: Schema.Struct({
        joules: Schema.Number,
        source: Schema.Literal("device-estimate"),
      }),
      blobRefs: () => [],
    },
    v2: {
      schema: Schema.Struct({
        joules: Schema.Number,
        source: Schema.Literal("device-estimate"),
        uncertainty: Schema.NullOr(Schema.Number),
      }),
      blobRefs: () => [],
    },
  },
  current: "v2",
  migrations: ({ v1, v2 }) => ({
    v1: {
      to: v2,
      migrate: (source, target) =>
        Effect.succeed(target.value({
          ...source.payload,
          uncertainty: null,
        })),
    },
  }),
});
```

如果 `null` 会伪造“已知为空”而不是表达 v1 缺失的事实，这条 edge 应改成 `unavailable`。converter 不能读取当前
GPU 或重新估算历史能耗。

项目 config 继续安装这份 definition，即使原 Eval 或 Plugin 已被删除：

```ts
export default defineConfig({
  recordAttachments: [gpuEnergy],
});
```

用户先确保 Record 位于 Git restore point，再运行：

```sh
niceeval migrate --record /project/.niceeval/record
```

CLI 从 config 取得 family-owned migration graph，生成绑定当前 root、registry 与 Git 状态的 plan，再原地执行。
失败或中断留下 sentinel；用户从 Git 恢复。definition 不可加载时，v1 bytes 保持 unsupported，CLI 不根据 name
下载或 import package。
