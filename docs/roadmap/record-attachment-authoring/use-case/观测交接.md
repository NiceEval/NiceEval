# 交接 Sandbox、Agent 与 Adapter 观测

Sandbox、Agent 与 Adapter 分别拥有资源、执行和协议适配。它们不是 Record owner，默认没有 raw Record
capability、definition install 权或泛化 writer。

Eval producer 可以把边界返回的观测写入自己的 Attempt context：

```ts
import { Schema } from "effect";
import { defineEval } from "niceeval";
import { defineRecordAttachment } from "niceeval/record";

export const agentObservation = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.agent-observation",
  versions: {
    v1: {
      schema: Schema.Struct({
        compilerVersion: Schema.String,
        turns: Schema.Number,
      }),
      blobRefs: () => [] as const,
    },
  },
  current: "v1",
  migrations: () => ({}),
});

export default defineEval({
  recordAttachments: { write: [agentObservation] },
  async test(ctx) {
    const compiler = await ctx.sandbox.runCommand("compiler", ["--version"]);
    const events = await runAdapterAttempt({
      agent: ctx.agent,
      sandbox: ctx.sandbox,
    });

    await ctx.record(agentObservation, {
      compilerVersion: parseCompilerVersion(compiler),
      turns: countTurns(events),
    });
  },
});
```

`runAdapterAttempt()` 返回观测数据，不接收 Record root、definition registry 或全局 writer。需要 adapter 协作
写入时，owner lifecycle 可以显式把已有的窄 context 交给只写入 `agentObservation` 的函数。这个传递不形成
新的 Adapter capability；更宽的 context、任意 name 写入或自行安装 definition 都不成立。完整 typed context 见
[Library](../library.md)。

读取与 migration 仍由应用显式安装：

```ts
import { defineConfig } from "niceeval";
import { agentObservation } from "./record-attachments/agent-observation.js";

export default defineConfig({
  recordAttachments: { install: [agentObservation] },
});
```

Sandbox facts、Adapter 观测和 Agent execution 都可以成为某个 owner 的 payload；它们不会因此成为新的
Record owner。Experiment producer 需要 Run 事实时使用同样的 `ctx.record()` 形状，见
[Experiment 生命周期写入 Run 事实](实验生命周期事实.md)。
