# 安装、读取与投影事实

应用选择信任 `gpuEnergy` 后，config 安装完整 family。install 是读取与 migration trust 的唯一配置入口；它不会扫描
producer、从 Record bytes 发现 package，或产生 write grant。

```ts
import { defineConfig } from "niceeval";
import { gpuEnergy } from "./record-attachments/gpu-energy.js";

export default defineConfig({
  recordAttachments: { install: [gpuEnergy] },
});
```

普通 reader 用 definition 的只读 `.reader` capability 读取；它不因此取得 write grant。

```ts
const state = yield* view.readAttemptAttachment(
  attempt,
  gpuEnergy.reader,
);
```

projector 与 writable definition 分离。它封装只读 attachment target 与 pure `project`，由 host 对 frozen view
执行；它不能打开 root、安装 definition、取得 writer 或运行 migration。

```ts
import { defineRecordAttachmentProjector } from "niceeval/projection";
import { gpuEnergy } from "../record-attachments/gpu-energy.js";

export const gpuEnergyView = defineRecordAttachmentProjector({
  attachment: gpuEnergy.reader,
  project: ({ payload }) => ({
    joules: payload.joules,
    source: payload.source,
  }),
});
```

需要对选定 Attempt 逐 slot 读取时，Projection Library 将 projector 绑定到固定的逻辑访问：

```ts
import { attemptSlotProjection } from "niceeval/projection";
import { gpuEnergyView } from "./gpu-energy-view.js";

export const energyByAttempt = attemptSlotProjection(gpuEnergyView);
```

Record reader 与 projector 都保留读状态，而不是把数据缺口变成猜测：

| 状态 | 读取方得到的事实 |
| --- | --- |
| `available` | payload 与完整 blob closure 已 materialize；projector 产生 view。 |
| `unavailable` | 当前 owner 没有该 Attachment。 |
| `migration-required` | 已安装 family 认识旧 schema，且完整 converter 链可用。 |
| `migration-unavailable` | 已安装 family 的相邻路径含不可无损 edge。 |
| `unsupported` | family 或 schema 没有安装；原 bytes 保留。 |
| `invalid` | envelope、payload、ref 或 closure 不能通过验证。 |

普通 reader 不执行 migration。`migration-required` 的下一步是显式 `niceeval migrate`；
`migration-unavailable` 和 `unsupported` 都不是自动 discovery 的理由。slot projection 还会把 `excluded`、
`not-recorded` 与 `core-invalid` 保留为独立 entry，详情见 [Projection Library](../../../feature/projection/library.md)
与 [Record Library](../../../feature/record/library.md)。
