# 轮换连接坐标

## 场景

被测服务经隧道暴露,隧道进程重启后 URL 就变了。变的只是通到那台服务的路,
服务本身、它里面的数据、它的版本都没动。这种轮换一天可能发生几次,
它一次都不该作废结果。

同一个 URL 值也可能因为换了一个新实例而变。那一次是被测对象换了,该全部重跑。
两种改动落在同一个键上,值的变化形态一模一样,区别只在改它的原因。

## 怎么写

把坐标、凭据与资源身份分开。
URL 和 API key 只负责连接，observer 返回连接背后的资源版本。

```typescript
import { defineExperiment, observeResource } from "niceeval";
import { e2bSandbox, fromSecret } from "niceeval/sandbox";

export default defineExperiment({
  resources: [
    observeResource({
      id: "memory-corpus",
      appliesTo: (e) => e.tags.includes("memory"),
      async observe({ env, signal }) {
        const response = await fetch(`${env.secret("NMEM_URL")}/version`, {
          headers: { authorization: `Bearer ${env.secret("NMEM_API_KEY")}` },
          signal,
        });
        return (await response.json()).corpusVersion;
      },
    }),
  ],

  sandbox: e2bSandbox({ template: "niceeval-agents" }).env({
    NMEM_URL: fromSecret("NMEM_URL"),
    NMEM_API_KEY: fromSecret("NMEM_API_KEY"),
  }),
});
```

对上三种改动:

| 发生了什么 | 改什么 | 结果 |
|---|---|---|
| 隧道重启，URL 变了 | 只改 `NMEM_URL` | observer 版本未变，历史 Evidence 沿用 |
| 清库或换实例 | 更新 URL；服务版本随状态变化 | observer 版本变化，相关槽位派发 |
| 轮换 API key | 只改 `NMEM_API_KEY` | 资源版本未变，历史 Evidence 沿用 |

需要审计实际地址时用
[`ctx.fact()`](../../../feature/record/architecture.md#facts运行事实) 上报。
沿用 Evidence 保留原始执行时的地址，不被当前地址覆盖。

## 边界

observer 必须只读。
它可以查询版本、实例 ID 或数据 epoch，不能顺手清库、启动隧道或导入数据。
有副作用的动作仍属于 setup，并且只在计划存在派发项时执行。

服务没有稳定版本接口时，改用静态 `corpusEpoch` observer。
两者都没有时，相关 Requirement 为 `opaque`，默认每次派发；
系统不能仅凭 URL 是否变化推断是不是同一个被测资源。
