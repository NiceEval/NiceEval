# 组合多个环境层

## 解决什么问题

一个 Experiment 可能同时需要公司证书、特定运行时和记忆工具。
这些内容都随 Experiment 变化,但安装存在明确先后关系。

## 按依赖顺序声明

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: BASE_TEMPLATE }),
  layers: [
    companyCertificates,
    nodeRuntime,
    mempal,
  ],
});
```

Experiment Layer 按数组顺序检查和补齐。
上例中 `nodeRuntime` 可以使用 `companyCertificates` 配好的内部 registry,mempal 又可以依赖前面就位的 Node.js。

Adapter 提供的 Agent Layer 自动排在 Experiment Layer 之后,实验文件不用手工加入 `codex`。
如果某个扩展必须在 Agent CLI 安装后才能配置,它属于 adapter factory 的安装后 Hook 或自定义 provisioner,不放进这个数组。

## 冲突会怎样

```typescript
layers: [node20, legacyToolchain]
```

如果 `legacyToolchain` 覆盖 PATH 并破坏了 `node20`,后续全栈复检会再次检查 `node20`。
Attempt 进入 `errored`,诊断点名复检失败的 Layer,并列出它上次通过后执行过 apply 的候选破坏者。

Layer 数组只表达简单的线性依赖。
一组工具需要拓扑求解、互相协商或共同回滚时,应先封装成一个 Layer,不要把内部包管理关系展开给 Runner。
