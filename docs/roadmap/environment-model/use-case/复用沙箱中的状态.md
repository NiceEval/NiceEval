# 复用 Sandbox 中的状态

## 解决什么问题

Layer 负责让 mempal 二进制与模型就位,但记忆数据库是运行状态。
状态需要在 Sandbox 创建时载入、销毁前回存,不属于 Layer identity、check 或 apply。

## 每个 Sandbox 载入与回存一次

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: BASE_TEMPLATE })
    .setup(async (sandbox, ctx) => {
      const restored = await loadMemoryState(sandbox, ctx.experimentId);
      ctx.fact("memory.restored", restored);
    })
    .teardown(async (sandbox, ctx) => {
      await saveMemoryState(sandbox, ctx.experimentId);
    }),
  layers: [mempal],
  maxConcurrency: 1,
});
```

不开 `sandboxReuse` 时,每条 Attempt 使用新 Sandbox,因此每条都会载入和回存一次。
`maxConcurrency: 1` 让同一 Experiment 对外部状态的读写保持串行。

## 让多条 Attempt 共用活状态

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: BASE_TEMPLATE })
    .setup(loadMempalState())
    .teardown(saveMempalState()),
  layers: [mempal],
  sandboxReuse: true,
  maxConcurrency: 1,
});
```

打开 `sandboxReuse` 后,Hook 仍然每个 Sandbox 执行一次。
同一复用窗口内的 Attempt 直接读写 Sandbox 中的活状态,窗口结束才回存。

这种顺序效应必须是实验有意测试的变量。
如果记忆累积只是噪声,不要开启 `sandboxReuse`,或者在 Eval 生命周期中显式恢复逐题快照。

状态文件也应放在 workdir 之外。
workdir 会在复用 Attempt 之间回到题间重置点;要逐题铺进 workdir 的内容属于 Fixture。
