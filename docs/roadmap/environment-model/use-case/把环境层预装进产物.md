# 把环境层预装进产物

## 解决什么问题

逐层计时显示 mempal 每次安装和预热都要 90 秒,而[实验环境较重的记忆实验](实验环境较重.md)会频繁运行。
这时可以用 provider 原生工具构建预装 mempal 的 image、template 或 snapshot。

## 只切换 Sandbox 起点

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: "acme/codex-mempal-0.9.0" }),
  layers: [mempal],
  flags: { memory: "mempal" },
});
```

`layers: [mempal]` 保持不动。
新 template 中的安装身份与声明相符时,check 命中并跳过 apply;预装内容缺失或过期时,Layer 现场补齐并复检。

构建脚本必须让预装内容满足 Layer 的完整 check。
如果 Layer 通过安装 manifest 核对配方与模型身份,预装过程也要写入同样的 manifest,不能只把同名命令放进 PATH。

## 接受一次实验代际切换

换 image、template 或 snapshot 会改变 sandbox case 身份,因此旧结果不携带。
Layer 的 check 只证明自己声明的内容,不能证明两个起点的系统包和运行时配置完全等价。

先用现场安装把实验跑对,根据逐层计时决定哪些 Layer 值得预装。
构建完成后切换 Sandbox 起点并接受一次全量重跑;新的实验代际内,Layer 声明继续提供身份、检查与漂移防护。
