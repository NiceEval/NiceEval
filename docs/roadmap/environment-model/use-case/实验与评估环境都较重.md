# 实验与评估环境都较重

## 项目形态

每道 Eval 有自己的 Compose,不同 Experiment 又要增加不同工具。
例如 241 道 terminal-bench 题各自构建任务环境,记忆实验还要安装 mempal,普通对照实验则不安装。

这两条变化轴分别声明,不构建「241 道题 × 每个实验变体」的组合 template:

```typescript
// 每道 Eval
export default defineEval({
  environment: composeSandbox({
    file: new URL("docker-compose.yaml", import.meta.url),
    mainService: "client",
    build: "on-demand",
  }),
  async test(t) {
    await t.send(TASK_PROMPT);
  },
});
```

```typescript
// 记忆 Experiment
export default defineExperiment({
  agent: claudeCodeAgent({ mcpServers: [mempalMcp] }),
  sandbox: dockerSandbox({
    materializers: { compose: dockerComposeMaterializer() },
  }),
  layers: [mempal],
});
```

每条 Attempt 先按 Eval 的 BuildKey 构建缺失产物并启动 Compose,再把 Experiment 的 mempal Layer 和 Adapter 的 Agent Layer 装进主 Sandbox。

## 断网题使用 staged Layer

部分题目的主 Sandbox 禁止访问外网时,直连版本的 mempal 会因 `requires: { network: "direct" }` 在计划期 `skipped`。
这类 Experiment 改用宿主侧准备 payload 的版本:

```typescript
const identity = {
  version: MEMPAL_VERSION,
  payloadDigest: MEMPAL_TARBALL_SHA256,
  modelDigest: MEMPAL_MODEL_SHA256,
};

export const mempalStaged = defineLayer({
  name: "mempal",
  identity,
  requires: { root: true },
  check: async (sandbox) => {
    const actual = await readMempalInstallation(sandbox);
    if (!actual) return { ok: false, reason: "missing" };
    return sameIdentity(actual, identity)
      ? { ok: true, actual: { version: actual.version } }
      : { ok: false, reason: "identity-mismatch", detail: actual.summary };
  },
  prepare: async (ctx) => {
    const archive = join(ctx.stageDir, "mempal.tar.gz");
    await downloadMempalRelease(MEMPAL_VERSION, archive);
    await verifySha256(archive, identity.payloadDigest);
    return { files: { archive } };
  },
  apply: async (sandbox, ctx) => {
    await sandbox.uploadFile("/opt/staged/mempal.tar.gz", ctx.prepared.files.archive);
    await installMempalOffline(sandbox, "/opt/staged/mempal.tar.gz");
    await writeMempalInstallation(sandbox, identity);
  },
});
```

```typescript
export default defineExperiment({
  agent: claudeCodeAgent({ mcpServers: [mempalMcp] }),
  sandbox: dockerSandbox({
    materializers: { compose: dockerComposeMaterializer() },
  }),
  layers: [mempalStaged],
});
```

`prepare` 在宿主侧下载并校验 payload,同一准备身份在 Run 中 single-flight;`apply` 只通过 Sandbox 文件 API 离线安装。

## `sandboxReuse` 能做什么

Layer 解决组合声明与身份问题,不会让不同 Compose case 共用同一个 Sandbox。
因此 `sandboxReuse` 不是消除「题目 × 实验」矩阵的必要条件,也不能让不同 case 的 Attempt 共用一次 mempal 安装。

同一个 case 有多次 Attempt 时,可以在该 environment 分组内复用 Sandbox,让首次 apply 后的检查命中。
是否开启仍取决于题目能否接受 workdir 外状态残留;不同 case 的 Sandbox 各自执行一次 Layer 安装。

这类项目的两种主要缓存互相独立:BuildKey 复用题目构建产物,Layer check 复用 Sandbox 中已经就位的实验工具。
