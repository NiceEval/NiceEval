# Assertion、Evidence 与外部 SQL Score

本例区分三种对象：官方 Assertion 表达测试判定，Evidence 保存实际使用的材料，第三方 Score 表达领域 evaluator 的预声明
rubric。SQL rows 不是自动可查询 schema。

## 官方 Assertion

```ts
await t.check("生成了迁移文件", async (assert) => {
  const diff = await t.sandbox.diff();
  assert.fileChanged(diff, "migrations/002_add_energy.sql");
});
```

普通作者只调用 Assertion 与 Sandbox 领域 API。NiceEval 内部保存：

- Assertion outcome；
- evaluator / producer identity；
- subject identity；
- 实际使用的 exact Evidence refs；
- File Diff 与 source site anchors。

Assertion 不是用户 `ScoreDefinition`，也不经动态 rubric key 模拟。

## 用户代码运行 SQL

领域 evaluator 预声明 Score 与 Artifact：

```ts
export const dataQualityScore = defineScore({
  id: "com.example.data-quality",
  rubrics: {
    correctness: numberRubric({ min: 0, max: 1, required: true }),
    freshness: enumRubric(["fresh", "stale"], { required: false }),
  },
});

export const qualityRows = defineArtifact({
  id: "com.example.quality-rows",
  mediaTypes: ["application/json"],
});

export const dataQualityCapture = defineScoreCapture({
  score: dataQualityScore,
  producer: {
    id: "com.example.sql-check",
    behaviorVersion: "3",
    config: { queryVersion: "2026-08-13" },
  },
  required: true,
});

export const qualityRowsCapture = defineArtifactCapture({
  artifact: qualityRows,
  producer: {
    id: "com.example.sql-check",
    behaviorVersion: "3",
    config: { queryVersion: "2026-08-13" },
  },
  required: false,
});
```

运行时由用户代码连接 warehouse：

```ts
export default defineEval({
  captures: [dataQualityCapture, qualityRowsCapture],

  async test(t) {
    const rows = await warehouse.query(checkSql);

    const evidence = await t.evidence.attach({
      name: "quality-check.json",
      mediaType: "application/json",
      value: rows,
    });

    await t.artifact(qualityRowsCapture).seal({
      state: "available",
      items: [{
        name: "quality-check.json",
        mediaType: "application/json",
        evidence: evidence.ref,
      }],
    });

    await t.score(dataQualityCapture).seal({
      state: "available",
      rubrics: {
        correctness: {
          state: "available",
          value: calculateCorrectness(rows),
          evidence: [evidence.ref],
        },
        freshness: {
          state: "available",
          value: classifyFreshness(rows),
          evidence: [evidence.ref],
        },
      },
    });
  },
});
```

如果 `t.evidence.attach()` 已拥有同一内容，Artifact Capture 可以只保存该 Evidence ref，而不复制 blob。无论物理去重结果如何，
Score 的 exact Evidence refs 都指向 sealed material。

SQL 列不会自动成为 Dimension。要按 region、engine 或数据版本分组，领域 SDK 必须把它们声明为 Score enum rubric、Metric enum
label，或平台拥有的稳定 Analysis Dimension。

## Analysis

```ts
export const correctness = scoreMeasure(
  dataQualityScore.rubrics.correctness,
  {
    producers: requireSameProducer(),
    withinEval: mean(),
    acrossEvals: mean(),
    denominator: allLogicalSlots(),
    missing: partial(),
  },
);

export const freshness = scoreDimension(
  dataQualityScore.rubrics.freshness,
);
```

Score bundle failed、required rubric failed、optional rubric absent 与 logical slot missing 都有不同状态。`correctness` 的
`MetricValue.refs` 保留 evaluator 实际使用的 Evidence。

## Report

```tsx
export const QualityOverview = defineComponent(async (_props, { sample }) => {
  const rows = await aggregate(sample, {
    by: { agent, freshness },
    values: { passRate, correctness },
  });

  return (
    <>
      <Bars
        points={rows}
        x="agent"
        y="correctness"
        color="freshness"
      />
      <Table
        rows={rows}
        evidence={{ target: attemptEvidencePage }}
      />
      <EvidencePreview
        refs={rows.flatMap((row) => row.correctness.refs)}
        maxItems={20}
      />
    </>
  );
});
```

组件显示 `observed / denominator`，并在唯一 Evidence Page target 存在时生成下钻。Report 不重新运行 SQL，也不读取 Artifact JSON
来重算 correctness。`EvidencePreview` 让用户自己产生的 SQL rows 在 terminal、Web 与 static 中有界展示；host 在 semantic tree
闭合前按 exact refs 读取并验证内容，Report callback 不取得 rows 内容。要把 SQL 列画成图或参与分组，Capture 必须同时产生预声明 Metric、Score 或
Dimension，不能把 preview 当作第二条查询路径。

## 历史事实

新 evaluator 不能向已发布 Attempt 追加 Score：

```text
old Attempt + new evaluator
  ≠ mutate old Attempt
```

可以做的是用新 Analysis field 重新解释既有 Score，或在未来由 NiceEval 定义新的 immutable Assessment Run。后者拥有自己的
identity、分母与 frozen Evidence refs，不重开旧 Attempt。
