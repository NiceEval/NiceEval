# 第三方 GPU Energy

本例展示领域 SDK 怎样从 Capture 一直走到 Report。普通 Eval 作者最终只选择 `gpuEnergy()` Plugin。

## 1. 定义 Metric

```ts
// @example/gpu-energy/capture
import {
  defineMetric,
  enumLabel,
  optionalEnumLabel,
} from "niceeval/capture";

export const gpuEnergyMetric = defineMetric({
  id: "com.example.gpu-energy",
  unit: "J",
  labels: {
    source: enumLabel(["device-estimate", "nvml"]),
    device: optionalEnumLabel(["gpu-0", "gpu-1"]),
  },
  uncertainty: "absolute",
});
```

定义只说明事实含义。它不选择图表，不定义 reducer，也没有 storage converter。

## 2. 定义 Capture token

```ts
export function createEnergyCapture(options: { device: 0 | 1 }) {
  const device = `gpu-${options.device}` as const;

  return defineMetricCapture({
    metric: gpuEnergyMetric,
    producer: {
      id: "com.example.nvml-meter",
      behaviorVersion: "2",
      config: { sampling: "attempt-boundary", device: options.device },
    },
    required: false,
    expectedCoordinates: [
      { source: "nvml", device },
    ],
  });
}
```

SDK options 改变测量行为时，canonical config fingerprint 随之改变。`gpuEnergyMetric` identity 不因此改变；Analysis 会决定不同
producer 是否能一起比较。

## 3. 封装成 Plugin

```ts
// @example/gpu-energy
import { definePlugin } from "niceeval/plugin";

export const gpuEnergy = definePlugin<GpuEnergyOptions>({
  name: "com.example.gpu-energy",
  behaviorRevision: "2",

  eval: (options) => {
    const capture = createEnergyCapture({ device: options.device });
    const device = `gpu-${options.device}` as const;

    return {
      captures: [capture],

      async setup(ctx) {
        const meter = await options.meter.open();
        const before = await meter.readJoules();

        ctx.onRelease(async () => {
          try {
            const after = await meter.readJoules();

            await ctx.metric(capture).seal({
              state: "available",
              cells: [{
                state: "available",
                labels: { source: "nvml", device },
                value: after.value - before.value,
                uncertainty: { absolute: after.uncertainty + before.uncertainty },
              }],
            });
          } catch (error) {
            await ctx.metric(capture).seal({
              state: "failed",
              reason: captureError(error),
            });
          } finally {
            await meter.close();
          }
        });
      },
    };
  },
});
```

`createEnergyCapture()` 在 Eval definition resolution 时运行，不在 Attempt 中动态增加事实。`ctx.metric()` 只接受本 occurrence
已注册的 token。它不能写另一个 Metric、选择 Record owner 或在 Attempt 关闭后 seal。

如果设备不存在，SDK 应封口 `unavailable`；如果 meter 正常工作但没有可测区间，应封口 `empty`。不调用 seal 会令 Attempt 失败，
不能作为 optional telemetry 的正常路径。

## 4. 普通 Eval 使用

```ts
import { defineEval } from "niceeval";
import { gpuEnergy, nvmlEnergyMeter } from "@example/gpu-energy";

export default defineEval({
  plugins: [
    gpuEnergy({
      meter: nvmlEnergyMeter({ device: 0 }),
    }),
  ],

  async test(t) {
    await t.send("完成任务");
  },
});
```

普通作者看不见 `energyCapture`，也不 import `niceeval/capture`。

## 5. 发布 Analysis fields

```ts
// @example/gpu-energy/analysis
import {
  allLogicalSlots,
  mean,
  metricMeasure,
  partial,
  requireSameProducer,
  sum,
} from "niceeval/analysis";
import { gpuEnergyMetric } from "./capture.js";

export const gpuEnergyJoules = metricMeasure(gpuEnergyMetric, {
  producers: requireSameProducer(),
  withinAttempt: sum(),
  withinEval: mean(),
  acrossEvals: mean(),
  denominator: allLogicalSlots(),
  missing: partial(),
});

export const gpuEnergySource = gpuEnergyMetric.labels.source;
export const gpuDevice = gpuEnergyMetric.labels.device;
```

多 GPU cells 先在 `withinAttempt` 合计，之后才处理同一 Eval 的 attempts 与跨 Evals 读数。合法零值、设备 unavailable、producer
failed 与未观察 slot 保持不同状态。

## 6. 在 Report 消费

```tsx
import {
  gpuDevice,
  gpuEnergyJoules,
  gpuEnergySource,
} from "@example/gpu-energy/analysis";
import {
  Bars,
  Table,
  aggregate,
  defineComponent,
} from "niceeval/report";

export const EnergyLeaderboard = defineComponent(
  async (_props, { sample }) => {
    const rows = await aggregate(sample, {
      by: {
        condition,
        source: gpuEnergySource,
        device: gpuDevice,
      },
      values: {
        passRate,
        energy: gpuEnergyJoules,
      },
    });

    return (
      <>
        <Bars
          points={rows}
          x="condition"
          y="energy"
          color="source"
          sort={{ field: "energy", direction: "asc" }}
          layout="horizontal"
        />
        <Table rows={rows} />
      </>
    );
  },
);
```

Report 作者不手写 slot join、Map 分组、denominator、状态 switch、百分比格式或 terminal fallback。

## 7. 演进

| 改动 | SDK 动作 |
|---|---|
| 新增 optional `device` label | 保持 Metric ID；旧事实显示 label missing |
| 增加 `gpu-2` enum member | 保持 Metric ID |
| 采样算法改变 | 更新 Producer behavior version / config |
| J 改成 kWh | 发布 `com.example.gpu-energy-kwh` |
| joules 含义改成平均功率 | 发布新的 Metric ID |

J 与 kWh 的关系写在 Analysis：

```ts
export const gpuEnergyKwh = convertMeasure(gpuEnergyJoules, {
  id: "com.example.gpu-energy-kwh-view",
  unit: "kWh",
  convert: (joules) => joules / 3_600_000,
});
```

这只转换 Analysis value，不重写历史 Metric facts。

## 8. Package 被移除

NiceEval 仍能通过 definition snapshot 显示 generic facts：

```text
com.example.gpu-energy
producer: com.example.nvml-meter@2
value: 123.4 J
labels: source=nvml, device=gpu-0
state: available
```

typed `gpuEnergyJoules` Measure 不再可用，直到恢复 package 或 import exact-compatible definition。平台 migration 不执行该 package
的代码，也不会丢弃 generic value。
