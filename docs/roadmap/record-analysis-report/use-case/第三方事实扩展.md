# 用户自定义 GPU 能耗事实

这个 Use Case 回答“用户自己想写一份新事实，要定义什么、怎样写、怎样迁移、怎样分析，又怎样在 Report 中消费”。
示例把 Attempt 的 GPU 能耗从 v1 演进到 v2。它与官方 Timing 的领域 schema 不同，但复用相同的机械路径：
RecordAttachment compiler、command kernel、reader、Projection、migration orchestration 与 Report authoring surface。

完整公共语法仍以 [RecordAttachment Library](../../record-attachment-authoring/library.md)、
[Record → Analysis → Report Library](../library.md) 和 [Reports Library](../../../feature/reports/library.md) 为单源。

```text
define v1 + v2 family
  → application install
  → Eval exact write grant + ctx.record(current payload)
  → frozen snapshot + attempt-slot Projection
  → explicit niceeval migrate for historical v1
  → deriveGpuEnergy()
  → Report Calculation / Page
```

## 1. 定义 versioned Attachment family

用户定义的是一个 owner-local `RecordAttachmentDefinition`，不是整个 Record。definition module 可以独立于 producer
长期保留，供历史读取与 migration 使用。

```ts
// record-attachments/gpu-energy.ts
import { Effect, Schema } from "effect";
import { defineRecordAttachment } from "niceeval/record";

export const gpuEnergy = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: Schema.Struct({
        joules: Schema.NonNegative,
        source: Schema.Literal("device-estimate"),
      }),
      blobRefs: () => [] as const,
    },
    v2: {
      schema: Schema.Struct({
        joules: Schema.NonNegative,
        source: Schema.Literal("device-estimate"),
        uncertaintyJoules: Schema.NullOr(Schema.NonNegative),
      }),
      blobRefs: () => [] as const,
    },
  },
  current: "v2",
  migrations: ({ v1, v2 }) => ({
    v1: {
      to: v2,
      migrate: (source, target) =>
        Effect.succeed(target.value({
          ...source.payload,
          uncertaintyJoules: null,
        })),
    },
  }),
});
```

这里每个字段都有明确含义：

| 字段 | 责任 |
|---|---|
| `owner: "attempt"` | 每个值归属于一个 exact Attempt；Run context 不能写它 |
| reverse-domain `name` | 用户拥有自己的 namespace；公共 constructor 拒绝 `niceeval.*` |
| `versions` | 一次声明完整、连续的 schema family |
| `current: "v2"` | 新 producer 只能提交 v2 payload |
| `blobRefs` | 声明 payload 自己引用的 closure；本例没有 blob |
| `migrations` | 只声明相邻 v1 → v2 edge；普通 read/write 不执行它 |

`uncertaintyJoules: null` 精确表示“历史 v1 没有保存不确定度”，不是 `0`。若 v2 要求该值必须是实际测量，v1
又没有足够事实，作者应把 edge 改成 `unavailable`，不能在 converter 中重新测 GPU 或猜一个默认值。

definition 编译成功后是 opaque object。复制它的字段、重建同名 object 或动态添加 brand 都不能取得 exact identity。

## 2. Application 安装读取与 migration trust

应用显式安装 definition：

```ts
// niceeval.config.ts
import { defineConfig } from "niceeval";
import { gpuEnergy } from "./record-attachments/gpu-energy.js";

export default defineConfig({
  recordAttachments: { install: [gpuEnergy] },
});
```

install 允许 application reader 解释 v1/v2，并允许 maintenance 执行这个 converter。它不会给任一 Eval、Plugin 或
Report 授予 write，也不会按历史 bytes 的 name 自动下载 package。

## 3. Eval 取得 exact grant 并写 current payload

Eval occurrence 把同一个 definition object 放进 write grant，然后在自己的 Attempt context 中写 v2 payload：

```ts
// evals/gpu-energy.eval.ts
import { defineEval } from "niceeval";
import { gpuEnergy } from "../record-attachments/gpu-energy.js";

export default defineEval({
  recordAttachments: { write: [gpuEnergy] },
  async test(ctx) {
    const measurement = await measureGpuEnergy();

    await ctx.record(gpuEnergy, {
      joules: measurement.joules,
      source: "device-estimate",
      uncertaintyJoules: measurement.uncertaintyJoules,
    });
  },
});
```

`ctx.record()` 是 Promise facade，方便普通 Eval 作者使用。它把 current payload 编码成 tracked Effect command，
不会创建第二个 writer 或 detached runtime。admission 同时核对 exact definition grant、Attempt owner 与 open context
lease。随后执行 reservation、plain-data snapshot、schema、closure、generic sink 与 publish barrier。

调用者捕获 rejection 或漏 `await` 都不会让已接受的 command 脱离 host 跟踪。接受后的 schema、closure 或 durable
write failure 会 poison owner，Run 不能发布 complete marker。同一个 Attempt 的同一个 `(owner, name)` 也不能写两次。

## 4. 定义只读 projector

projector 只绑定 definition 的 `.reader` capability，并把 materialized v2 value 解释成 Analysis 需要的 view：

```ts
// analysis/gpu-energy.ts
import {
  attemptSlotProjection,
  defineRecordAttachmentProjector,
  projectAnalysisSample,
} from "niceeval/projection";
import { gpuEnergy } from "../record-attachments/gpu-energy.js";

export interface GpuEnergyView {
  readonly joules: number;
  readonly uncertaintyJoules: number | null;
}

export const gpuEnergyProjector = defineRecordAttachmentProjector({
  attachment: gpuEnergy.reader,
  project: ({ payload }) => ({
    joules: payload.joules,
    uncertaintyJoules: payload.uncertaintyJoules,
  }),
});

export const energyByAttempt = attemptSlotProjection(
  gpuEnergyProjector,
);
```

reader/projector 没有 writable definition、root、path 或 migration capability。它只在 Attachment 为 `available` 时执行；
其余读取状态由 Projection 原样保留。

## 5. 历史 v1 先读出状态，再显式迁移

在迁移前读取一个 v1 owner，Projection 得到：

```ts
{
  state: "attachment-result",
  slot,
  owner: { kind: "attempt", attempt: slot.attempt },
  attachment: {
    state: "migration-required",
    from: "com.example.gpu-energy/v1",
    to: "com.example.gpu-energy/v2",
    command: "niceeval migrate",
  },
}
```

普通 Analysis 与 Report 不运行 converter，也不把 v1 当成 v2。用户显式执行：

```sh
niceeval migrate --record /project/.niceeval/record
```

CLI 使用 application 已安装的 exact family 做 preflight、取得 exclusive maintenance lock、创建 sentinel，再按相邻 edge
写入 v2。成功后的新 frozen snapshot 才读到：

```ts
{
  state: "available",
  value: {
    joules: 418.5,
    uncertaintyJoules: null,
  },
}
```

`null` 保留历史事实缺口。migration 不读取当前设备、网络、clock、environment 或另一个 Attachment；target value 仍经过
同一 schema、plain-data 与 closure validators。

## 6. 普通 Analysis 读取并派生

```ts
const projected = yield* projectAnalysisSample({
  sampleHandle,
  projection: energyByAttempt,
});

const energy = deriveGpuEnergy(projected);
```

`deriveGpuEnergy()` 是用户自己的普通纯函数。下面先固定这个 module 的输入输出签名，函数体遵守随后列出的规则。
一个可扩展但不丢口径的结果形状是：

```ts
import type {
  AnalysisSlotRef,
  CoreInvalidAnalysisSlot,
  IncludedAnalysisSlot,
  NotRecordedAnalysisSlot,
  RecordAttemptRef,
} from "niceeval/analysis";
import type {
  ProjectedRecordAttachmentResult,
  ProjectedSample,
} from "niceeval/projection";

interface GpuEnergyRef {
  readonly slot: AnalysisSlotRef;
  readonly attempt: RecordAttemptRef;
}

type GpuEnergyIssue =
  | {
      readonly code: "slot-not-recorded";
      readonly slot: NotRecordedAnalysisSlot;
    }
  | {
      readonly code: "core-invalid";
      readonly slot: CoreInvalidAnalysisSlot;
    }
  | {
      readonly code: "attachment-not-available";
      readonly slot: IncludedAnalysisSlot;
      readonly source: Exclude<
        ProjectedRecordAttachmentResult<GpuEnergyView>,
        { readonly state: "available" }
      >;
    }
  | {
      readonly code: "total-not-finite";
      readonly refs: readonly GpuEnergyRef[];
    };

interface GpuEnergyRow {
  readonly slot: AnalysisSlotRef;
  readonly attempt: RecordAttemptRef | null;
  readonly state:
    | "excluded"
    | "not-recorded"
    | "core-invalid"
    | "unavailable"
    | "migration-required"
    | "migration-unavailable"
    | "unsupported"
    | "invalid"
    | "observed";
  readonly joules: number | null;
  readonly uncertaintyJoules: number | null;
  readonly issues: readonly GpuEnergyIssue[];
  readonly refs: readonly GpuEnergyRef[];
}

interface GpuEnergySummary {
  readonly rows: readonly GpuEnergyRow[];
  readonly observed: number;
  readonly denominator: number;
  readonly totalJoules: number | null;
  readonly state: "complete" | "partial";
  readonly issues: readonly GpuEnergyIssue[];
  readonly refs: readonly GpuEnergyRef[];
}

declare const deriveGpuEnergy: (
  projected: ProjectedSample<"attempt-slot", GpuEnergyView>,
) => GpuEnergySummary;
```

函数按 `projected.entries` 穷尽形成 rows：

- 每个 Sample logical slot 恰好一行，excluded 也保留；
- `denominator` 等于 `projected.sample.denominator`，不从 available entry 数反推；
- `observed` 只数 available GPU values；
- `totalJoules` 只在 `denominator > 0` 且每个 denominator slot 都 observed 时形成，否则为 `null`，避免把无样本或
  缺失当零；
- 求和使用 checked finite addition；超出 finite number 时 `totalJoules` 为 `null`，并增加 `total-not-finite` issue；
- 每个 observed row 的 refs 同时保留 slot 与 exact Attempt；
- not-recorded、core-invalid 与 Attachment 五种非 available 状态进入 issues，并让整体 state 为 partial。

这是领域作者选择的 completeness policy。另一个 GPU package可以选择“partial 时仍给 observed subtotal”，但必须改用清楚的
字段名并显式携带 observed、denominator、state、issues 与 refs；Record 或 Report host 不替作者猜。

## 7. Report 复用同一个纯函数

```ts
import { Either } from "effect";
import {
  defineCalculation,
  definePage,
  defineReport,
  reportComponentId,
  reportDocument,
  reportId,
  reportInputs,
  reportMetric,
  reportRoute,
} from "niceeval/report";
import {
  deriveGpuEnergy,
  energyByAttempt,
} from "../analysis/gpu-energy.js";

const inputs = reportInputs({ energy: energyByAttempt });

const gpuEnergySummary = defineCalculation({
  id: Either.getOrThrow(reportComponentId("gpu-energy-summary")),
  inputs,
  completeness: "allow-partial",
  calculate: ({ inputs }) => deriveGpuEnergy(inputs.energy),
});

const gpuEnergyPage = definePage({
  id: Either.getOrThrow(reportComponentId("gpu-energy")),
  route: Either.getOrThrow(reportRoute("/gpu-energy")),
  calculations: { gpuEnergySummary },
  render: ({ calculations }) => {
    const result = calculations.gpuEnergySummary;

    if (result.state !== "available") {
      return reportDocument({
        title: "GPU energy",
        children: [{
          type: "status",
          tone: "negative",
          label: "GPU energy calculation unavailable",
        }],
      });
    }

    const value = result.value;
    return reportDocument({
      title: "GPU energy",
      children: [
        reportMetric({
          label: "Observed slots",
          value: `${value.observed}/${value.denominator}`,
        }),
        reportMetric({
          label: "Total energy",
          value: value.totalJoules,
          unit: "J",
        }),
        {
          type: "table",
          caption: "GPU energy by logical slot",
          columns: [
            { key: "slot", label: "Slot" },
            { key: "attempt", label: "Attempt" },
            { key: "state", label: "State" },
            { key: "joules", label: "Energy (J)", align: "end" },
            { key: "uncertainty", label: "Uncertainty (J)", align: "end" },
          ],
          rows: value.rows.map((row) => ({
            slot: `${row.slot.runId}/${row.slot.slotId}`,
            attempt: row.attempt?.attemptId ?? null,
            state: row.state,
            joules: row.joules,
            uncertainty: row.uncertaintyJoules,
          })),
        },
      ],
    });
  },
});

export default defineReport({
  id: Either.getOrThrow(reportId("gpu-energy")),
  calculations: { gpuEnergySummary },
  pages: [gpuEnergyPage],
});
```

普通 Analysis 与 Report Calculation 调用的是同一个 `deriveGpuEnergy()`。Page 只呈现 closed value；它没有 reader、
definition、converter 或 `ctx.record()`，也不能把 host-owned migration / invalid problems 隐藏掉。

## 官方与第三方到底哪里相同

```text
third-party ctx.record ─────────────┐
                                    ├─ canonical RecordAttachment command kernel
official ctx.recordEffect ──────────┘
```

| 维度 | 第三方 GPU fact | 官方 Timing |
|---|---|---|
| namespace authority | public reverse-domain name | package-private `niceeval.*` authority |
| writable definition | 用户 module 导出 | package-private，不导出 |
| write grant | Eval occurrence 明确声明 | built-in occurrence 明确声明 |
| owner context | 当前 Attempt lease | 当前 Attempt lease |
| admission / reservation / snapshot | generic | generic |
| schema / closure / poison | generic | generic |
| sink / publication | generic | generic |
| reader / projector / migration orchestration | generic | generic |

中立性是机械路径相同，不是 authority 相同。第三方不能定义 `niceeval.gpu-energy`、冒充 official token 或写入另一个
Attempt；官方 producer 也没有 raw draft、schema bypass 或自动 migration 特权。

## 失败反例

| 尝试 | 结果 |
|---|---|
| 只 install definition，然后在任意代码中写 | install 不产生 write grant，也不产生 owner-local context |
| grant 中放一个重建的同名 definition | exact-object admission 拒绝 |
| 用 Run context 写 Attempt definition | owner mismatch；command 不进入 sink |
| producer 继续写 v1 payload | current schema encode 拒绝；新事实只能写 v2 |
| reader 看到 v1 后自动运行 converter | 不存在；返回 `migration-required` |
| converter 读取当前 GPU 补 uncertainty | 违反 deterministic migration contract |
| Report callback 直接读 root 或执行 migrate | API 不提供 capability；host 只交付 closed values |
| missing GPU value 按 `0 J` 计入 total | 本例禁止；`totalJoules` 为 `null`，缺口留在 issues |
