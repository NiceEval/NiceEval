# 第三方事实进入同一 Record

第三方 Eval 为 Attempt 写入 GPU 能耗事实。它与 Assertions、File Diff 的 schema 完全不同，但不需要 Plugin writer
或另一套持久 primitive。

definition 的完整 API 单源见 [定义并写入自定义事实](../../record-attachment-authoring/use-case/定义并写入自定义事实.md)。
本例只展示它怎样进入三层组合。

```ts
import { Schema } from "effect";
import { defineRecordAttachment } from "niceeval/record";

export const gpuEnergy = defineRecordAttachment({
  owner: "attempt",
  name: "com.example.gpu-energy",
  versions: {
    v1: {
      schema: Schema.Struct({ joules: Schema.Number }),
      blobRefs: () => [] as const,
    },
  },
  current: "v1",
  migrations: () => ({}),
});
```

Eval occurrence 取得 exact write grant，再用 owner-local context 写入：

```ts
export default defineEval({
  recordAttachments: { write: [gpuEnergy] },
  async test(ctx) {
    await ctx.record(gpuEnergy, { joules: await measureGpuEnergy() });
  },
});
```

应用另行安装 definition，表示信任它的 reader 与 migrations；install 不产生 write grant。

```ts
export default defineConfig({
  recordAttachments: { install: [gpuEnergy] },
});
```

## 与官方事实的同与不同

```text
third-party ctx.record ─────────────┐
                                    ├─ canonical RecordAttachment command kernel
official ctx.recordEffect ──────────┘
```

| 阶段 | 第三方 GPU fact | 官方 Assertions / Diff |
|---|---|---|
| namespace authority | public reverse-domain name | package-private `niceeval.*` authority |
| definition | public opaque value | writable value不导出 |
| write grant | Eval occurrence 明确声明 | built-in occurrence 明确声明 |
| owner context | 当前 Attempt lease | 当前 Attempt lease |
| admission / reservation | generic | generic |
| snapshot / closure / poison | generic | generic |
| sink / publication | generic | generic |

这证明的是机制中立，不是权限相同。官方事实没有 raw draft bypass，第三方也不能取得 official authority。

## Analysis 与 Report 扩展

第三方定义自己的 pure projector，再使用同一个 direct Projection API：

```ts
const gpuEnergyProjector = defineRecordAttachmentProjector({
  attachment: gpuEnergy.reader,
  project: ({ payload }) => ({ joules: payload.joules }),
});

const energyByAttempt = attemptSlotProjection(gpuEnergyProjector);

const projected = yield* projectAnalysisSample({
  sampleHandle,
  projection: energyByAttempt,
});
```

普通脚本可以直接消费 `projected`。Report 可以把 `energyByAttempt` 放入自己的 input manifest；两者不会获得
reader、path、write grant 或 migration capability。

## 权限与完整性反例

| 尝试 | 结果 |
|---|---|
| 第三方定义 `niceeval.gpu-energy` | public constructor 同步拒绝官方 namespace |
| 未把 exact definition object 放进 occurrence grant 就调用 `ctx.record()` | admission 拒绝，不发布 Attachment |
| 复制 definition 字段后冒充原对象 | exact-object grant 不匹配 |
| 同一 owner/name 写两次 | link reservation 或 runtime duplicate guard 拒绝 |
| 把另一个 Attachment 的 blob ref 作为 payload 字段传入 | own-closure validation 拒绝；已接受 command 的失败 poison owner |
| writer 发现旧 schema 后自动 migrate | 没有这条路径；read 返回 migration state，maintenance 显式执行 |
| 把 relation 直接压成未包装的 `passRate` number 再交给 metric 组件 | 类型不接受；metric constructor 必须携带 coverage、basis 与 refs |
