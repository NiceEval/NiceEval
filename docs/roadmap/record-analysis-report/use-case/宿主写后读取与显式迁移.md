# 写后读取与显式迁移

本例证明两件事：一次 Invocation 可以在发布 Run 后立即从 fresh snapshot 出报告；旧数据升级只执行 NiceEval 平台 converter。

## Invocation 写后显示

用户运行：

```console
niceeval exp ./experiments/memory.ts
```

内部时序：

```text
open RecordAccessRuntime
  → freeze reuse-planning view
  → open write session
      → execute fresh Attempts
      → satisfy Capture obligations
      → publish complete Run
  → close write session
  → open fresh snapshot
      → form ReportSample
      → execute project Report
      → render terminal output
  → close snapshot and runtime
```

Report 能看到本次刚发布的 Run，因为它使用写后 fresh snapshot。它不会在 write session 持锁时打开第二个 reader，也不会用写前
cache 猜新 generation。

## 普通读取遇到旧 envelope

```console
$ niceeval show
error[migration-required]: Metric envelope v1 requires v2
next: niceeval migrate
```

`show` 不自动改盘，不从 Report module 加载 converter，也不把旧 envelope 当作 missing。

## Preflight

```console
$ niceeval migrate
Record v1 → v2
Metric envelope v1 → v2
Score envelope: already current
Unknown envelope com.future.trace/v3: preserved

2 runs, 41 facts, 3 blobs
Run again with --yes to apply this exact plan.
```

preflight 固定：

- exact source snapshot；
- Core 与固定 envelope 版本；
- 平台 converter set；
- unknown envelope exact bytes 与 blob closure；
- Git recovery point 与磁盘条件。

它不 import GPU package。用户定义的 `com.example.gpu-energy` 是 Metric definition snapshot，不是一份用户 migration family。

## Apply

```console
$ niceeval migrate --yes
Migration complete.
Receipt: 01K2...
```

平台在 staging snapshot 中完成全部 converter 与 validation，再原子发布。source snapshot 在 apply 前改变时，CLI 返回：

```text
error[migration-plan-stale]: Record changed after preflight
next: run niceeval migrate again
```

## Unknown future envelope

假设 Record 中存在当前 NiceEval 无法解释的 `com.future.trace/v3`：

```text
envelope bytes
  ├─ manifest
  ├─ payload
  └─ referenced blobs
```

migration 必须逐字节携带完整 closure。任一 blob 缺失，或目标 layout 无法无损表达该 closure 时：

```text
error[migration-unsupported]: cannot preserve com.future.trace/v3 blob closure
source unchanged
receipt not created
```

CLI 不跳过该 family，也不发布已经转换一半的 snapshot。

## Package 被移除后的重分析

GPU package 被卸载后，平台仍能 generic inspect：

```console
$ niceeval show --facts
com.example.gpu-energy = 123.4 J
producer = com.example.nvml-meter@2
state = available
```

自定义 Report import `gpuEnergyJoules` 时，如果 package 不存在，module load 明确失败。恢复 package，或提供 exact-compatible pure
definition 后，可以在同一 frozen facts 上运行新的 Analysis / Report：

```console
niceeval show --report ./reports/new-energy.tsx --run old-run
```

这不会写回 Record，也不会为旧 Attempt 增加 Score。

## 语义变化不是 migration

焦耳改为千瓦时：

```text
com.example.gpu-energy       unit J
com.example.gpu-energy-kwh   unit kWh
```

SDK 发布新 Metric ID。Analysis 可以把 J 转成 kWh，再进行并列比较；平台 converter 不重写旧 value。

历史 value 确实错误时，产品使用追加的具名 correction 或新 identity，并保留 provenance。数据修复不冒充 storage migration。
