# 写回归测试

## 用户目标

维护者要把实现违反性质的缺陷缩减成可重复的反例，并让同一性质继续探索其它操作序列。

## 起始状态

- 已定位受影响的 Feature 并读过 [Bug 修复](../README.md#bug-修复)。
- 示例为目标命令，根 `package.json` 入口由实现阶段提供。

## 完整路径

1. 找到被违反的性质。 {#locate}

   补足现有观察或动作。若缺少性质，从当前 Feature 契约写出规则并选择能够看到故障的最低一层。

2. 在修复前取得失败并缩减。 {#shrink}

   fast-check 记录缩减后的输入、seed 与 path。Bombadil 对 test 或 fuzz 产生的 trace 执行 `shrink`。检查最小序列仍然触发目标断言。

3. 保存反例并重新复现。 {#save}

   集成层将输入加到原性质的 `examples`。界面层将 trace 放到 spec 旁的 `regressions/`，将该 trace 传给 Bombadil 的 `--reproduce`。把失败定位到具体公开结果。

4. 修根因并复验。 {#fix}

   保持原动作范围和性质不变，运行同一反例与常规探索。修复前后均记录命令、观察与实际执行范围。

## 结果

缩减反例随测试保留。现有缺陷复现和修复验证使用同一条性质。
