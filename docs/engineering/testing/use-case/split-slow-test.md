# 拆分慢测试

## 用户目标

维护者发现测试的 p50 超过所在层上限，需要减少真实开销并保留原来守护的性质。

## 起始状态

- 已有测试工具的原始耗时结果，已确认[成本上限](../architecture.md#成本上限)。
- 示例为目标命令，根 `package.json` 入口由实现阶段提供。

## 完整路径

1. 定位并复测。 {#find}

   确认超限的是哪个性质。在负载稳定时点名测试文件复测，记录 p50 和运行条件。

2. 将领域情形下沉。 {#sink}

   用进程内 CLI 或公开 Library API 验证可以在低层观察的结果。高层保留能区分真实进程、资源或界面行为的性质。

3. 按独立性质拆分。 {#split}

   用各性质的稳定链接划分测试。把标记和缩减反例随测试一起移动。去掉重复冷启动，用公开状态替代固定时长等待。

4. 重跑并对账。 {#validate}

   逐个运行受影响文件。比较前后 p50、性质链接、有效动作及反例，确认验证范围完整。全量执行交给 CI。

## 结果

相关测试回到所属层的成本上限内。交付说明记录拆分或下沉的位置、前后耗时和运行范围。
