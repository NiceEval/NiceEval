## 心智模型

NiceEval 的正确性用**性质**描述：在用户能触达的所有状态和操作序列上都应成立的规则。测试工具负责探索状态空间并检查性质；具体例子只是性质的种子或回归记录，不是测试的主体。

例子测试只覆盖写测试的人想到的路径。NiceEval 的风险恰恰集中在没人想到的组合上：中途取消、改一行源码后重跑、并发读写结果、终端尺寸变化、异常输入。性质加探索能找到这些组合，并把失败缩减成最短的复现。

测试只有两层，都从公开入口进入：

| 层 | 进入方式 | 工具 | 测什么 |
|---|---|---|---|
| E2E | 真实 `niceeval` 进程与真实浏览器 | [Bombadil](https://github.com/antithesishq/bombadil)（终端与浏览器驱动）、[execa](https://github.com/sindresorhus/execa) | 交互终端、`view` 界面，以及只有真实进程才能观察的跨进程保证 |
| 集成 | 进程内调用公开 Library API，或在测试进程里运行同一个 CLI 命令程序（注入 argv、cwd、环境与标准流） | Vitest、[fast-check](https://github.com/dubzzz/fast-check) | 发现、身份、缓存、运行、取消、断言与展示的组合行为；CLI 参数、`--json` 结构、退出码与人读呈现 |

能在集成层观察到的结果就在集成层测；E2E 只为它新增的边界写测试，不重复枚举集成层已覆盖的情形。每个 E2E 测试文件开头声明它依赖的跨进程保证类别（见[测试架构](architecture.md#跨进程保证)）。

不设单元测试层。只能经内部函数才测得到的风险，说明公开接口缺少观察点，应改接口而不是补一条内部测试。输入空间大的算法（身份规范化、脱敏、解析）在集成层用 fast-check 经公开 API 覆盖。

## 测试目标在哪里

每个 Feature 的性质写在该 Feature 文档的「性质」一节，紧挨产品契约：契约变化时性质在同一处跟着改。本目录不维护按产品域的测试义务清单。
工具、运行场合、CI 与仓库布局等技术方案见 [测试架构](architecture.md)。

## 写性质

性质从 [Feature 契约](../../feature/) 推出，不从现有实现反推。每条性质写清三件事：

- **观察**：从公开输出取出的状态，例如 `show --json` 的文档、终端网格上的文字、`view` 页面的 DOM。Bombadil 用 extractor 表达，集成层用普通函数表达。
- **规则**：不变式（`always`）、最终性（`eventually(...).within(...)`）、逐步关系（`next`、`implies`）。集成层用同样的词汇组织断言。
- **动作**：生成操作序列的规则。Bombadil 用 action generator；集成层用 fast-check 的 arbitrary 与 `fc.commands` 模型。

默认性质全部启用，不逐条关闭：终端的正常退出、无替换字符；浏览器的无未捕获异常、无控制台错误。领域性质按 Feature 导出，导出名就是报告里的性质名。

性质必须对所有合法状态成立。只在某条路径上成立的规则写成 `implies` 的前件，不要靠收窄动作生成器来回避反例。

## Bug 修复

1. 找到这个 bug 违反的性质。已有就加强它的观察或动作；没有就从 Feature 契约新写一条。
2. 让工具产生违反并缩减：Bombadil 用 `test` / `fuzz` 后 `shrink`，fast-check 自动缩减并给出 seed 与 path。
3. 把缩减后的反例存为回归：fast-check 写进该性质的 `examples`；Bombadil 的 trace 放进 spec 旁的 `regressions/`，用 `--reproduce` 复现。
4. 修生产根因，同一性质在原探索与回归反例上都通过。

不能为了让性质通过而收窄性质或动作生成器。确认性质本身写错时，先改 Feature 契约，再改性质。

## 质量标准

每个测试满足五条：

1. **指向性质**：测试用一行标记指向它验证的性质，例如 `// @use-case docs/feature/run/README.md#interrupt-recovery`；一个测试只验证一条性质，失败信息带输入、期望与实际。
2. **断言公开结果**：只经公开入口断言 Library 返回值、CLI 的 `--json` 结果与退出码、Record 经 `show` 的读取结果、终端网格与 DOM。不断言内部函数是否被调用、私有状态或日志措辞。
3. **会失败**：交付前至少在目标行为缺失或受控回退时运行一次并失败，交付说明记录这次失败。
4. **确定**：不依赖时长、调度顺序、机器负载或网络；时钟、端口与随机种子由测试注入或向系统申请。fast-check 与 Bombadil 的随机性可由 seed 或 trace 复现。
5. **便宜**：在能观察到结果的最低一层测试，满足[测试架构](architecture.md#成本上限)的耗时上限。

## 断言

- 结构化输出用公开 Schema 严格解码后比较领域事实；错误按错误码断言，不按消息文本。
- 人读输出只在呈现测试中断言，规范化动态值（摘要、时间、路径前缀）后比较。
- 断言具体值，不断言“不为空”“大于零”这类任何实现都能满足的条件；集合排序后比较完整内容。
- 测试不手写受管格式的配置、Record 或 JSON，由格式的 owner 生成。

## 共享资源与同步

- 每个测试拥有自己的临时目录、动态端口与进程组；依赖全局状态的用例在文件内串行，不降低全局并发。
- 等待真实的产品状态（某个输出、文件内容或 Record 结果）；固定时长只是等待上限，不以延长超时、重试整段操作或 mock 成功响应代替同步。
- 并行度用测试工具自带参数设置，不维护共享队列或锁。
- 确定性测试不配置模型、不需要凭据、不发出付费调用；重试与结果缓存关闭。

## 可追溯

测试与性质的关系由测试标记拥有，`concord trace gaps` 从标记派生没有测试的性质。新增或修改性质时同一次交付提交对应测试；行为删除时对应测试一起删除。已有测试能观察某条性质时，给它加标记，不另写重复测试。

## 不再使用的机制

场景 Repo 的整套复制与候选形态（source、built、tarball）、根 E2E runner、Testkit、证据证书、Portfolio 登记、takeover 门禁、单元测试层，都不属于本体系。迁移期间旧测试继续在 CI 运行，按产品域逐个改写为性质后删除。
