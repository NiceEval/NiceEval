# 混合模板矩阵：一个 Run 中的多个 root

契约单源见 [Architecture · 一个 Run 可以有多个 root](../architecture.md#一个-run-可以有多个-root)与 [Lifecycle · 多 root matrix 的执行](../lifecycle.md#多-root-matrix-的执行)。

## Eval 决定不同 root

一个 Experiment 同时选中三道 Eval：

```text
Experiment X: extension-only

Eval A: dockerComposeSandbox(...)
Eval B: e2bSandbox(...)
Eval C: dockerImageSandbox(...)
```

linker 按 pair 得到：

| Pair | Root owner | Root | Provider |
|---|---|---|---|
| A × X | Eval A | Compose A | Docker Compose |
| B × X | Eval B | E2B B | E2B |
| C × X | Eval C | image C | Docker |

这张矩阵有三个 template，但没有任何 pair 有多个 template，所以合法。
每个 pair 都按 Eval → Experiment → Agent 准备；Runner 可以按 Provider 能力并发调度，并按 BuildKey 共享相同构建输入。

## Experiment 决定不同 root

同一道 command-only Eval 可以由两个 Experiment 放进不同的 Sandbox 实例：

```typescript
const evalQ = defineEval({
  sandbox: sandboxLayer().prepare(checkoutLockedRepository),
  // ...
});

const cpu = defineExperiment({
  sandbox: dockerImageSandbox({ image: "acme/cpu@sha256:..." }),
  evals: [evalQ],
  agent: codexAgent(),
});

const gpu = defineExperiment({
  sandbox: e2bSandbox({ template: "acme-gpu-v4" }),
  evals: [evalQ],
  agent: codexAgent(),
});
```

两个 pair 分别以 CPU / GPU Experiment 为 root owner，顺序都是 Experiment → Eval → Agent。
它们共享 Eval 命令源码，但 fingerprint 包含不同 root physical identity 和 Experiment identity。

## 非法完整乘积

下面四个声明形成两个合法 cell 和两个非法 cell：

```text
                    X extension       Y E2B root
A Compose root          valid            conflict
B extension             missing           valid
```

PLAN-10 不选择“更具体”或“Experiment 优先”。
作者必须把选择图改成 `X -> A`、`Y -> B`，或重新分配 root：

```typescript
const experimentX = defineExperiment({
  evals: ["A"],
  agent: codexAgent(),
});

const experimentY = defineExperiment({
  sandbox: e2bSandbox({ template: "y-v2" }),
  evals: ["B"],
  agent: codexAgent(),
});
```

linker 只检查 selector 实际产生的边，不要求未配对的 Eval 与 Experiment 互相兼容。

## 一个 root 的多个物理 variant

`dockerImageSandbox({ image: "acme/tool:v3" })` 可以在 Provider planning 时按目标平台选用不同 digest。
这是一个 logical root 的多个物理 variant，不是同一 pair 的多个 root：

```text
logical root acme/tool:v3
  -> linux/amd64 digest A
  -> linux/arm64 digest B
```

planner 在 fingerprint 前确定当前 pair 的有效平台和唯一 digest。
如果平台不受支持，physical planning 失败；不能运行时偷偷 fallback 到另一 template。

## 一个 root 的多容器 Case

Compose root 可以启动 `client`、数据库、代理和测试 service。
这些资源属于同一个 Sandbox 实例，拥有唯一主 Sandbox 与整组 finalizer：

```text
one Docker Compose root
  -> one Sandbox Case
     -> primary client Sandbox
     -> database service
     -> proxy service
     -> network / volumes / ready / finalizer
```

因此“每个 pair 一个 root”不会阻止多容器题，也不要求把每个 service 当成独立 template。
