# 组合多个预置项

返回 [PLAN-1 用例手册](README.md)。场景定义见根 [CASES · C4](../../CASES.md#c4组合多个条件)。

## 解决什么问题

一个 Experiment 可能同时需要公司证书、特定运行时和记忆工具。
这些 Provision 都随 Experiment 变化,并且存在明确安装顺序。

## 按依赖顺序声明

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: BASE_TEMPLATE }),
  provisions: [
    companyCertificates,
    nodeRuntime,
    mempal,
  ],
});
```

Runner 按数组顺序 inspect 和 install。
上例中 `nodeRuntime` 可以使用 `companyCertificates` 配好的内部 registry,mempal 又可以依赖前面就位的 Node.js。

Adapter 自己确保 Agent CLI 就位,Experiment 不手工加入 `codex`。
如果扩展必须在 Agent CLI 安装后才能配置,它属于 adapter factory 的安装后扩展点,不放进 `provisions`。

## 冲突会怎样

```typescript
provisions: [node20, legacyToolchain]
```

如果 `legacyToolchain` 覆写 PATH 并破坏 `node20`,最后的全组 inspect 会发现 `node20` 实际 identity 不再匹配。
Attempt 进入 `errored`,诊断点名失败 Provision,并列出它上次通过后执行过 install 的候选破坏者。

数组只表达简单的线性依赖。
一组工具需要拓扑求解、互相协商或共同回滚时,应先封装成一个 Provision,不要把内部包管理关系展开给 Runner。

这个办法能发现 Provision 之间的后装破坏,却要求作者靠数组位置表达顺序。
它也无法把 Adapter 的 Agent CLI 安装放进同一冲突图,因此只部分满足 C4。
