# 复用 Sandbox 中的状态

返回 [PLAN-1 用例手册](README.md)。场景定义见根 [CASES · C7](../../CASES.md#c7复用-sandbox-活状态)。

## 解决什么问题

Provision 负责让 mempal 二进制与模型就位,但记忆数据库是运行状态。
实验要观察记忆随 Attempt 累积时,状态需要在 Sandbox 创建时载入、销毁前回存,并让多条 Attempt 共用同一个 Sandbox。

## Provision 与状态 Hook 分开

```typescript
export default defineExperiment({
  agent: codexAgent({ mcpServers: [mempalMcp] }),
  sandbox: e2bSandbox({ template: BASE_TEMPLATE })
    .setup(async (sandbox, ctx) => {
      const restored = await loadMemoryState(sandbox, ctx.experimentId);
      ctx.fact("memory.restored", restored);
    })
    .teardown(async (sandbox, ctx) => {
      await saveMemoryState(sandbox, ctx.experimentId);
    }),
  provisions: [mempal],
  sandboxReuse: true,
  maxConcurrency: 1,
});
```

执行顺序是 mempal Provision 与 Agent CLI 先就位,随后 Sandbox setup 载入记忆。
同一复用窗口内的 Attempt 直接读写活状态,窗口结束时 teardown 回存。

`maxConcurrency: 1` 保证同一 Experiment 不会同时推进两条有顺序依赖的 Attempt。
Sandbox 到期或 reset 失败时会产生新窗口;每个窗口分别载入与回存,记录保留窗口 id 与序号。

## 什么时候不能复用

如果记忆累积只是噪声,不要开启 `sandboxReuse`。
保持每条 Attempt 使用全新 Sandbox,或者在 Eval 生命周期中显式恢复逐题快照。

状态文件应放在 workdir 之外。
workdir 会在复用 Attempt 之间回到题间重置点;逐题写入 workdir 的内容属于 Fixture。

这个用例使用 Sandbox 复用是因为跨 Attempt 状态本身就是实验变量,不是因为 mempal 安装较慢。
