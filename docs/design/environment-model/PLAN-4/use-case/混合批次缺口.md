# C10:混合批次缺口

契约单源见 [Architecture · Base Case 选择](../architecture.md#base-case-选择)。
本篇展示方案 4 无法满足的输入,不是一条可推荐写法。

## 问题

同一批次包含两类 Eval:

- `terminal-bench/sheets` 自带 Compose Base。
- `plain/reasoning` 没有 Base,可以从普通 Node template 启动。

Experiment 只想给没有题目 Base 的 Eval 一个普通运行起点。
这个 Node template 不代表 mempal、证书或其它 Experiment Requirement。

## 声明

```typescript
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirement: plainExperimentRequirement,
  }),
  sandbox: e2bSandbox({
    template: "base-node-22",
  }),
  agent: codexAgent(),
});
```

## 方案 4 的解析

方案 4 把 `sandbox.template` 归一成 Experiment Base:

```text
terminal-bench/sheets
  Eval Base       = Compose case
  Experiment Base = base-node-22
  result          = double Base conflict

plain/reasoning
  Eval Base       = none
  Experiment Base = base-node-22
  result          = select base-node-22
```

因此 sheets 必须增加融合 `cases` 表项。
但用户没有声明 `base-node-22` 满足任何 Experiment Requirement,这次冲突只来自字段位置。

## 为什么不能靠优先级修补

让 Eval Base 静默覆盖 `base-node-22` 可以让这一个例子运行,却会破坏真正的 Experiment Base。
如果 template 确实预装了实验条件,静默覆盖就会丢失 Experiment 的完整起点。

方案 4 的模型里没有一个位区分这两种意图:

- Provider 创建普通 Sandbox 时使用的默认 case。
- 与 Experiment Requirement 绑定、参与双 Base 冲突的条件基底。

因此 C10 是模型缺口,不能用另一条隐式优先级消除。
