# C8:Experiment 提供起点

契约单源见 [Library · Experiment 贡献 Base](../library.md#experiment-贡献-base-或-ensure)与 [Architecture · Base Case 选择](../architecture.md#base-case-选择)。

## 问题

Experiment 已经有预装 mempal 的 E2B template。
Eval 没有完整 Base,只要求 Python 3.12 与一个题目数据目录。
Runner 应从 Experiment Base 创建 Sandbox,再验证并补齐 Eval Requirement。

## 声明

```typescript
// eval.ts
export default defineEval({
  environment: defineEvalEnvironment({
    requirement: pythonTaskRequirement({
      python: "3.12",
      datasetDigest: DATASET_SHA256,
    }),
  }),
  async test(t) {
    await t.send(TASK);
  },
});

// experiment.ts
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirement: mempalRequirement({
      version: "0.9.0",
      modelDigest: MODEL_SHA256,
    }),
    base: { template: "acme/mempal-runtime-v5" },
  }),
  sandbox: e2bSandbox(),
  agent: codexAgent(),
});
```

## 运行路径

1. 规划器发现 Eval 没有 Base,Experiment 有 Base,选择 `acme/mempal-runtime-v5`。
2. Sandbox ready 后分别 verify Python 题目条件与 mempal 实验条件。
3. mempal verify 命中也不会跳过 Python verify。
4. Python 条件缺失时,Runner 只在此时检查安装能力并执行 Eval Ensure。
5. Eval 与 Experiment 全组验证通过后,AgentProvisioner 执行自己的 Ensure。
6. 最终屏障再次验证三份 Requirement,然后 Agent 开始做题。

Eval verify 未命中且没有 `install` 时,该组合记为运行期不兼容。
结果没有 Agent turn,也不会把缺失条件误记成 Agent 解题失败。

## 可观察结果

- 所选 Base Case、CaseKey 与 E2B template identity 进入该 Eval fingerprint。
- mempal 登记初始检查命中,`installed: false`。
- Python 登记初始检查、安装活动、复检与最终检查。
- Agent 安装发生后,三份 Requirement 都有最终屏障结果。
