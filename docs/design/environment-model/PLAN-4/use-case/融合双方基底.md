# C9:融合双方基底

契约单源见 [Library · 融合 cases 表](../library.md#融合-cases-表)与 [Architecture · 融合 case](../architecture.md#融合-case-与多-eval)。

## 问题

两个 Eval 分别自带不同 Compose Base。
Experiment 也提供预装 mempal 的完整 template,两类起点不能在运行时叠加。
Experiment 必须为每个 environment profile 提供已经融合双方条件的完整 case。

## 声明

```typescript
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirement: mempalRequirement({
      version: "0.9.0",
      modelDigest: MODEL_SHA256,
    }),
    base: { template: "acme/mempal-runtime-v5" },
    cases: {
      "terminal-bench/sheets": {
        template: "acme/tb-sheets-mempal-v5",
      },
      "terminal-bench/postgres": {
        template: "acme/tb-postgres-mempal-v3",
      },
    },
  }),
  sandbox: e2bSandbox(),
  agent: codexAgent(),
});
```

## 运行路径

规划器按完整 Eval 矩阵查表:

```text
terminal-bench/sheets
  -> acme/tb-sheets-mempal-v5

terminal-bench/postgres
  -> acme/tb-postgres-mempal-v3
```

每条 Attempt 只选择一个表项。
融合 case 替代两个独立 Base,但 Eval 与 Experiment Requirement 都保留。
Sandbox ready 后,Runner 分别验证题目服务、ready 条件和 mempal 实际状态。

## 缺项反馈

如果批次还包含 `terminal-bench/redis`,但表中没有对应 key,Runner 在创建任何 Sandbox 前报告:

```text
Environment base conflict: fused cases are missing
- terminal-bench/redis

Eval and Experiment both provide a Base Case.
Add an exact environment.cases entry for every listed profile.
```

诊断一次列出所有缺失 profile。
Runner 不先运行 sheets 与 postgres,也不为 redis 隐式选择任意一侧。

## 可观察结果

- `cases` 全表进入 Run 配置。
- 每个 Eval 只把自己选中的 case identity、BuildKey 与 CaseKey 写入 fingerprint。
- 启动后的两份实际检查分别落盘,融合输出名不代替它们。
