# C9:融合双方基底

契约单源见 [Library · 融合 cases 表](../library.md#融合-cases-表)与 [Architecture · 融合 case](../architecture.md#融合-case-与多-eval)。

## 问题

两个 Eval 分别自带不可叠加的题目 Base。
Experiment 也声明一个预装证书与 mempal 的条件基底。
Runner 不能覆盖任意一侧,必须按 environment profile 选择已经融合双方条件的完整 case。

## 声明

```typescript
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirements: [
      companyCertificates({ bundleDigest: COMPANY_CA_SHA256 }),
      mempalRequirement({
        version: "0.9.0",
        modelDigest: MODEL_SHA256,
      }),
    ],
    base: {
      image: "ghcr.io/acme/mempal-runtime:v5",
    },
    cases: {
      "terminal-bench/sheets": {
        compose: {
          file: "environments/tb-sheets-mempal.compose.yaml",
          mainService: "client",
          build: "on-demand",
          executionUser: "image",
          env: harborComposeEnv("simple-sheets-put"),
        },
      },
      "terminal-bench/postgres": {
        compose: {
          file: "environments/tb-postgres-mempal.compose.yaml",
          mainService: "client",
          build: "on-demand",
          executionUser: "image",
          env: harborComposeEnv("postgres"),
        },
      },
    },
  }),
  sandbox: dockerSandbox({
    image: "node:22",
    materializers: {
      compose: dockerComposeMaterializer(),
    },
  }),
  agent: codexAgent(),
});
```

两道题的 folder-local Compose 是各自 Eval Base。
Experiment `base` 是条件基底。
两者同时存在时,融合 `cases` 表优先,分别选择两份完整的 fused Compose Case。

## 运行路径

```text
terminal-bench/sheets
  Eval Base        = folder-local Compose case
  Conditional Base = ghcr.io/acme/mempal-runtime:v5
  Selected Case    = environments/tb-sheets-mempal.compose.yaml

terminal-bench/postgres
  Eval Base        = folder-local Compose case
  Conditional Base = ghcr.io/acme/mempal-runtime:v5
  Selected Case    = environments/tb-postgres-mempal.compose.yaml
```

每条 Attempt 只选择一个完整 Case,并只暴露一个主 Sandbox。
融合 case 不删除 Eval 与 Experiment 的 Requirement 集合。
启动后,client、api、db、ready、network、证书与 mempal 都保持各自验证义务。

## 缺项反馈

如果批次还包含 `terminal-bench/redis`,但融合表没有该 profile,Runner 在创建任何 Sandbox 前报告:

```text
Environment base conflict: fused cases are missing
- terminal-bench/redis

Eval and Experiment both provide a Base Case.
Add an exact environment.cases entry for every listed profile.
```

诊断一次列出全部缺失 profile。
Runner 不先运行已配置条目,也不静默选择 Eval Base 或条件基底。

## 可观察结果

- `environments`、条件基底与融合 `cases` 全表进入 Run 配置。
- 每个 Eval 只把自己选中的表项、全部 BuildKey、locator 与 CaseKey 写入 fingerprint。
- Eval 与 Experiment 成员分别记录实际 identity;融合产物名不代替检查。
