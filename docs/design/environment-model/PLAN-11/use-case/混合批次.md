# C10:混合批次

契约单源见 [Library · 固定的 Base 选择次序](../library.md#固定的-base-选择次序)与 [Architecture · Base 解析](../architecture.md#eval-base-解析)。

## 问题

同一批次包含两类 Eval:

- `terminal-bench/sheets` 自带 Compose Base。
- `plain/reasoning` 没有 Base。

SandboxSpec 配置普通 Node 默认 case。
Experiment 可以只声明 Ensure,也可以另外声明与实验条件绑定的条件基底。

## 只有普通默认 case

```typescript
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirements: [
      companyCertificates({ bundleDigest: COMPANY_CA_SHA256 }),
    ],
  }),
  sandbox: dockerSandbox({
    image: "node:22",
    materializers: {
      compose: dockerComposeMaterializer(),
    },
  }),
  agent: codexAgent(),
});
```

选择结果:

```text
terminal-bench/sheets
  Eval Base        = Compose case
  Conditional Base = none
  Default Case     = node:22
  Selected Case    = Compose case

plain/reasoning
  Eval Base        = none
  Conditional Base = none
  Default Case     = node:22
  Selected Case    = node:22
```

默认 case 不构成 Experiment Base。
因此 sheets 使用自己的题目 Base,不需要融合表项。
两条 Attempt 都在所选 case 上验证证书 Requirement。

## 另外声明条件基底

Experiment 确实有预装 mempal 的实验条件起点时,显式把它与 Requirement 集合绑定:

```typescript
export default defineExperiment({
  environment: defineExperimentEnvironment({
    requirements: [
      companyCertificates({ bundleDigest: COMPANY_CA_SHA256 }),
      mempalRequirement({
        version: "0.9.0",
        modelDigest: MODEL_SHA256,
      }),
    ],
    base: {
      image: "ghcr.io/acme/mempal-runtime:v5",
    },
    cases: {
      "terminal-bench/sheets": {
        compose: {
          file: "environments/tb-sheets-mempal.compose.yaml",
          mainService: "client",
          build: "on-demand",
          executionUser: "image",
          env: harborComposeEnv("simple-sheets-put"),
        },
      },
    },
  }),
  sandbox: dockerSandbox({
    image: "node:22",
    materializers: {
      compose: dockerComposeMaterializer(),
    },
  }),
  agent: codexAgent(),
});
```

选择结果:

```text
terminal-bench/sheets
  Eval Base        = Compose case
  Conditional Base = ghcr.io/acme/mempal-runtime:v5
  Selected Case    = fused cases["terminal-bench/sheets"]

plain/reasoning
  Eval Base        = none
  Conditional Base = ghcr.io/acme/mempal-runtime:v5
  Selected Case    = ghcr.io/acme/mempal-runtime:v5
```

只有 sheets 同时收到 Eval Base 与条件基底,因此只有它需要融合 case。
plain 直接使用条件基底。
普通默认 case 在这两条 Attempt 中都没有被选中,也没有制造额外冲突。

## 可观察结果

- 解析记录明确区分 `eval-base`、`conditional-base`、`fused-case` 与 `default-case`。
- 默认 case 让位是正常选择结果,不是警告或错误。
- 条件基底与融合 case 都不能跳过证书、mempal 和题目 Requirement 的逐成员 verify。
- 同一个 Experiment 仍形成一条 Run 和一个比较横截面。
