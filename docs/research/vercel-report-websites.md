# Vercel 报告网站：读者任务、证据构图与视觉验收

> 观察日期：2026-08-13
>
> 观察对象：Vercel `design.md`
>
> 文档性质：外部产品研究与设计输入，不是 NiceEval 目标契约

## 研究判断

Vercel 的 `design.md` 不是通用产品 UI 规范。它是一套面向 Vercel 官方报告、比较、提案、benchmark、数据叙事页和计算器的设计工作流，同时附带品牌外壳、Geist、固定网格和 `vbg-*` CSS API。

对 NiceEval 最有价值的不是黑白观感，而是三层方法：先确定读者要判断什么，再让证据关系决定版式，最后用真实渲染反复检查首屏、层级、证据、主题、响应式和可访问性。

NiceEval 已经有闭合语义树、text / web 同源、`observed` / `denominator`、不可隐藏的问题面、Basalt / Chalk 和无 JavaScript 可读性。这些地基能承接 Vercel 方法，但现有视觉总纲主要规定色板、边框和主题，没有把报告的信息架构、证据几何和视觉验收定成共同规则。

## 一手材料

本研究只把 [Vercel `design.md`](https://vercel.com/design.md) 当作外部事实材料。观察日的文档名称是 `vercel-brand-guidelines`，目标是设计或显著改进 Vercel 官方报告网站。

页面中的品牌资产链接、`vercel-brand.css`、Geist、Vercel 字标与三角标、12 / 6 / 4 栏网格和 `vbg-*` class 都属于 Vercel 品牌实现，不是通用报告规范。

## 与 NiceEval 的概念映射

| Vercel 方法 | NiceEval 对应面 | 关键差异 |
|---|---|---|
| 从读者要理解或决定什么开始 | Report Page 的标题、章节、Calculation 与问题面 | NiceEval 还要让终端与静态 HTML 从同一棵树表达同一事实 |
| 判断路径与复核路径并存 | 摘要数值、状态、精确表格、分母、问题和下钻 | NiceEval 的复核路径必须回到 Run / Attempt 与 RecordAttachment 证据 |
| 首屏让最强判断和决定性证据共同主导 | 默认报告首页与自定义 Page 的第一阅读区 | NiceEval 不能假设每份报告都有建议或赢家；没有足够证据时应突出限制或尚未回答的问题 |
| 用证据关系选择几何 | table、metric、bar / line chart 与语义树的文字投影 | NiceEval 的图形不能拥有文字面无法取得的事实 |
| 表面和边界必须有真实语义 | NiceEval 的 surface、border 与 status tone | Basalt 的直角和 Chalk 的圆角可以不同，分组逻辑不能随主题改变 |
| 检查首屏、整页、两套主题和响应式 | view、static export、Basalt / Chalk 与 E2E 报告域 | NiceEval 还要检查终端面与禁用 JavaScript 的静态站 |

## 值得吸收

### 每页只承担一个读者任务

页面顺序按读者问题组织，不按输入数据或作者代码顺序组织。每个章节推进一个新问题；标题、关键值、状态与图注组成快速判断路径，表格、分母、方法、限制和结果 provenance 组成复核路径。

同一判断只设一个主要证据归属。图表、表格和摘要可以服务不同查阅任务，但不能在同一层级反复说同一个答案。

### 首屏是论点与证据

首屏应让读者记住核心差异、状态、阈值或工具，不只记住标题。比较报告把各方案放到共同基准上；趋势报告让关系或异常领先；证据不足以支持决策时，领先内容是最强已知状态、限制或尚未回答的问题。

这条规则不等于每页都放巨大英雄区。关键是让决定性证据和问题具有最高视觉后果，而不是让品牌、介绍文字或一排等权卡片先占满屏幕。

### 先选几何，再选组件

大小与排名适合共同尺度上的位置或长度，时间变化适合水平顺序，构成适合比例，阈值适合到边界的距离，依赖适合连接和顺序，精确查数适合表格。

图表只有在关系因此更快被理解时才成立。有数字不自动产生柱状图；一组不共享尺度的长条也不能假装比较。

### 证据必须诚实且就近解释

单位、时间段、样本范围、基准、分母和精度要靠近被限定的证据。长度编码默认从零开始；使用范围或差值视图时明确标出基准。同类表格数值使用一致单位和精度，文本与数值列分别对齐。

图表优先直接标注。图注既说读者应看见什么，也说图表不能证明什么。NiceEval 继续要求同一结构产生表格或文字等价内容，颜色、hover 和几何不拥有唯一事实。

### 连续画布优先于组件堆栈

位置、对齐、排版和留白先表达关系。表面、边框、卡片、胶囊和图标只有在表达分组、选择、交互、状态或对照时才出现。

真正的同类项才重复同一结构。重要程度不同的发现不应为了整齐变成等权卡片；每个章节也不应复制相同的标题、三列卡片和结尾说明轮廓。

### 真实渲染决定是否完成

检查顺序从首屏和构图开始，再看排版、证据、克制、主题与重排，最后看语义、焦点和文字等价内容。缩小预览与遮住文字可以快速暴露主对象不清、分组不稳和所有块等权的问题。

NiceEval 应在 Basalt、Chalk、桌面、窄屏、终端和无 JavaScript 静态站上做同一轮检查。仅阅读组件树或 CSS diff 不能证明视觉结果。

## 不应照搬

1. **不采用 Vercel 品牌外壳。** Vercel 字标、三角标、客户元数据位置和官方署名只适用于 Vercel 资产。NiceEval 保留自己的品牌位与报告身份。
2. **不采用 Geist 与固定网格作为产品契约。** NiceEval 主题允许选择字体、字号与圆角；布局语义需要跨主题稳定，不应绑定某一品牌 CSS。
3. **不引入 `vercel-brand.css` 或 `vbg-*` API。** NiceEval 已有 `.niceeval-report`、`--niceeval-*` 和闭合语义树。第二套 token 与 class 会产生双真源。
4. **不把计算器协议并入当前 Report 作者面。** Vercel 文档的计算器允许浏览器状态和公式交互；NiceEval 当前契约要求初始 HTML 无 JavaScript 完整可读，Report 也不在浏览器重新计算事实。
5. **不复制 Vercel 的官方语气。** NiceEval 报告可以陈述判断、限制和建议，但不能因为品牌姿态发明确定性、推荐、紧迫性或因果关系。
6. **不把黑白、细线和大留白误当成全部设计。** NiceEval 吸收的是信息层级、证据几何与验收纪律，不是视觉装饰表面。

## 契约落点与下一步证据

已经可以直接定稿的原则进入仓库根 [`DESIGN.md`](../../DESIGN.md)：读者任务、双路径、首屏、单一证据归属、几何选择、表格与图表纪律、连续画布和视觉验收。

本研究不直接扩充 `ReportBlock`。是否需要新的开场、比较、evidence provenance 或布局语义，要先用至少两份真实报告证明现有 section、paragraph、table、metric、status 和 chart 无法表达清楚；否则新增节点只会把视觉模板固化进公开 API。

下一轮实现证据按以下顺序取得：

1. 渲染默认报告和一份质量—成本比较报告，检查首屏是否显出核心判断与决定性证据。
2. 在 Basalt / Chalk 和桌面 / 窄屏下检查同类角色、数值对齐、表格宽度与信息层级。
3. 检查终端与无 JavaScript 静态站是否保留同一判断、分母、问题与复核路径。
4. 只在真实报告反复需要同一种新语义时，进入 Reports 设计裁决并更新闭合语义树。
