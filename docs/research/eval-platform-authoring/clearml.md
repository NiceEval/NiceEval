# ClearML：用户代码运行、SDK 写入、同一产品读取与展示

> 观察日期：2026-08-13
>
> 观察对象：ClearML Python SDK、ClearML Server、ClearML Web UI、ClearML Reports 与 Project Dashboard
>
> 文档性质：外部产品研究与产品建议，不是 NiceEval 目标契约

ClearML 不是外接 SQL 后再画图的 BI 产品。
用户脚本调用 `Task.init` 后真实执行；SDK 把执行细节与输出写入 ClearML Server；同一产品的 Web UI、比较页、Reports 与 SDK 读取面再消费这些事实。[TASK-FUND] [SDK-TASK] [WEB-TRACK]

本文按共同目录的八个问题和四个 NiceEval 场景组织。
每段先标 **产品事实**、**研究判断** 或 **NiceEval 建议**。

## 2. 定位与真实边界

**产品事实。** ClearML 把自己写成一套 ML/DL 开发与生产套件。
`Task` 是一次代码执行会话，可以表示 experiment、workflow 一步或自定义实现。[TASK-FUND]

把已有脚本变成 Task 的最小动作是 `Task.init(project_name, task_name)`。
初始化后，SDK 自动捕获执行信息与输出，并默认上传到 ClearML Server，供 Web UI 查看。[TASK-FUND] [SDK-OVER]

官方把 Task 捕获的内容分成两类：

| 执行信息 | 执行输出 |
| --- | --- |
| Git、未提交改动、Python 包清单、超参数与配置 | 控制台输出、scalars、plots、debug samples、models |

这些内容用于追踪、复现、调参、比较和执行 workflow。[TASK-FUND] [WEB-TRACK]

**产品事实。** 同一进程默认只有一个 main execution Task。
要在同一进程开下一个 Task，必须先 `Task.close()`。[SDK-OVER] [SDK-TASK]

**产品事实。** `Task.create` 可以不执行用户代码就建 Task，此时没有 auto-logging。[SDK-OVER]

**产品事实。** 公开 SDK 包里没有名为 `Report` 的作者类。
官方 REST 参考页是占位符。
本次检查的一手公开面未提供可编程的 Report 构造器。[API-STUB] [WEB-RPT]

**研究判断。** ClearML 的产品中心是「一次执行会话 + 自动捕获 + 固定 UI 页签」。
它不是以不可变 revision、sealed domain value 或 Analysis population 为中心的评估内核。

**NiceEval 建议。** 对照 ClearML 时，只吸收「用户代码真实运行、同一产品再读」这条闭环。
不要把它的 Task 直接当成 Record，也不要把 Web Reports 当成 typed `ReportData`。

## 3. 问题 1：一次 Task 怎样开始、封口并形成稳定身份

### 3.1 开始

**产品事实。** 官方列出三种创建路径：用户代码调用 `Task.init`、克隆已有 Task、用 `clearml-task` CLI 创建。[TASK-FUND]

`Task.init` 的公开签名与默认值如下。[SDK-TASK]

```python
task = Task.init(
    project_name='example',
    task_name='task template',    # task name of at least 3 characters
    task_type=None,
    tags=None,
    reuse_last_task_id=True,
    continue_last_task=False,
    output_uri=None,
    auto_connect_arg_parser=True,
    auto_connect_frameworks=True,
    auto_resource_monitoring=True,
    auto_connect_streams=True,
)
```

文档要求尽早调用，理想位置是 `if __name__ == "__main__":` 之后。
原因是 SDK 会拦截 PyTorch、TensorFlow 等库；初始化太晚会有内存泄漏或子进程挂起。[SDK-OVER] [SDK-TASK]

**产品事实。** 身份有两套：

| 标识 | 能否改 | 作用 |
| --- | --- | --- |
| Task ID（UUID 字符串） | 不能改 | 稳定系统身份 |
| `project_name` + `task_name` | 执行后可改 | 人读定位；重名时 `get_task` 返回最后修改的那一个 |

[SDK-OVER]

项目不存在会当场创建。
子项目用路径写法，例如 `main_project/sub_project`。[SDK-OVER]

### 3.2 复用与续跑

**产品事实。** `Task.init` 并不总是新建 Task。
官方说明在以下情况会新建：从未跑过；以前跑过且已有 models / artifacts，或状态为 Published / Archived；或 `reuse_last_task_id=False`。
否则返回同一 `project_name` + `task_name` 的已有对象。[SDK-TASK]

文档另写一条本机复用规则：上次在本机执行不超过 24 小时，且上次没有 artifacts / models，则复用。[SDK-OVER]

复用时，上次执行的控制台输出与日志会被删除。[SDK-TASK]

`continue_last_task=True` 会保留上次的 artifacts / models / logs。
下一次 scalar 从上次最大 iteration 之后继续，例如上次 `train/loss` 在 100，下次从 101 开始。[SDK-OVER] [SDK-TASK]

### 3.3 封口

**产品事实。** 脚本正常结束时，Task 状态变为 `Completed`、`Failed` 或 `Aborted`。[TASK-FUND]

显式封口有两条调用：

```python
task.close()
```

`close()` 把状态改为 `Completed`，不终止当前 Python 进程。
调用后该对象不能再 `connect` / `connect_configuration`，否则抛 `ValueError`。
要再次拿到同一 Task，必须 `Task.get_task`。[SDK-TASK]

```python
task.mark_completed()
```

`mark_completed()` 同样把状态改为 `Completed`，并终止创建该 Task 的 Python 进程。[SDK-BI]

离线模式把会话先写到本地 zip，再导入 Server：

```python
from clearml import Task

Task.set_offline(True)
task = Task.init(project_name='DEBUG', task_name="offline")
task.upload_artifact("large_artifact", "test_string")
task.close()
Task.set_offline(False)

imported_task = Task.import_offline_session(task.get_offline_mode_folder())
```

`set_offline` 只支持 `Task.init`，不支持 `Task.create`。[SDK-TASK] [SDK-OVER]

### 3.4 状态词表

**产品事实。** Web 文档使用一套人读状态；SDK 枚举是另一套字符串。

| Web 文档 | SDK `TaskStatusEnum` |
| --- | --- |
| Draft、Pending、Running、Completed、Failed、Aborted、Published | `created`、`queued`、`in_progress`、`stopped`、`published`、`publishing`、`closed`、`failed`、`completed`、`unknown` |

[TASK-FUND] [SDK-BI]

文档写：只有 Draft 可编辑；Published 只读，不能 reset，只能 clone 出新的 Draft。[TASK-FUND]

本次检查的一手公开面未提供这两套词表的完整对照表。

**产品事实。** 文档列出的 Task type 含 `agent`（Agentic AI workloads）。
SDK `TaskTypes` 枚举在 v2.1.11 与观察日 `master` 上都没有 `agent`。
公开枚举是 `training`、`testing`、`inference`、`data_processing`、`application`、`monitor`、`controller`、`optimizer`、`service`、`qc`、`custom`。[TASK-FUND] [SDK-BI]

### 3.5 研究判断与 NiceEval 建议

**研究判断。** ClearML 的稳定身份是 Server 分配的 Task ID。
`project` + `name` 是可改的人读键。
默认 `reuse_last_task_id=True` 会让调试期复用同一 ID，并删除上次输出。
这与「每次执行形成一个不可变 sealed outcome」相反。

**NiceEval 建议。** Run / Attempt 身份必须在发布后不可复用、不可删改输出。
复用历史只能走独立 reuse contract，不能作为 `init` 默认行为。

## 4. 问题 2：官方事实怎样写入

ClearML 把写入分成自动捕获与显式 report。
自动捕获在 `Task.init` 之后开始；显式 report 走 `Logger`、`Task.connect*`、`upload_artifact` 与 `OutputModel`。[SDK-OVER] [LOGGER-FUND]

### 4.1 Auto capture

**产品事实。** `Task.init` 之后自动写入：

| 类别 | 官方列出的内容 |
| --- | --- |
| 超参数 | argparse / click / Fire / LightningCLI、TensorFlow Definitions、Hydra `OmegaConf` |
| Models | TensorFlow、Keras、PyTorch、Fast.ai、XGBoost（joblib）、scikit-learn（joblib）等框架保存的权重与 snapshot 路径 |
| Metrics / plots / debug images | TensorBoard、TensorBoardX、Matplotlib |
| 执行细节 | Git、未提交改动或整份脚本、Python 包清单、执行配置 |
| 资源 | GPU、CPU、Memory、Network |
| 流 | stdout / stderr |

[SDK-OVER] [LOGGER-FUND] [HP-FUND]

控制开关是 `auto_connect_frameworks`、`auto_connect_arg_parser`、`auto_resource_monitoring`、`auto_connect_streams`。[SDK-TASK]

资源监视默认打开，并写成 scalar。
`Task.init` 文档说这些图画在 SCALARS 页，标题为 `:resource monitor:`。[SDK-TASK]
v2.1.11 源码实际标题是 `:monitor:machine` 与 `:monitor:gpu`：[MON]

```python
_title_machine = ":monitor:machine"
_title_gpu = ":monitor:gpu"
```

```python
self._task.get_logger().report_scalar(
    title=title, series=series, iteration=iteration, value=value
)
```

官方 Timing 并不是 OTel span。
本次检查的一手公开面未提供 OpenTelemetry 写入 API。

### 4.2 Scalar / table / plot / media

**产品事实。** 显式写入入口是 `task.get_logger()` 或 `Logger.current_logger()`。
不要手工构造 `Logger`。[SDK-LOG]

官方例子：

```python
task = Task.init(project_name="examples", task_name="Scalar reporting")
logger = task.get_logger()

for i in range(100):
    logger.report_scalar(title="unified graph", series="series A", iteration=i, value=1. / (i + 1))
    logger.report_scalar(title="unified graph", series="series B", iteration=i, value=10. / (i + 1))

logger.report_single_value(name="metric A", value=486)
logger.flush()
```

[EX-S]

`report_single_value` 在源码里就是一次特殊 scalar：`title="Summary"`，`iteration=-(2**31)`。[SDK-LOG]

表进入 **PLOTS** 页，不是独立 table store：

```python
logger.report_table("table pd", "PD with index", iteration=iteration, table_plot=df)
```

[SDK-LOG] [`examples/reporting/pandas_reporting.py` @ v2.1.11](https://github.com/clearml/clearml/blob/v2.1.11/examples/reporting/pandas_reporting.py)

媒体进入 **DEBUG SAMPLES**。
官方建议后续还要用的输出走 artifact，debug 才走 media。
每种 title / series 只保留最后 X 份，默认配置为 5，负数表示不限。[LOGGER-FUND] [SDK-LOG]

```python
Logger.current_logger().report_media(
    'audio', 'tada', iteration=1,
    local_path=os.path.join('data_samples', 'sample.mp3'))
```

[EX-M]

Plotly / Matplotlib / histogram / confusion matrix / scatter 都走同一套 `title` + `series` + `iteration`，并带 `extra_layout` 这类展示参数。[SDK-LOG]

NaN / Inf 默认写成 `0`。
可用 `Logger.set_reporting_nan_value` / `set_reporting_inf_value` 改默认值。[LOGGER-FUND]

### 4.3 Artifact / model / config

**产品事实。** Artifact 是挂在 Task 上的对象，供以后取用、修改和接入后续 Task。[ART-FUND]

静态上传：

```python
task.upload_artifact('Pandas', artifact_object=df)
task.upload_artifact('dictionary', df.to_dict())
task.upload_artifact('local file', artifact_object=os.path.join('data_samples', 'dancing.jpg'))
```

[EX-A]

同名 artifact 会把旧文件换掉。[SDK-TASK]

动态同步的公开面只支持 `pandas.DataFrame`：`register_artifact` 在后台监视并上传变更。[SDK-TASK] [EX-A]

读取另一 Task 的 artifact：

```python
preprocess_task = Task.get_task(
    project_name='examples',
    task_name='Create artifact',
    task_filter={'status': ['completed']},
)
local_json = preprocess_task.artifacts['data file'].get_local_copy()
```

[EX-UA]

**产品事实。** Model 也作为 experiment artifact 保存，但拥有独立 Model ID，可脱离创建它的 Task 访问。[MODEL-FUND]

```python
output_model = OutputModel(task=task)
output_model.update_labels({"background": 0, "cat": 1, "dog": 2})
output_model.update_weights(register_uri=model_url)
```

[EX-MD]

**产品事实。** 配置有两条写入通道。[HP-FUND]

```python
parameters = task.connect(parameters)
complex_nested_dict_configuration = task.connect_configuration(
    complex_nested_dict_configuration, name='configuration dictionary')
config_file = task.connect_configuration(
    Path("data_samples") / "sample.json", name='json config file')
```

[EX-HP] [EX-CF]

`connect` 把对象的字段写成超参数，并在远程执行时用 UI / Server 上的值替换本地值。
`connect_configuration` 把字典或文件当成 blob 保存；ClearML 不理解其内部结构。[HP-FUND] [SDK-TASK]

### 4.4 研究判断

**研究判断。** 官方事实不是中立的「发生了什么」文档。
Logger 的 title / series / iteration 同时是存储键和图表坐标。
Artifact / Model / Configuration 更接近可再消费的对象。
资源监视是官方 Timing 的公开替代物，但写法和自定义 scalar 相同。

## 5. 问题 3：用户能否增加自定义事实

**产品事实。** 用户扩展走四条已有通道，没有独立的版本化 schema SPI。

| 通道 | 用户扩展什么 | 固定外壳 |
| --- | --- | --- |
| `Logger.report_*` | `title` / `series` 名字，以及该类型允许的值 | `metric` + `variant` + `iter` + 类型常量 |
| `Task.connect` / `set_parameters` | section + name + value | `ParamsItem`：`section`、`name`、`value`、`type`、`description`，值是字符串 |
| `Task.connect_configuration` | 具名 blob | `ConfigurationItem`：`name`、`value`、`type`、`description` |
| `Task.set_user_properties` | 不参与执行的人读属性 | name / value / description / type，全部按字符串字段描述 |
| `upload_artifact` | 具名对象 + 可选 `metadata` 字典 | 按对象类型选序列化格式；同名替换 |

[API-T] [API-E] [HP-FUND] [SDK-TASK]

User properties 的官方例子：

```python
task.set_user_properties(custom1='great', custom2=True)
task.set_user_properties(custom3=1, custom4=2.0)
task.set_user_properties(backbone={"type": int, "description": "network type", "value": "great"})
```

文档写：user properties 不影响 Task 执行，可在任何阶段修改，方便在任务表里加列、搜索和过滤。[HP-FUND] [EX-HP] [SDK-TASK]

源码把它们存在超参数的 `properties` section。
Server API 低于 2.9 时，`get_user_properties` 返回空字典并打日志。[SDK-TASK]

后端 `ParamsItem` 把 `value` 定为字符串。[API-T]

Scalar 事件的固定类型是 `training_stats_scalar`，字段是 `task`、`iter`、`metric`、`variant`、`value`、`timestamp`。
Plot 是 `plot` + `plot_str`。
Debug 媒体是 `training_debug_image` + `url` / `key`。[API-E]

`EventTypeEnum` 只有五种：`training_stats_scalar`、`training_stats_vector`、`training_debug_image`、`plot`、`log`。[API-E]

**产品事实。** 本次检查的一手公开面未提供用户声明 family、current schema、相邻 migration 或 sealed domain value 的 API。

**研究判断。** 用户扩展的是**名字和值，外加一条产品固定 envelope**。
不是任意 JSON 文档，也不是版本化 schema。
User properties 是固定四字段；configuration 是不透明 blob；Logger 事件是固定 event type。

**NiceEval 建议。** 不要学「给用户一把 title/series 或任意 metadata 字典」。
新事实必须有领域语义、版本族和 total producer obligation。
ClearML 证明：固定 envelope 足以支撑实验追踪，但撑不住「旧数据按新 schema 再分析」。

## 6. 问题 4：写入 API 是否要求预先决定图表

**产品事实。** Logger 写入与展示页签绑定。

| 调用 | 官方指定的 UI 落点 |
| --- | --- |
| `report_text` | RESULTS → CONSOLE |
| `report_scalar` / `report_single_value` | RESULTS → SCALARS |
| `report_table` / `report_plotly` / histogram / scatter | RESULTS → PLOTS |
| `report_media` / `report_image` | RESULTS → DEBUG SAMPLES |

[SDK-LOG] [LOGGER-FUND] [WEB-TRACK]

`report_scalar` 的 `title` 是图名，`series` 是同一图上的曲线名，`iteration` 是横轴。[SDK-LOG]

`report_matplotlib_figure(..., report_image=True)` 会把图改送到 debug samples，而不是 Plots。[SDK-LOG]

`report_table` / `report_histogram` 接受 `extra_layout`，直接传入 Plotly layout。[SDK-LOG]

**研究判断。** ClearML 的默认作者心智是「边跑边画」。
metric 的存储键就是图表键。
只有 artifact / model / configuration / user property 接近中立事实。

**NiceEval 建议。** 普通领域 API 只提交 sealed value。
图表声明必须留在 Report。
若把 `title`/`series` 写进持久事实，Analysis 就无法在不改历史的情况下改图。

## 7. 问题 5：读取与分析怎样选择、聚合并处理缺口

### 7.1 选择 Task

**产品事实。** 读取入口是同一个 `Task` 类。[SDK-OVER]

```python
a_task = Task.get_task(task_id='123456deadbeef')
a_task = Task.get_task(project_name='examples', task_name='artifacts')

task_list = Task.get_tasks(
    project_name='Example Project',
    allow_archived=False,
    task_filter={
        'system_tags': ['-archived'],
        'status': ['completed', 'published'],
        'type': ['training'],
        'search_text': 'reg_exp_text',
        'order_by': ['last_update'],
    },
)
```

[SDK-OVER] [SDK-TASK]

`get_tasks` 最多返回最近 500 个。
更早的要用 `Task.query_tasks()`。[SDK-TASK]

可按 metric 排序，但 metric / variant 名字必须先做 MD5：[SDK-OVER]

```python
title = hashlib.md5(str("testing").encode("utf-8")).hexdigest()
series = hashlib.md5(str("epoch_accuracy").encode("utf-8")).hexdigest()
tasks = Task.get_tasks(
    project_name='Example Project',
    task_filter={'order_by': [f'-last_metrics.{title}.{series}.max_value']},
)
```

本次检查的一手公开面未提供 Sample 分母、logical slot 或 nominal population API。

### 7.2 读回写入的事实

**产品事实。**

```python
# 可能被降采样，最多 5000 点
scalars = task.get_reported_scalars(x_axis='iter')
# 全量 scroll events
all_scalars = task.get_all_reported_scalars(x_axis='iter')
# last / min / max
last = task.get_last_scalar_metrics()
plots = task.get_reported_plots()
params = task.get_parameters()
props = task.get_user_properties()
```

`get_reported_scalars` 走 `events.ScalarMetricsIterHistogramRequest`。
失败或空响应返回 `{}`。
即使 `max_samples` 更大，也限制在 5000。[SDK-BI]

`get_all_reported_scalars` 按 `event_type="training_stats_scalar"` 分页拉取。[SDK-BI]

`get_last_scalar_metrics` 读 Task 文档上的 `last_metrics`，形状是 `{title: {series: {last, min, max}}}`。[SDK-TASK]

`get_reported_single_values` 要求 Server API >= 2.20，否则抛 `ValueError`。[SDK-BI]

`get_parameters` 返回扁平 `'section/parameter': 'value'`。
API < 2.9 时改读 `execution.parameters`。
`backwards_compatibility=True` 时，旧的 `legacy` 参数出现在根级而不是 `Args/` 下。[SDK-BI] [SDK-OVER]

比较页是 Web UI 功能，不是 SDK 方法。
可选 Tasks 后点 **COMPARE**，看 details、hyperparameters、scalars、plots、debug samples。
标量可看 last / min / max，可导出 CSV。
超参数可看平行坐标和散点。[WEB-CMP] [FAQ]

### 7.3 missing / partial / unsupported

**产品事实。** 公开读取面用空值或异常表达缺口，没有穷尽状态枚举：

| 情况 | 公开行为 |
| --- | --- |
| 拉 scalar 失败 | 返回 `{}` |
| 没有 single value | 返回 `None` |
| Server 太旧，没有 user properties | 返回 `{}` |
| Server 太旧，没有 single values | 抛 `ValueError` |
| Server 太旧，没有多 configuration | 抛 `ValueError` |
| NaN / Inf | 默认写成 `0` |
| Console UI | 只显示最后数百行；全文要下载 |
| media | 每种 title / series 只留最后 X 份 |
| `get_tasks` | 只给最近 500 个 |

[SDK-BI] [SDK-TASK] [LOGGER-FUND] [FAQ]

**研究判断。** ClearML 的分析是「按 Task 集合做 UI 比较和 SDK 拉曲线」。
它不固定分母，也不把 missing / partial / unsupported 收成 Analysis 状态。
降采样发生在默认读 API 里，调用方必须知道还有 `get_all_reported_scalars`。

**NiceEval 建议。** Analysis 必须显式选择 Run、固定分母，并保留每行状态、issues 与 refs。
不要把空字典、`None` 和静默 `0` 当成三种缺口语义。

## 8. 问题 6：图表、Dashboard 与 Report 怎样消费结果

### 8.1 单 Task 展示

**产品事实。** 每个 Task 有固定页签：EXECUTION、CONFIGURATION、ARTIFACTS、INFO、CONSOLE、SCALARS、PLOTS、DEBUG SAMPLES。[WEB-TRACK]

这些页签直接消费写入时的 title / series / artifact 名。
作者不另写展示声明。

项目 OVERVIEW 可加 metric snapshot：选 metric / variant 的 LAST、MIN、MAX，看跨 Task 的点图。
项目描述是 Markdown，可放 Task 链接。[WEB-OV]

### 8.2 Dashboard

**产品事实。** Project Dashboard 是 Pro 方案应用，不是开源 Server 的默认可编程面。
它聚合 Task 状态、选定 metric 随时间变化、GPU 与 worker 用量，并可向 Slack 发失败提醒。
配置靠启动表单：监控范围、metric title / series、趋势方向。
可导出 / 导入 JSON 配置，也可 clone 旧实例。[WEB-DASH]

本次检查的一手公开面未提供用 Python 定义 Dashboard 布局的 SDK。

### 8.3 Reports

**产品事实。** ClearML Reports 是项目里的可编辑 Markdown 文档。
支持标题、列表、表格、代码块、图片，以及嵌入 Task / model / app 的 plots 与 debug samples。
Publish 后锁定编辑。可分享 URL，可下载 PDF，可复制 Markdown。[WEB-RPT]

嵌入方式是从已有图上复制 iframe，再贴进报告：

```
<iframe
  src="<web_server>/widgets/?type=sample&objectType=task&objects=<object_id>&xaxis=iter&metrics=<metric_name>&variants=Plot%20as%20an%20image&company=<company/workspace_id>"
  width="100%" height="400"
```

可视化会随对象更新而直播更新。

**产品事实。** `docs/references/api/reports.md` 与 `docs/references/enterprise/reports.md` 都是占位符。
SDK 源码没有 `class Report`。
本次检查的一手公开面未提供代码定义 Report 页面树的 API。[API-STUB]

### 8.4 研究判断与 NiceEval 建议

**研究判断。** ClearML 的展示作者面是 UI。
普通作者不写 Report 代码；他们在写入时已经决定了图。
Report 是叙事层，把已画好的 widget 嵌进 Markdown。
这与 NiceEval「Analysis fields → typed `ReportData` → 组件」相反。

**NiceEval 建议。** 可以吸收「报告引用已有分析结果，而不是再查库」。
不要吸收「写入即出图」和「报告等于 Markdown + 直播 iframe」。
NiceEval Report 必须能在不改历史事实的情况下改页面。

## 9. 问题 7：历史数据怎样面对 SDK、schema 与产品升级

### 9.1 Server 与数据库

**产品事实。** 公开升级文档处理的是基础设施换代，不是用户自定义事实的 migration：

| 升级 | 官方要求 |
| --- | --- |
| Trains Server ≤0.15 → ClearML | 先跑 Elasticsearch 5.6 → 7.6 数据迁移脚本 |

[UPG-LNX] [UPG-ES] [UPG-MONGO]

Elasticsearch 为 scalar / plot / debug image / log 准备了不同 index template。[SRV-REL 相关树]

### 9.2 SDK / API schema

**产品事实。** SDK 内置多份 backend service 定义：`v2_9`、`v2_13`、`v2_20`、`v2_23`。
`Session.api_version` 默认 `"2.9"`，连接后改成 Server 宣告的版本。[SESS]

| 能力 | 最低 API | 旧 Server 行为 |
| --- | --- | --- |
| user properties、多 configuration | 2.9 | 读返回 `{}`，或写时报错要求升级 |
| single value metrics | 2.20 | 抛 `ValueError` |
| `CompletedRequest` 的 publish 语义 | 2.20 | 走旧完成路径 |

[SDK-TASK] [SDK-BI]

`get_parameters(backwards_compatibility=True)` 专门兼容 API < 2.9 的无 section 参数。[SDK-BI]

### 9.3 谁声明 migration，何时重写持久数据

**产品事实。** 声明 migration 的是 Server 发布与运维脚本，不是应用作者，也不是领域 SDK。
公开文档要求先关机、备份，再跑官方脚本；成功后旧 Trains / 旧 Mongo 数据目录不再给旧 Server 用。[UPG-ES] [UPG-MONGO]

本次检查的一手公开面未提供：

- 用户为自己的 title / series / user property 声明相邻 migration
- 按 family 重写历史 scalar / artifact
- migration plan / authorization / receipt
- 把旧 blob configuration 升到新结构的官方转换器

Reports 是直播 embed。
本次检查的一手公开面未提供「升完级后冻结再分析、再生成报告」的独立 API。

**研究判断。** ClearML 把兼容性放在 Server 与 SDK 的版本协商上。
旧客户端用旧字段；新能力直接拒绝。
这能保护平台自己的 envelope，但不能让第三方事实带着版本族演进。

**NiceEval 建议。** migration 必须由 application maintainer 对 exact snapshot 显式 plan / authorize。
领域 SDK 只声明相邻 converter。
不要学 ClearML 把「换 Mongo / ES」和「改用户事实含义」混成同一次运维动作。

## 10. 问题 8：四类作者分别看到几层

| 角色 | ClearML 里实际看见的入口 | 层数 | 不必理解的东西 |
| --- | --- | --- | --- |
| 普通应用作者 | `Task.init`；可选 `get_logger` / `connect` / `upload_artifact` | 1 层：Task | Server schema、ES index、API 版本、migration 脚本 |
| 扩展作者 | 同一套 `Logger.report_*`、`set_user_properties`、`connect_configuration`、`upload_artifact` | 仍是 Task / Logger，没有第二套 SPI | family、adapter、installation、producer obligation |
| 分析作者 | `Task.get_tasks` / `get_reported_scalars` / `get_parameters`；或 Web COMPARE | 同一 `Task` 对象，外加 UI 比较页 | Analysis population、denominator、穷尽状态 |
| 报告作者 | Web Markdown 编辑器 + iframe embed；Pro Dashboard 表单 | UI 层，不是代码层 | `ReportData`、PageFamily、静态 fields |

[SDK-OVER] [WEB-CMP] [WEB-RPT] [WEB-DASH]

**产品事实。** 文档把 Task 同时叫做 Task 与 experiment。
SDK 负责写入与读取；Web-App 负责分析、比较、复制和管理。[SDK-TASK]

**研究判断。** ClearML 用「一个 Task 对象 + 固定 UI」压扁了 NiceEval 的三层。
代价是：扩展作者无法单独发布版本化事实；分析作者无法脱离 title/series；报告作者无法在代码里组合 fields。

**NiceEval 建议。** 保持三层 import surface：

```text
普通 Eval 作者     → 领域 API
领域 SDK 作者     → adapter + installation + 领域 Analysis fields
Analysis 作者     → analyze() / Dimension / Measure
Report 作者       → aggregate() + 组件
application       → 显式安装与 migration
```

同一个人可以戴多顶帽子，但 authority 不能合成一个 `Task`。

## 11. 四个 NiceEval 场景

### 11.1 官方 OTel Timing

**产品事实。** 本次检查的一手公开面未提供 OTel exporter、span 写入或 Timing attachment。

最接近的官方计时 / 资源事实是 `auto_resource_monitoring=True` 时的 `:monitor:gpu` / `:monitor:machine` scalars。[SDK-TASK] [MON] [LOGGER-FUND]

它们与用户 `report_scalar` 走同一存储与同一 SCALARS 页。
没有 sealed Timing value，没有 official namespace，也没有独立 projection。

**研究判断。** ClearML 把「官方资源监视」做成一条内置 scalar 系列，而不是一条与用户事实分权的官方 adapter。

**NiceEval 建议。** 官方 Timing 必须走不导出的 official adapter，与第三方 GPU 同形。
不要把官方事实写成一组魔法 title。

### 11.2 用户 GPU Energy

**产品事实。** 用户若要保存 GPU 能耗，公开可调用的是：

```python
logger.report_scalar(title="gpu", series="energy_j", iteration=i, value=joules)
# 或
task.set_user_properties(gpu_energy_j=joules)
# 或
task.upload_artifact("gpu_energy", {"joules": joules})
```

没有 `gpuEnergy({ meter })` 这种领域 Plugin。
没有 adapter、installation 或 `analyzeGpuEnergy()`。
Analysis / Report 作者若要读它，只能按自己写过的 title / artifact 名去取。

**研究判断。** 这正是「扩展名字和值」路径。
它很快，但没有 total producer obligation：不写就等于没有，无法表达 empty / unavailable。

**NiceEval 建议。** GPU Energy 必须先形成 sealed domain value，再经 adapter 变成版本化 Attachment。
普通 Eval 只看到 `gpuEnergy({ meter })`。

### 11.3 Assertion 与 Evidence

**产品事实。** 本次检查的一手公开面未提供 Assertion、Evidence、Claim 或 evaluator 身份类型。

最接近的做法是 `report_table` 放一张判定表，或 `upload_artifact` 保存某份 JSON，或 `report_text` 打一行日志。
这些对象没有 evaluator 版本，也没有 evidence basis。

**研究判断。** ClearML 把评价当成又一条 metric 或又一份 artifact。
它不区分 Observation 与 Claim。

**NiceEval 建议。** Assertion 必须拥有自己的官方 family 与 Evidence。
不要让报告作者从任意 table / artifact 反推判定。

### 11.4 旧数据升级后再分析、再报告

**产品事实。** Server 升级会迁移 Mongo / Elasticsearch 数据目录，并可能重建索引。[UPG-LNX] [SRV-MIG]

SDK 读旧超参数时有 `backwards_compatibility`。
新读 API 在旧 Server 上直接失败或返回空。[SDK-BI]

Reports 的 embed 是直播查询，升级后仍指向同一 Task ID 与 metric 名。[WEB-RPT]

本次检查的一手公开面未提供：把旧 user property 升成新 schema、重算 Analysis、再生成一份冻结 Report 的官方流程。

**研究判断。** ClearML 的「升级后再看」依赖直播 UI 与 Task ID 稳定。
它不保证旧名字在新含义下仍可解释，也不产出 migration receipt。

**NiceEval 建议。** 旧数据必须先经过显式 migration，再在新的 frozen view 上跑 Analysis 与 Report。
直播 embed 不能代替这条链。

## 12. 与 NiceEval 词表的对应

| ClearML | 不能直接当成 | 原因 |
| --- | --- | --- |
| Task | Record 或 Attempt | Task 默认可复用 ID、可续跑、可 reset 删除输出；Draft 仍可编辑 |
| Task ID | Record revision | 它标识可变会话，不标识不可变 snapshot |
| Logger title / series | RecordAttachment family | 名字即图表键，没有版本 |
| `ParamsItem` / user properties | 版本化 Attachment | 固定字符串 envelope，没有相邻 migration |
| `upload_artifact` | RecordAttachment value | 同名替换；没有 owner-specific total obligation |
| `get_tasks` + COMPARE | Analysis | 没有分母、population 或穷尽状态 |
| Web Reports / Dashboard | Report | Markdown + 直播 widget / Pro 表单，不是 typed `ReportData` |
| Server mongo/ES 脚本 | Record migration plan | 运维换引擎，不是应用授权的 family 转换 |

**NiceEval 建议。** 从 ClearML 只取闭环形状：用户代码运行 → SDK 写入 → 同一产品读取。
三层心智、adapter SPI 与显式 migration 必须留在 NiceEval。

## 13. 值得吸收 / 不应复制 / 尚缺证据

### 值得吸收

- 最小闭环：`Task.init` 之后用户代码照常跑，同一产品立刻能读、能比、能看。[TASK-FUND] [WEB-TRACK]
- 自动捕获执行上下文：Git、未提交改动、Python 包清单、argparse。[SDK-OVER]
- 读取与写入共用一个对象：`Task.get_task` 后直接 `get_reported_scalars` / `artifacts[...].get_local_copy()`。[SDK-OVER] [EX-UA]
- 把「影响执行的超参数」和「不参与执行的 user properties」分开。[HP-FUND]
- 把「结构化 name/value」和「不透明 configuration blob」分开。[HP-FUND]
- 比较页一等公民：last / min / max、平行坐标、散点、叠加曲线。[WEB-CMP]
- 离线会话再导入，避免开发机必须连 Server。[SDK-TASK]
- 用 API 版本门控新读法，并给旧参数留 `backwards_compatibility`。[SDK-BI] [SESS]
- Model 有独立 ID，可做血缘，而不是永远依附创建它的 Task。[MODEL-FUND]

### 不应复制

- 默认复用 Task ID 并删除上次输出。[SDK-TASK] [SDK-OVER]
- 写入 API 绑定展示：`title`/`series` 既是存储键也是图。[SDK-LOG]
- 用户扩展停在名字和值，没有版本化 schema，也没有 total producer obligation。[API-T] [API-E]
- 分析没有分母与穷尽状态；缺口用 `{}`、`None` 或静默 `0` 表示。[SDK-BI] [LOGGER-FUND]
- Report 不是代码可定义的闭合语义树，而是 Markdown + 直播 iframe。[WEB-RPT]
- Dashboard 放进付费应用表单，而不是与写入共用的声明。[WEB-DASH]
- 把基础设施换库当成用户事实升级。[UPG-LNX]
- 普通作者、扩展作者、分析作者、报告作者共用一个 `Task` 心智。[SDK-TASK]
- NaN / Inf 默认变成 `0`，media 默认丢弃旧样本。[LOGGER-FUND] [SDK-LOG]

### 尚缺证据

- Web 状态名与 SDK `TaskStatusEnum` 的官方完整映射。
- 可用的 REST `tasks` / `events` / `reports` 正文；当前文档页是占位符。[API-STUB]
- Report Markdown 是否有版本，以及直播 embed 能否固定到某次 iteration。
- Publish 之后是否仍允许追加 scalar；公开页只说 Published 只读，未逐项列出禁止的写入 API。[TASK-FUND]
- 用户自定义 title / configuration 的演进规则。
- OTel、Assertion、Evidence 的任何公开写入面。
- Server 2.4.0 实际绑定的 Mongo 大版本；升级文档写 6.x，启动器检查 7.0 → 8.0。[UPG-LNX] [SRV-MIG]
- 开源 Web UI 如何把 `created` 显示成 Draft；本次未把 `clearml-web` 源码当作产品契约展开。
